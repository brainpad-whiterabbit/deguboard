## 概要

e1 で動くようになった画面（Web UI と VS Code 拡張の Webview）の見た目と使い勝手を整える。機能を足すのではなく、カンバン・バックログ・チケット詳細・Epic・Iteration の各画面を、配色・余白・文字・レイアウト・操作の手触りの面で揃え、迷わず使える状態にする。

## 範囲

- 画面全体の見た目の統一：配色・余白・文字サイズ・コンポーネントの形を一貫させる（自前 CSS、Tailwind は採らない）
- VS Code の Webview でテーマ（ライト・ダーク）に馴染む配色
- カンバン（UI-2）：カードの情報量と並び、ドラッグ＆ドロップの手触り、拒否時の表示
- バックログ（UI-3）：一覧の読みやすさ、検索と絞り込みの置き方
- チケット詳細（UI-4）：本文と属性の配置、編集の導線
- Epic（UI-10）・Iteration（UI-5）：一覧と進捗の見せ方
- 同期の印（UI-6）とエラー・空状態・読み込み中の表示
- 画面幅が狭いとき（Webview のサイドパネル）の崩れを直す

## 含まない

- 新しい画面や機能（Run の画面は e3、Plan は e2）
- Core のコマンドや HTTP の変更を伴うもの。必要になったら別のチケットに切り出す
