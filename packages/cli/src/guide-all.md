# 一気通し（all）

Iteration かチケットを、割り当てからリリースまでの段階で続けて進める。ここには段階の順と進み方だけを書く。各段階の手順は、段階に入るときにそのトピックを読んで従う。

## 対象を決める

- Iteration（`s3`）：その Iteration のチケットと、そこに入れる候補（Iteration に入っていない todo）。候補を扱うのは割り当ての段階だけ
- チケットの ID（1 つ以上）：そのチケットを扱う。見直しとリリースは、チケットの Iteration のチケットがすべて done になったときだけ、その Iteration を対象に行う
- 指定が空：`dg guide release` の「対象を決める」と同じ
- `--no-assign`：割り当ての段階を飛ばす。点検で Iteration に入れる案が出ても反映せず、終わりの報告に残す
- `--auto`：下の「`--auto` で自動で選ぶ」。`--no-assign` と一緒に指定できる

以下の `<S>` は対象の Iteration。聞かずに始め、閉じるのは人の指示で行う。

## 段階

| 段階     | 読むトピック                                                       | 承認を求める場所                 |
| -------- | ------------------------------------------------------------------ | -------------------------------- |
| 割り当て | `dg guide assign`（`<S>` に入れるか入れないかだけ）               | 入れる行                         |
| 点検     | `dg guide check`                                                   | 直す行、削除・abandoned・閉じる  |
| 計画     | `dg guide plan`                                                    | Plan                             |
| 作業     | `dg guide work`・`dg guide parallel`。マージのたびに `dg guide done` | PR ごとのマージ                  |
| 見直し   | `dg guide audit`                                                   | 指摘の表                         |
| リリース | `dg guide release`（手順がなければ `dg guide done`）               | リリースの PR のマージ・公開・閉じる |

## 今の段階を求める

始めるときと各段階を終えたときに、`dg --json --actor agent sync` のあと `iteration show <S>`・`ticket list`・`plan list --status open` と `plan show <p>`・`ticket list --label audit-<S>` を読み、次の順で最初に当たるものを今の段階にする。

1. 割り当て：この実行で割り当てを終えておらず、`<S>` が見直し済みでなく、Iteration に入っていない todo（ラベル `audit-<S>` を除く）があり、`--no-assign` がない
2. 点検：この実行でまだ点検していない（起動のたびに 1 回）
3. 計画：対象のチケットを含む承認待ちの Plan がある、または開いた Plan に入っていない todo がある
4. 作業：対象のチケットを含む承認済みの Plan に、done でないチケットがある（`dg next` が手を返す対象）
5. 見直し：対象のチケットがすべて done か abandoned で、`<S>` が見直し済みでない
6. リリース：対象のチケットがすべて done か abandoned で、`<S>` が見直し済み
7. どれにも当たらない（PR のない in_progress だけ、マージ待ちの review だけ、など）：状態を示して止まる

- **見直し済み**：ラベル `audit-<S>` のチケットがある（状態と所属は問わない）か、この実行で見直しを終えた。見直しで起票したチケットを進めて done に戻っても、もう一度は見直さずにリリースに進む
- 同じ段階が続けて求められ、状態が変わらない（承認が得られなかった、マージを待っている）ときは、繰り返さずに状態を示して止まる。同じ引数で起動し直せば、状態から求め直して再開する

## 段階の間の進み方

- **段階の間は止まらない**：各段階の「次の手順を選ぶ」は聞かず、上の求め方で次の段階に進む。求め方で決まらない行き先を勧められたときだけ聞く
- **承認の場所は残す**：上の表と各段階の手順が承認を求める操作は、そのとおりに承認を得る。選択肢には「ここで止める」を入れる
- **マージは人が行う**：PR を出したら、マージは人に頼むか承認を得てから行う。マージを待つ間も、Plan のほかのチケットを進め、なければ止まる

## `--auto` で自動で選ぶ

`--auto` のときは、承認を求める場面のうち、勧める選択肢があって `dg` で戻せる判断を、聞かずに勧める選択肢で進める。選んだものと判断の材料はその場で短く示す。

- **自動で選ぶ**：割り当て・点検の直す行（直し方が 1 つに決まるもの）・Plan の承認（`plan approve`）・見直しの指摘の表（「直さない」以外を反映する）・照合の後の受け入れ条件の確認。PR のマージは、`auto.merge` が true（今の設定：`{{auto.merge}}`）のときだけ、`dg guide review` の「品質ゲート」を満たす PR を `dg --json --actor agent pr merge <id>` で行う。満たさなければ、満たさなかった条件を示して承認を求めて止まる
- **自動にしない（承認を求めて止まる）**：`auto.merge` が false のときのマージ。リリースの PR のマージと公開（タグ・配布先）は `auto.merge` によらず聞く。チケットの削除・abandoned、Epic・Iteration・Plan を閉じる・再開する。Plan の待ち（`after`）と範囲を変えること、`--force` の付く操作。勧めるものがない判断と、選択肢にできない答え
- 実装が失敗したチケットは `dg guide parallel` のとおり todo に戻し、それを待たないチケットを進める。手直し・見直しが返らないチケットは todo に戻さず、`dg guide review` の「終わり方」に従う
- 自動にするのは戻せる判断と、`auto.merge` で明示したマージだけ。戻しにくい操作の前には人の判断を残す

## 文脈の扱い

親は段階の進行・承認・`dg` の読み書きだけを行う（計画の段階を除く）。チケットの実装は件数にかかわらずチケットごとにサブエージェントに任せ、作業の段階は `dg guide parallel` に従う。

## 結果を伝える

流れの終わりに、段階ごとの結果を伝える（割り当て・点検で直した行・承認した Plan・出した PR とマージ・起票したチケット・リリースした版と Iteration の状態・反映しなかった割り当ての案・残ったチケット）。`--auto` のときは、自動で選んだ判断と、自動でマージした PR の条件の確かめの結果も伝える。
