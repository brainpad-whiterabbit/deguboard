# 見直しと品質ゲート（review）

PR を人に出す前（`dg guide work`）と、自動でマージする前（`dg guide all` の `--auto`）の両方で確かめる品質ゲートと、実装したのとは別のサブエージェントによる見直し・上限付きの修正ループ。work と all はここを参照する。記録と Git・PR の事実で判定できる条件（受け入れ条件・見直し・修正ループの回数・衝突）は `dg --json --actor agent gate <id> --for ready`（PR を出す前）・`--for merge`（マージの前）が判定し、条件の正本は `dg gate --help`。`dg hooks install` でフックを入れていれば、`gh pr ready`・`gh pr merge` の前にフックが `dg gate` を呼び、満たさなければ止める（止めた理由が返る）。下の例外（見直し役を起動できない・上限を超えて ready にする・版上げの PR で見直しを省く・人が回数を指示した）で満たさないまま進めるのは人の判断なので、フックが止めたら人に `gh pr ready`・`gh pr merge` を打ってもらう。フックの Bash の判定は字句の手がかりで、書き間違いを防ぐためのもの（すり抜けを防ぎきるものではない）なので、止められなくてもゲートを自分で `dg gate` で確かめる。進めるセッション（親。サブエージェントを使わずにひとりで進めるなら自分）が見直し役を起動し、指摘を振り分けて回数を数える。サブエージェントを起動できない環境では、見直しを人に頼む（PR を ready にして、見直していないことを報告する）。

## 品質ゲート

| 条件                         | 確かめ方                                                                                                                           | PR を出す前                                                            | マージの前                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 検査が通る                   | リポジトリの規約にある検査（書式・lint・テスト）が、ブランチの最新のコミットで通る。CI があれば CI も通っている                    | 要る                                                                   | 要る                                                                    |
| 受け入れ条件                 | `dg gate <id> --for merge` の `acceptance`（`ticket show <id>` の `acceptance`）                                                     | 確かめた項目に印がある。付けられない項目は PR の本文と報告に理由を書く | すべて印あり                                                            |
| 別のサブエージェントの見直し | 下の「見直す」で、重い指摘が残っていない（版上げの例外は下）。`dg gate` の `review`（最後の push より後の見直しが通っている）と `fix_rounds` | 要る                                                                   | 要る。PR を出す前の見直しの後にブランチが変わっていなければ、それを使う |
| base と衝突しない            | `dg gate <id> --for merge` の `mergeable`（gh の `mergeable` が `MERGEABLE`）。マージで base が進むとほかの PR は `UNKNOWN` になるので、マージの前に確かめ直す。衝突を直して push したら、`review` のため差分を見直し直す | 見ない                                                                 | 要る                                                                    |

条件を確かめた後にブランチを直したら、検査と受け入れ条件を確かめ直す。

- **版上げの PR は見直しを省ける**：リポジトリのリリースの手順で作る版上げの PR（`dg guide release`）は、変更が版の数字（package.json などの `version`）と、手順が決めた CHANGELOG・ロックファイルだけで、コード・文書・手順を変えないときに限り、別のサブエージェントの見直しを省いてよい。版上げの PR のマージは `auto.merge` によらず人が承認する（`dg guide all`）ので、人の承認が見直しの代わりになる。それ以外のファイルを 1 つでも変える版上げの PR は省かない。省いたら PR の本文に、版上げだけで見直しを省いたと書く。ほかの条件（検査・受け入れ条件・衝突なし）は省かない

## 見直す

実装者は PR を draft で作って返す（`gh pr create --draft`。実装の Run は親の `ticket update --pr` が閉じる）。draft のうちは照合が review に進めない。親は、実装したのとは別のサブエージェントを見直し役として起動する。見直し役は Plan の段階によらず親のモデルで起動する（品質ゲートを弱めない）。

- **渡す**：文は `dg --json --actor agent brief <id> --role review` が組む（`dg next` の brief と同じ）。チケットの本文（`dg --json --actor agent ticket show <id>`）・ブランチと worktree のパス・差分の取り方（`git fetch {{git.remote}}` の後 `git diff {{git.remote}}/{{git.base_branch}}...<ブランチ>`）・規約の場所を入れる。一時ファイルの置き場所は親が文に添える。文の先頭の印で、フックが `review` の Run を開き閉じる。見直し役が `--agent` を渡すときは、自分の Adapter の名前。Claude Code なら `claude-code`。`claude-code-reviewer` のような役割名にすると使用量とモデル名を取り込めない
- **見る**：受け入れ条件の漏れ・不具合・文書との食い違い・規約の違反・範囲の外の変更。チケット本文に `## 参考` 節があれば、そこに書いたファイルと差分で変えたファイルを見比べ、参考節にないところへの大きな広がりと、参考節のファイルに触れていない変更を「参考節との食い違い」として返す（節がなければ見比べない。範囲の外の変更でもあるものは「範囲の外の指摘」で扱う）
- **Run**：`review` の Run は文の印でフックが開き閉じる。見直し役は一覧を返す前に `dg --json --actor agent run review-result <id> --heavy <重い指摘の数> --light <軽い指摘の数>`（重い指摘がなければ `--passed` も付ける）で結果を書く（下の「Run の分け方」）。見直し役は 1 つの Run で 1 枚のチケットを見る。複数のチケットはチケットごとに見直し役を起動する（同じ会話で Run を重ねると、応答は後に始めた Run にだけ数える）
- **しない**：ファイルを変える・コミットする・push する・Run のほかに `dg` に書き込む
- **返す**：指摘を重い（受け入れ条件の漏れ・不具合・文書との食い違い・規約の違反）と軽い（言い回し・好み）に分けた一覧（ファイルと行・理由・直し方）と、最新のコミットで回した検査の結果。参考節との食い違いは軽い指摘の欄に分けて書き、重い指摘に数えない

## 指摘を直す（修正ループ）

- **重い指摘と、受け入れ条件の文言に当たる軽い指摘**：新しいサブエージェント（実装者と同じモデル）を起動して、同じブランチで直させて push させる。同じ会話の続き（SendMessage）で頼まない（続きの起動では印が読まれず、手直しの Run が開かない）。渡すのは `dg --json --actor agent brief <id> --role fix --findings <指摘の一覧>` の文で、文の先頭の印でフックが `fix` の Run を開き（開いたままの前の手直しの Run はそこで区切って閉じる）、文に、直し始める前に `dg --json --actor agent run retry-reason <id> --reason <指摘の要約>` で理由を書く手順が入る（サブエージェントは claim・`run start`・`run finish` を使わない。下の「Run の分け方」）。親が自分で直すなら、親が同じチケットをもう一度 `dg --json --actor agent ticket claim <id> --retry-reason <指摘の要約>` で claim して直す。ほかの軽い指摘は直すかを実装者に任せる。直さなかった軽い指摘（参考節との食い違いを含む）と理由は、見直しは実装者が本文を書いた後に返るので、親が PR の本文に書き足す（`gh pr edit`。既存の本文は残す）。手直し（fix）が返すときも、直さなかった軽い指摘と理由を含める。参考節との食い違いは修正ループの回数にも数えない
- **直した後**：親が最新のコミットで検査を回し直し、受け入れ条件を確かめ直す。重い指摘を直したときは、見直し役（新しく起動してよい）に見直し直させる。軽い指摘だけを直して push したときも、`dg gate` の `review` は最後の push より後の見直しを求めるので、見直し役に前回からの差分だけを見直させて結果を記録させる（重い指摘が出なければ修正ループの回数に数えない）。印で頼んだ手直しの Run は、サブエージェントが push して返ったときにフックが閉じる。親のもう一度の claim が開いた手直しの Run は、次の見直しの `review` の Run の開始か PR の ready を区切りとして、その後の `sync`（`dg guide work` の手順 7 など）が最後の push の時刻で閉じる。`dg next` は、開いたままの手直しの Run より後に push があれば見直しの手を返す。途中の push と直し終えた push はデータで区別できないので、手直しのサブエージェントが返るまで親は `dg next` を呼ばない
- **範囲の外の指摘**：そのチケットで直さず、`dg guide import` の起票の候補として人に示す
- **上限**：重い指摘を直すのは 2 回まで（見直しは最初を含めて 3 回まで）。回数は親が、重い指摘を直した回で数える（`fix` の Run の数では数えない。人のレビューの手直しや始め直した Run も `fix` になる）。人が回数を指示したらそれに従う

## Run の分け方

実装・見直し・手直しは別の Run に分け、`metrics show --step` で量を見る。step は Workflow の `steps` から選び（`dg guide run`）、作業するエージェント自身が開く（実装を委譲する親は `--no-run` で claim し、実装・手直しを委譲するなら `brief` の文の先頭の印でフックが開く。サブエージェントは claim しない）。使用量は Run の ID を最初に含む会話記録から取るので、親が代わりに開くと作業した分を数えない。

| 作業                  | step        | 始める                                                | 閉じる                                                      |
| --------------------- | ----------- | ----------------------------------------------------- | ----------------------------------------------------------- |
| 実装して PR を作る    | `implement` | claim（`--no-run` なら run start）                    | `ticket update --pr`（PR の作成時刻）                       |
| 見直し役の見直し      | `review`    | 見直しの前（サブエージェントは文の印でフックが開く。前景で見直すなら run start）                               | 指摘の一覧を返す前（`run review-result` で結果を書いてから。指摘の有無によらず `success`） |
| 修正ループの 1 回・人のレビューの手直し | `fix` | サブエージェントは文の印でフックが開く（前の手直しの Run を区切って閉じる）。親や人が自分で直すなら、直し始める前に自分の PR のあるチケットを `ticket claim <id> --retry-reason <指摘の要約>` | 印の Run はサブエージェントが push して返ったときにフックが閉じる。claim の Run は `sync` が次の区切り（次の見直しの Run の開始・PR の ready など。`guide run` の「Run を記録する」）で閉じる（その後の最後の push の時刻。なければ区切りの時刻） |

- **やり直しの理由**：手直し（修正ループと人のレビュー）は、直す指摘を、印で頼んだサブエージェントなら `run retry-reason <id> --reason <直した指摘の要約>` で開いている手直しの Run に書き足し（Run がまだない前景の起動では保留になり、フックが閉じるときに結び付ける）、自分で直すならもう一度の claim の `--retry-reason <直した指摘の要約>` に書いて開く（自分で `run finish` で閉じるなら `--retry-reason` は省く。渡すと claim で入れた理由が置き換わる）。書くのは直した指摘（見直し役・人のレビュー）だけで、指摘 1 件に 1 つ繰り返す。検査の失敗を直したことは書かない。回数は理由の数になる（`--retries` は省く）。要約は 1 行で、秘密・コマンドの文字列・パスは書かない。実装と見直しの Run には付けない
- **合う step がない**：Workflow に `fix`・`review` がなければ、`dg guide run` の「Run を記録する」の代わりの step で記録する
- **直せなかった**：手直しを途中でやめたら、印で頼んだサブエージェントは Run を閉じずに理由を親に返す（親が `run finish <Run の ID> --result failure --error <理由>` で閉じる）。自分で claim して直していたなら、自分で同じく閉じる
- **続けられない・返らない**：直し直すときは、新しいサブエージェントを `brief --role fix` の文（先頭の印）で起動する（フックが前の手直しの Run を区切って閉じ、新しい `fix` の Run を開く）。返らないまま止まった Run は、`dg guide parallel` のとおり親が `interrupted` で閉じる（その後は下の「終わり方」）

## 終わり方

- **通った**：親が `gh pr ready <PR>` で PR を出し（人にレビューを頼む）、`dg guide work` の手順 7（`sync`）に進む
- **上限を超えた**（重い指摘が残る）：3 回目の手直しは始めない。PR は draft のまま、チケットは in_progress のまま置き、残った指摘・直した回数・PR を人に報告して、続けて直すか・ready にするか・やめる（`ticket unclaim`）かを聞く。実装の失敗とは違い、自分では unclaim しない。人を待つ間も、それを待たないチケットは進める
- **手直しが failure で返った・返らない**：上限を超えたときと同じく、PR は draft・チケットは in_progress のまま置いて人に報告する。返らずに `interrupted` で閉じた手直しの Run（閉じ損ねた Run を含む）も同じ扱い。unclaim しない（`dg guide work` の unclaim は実装の失敗と、実装を途中でやめたときだけ）
- **手直しが push なしで返って止まった**（待ちの印の付いた Run。`dg next` は `wait_human` を返す）：親は続けさせるなら同じ会話に続きを送り（印が消え、同じ Run が続く）、質問なら人に伝えて答えを送る。直さないと決めたら、その Run を `run finish <Run の ID> --result failure --error <理由>` で閉じてよいかを人に聞く（手直しを途中でやめたときと同じ）。続きが push で終わったら、印で頼んだ手直しの Run は返ったときにフックが閉じる（自分のもう一度の claim で開いたものは `sync` が区切りで閉じる）
- **見直し役が閉じ損ねた・返らない**：親が `dg guide run` の「閉じ損ねた Run を閉じる」のとおり見直し役の Run（代わりの step で記録したものを含む。step ではなく起動したサブエージェントで見分ける）を `interrupted` で閉じ、見直し役を起動し直す（新しい見直し役が自分の Run を始める）。PR は draft・チケットは in_progress のまま置き、unclaim しない。起動し直しても返らなければ「見直し役を起動できない」に従う
- **見直し役を起動できない**：PR を ready にし（フックが `dg gate` で止めたら、人に `gh pr ready` を打ってもらう）、見直していないことを PR の本文と人への報告に書く
- **人を待つ**：上限を超えた・手直しが failure で返った・返らないチケットは、draft・in_progress のまま人を待つ間、同時に進める枠に数えない。続けて直すと決まったら、自分で直すなら同じチケットをもう一度 claim して手直しの Run を開いて直し、サブエージェントに頼むなら「指摘を直す」のとおり新しいサブエージェントを印付きの文で起動して、同じ見直しと修正ループに戻す
