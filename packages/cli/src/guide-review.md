# 見直しと品質ゲート（review）

PR を人に出す前（`dg guide work`）と、自動でマージする前（`dg guide all` の `--auto`）の両方で確かめる品質ゲートと、実装したのとは別のサブエージェントによる見直し・上限付きの修正ループ。条件の正本はここで、work と all はここを参照する。進めるセッション（親。サブエージェントを使わずにひとりで進めるなら自分）が見直し役を起動し、指摘を振り分けて回数を数える。サブエージェントを起動できない環境では、見直しを人に頼む（PR を ready にして、見直していないことを報告する）。

## 品質ゲート

| 条件                         | 確かめ方                                                                                                                           | PR を出す前                                                            | マージの前                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 検査が通る                   | リポジトリの規約にある検査（書式・lint・テスト）が、ブランチの最新のコミットで通る。CI があれば CI も通っている                    | 要る                                                                   | 要る                                                                    |
| 受け入れ条件                 | `ticket show <id>` の `acceptance`                                                                                                 | 確かめた項目に印がある。付けられない項目は PR の本文と報告に理由を書く | すべて印あり                                                            |
| 別のサブエージェントの見直し | 下の「見直す」で、重い指摘が残っていない（版上げの例外は下）                                                                       | 要る                                                                   | 要る。PR を出す前の見直しの後にブランチが変わっていなければ、それを使う |
| base と衝突しない            | `gh pr view <PR> --json mergeable` が `MERGEABLE`。マージで base が進むとほかの PR は `UNKNOWN` になるので、マージの前に確かめ直す | 見ない                                                                 | 要る                                                                    |

条件を確かめた後にブランチを直したら、検査と受け入れ条件を確かめ直す。

- **版上げの PR は見直しを省ける**：リポジトリのリリースの手順で作る版上げの PR（`dg guide release`）は、変更が版の数字（package.json などの `version`）と、手順が決めた CHANGELOG・ロックファイルだけで、コード・文書・手順を変えないときに限り、別のサブエージェントの見直しを省いてよい。版上げの PR のマージは `auto.merge` によらず人が承認する（`dg guide all`）ので、人の承認が見直しの代わりになる。それ以外のファイルを 1 つでも変える版上げの PR は省かない。省いたら PR の本文に、版上げだけで見直しを省いたと書く。ほかの条件（検査・受け入れ条件・衝突なし）は省かない

## 見直す

実装者は PR を draft で作り（`gh pr create --draft`）、実装の Run を閉じて返す。draft のうちは照合が review に進めない。親は、実装したのとは別のサブエージェントを見直し役として起動する。見直し役は Plan の段階によらず親のモデルで起動する（品質ゲートを弱めない）。

- **渡す**：チケットの本文（`dg --json --actor agent ticket show <id>`）・ブランチと worktree のパス・差分の取り方（`git fetch {{git.remote}}` の後 `git diff {{git.remote}}/{{git.base_branch}}...<ブランチ>`）・規約の場所・一時ファイルの置き場所・`review` の Run を始めて閉じること（`--agent` は見直し役も自分の Adapter の名前。Claude Code なら `claude-code`。`claude-code-reviewer` のような役割名にすると使用量とモデル名を取り込めない）
- **見る**：受け入れ条件の漏れ・不具合・文書との食い違い・規約の違反・範囲の外の変更。チケット本文に `## 参考` 節があれば、そこに書いたファイルと差分で変えたファイルを見比べ、参考節にないところへの大きな広がりと、参考節のファイルに触れていない変更を「参考節との食い違い」として返す（節がなければ見比べない。範囲の外の変更でもあるものは「範囲の外の指摘」で扱う）
- **Run**：見直し役自身が `review` の Run を始めて見直し、一覧を返す前に閉じる（下の「Run の分け方」）
- **しない**：ファイルを変える・コミットする・push する・Run のほかに `dg` に書き込む
- **返す**：指摘を重い（受け入れ条件の漏れ・不具合・文書との食い違い・規約の違反）と軽い（言い回し・好み）に分けた一覧（ファイルと行・理由・直し方）と、最新のコミットで回した検査の結果。参考節との食い違いは軽い指摘の欄に分けて書き、重い指摘に数えない

## 指摘を直す（修正ループ）

- **重い指摘と、受け入れ条件の文言に当たる軽い指摘**：実装したエージェント（サブエージェントなら同じ会話の続き。続けられなければ新しいサブエージェント）に、同じブランチで直させて push させる（新しいサブエージェントも実装者と同じモデルで起動する）。渡すのは指摘の一覧と、`fix` の Run を始めて `--retry-reason` で閉じること（下の「Run の分け方」）。ほかの軽い指摘は直すかを実装者に任せる。直さなかった軽い指摘（参考節との食い違いを含む）と理由は、見直しは実装者が本文を書いた後に返るので、親が PR の本文に書き足す（`gh pr edit`。既存の本文は残す）。手直し（fix）が返すときも、直さなかった軽い指摘と理由を含める。参考節との食い違いは修正ループの回数にも数えない
- **直した後**：親が最新のコミットで検査を回し直し、受け入れ条件を確かめ直す。重い指摘を直したときだけ、見直し役（新しく起動してよい）に見直し直させる
- **範囲の外の指摘**：そのチケットで直さず、`dg guide import` の起票の候補として人に示す
- **上限**：重い指摘を直すのは 2 回まで（見直しは最初を含めて 3 回まで）。回数は親が、重い指摘を直した回で数える（`fix` の Run の数では数えない。人のレビューの手直しや始め直した Run も `fix` になる）。人が回数を指示したらそれに従う

## Run の分け方

計画・実装・見直し・手直しは別の Run に分け、それぞれの量を `metrics show --step` で見られるようにする。step は Workflow の `steps` から選ぶ（`dg guide run` の「Run を記録する」）。どの Run も、作業するエージェント自身が start と finish を呼ぶ。使用量は Run の ID を最初に含む会話記録から取るので、親などが代わりに start すると作業した分を数えない。

| 作業                                    | step        | 始める                   | 閉じる                                             |
| --------------------------------------- | ----------- | ------------------------ | -------------------------------------------------- |
| 親が調べて Plan の範囲・方針を書く      | `plan`      | チケットを調べ始めるとき | Plan に書き終えたとき（`dg guide plan`）           |
| 実装して draft の PR を作る             | `implement` | claim の後               | draft の PR を作ったとき                           |
| 見直し役の見直し                        | `review`    | 見直しを始めるとき       | 指摘の一覧を返す前（指摘の有無によらず `success`） |
| 修正ループの 1 回・人のレビューの手直し | `fix`       | 指摘を直し始めるとき     | 直して push したとき                               |

- **やり直しの理由**：手直しの Run（`fix`、または下の代わりの step で記録した手直し）は `run finish <Run の ID> --result success --retry-reason <直した指摘の要約>` で閉じる。書くのは直した指摘（見直し役・人のレビュー）だけで、指摘 1 件に 1 つ繰り返す。検査の失敗を直したことは書かない。回数は理由の数になる（`--retries` は省く）。要約は 1 行で、秘密・コマンドの文字列・パスは書かない。実装と見直しの Run には付けない
- **合う step がない**：Workflow の `steps` に `fix` がなければ `review`、`review` もなければ実装の step で代わりに記録する（`review` がなければ見直し役も実装の step で記録する）。同梱のテンプレートが持つ `fix`・`review` が Workflow にない（init の前からある Workflow など）ときだけ、足すよう人に伝える。consulting のようにテンプレートにも `fix` がない Workflow では伝えず、代わりの step で記録するだけにする。足すのは `dg --json --actor agent workflow show <id>` の `data.definition` の `steps` に項目を足したファイルを `dg workflow set <id> --file <path>` で書く（`dg init` は既にある Workflow を書き換えない。`--template` は labels・transitions・fields・独自の steps を捨てて定義を丸ごと置き換えるので、手を加えた Workflow には使わない）
- **直せなかった**：手直しを途中でやめたら `--result failure --error <理由>` で閉じ、親に返す
- **続けられない・返らない**：会話を続けられなければ、新しいサブエージェントが自分の `fix` の Run を始めて直す。返らないまま止まった Run は、`dg guide parallel` のとおり親が `interrupted` で閉じる（その後は下の「終わり方」）

## 終わり方

- **通った**：親が `gh pr ready <PR>` で PR を出し（人にレビューを頼む）、`dg guide work` の手順 7（`sync`）に進む
- **上限を超えた**（重い指摘が残る）：3 回目の手直しは始めない。PR は draft のまま、チケットは in_progress のまま置き、残った指摘・直した回数・PR を人に報告して、続けて直すか・ready にするか・やめる（`ticket unclaim`）かを聞く。実装の失敗とは違い、自分では unclaim しない。人を待つ間も、それを待たないチケットは進める
- **手直しが failure で返った・返らない**：上限を超えたときと同じく、PR は draft・チケットは in_progress のまま置いて人に報告する。返らずに `interrupted` で閉じた手直しの Run（閉じ損ねた Run を含む）も同じ扱い。unclaim しない（`dg guide work` の unclaim は実装の失敗と、実装を途中でやめたときだけ）
- **見直し役が閉じ損ねた・返らない**：親が `dg guide run` の「閉じ損ねた Run を閉じる」のとおり見直し役の Run（代わりの step で記録したものを含む。step ではなく起動したサブエージェントで見分ける）を `interrupted` で閉じ、見直し役を起動し直す（新しい見直し役が自分の Run を始める）。PR は draft・チケットは in_progress のまま置き、unclaim しない。起動し直しても返らなければ「見直し役を起動できない」に従う
- **見直し役を起動できない**：PR を ready にし、見直していないことを PR の本文と人への報告に書く
- **人を待つ**：上限を超えた・手直しが failure で返った・返らないチケットは、draft・in_progress のまま人を待つ間、同時に進める枠に数えない。続けて直すと決まったら、`fix` の Run を始めて直し、同じ見直しと修正ループに戻す
