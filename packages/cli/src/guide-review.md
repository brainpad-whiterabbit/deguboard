# 見直しと品質ゲート（review）

PR を人に出す前（`dg guide work`）と、自動でマージする前（`dg guide all --auto`）の両方で確かめる品質ゲートと、実装したのとは別のサブエージェントによる見直し・上限付きの修正ループ。条件の正本はここで、work と all はここを参照する。進めるセッション（親。サブエージェントを使わずにひとりで進めるなら自分）が見直し役を起動し、指摘を振り分けて回数を数える。サブエージェントを起動できない環境では、見直しを人に頼む（PR を ready にして、見直していないことを報告する）。

## 品質ゲート

| 条件                         | 確かめ方                                                                                                                           | PR を出す前                                                            | マージの前                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 検査が通る                   | リポジトリの規約にある検査（書式・lint・テスト）が、ブランチの最新のコミットで通る。CI があれば CI も通っている                    | 要る                                                                   | 要る                                                                    |
| 受け入れ条件                 | `ticket show <id>` の `acceptance`                                                                                                 | 確かめた項目に印がある。付けられない項目は PR の本文と報告に理由を書く | すべて印あり                                                            |
| 別のサブエージェントの見直し | 下の「見直す」で、重い指摘が残っていない                                                                                           | 要る                                                                   | 要る。PR を出す前の見直しの後にブランチが変わっていなければ、それを使う |
| base と衝突しない            | `gh pr view <PR> --json mergeable` が `MERGEABLE`。マージで base が進むとほかの PR は `UNKNOWN` になるので、マージの前に確かめ直す | 見ない                                                                 | 要る                                                                    |

条件を確かめた後にブランチを直したら、検査と受け入れ条件を確かめ直す。

## 見直す

実装者は PR を draft で作る（`gh pr create --draft`）。draft のうちは照合が review に進めない。親は、実装したのとは別のサブエージェントを見直し役として起動する。

- **渡す**：チケットの本文（`dg --json --actor agent ticket show <id>`）・ブランチと worktree のパス・差分の取り方（`git fetch {{git.remote}}` の後 `git diff {{git.remote}}/{{git.base_branch}}...<ブランチ>`）・規約の場所・一時ファイルの置き場所
- **見る**：受け入れ条件の漏れ・不具合・文書との食い違い・規約の違反・範囲の外の変更
- **しない**：ファイルを変える・コミットする・push する・`dg` に書き込む
- **返す**：指摘を重い（受け入れ条件の漏れ・不具合・文書との食い違い・規約の違反）と軽い（言い回し・好み）に分けた一覧（ファイルと行・理由・直し方）と、最新のコミットで回した検査の結果

## 指摘を直す（修正ループ）

- **重い指摘と、受け入れ条件の文言に当たる軽い指摘**：実装したエージェント（サブエージェントなら同じ会話の続き。続けられなければ新しいサブエージェント）に、同じブランチで直させて push させる。ほかの軽い指摘は直すかを実装者に任せ、直さないものは PR の本文に残す
- **直した後**：親が最新のコミットで検査を回し直し、受け入れ条件を確かめ直す。重い指摘を直したときだけ、見直し役（新しく起動してよい）に見直し直させる
- **範囲の外の指摘**：そのチケットで直さず、`dg guide import` の起票の候補として人に示す
- **上限**：重い指摘を直すのは 2 回まで（見直しは最初を含めて 3 回まで）。人が回数を指示したらそれに従う

## Run と終わり方

実装の Run は見直しが終わるまで閉じない。実装者は draft の PR を作ったら Run を開けたまま返し、直すたびに同じ Run で作業する。閉じるのは実装者自身（`dg guide work` の「Run を記録する」）で、親は見直しの結果を伝えて閉じさせる。`--retries` は重い指摘を直した回数。

- **通った**：`run finish <Run の ID> --result success --retries <回数>`。親が `gh pr ready <PR>` で PR を出し（人にレビューを頼む）、`dg guide work` の手順 7（`sync`）に進む
- **上限を超えた**（重い指摘が残る）：`run finish <Run の ID> --result failure --retries <回数> --error <残った指摘の要約>`。PR は draft のまま、チケットは in_progress のまま置き、残った指摘・直した回数・PR を人に報告して、続けて直すか・ready にするか・やめる（`ticket unclaim`）かを聞く。作業の失敗とは違い、自分では unclaim しない。人を待つ間も、それを待たないチケットは進める
- 実装者が返らなくなったら、`dg guide work` の「着手できるチケットを並べて進める」のとおり親が Run を閉じる
