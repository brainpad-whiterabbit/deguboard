# 見直しと品質ゲート（review）

PR を人に出す前（`dg next` の `review`・`fix`・`ready`）と、自動でマージする前（`dg guide all` の `--auto`）に確かめる。判定は `dg gate <id> --for ready`・`--for merge` が行い（条件の正本は `dg gate --help`）、PR は `dg --json --actor agent pr ready <id>`、マージは `dg --json --actor agent pr merge <id>` で出す。どちらも判定してから gh を呼び、満たさなければ `GATE_FAILED` で満たさない条件と理由を返す。`gh pr ready`・`gh pr merge` は自分で打たない（フックが拒む）。ゲートを満たさないまま進めるのは人の判断なので、人に `gh` を打ってもらう。

## 品質ゲート

- **検査**：リポジトリの規約の検査（書式・lint・テスト）が最新のコミットで通る。CI があれば CI も。`dg gate` は判定しないので、親が確かめる
- **受け入れ条件**：PR を出す前は確かめた項目に印があり、付けられない項目は PR の本文と報告に理由がある。マージの前はすべて印あり（`dg gate` の `acceptance`）
- **見直し**：別のサブエージェントの見直しで重い指摘が残っていない。`dg gate` の `review` が最後の push より後の見直しの通過を、`fix_rounds` が上限以内を確かめる
- **衝突**（マージの前だけ）：`dg gate` の `mergeable` が MERGEABLE。マージで base が進むと他の PR は `UNKNOWN` になるので、マージの直前に確かめ直す
- 条件を確かめた後にブランチを直したら、検査と受け入れ条件を確かめ直す。衝突を直して push したら見直し直す
- **版上げの PR は見直しを省ける**：`dg guide release` の版上げの PR は、変更が版の数字（`version` など）と、手順が決めた CHANGELOG・ロックファイルだけで、コード・文書・手順を変えないときに限り、見直しを省いてよい。版上げの PR のマージは `auto.merge` によらず人が承認するので、人の承認が見直しの代わりになる。省いたら PR の本文に書く。ほかの条件は省かない

## 見直す

親は、実装したのとは別のサブエージェントを見直し役として起動する。見直し役は段階によらず親のモデルで起動する（品質ゲートを弱めない）。実装者は PR を draft で作って返し、draft のうちは照合が review に進めない。

- **渡す**：`dg next` が `review` の手で返す `brief`（`dg --json --actor agent brief <id> --role review` と同じ文）を渡し、後ろに一時ファイルの置き場所を足す。1 Run で 1 枚のチケットを見るので、複数のチケットはチケットごとに起動する
- **見る**：受け入れ条件の漏れ・不具合・規約の違反・範囲の外の変更。文書との食い違いは、この PR が変えた約束・手順・規約の文書を同じ PR で直していないときだけ重い指摘にする。前からあるずれは重い指摘にせず、`dg guide audit` でまとめて直す（ADR-001 の「文書の見直し」）。範囲の外の変更は「範囲の外の指摘」で返す。チケット本文に `## 参考` 節があれば、そこに書いたファイルと差分で変えたファイルを見比べ、参考節にない大きな広がりと、参考節のファイルに触れていない変更を「参考節との食い違い」として返す（節がなければ見比べない）
- **返す**：指摘を重い（受け入れ条件の漏れ・不具合・規約の違反・この PR の文書の食い違い）と軽い（言い回し・好み・参考節との食い違い）に分けた一覧（ファイルと行・理由・直し方）と、最新のコミットで回した検査の結果

## 指摘を直す（修正ループ）

- **直す指摘**：重い指摘と、受け入れ条件の文言に当たる軽い指摘。新しいサブエージェント（実装者と同じモデル）を起動し、同じブランチで直して push させる。文は `dg --json --actor agent brief <id> --role fix --findings <指摘の一覧>`。同じ会話の続きでは頼まない。親が自分で直すなら、`ticket claim <id> --retry-reason <指摘の要約>` で claim してから直す（`dg guide run`）
- **直さなかった軽い指摘**（参考節との食い違いを含む）と理由は、親が PR の本文に書き足す（`gh pr edit`。既存の本文は残す）。手直しが返すときも理由を含めてもらう。参考節との食い違いは回数に数えない
- **直した後**：親が最新のコミットで検査を回し、受け入れ条件を確かめ直す。重い指摘を直したら見直し役（新しく起動してよい）に見直し直させる。軽い指摘だけを直したときも、`dg gate` の `review` が最後の push より後の見直しを求めるので、前回からの差分を見直させる（重い指摘が出なければ回数に数えない）。手直しのサブエージェントが返るまで `dg next` を呼ばない（途中の push と直し終えた push は区別できない）
- **上限**：手直しの回数は dg が数え（`dg gate` の `fix_rounds`）、超えると `dg next` が `wait_human` を返す（下の「終わり方」）。人が回数を指示したらそれに従う
- **範囲の外の指摘**：そのチケットでは直さず、`dg guide import` の起票の候補として人に示す

## 終わり方

- **通った**：`dg --json --actor agent pr ready <id>` で PR を出し（人にレビューを頼む）、`sync` を回す（`dg next` の `ready`）
- **見直し役を起動できない**（サブエージェントを起動できない環境）：見直しを人に頼む。PR を `dg pr ready` で出し（`GATE_FAILED` なら人に `gh pr ready` を打ってもらう）、見直していないことを PR の本文と報告に書く
- **上限を超えた**（重い指摘が残る）・**手直しが failure で返った・返らない**：上限を超えた手直しは始めない。PR は draft、チケットは in_progress のまま置き、残った指摘・直した回数・PR を人に報告して、続けて直すか・ready にする（人が `gh pr ready`）か・やめる（`ticket unclaim`）かを聞く。自分では unclaim しない。人を待つ間も、それを待たないチケットは進める
- **止まって待っている**（`dg next` が `wait_human` を返す）：`ask_human` に従い、続けさせるなら同じ会話に続きを送る。直さないと決めたら、その Run を閉じてよいかを人に聞く
- **見直し役が返らない**：`dg guide run` の「止まった Run」で閉じ、見直し役を起動し直す。PR は draft、チケットは in_progress のまま。起動し直しても返らなければ「見直し役を起動できない」
