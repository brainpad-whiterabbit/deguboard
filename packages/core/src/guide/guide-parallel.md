# Advancing ready tickets in parallel (parallel)

When `next` returns `implement`, `review`, `fix`, or `ready` for several tickets, and subagents can be started, you may start one for each ticket and advance them at the same time. `dg` only shows the order. Starting and waiting for them is done by these steps. The session that advances (the parent) only advances, gets approvals, and reads and writes `dg`.

- **Limit**: up to 3 at the same time. If a human gives a number, follow it. If checks fail under load, reduce it
- **Before starting**: look at the open Plan and the PRs, and check that no two tickets change the same file. Do not run tickets that change the same file side by side. Propose to a human that they run in order with `after`
- **Parent**: for each ticket, do the `implement` step of the "Flow" section of `dg guide work`, and the "Before and after claim" section of `dg guide work`, one at a time (claim with `--no-run`; claim creates the worktree), and start a subagent. When it returns, do the "Receive the implementation result" section of `dg guide work`, and the review and fix loop in `dg guide review` (light findings you did not fix are added to the PR body by `dg pr ready`). With the free slot, read `dg next` again and start the next one. Tickets waiting for a merge and tickets waiting for a human do not count toward the slots
- **Passing the text**: pass the `brief` from `dg next` as it is (for fixes, the `--role fix` text). The steps of each role are already in the text, so do not have the subagent read the guide. The model is `model` from `dg next` (`null` means the parent's model)
- **The subagent does not**: claim, unclaim, `iteration add`, Plan operations, start a reviewer, `dg pr ready`, merge, `ticket check`, `ticket update --pr`, or work on other tickets
- **One ticket does not stop the others**: on `CLAIM_LOST`, skip that ticket. If implementation fails, `ticket unclaim` it back to todo, keep the worktree, and do not claim it again in the same flow. If a review or fix returns failure or does not return, follow the "How to finish" section of `dg guide review`. Wait only for tickets linked by `after`
