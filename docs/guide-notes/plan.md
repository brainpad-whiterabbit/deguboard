Count as likely any ticket that changes what a requirement item of docs/requirements.md promises to users (the behaviour or data shape it states; search the file for the command, data, or screen being changed), even when its References do not name the file, because a change of a promise goes into requirements.md in the same PR.
Basis: in s36 concurrent-overlap-rate was 11/27, and in s43 it was 8/21 with 5 pairs sharing docs/requirements.md (in 2 both References named different sections, in 3 one ticket's References did not name the file). Drop this rule when, for 3 Iterations in a row, no pair counted by concurrent-overlap-rate shares docs/requirements.md.
