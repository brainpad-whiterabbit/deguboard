When a PR adds, renames, or deletes a source file, or moves a decision or a value it outputs from one file into another, run `git grep -n -E '<old file>|<new file>' -- docs` with the base names of every file involved, and read each hit in an ADR's "細部の正本" section and in docs/usage.md and docs/usage.ja.md, and the row of the "パッケージ" table in docs/development.md for each file's directory (such as `git/`); if one of them still names the old place or misses the new file or value and the PR left it unchanged, raise it as a heavy finding.
Basis: in s41 escaped-defect-rate was 4/30 (0.13), and all four (t1105→t1120, t1128→t1129, t1106·t1119·t1128→t1130) were documents that still named the old place of code the PR had added or moved. Drop this rule when, for 3 Iterations in a row, no escaped defect has the origin_cause documents.
