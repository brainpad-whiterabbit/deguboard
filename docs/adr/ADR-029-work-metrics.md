# ADR-029 作業の使用量とツールの回数（失敗した数を含む）は Run ごとに公式の記録から実測し、数だけを Git に写す

- ステータス：承認

## 要約

作業の使用量は Run ごとに公式の会話記録から実測し、エージェントの自己申告は使わない。使用量・ツールの呼び出しの回数と失敗した数は、Git に数とモデル名だけを写し、プロンプトや中身は写さない。実装・見直し・手直しは別の step の Run にし、会話記録を読む許可はリポジトリの config に置く。親の依頼を待った時間も会話記録から数えて Run に残し、作業時間は経過時間から待ちを引いて出す。作業の大きさはマージされた PR の行数をチケットに記録し、1 行あたりのトークンを output と読んだ文脈に分けて出す。手戻りの原因の種類と、見つけ損ねた不具合の元のチケット（origin・origin_cause）は [ADR-036](ADR-036-rework-causes-and-origin.md) が決める。

## 背景

チケットの分割の粒度やモデルの選び方を決めるのに、AI エージェントがどれだけのトークンと時間を使ったかの実績が欲しい。ただし AI の自己申告は正確でなく、会話記録は個人のデータでもある。何を、どこから、どこまで記録するかを決める。

## 決定

### 実測し、自己申告しない

- 使用量は Run 単位で記録する。1 つのチケットに複数の Run を紐づける
- 数は公式に提供される使用量の情報（今は会話記録）から取る。エージェントに数字を言わせて書かない
- 取れない指標は `null` にして警告する。架空の値で補完せず、推定した値には `estimated: true` を付ける（RN-2）
- エージェントごとに取得方法が違う部分は Adapter が吸収する。Run のエージェント名も、省けば Adapter が dg を呼んだプロセスの環境から判定する（エージェントに名前を言わせずに済む）

### 記録するもの

- エージェント・モデル・日時・トークン数・結果・エラー・やり直しの理由・step（項目は RN-1）と、ツールの呼び出しの種類ごとの回数と最初に書くまでの読む・探すの回数
- 親の依頼を待った秒数（`waited_seconds`。[下の節](#親の依頼を待った時間は会話記録から数え作業時間から除く)）
- 失敗したツールの呼び出しの数（`tools.errors`）。会話記録の結果の失敗の印だけで数え、結果の文は読まない。印を読めない Run と前の Run は 0 で補わず、`metrics show` が件数を出す
- 集計は Run から Step までの単位で表示のたびに求め、保存しない（MT-3）
- Epic・Iteration へは、Run の持つチケットの今の所属でたどる

### 親の依頼を待った時間は会話記録から数え、作業時間から除く

- サブエージェントが止まって親の続きの依頼を待つ間も Run は開いたまま（[ADR-025](ADR-025-runs-by-hooks.md)）なので、Run の時刻の差（経過時間）は待ちを含む。Run を閉じるときに、使用量と同じ会話記録から待ちの区間を数え、Run の開始から終了の範囲で切った秒数（`waited_seconds`）を Run に残す
- 待ちは、ターンが終わってから親の依頼が記録に入るまでの空きだけにする。自分のバックグラウンドのコマンドの通知・harness の催促で続いた空きと、ツールの結果を待つ間は作業に数える。入力の出どころは記録の文でなく項目で見分け、知らない形の入力があれば数えない
- 経過時間はそのまま残す。作業時間（`active_seconds`）は保存せず、表示と集計のたびに経過時間から待ちを引いて出す
- 待ちを数えられない Run（親が自分で開いた Run、待ちを数えない Adapter の Run、待ちを記録する前に閉じて `run refresh` が数え直せない Run）は 0 で補わず `null` にし、`metrics show` が件数を出す
- フックの止まって待っている印（ADR-025）は `dg next` の表示にだけ使い、待ちの数には使わない

### 変更行数はチケットに記録し、1 行あたりのトークンは内訳で出す

- 作業の大きさの目安として、マージされた PR の追加・削除の行数をチケットに記録する（TK-11）。照合がマージを見たときに採る
- `metrics show` は、Run のトークンをそのチケットの行数で割った 1 行あたりのトークンを出す。合計では割らず、output と読んだ文脈（input + cache）に分ける。行数のないチケットは計算から外し、件数を出す（MT-6）
- 行数のない done のチケットには、人が呼ぶ `metrics lines` が後から記録する

### 実装・見直し・手直しを別の Run にする

- 実装・見直し・手直しを別の step の Run にし、`metrics show --step` で分けて比べる
- 実装の Run は作業する主体のチケットの操作が開け閉めする。開くのは claim（RN-5）、閉じるのは PR の記録か照合が PR を見つけたとき（`success`）、やめるときは `unclaim` と abandoned（`failure`）、PR の要らない作業は review・done への move（RN-6）
- サブエージェントの Run と、手直しの Run の開き方と閉じ方は [ADR-025](ADR-025-runs-by-hooks.md)
- 手直しの Run には直した指摘を `retry_reasons` に 1 件 1 行で残す。`fix` の Run の数は手直しの回数の目安にとどまり、修正ループの回数は見直しの結果から数える（ADR-025・[ADR-011](ADR-011-procedure-in-code.md)）
- 実装・手直しの Run の抜けは `dg lint` が指摘する（安全網）

### 手戻りの原因の種類と、見つけ損ねた不具合の元は ADR-036 が決める

- 見直しの指摘の原因の種類（`cause`）と、直すチケットの元のチケット（`origin`・`origin_cause`）は [ADR-036](ADR-036-rework-causes-and-origin.md) が決める。この ADR が扱うのは、その原因ごとの数を含む Run の数だけ（[写すのは数だけ](#写すのは数だけ)）

### 親の使用量は Run で測らない

- 計画を立て、サブエージェントを進める親の作業は Run にしない。フックが届くセッションでは実装と手直しをいつもサブエージェントに頼み、チケットの Run の使用量をサブエージェントの会話記録から数えた値にそろえる（[ADR-025](ADR-025-runs-by-hooks.md)）。フックが届かないセッションで親が自分で実装・手直しする分は、その step の Run に入る。Run の合計はチケットの作業の量として読み、全体の費用とみなさない
- 親の使用量を測るなら、まず期間を指定した会話記録の親と子の集計から考える

### 推定費用は持たない

- 費用の単価は持たず、トークン数だけを記録する。費用が要るときは利用者が単価を掛ける

### 会話記録を読む許可はリポジトリの設定に置く

- 会話記録を読むかどうかは `config.yaml` の `metrics.read_transcripts` で決め、チームの方針として Git で共有する
- 個人が拒むときは環境変数 `DEGUBOARD_NO_TRANSCRIPTS` で、そのマシンでは読まない（MT-2）
- 許可がなければ使用量は `null` のまま、日時・結果などの Run の記録だけを残し、Run を閉じる操作が警告を返す

### 会話記録を Run に結び付ける

- Run を閉じる操作が Run の `agent` の Adapter で会話記録から使用量を取る。`run refresh` は後から同じ探し方で取り直し、取れた値だけを書き換える（MT-5）。待った秒数も閉じるときと同じ数え方で数え直し、会話記録の場所が残る期間（RN-3）の Run に、待ちを数える前に閉じた Run も含めて入れる。ツールの回数は取り直さない（RN-4）
- Run はセッション ID を持ち、会話記録のパスはマシンごとのローカル（`deguboard-local/`）に置いて Git に入れない。数える範囲は記録の場所で決め、場所がなければ Run の ID を最初に含む記録から推測する。1 つの応答は 1 つの Run にだけ数える。セッションと記録の場所の取り方は [ADR-025](ADR-025-runs-by-hooks.md)

### 写すのは数だけ

- Git に入る記録には、使用量とツールの回数の数とモデル名だけを会話記録から写す。見直しの結果も指摘の数と原因ごとの数だけで、指摘の文は入れない。プロンプト・ツールの結果・ファイルの中身・コマンドの文字列・ファイルのパスは写さない。例外はセッション ID だけで、後から数え直すのに残す
- 実行中の記録は Git 管理せず、Git に入れるのは Run 完了時の集計だけ（RN-3）
- Run はチケットの ID を持ち、チケットには Run の ID を書き足さない。チケットの Run は Run の側から引く

### 細部の正本

エージェント名の判定・ツールの種類の分け方・数える範囲と重なりの分け方・待ちの区間の数え方・モデル名の選び方・閉じる時刻・閉じた Run への操作・抜けの指摘の条件は、次のコードとテストとヘルプが正本で、「なぜ」はそのコメントとテスト名にある。

- `packages/core/src/agents/index.ts`（`detectAgent`・読む許可）・`packages/core/src/agents/adapters/`（製品ごとの Adapter と `transcript.ts` の `bindFile`・`OverlapClaims`）・`packages/core/src/agents/agents.test.ts`
- `packages/core/src/model/run.ts`（Run の形）・`packages/core/src/commands/run.ts`（`run start`・`run finish`・`run refresh`）・`packages/core/src/run/record.ts`・`packages/core/src/commands/run.test.ts`
- `packages/core/src/commands/ticket.ts`（`ticket update --pr`）・`packages/core/src/commands/setup.ts`（照合が閉じる Run と `dg lint`）・`packages/core/src/commands/commands-flow-reconcile.test.ts`
- `packages/core/src/model/metrics.ts`・`packages/core/src/commands/metrics.ts`（`dg metrics show --help`・`dg metrics lines --help`・`dg metrics sources --help`）・`packages/core/src/git/facts.ts`（PR の行数と変えたファイル）

## 理由

- 自己申告は過小・過大になり、比べられない。公式の使用量なら後から測り直せる
- 単価はモデルや契約で変わり、更新し続ける必要がある。トークン数を残せば費用はいつでも計算できる
- 集計結果はどのみち共有リポジトリに入るので、「読むかどうか」もチームで決めるのが筋。個人の逃げ道は環境変数で足りる
- 数だけなら、チケットをまたいで比べられ、秘密情報が Git に入らない
- ツールの回数を持つのは、手引き（`dg guide`）を変えたとき、調べる量が減ったかを Run で比べるため。失敗した呼び出しの数は、成功した Run の中の遠回りを数えるため
- 待ちを含む経過時間では、親が人に質問している間が作業に見える（調べた手直しの Run は、経過 4h09m56s のうち作業が約 5m31s だった）。待ちを除かないと、step ごとの時間が作業の量でなく待ちの長さで決まる
- フックの待ちの印はフックの処理の時刻で付け外しされ、閉じるときに消えるので、待ちが残らず、時刻と順序に左右される。会話記録の行の時刻から数えれば、後から同じ値を数え直せる。そのため `run refresh` で数え直しても値は変わらず、進行中の Iteration の振り返りに待ちを数える前の Run の作業時間も使える
- 経過時間を書き換えずに待ちを別に持てば、待ちを数える前の Run と経過時間で比べられ、待ちの数え方を直しても時刻は変わらない。待ちを数えられない Run を 0 にすると、待たなかった Run と見分けられない
- 実装の Run の中で修正ループを回すと、見直しと手直しの量が実装に混ざり、チケットの粒度とモデルの選び方の判断に使えない。Run を分ければ `metrics show --step` で比べられる
- 実装の Run の開閉をチケットの操作に付けたのは、手順書を通らずに実装すると `run start`・`run finish` が呼ばれず、Run が残らないか開いたままになったため
- 親の使用量を Run で測るには Run の形と多くのコードを変えることになる。親の分は 2026-11-05 の会話記録で単価の比の重みを付けて全体の約 3 割と小さくないが、それを見たうえでも、今はチケットの粒度とモデルの選び方を決める数があれば足りると判断した
- 集計値を保存せず、チケットに Run の ID を書き足さないのは、Run を足すたびに複数のファイルを書き換えて衝突させないため。所属を Run に写さないのは、チケットを動かしたときに Run と食い違うため
- トークンの大半は cache_read なので、合計を行数で割ると読んだ文脈の量だけが見え、書いた量の違いが埋もれる。行数をチケットに持つのは、表示のたびに gh を呼ばずに済み、gh のないマシンでも同じ数になるため
- 記録のパスはホームのパスとユーザ名を含み、Git に入れると他人に見え、別のマシンでは読めないので、マシンごとのローカルに置き、Git にはセッション ID だけを残す

## 採らなかった案

- **推定費用を記録する**：単価表の保守が要り、「推定」が独り歩きする
- **読む許可を利用者ごとにリポジトリの外に置く**：許可の有無がマシンごとに違い、チームで集計が揃わない
- **OpenTelemetry で収集する**：collector が要り、チケットとの紐づけが別に要る
- **チケットごとの `plan` の Run**：入るのは 1 枚を読んで決める 1〜2 回の応答だけで、全体を比べて順を決める考えが入らない
- **Plan に結び付ける親の Run**：Plan の ID は計画の後にしかできず、親の Run は会話の再開をまたいで長く、チケットがある前提のコードを直すことになる
- **すべての Run を Plan に結び付け、1 枚の作業にも軽い Plan を作る**：Plan のない作業と Skill なしの使い方が止まる
- **実装の Run を開けたまま修正ループを回し、`retries` に直した回数を書く**：見直しと手直しの量が実装と分かれない
- **トークンの合計を行数で割る**：cache_read に埋もれて、書いた量の違いが見えない
- **`dg sync` が行数のない done のチケットを毎回 gh で引く**：マージされなかった PR の done を sync のたびに読み続け、照合が遅くなる
- **フックの止まって待っている印の時刻から待ちを数える**：フックの処理の時刻なので実際の空きとずれ、届かないフックと順序の前後で欠ける
- **待ちを引いた作業時間を Run に保存する（経過時間を作業時間に置き換える）**：経過時間が分からなくなり、待ちを数える前の Run と時間の意味が変わる
- **入力の文（「coordinator」などの語）で親の依頼を見分ける**：文の形に依存し、会話の中身を読むことになる
- **AI に振り返りを書かせて数字を残す**：正確でない
- **失敗した結果の文を読んで失敗の種類に分ける**：結果の中身を読むことになる
- **会話の中身を記録する**：個人データと秘密情報が Git に入る
- **Run の ID が最初に出た会話記録だけで結び付ける**：後から開いた見直しの応答を数えられない。場所がないときの落ち先にだけ残す
