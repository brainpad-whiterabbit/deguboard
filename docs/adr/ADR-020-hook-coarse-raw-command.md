# ADR-020 フックは字句を伏せずに生のコマンドで gh pr ready・merge を粗く止め、本文の語はファイル渡しへ案内する

- ステータス：承認
- 更新日：2026-11-08

## 背景

[ADR-019](ADR-019-pr-advance-through-dg.md) は、ツールを使う前のフックが dg を経由しない `gh pr ready`・`gh pr merge` を粗く拒むと決めた。そのうえで止めすぎを減らすために、字句で文字と言い切れる部分（引数をコードとして走らせない、知っているコマンドの引用符・ヒアドキュメントの中と、コメント）を伏せてから判定する形にした（t545）。

伏せる部分は、そのまま抜け道の候補になる。知っているコマンドの一覧、引数でプログラムを渡せるフラグ、ANSI-C の引用、置き換えを含む引用、終わりの語を越えるヒアドキュメント、コメントの中の引用符と、見直しのたびに伏せてよい条件の分岐が増え、t532 の字句の分解と同じく指摘が尽きない形に戻った。わざと隠した形（`g\h`・`"mer""ge"`・`$GH`）まで個々に塞ぐのは、ADR-019 が事後の検査（t546）に任せた範囲と重なる。

## 決定

### フックは字句を伏せずに粗く止める

- フックは Bash のコマンドを字句に分けて読まない。生のコマンドから、正しい道の `dg pr ready`・`dg pr merge`（`mise run dg -- pr …`・`dg.js` も）と、取り消しの `gh pr ready … --undo` を除き、残りに `gh` の語があり、`pr` の語と `merge`・`ready` の語がどこかにあれば止める。`gh api` の同じ操作（`pulls/<n>/merge`・GraphQL の mutation 名）も、`gh` の語があれば止める。PR の指定は読まない
- 引用符・ヒアドキュメント・コメントの中も伏せない。本文にその語を書いたコマンド（`git commit -m "… gh pr merge …"`・`gh pr create --body "…"`）も止める
- 止めすぎは、拒む文の逃げ道で受け止める。拒む文は、正しい道の dg のコマンドと人に頼む例外に加えて、本文の語は Write でファイルに書いて `gh pr create --body-file`・`git commit -F` で渡すこと、ほかのコマンドと一緒に打って止まったなら分けて打つことを案内する
- わざと隠した形（`g\h`・`"mer""ge"`・`$GH`・`gh pr $OP`・`$(which gh)` で組み立てた呼び出し・gh のエイリアス・ファイルに書いたスクリプト）は個々に見ない。語として現れれば止まるだけで、すり抜けは事後の検査（t546）で補う
- ※ ADR-021 で置き換え（この項は失効）。`.git/deguboard/` への書き込みを拒む判定（t532）は変えない

### 置き換えるもの

- [ADR-019](ADR-019-pr-advance-through-dg.md) の「フックは dg を経由しない呼び出しを粗く拒む」の節を、この決定で置き換える。ADR-019 の「制限」の節のうち、伏せられない場所の語を止める項と、展開の語があるコマンドの項も置き換える（伏せないので、どこにあっても止める）

## 理由

- 伏せる処理をなくすと、判定は「語があるか」だけになり、読み違えて通す余地がない。止めすぎの側にしか倒れない
- 止めすぎた本文は、ファイルに書いて渡せば必ず通る。逃げ道が 1 つに決まっているので、拒む文で案内しきれる
- 本文に `gh pr merge` を書く場面は、フックやゲートを変える PR の本文とコミットメッセージにほぼ限られ、ファイル渡しの手間は小さい
- 隠した形を個々に塞ぐ分岐は、塞ぐたびに次の形が見つかり閉じない。ADR-019 の 3 つの守り方（正しい道・粗い拒否・事後の検査）のうち、粗い拒否は書き間違いを防ぐ分だけを受け持つ

## 採らなかった案

- **伏せる条件を直し続ける**（t545 の形）：伏せた所が抜け道の候補で、見直しのたびに条件が増えた。t532 で採らなかった形と同じ
- **区切り（`;`・`&`・`|`・改行）ごとに語の並びを見る**：任意の言語のコード（1 要素ずつ改行した配列・`'gh pr ' + 'merge'`）で語が隣り合わず、また字句の読みに戻る
- **本文の語を止めない（引用符の中だけ伏せる）**：どの引用符が文字か（`sh -c`・`python -c`・`--upload-pack`）を決めるのが t545 の分岐そのもの

## 制限

- 同じコマンドの別の所に `gh` の語と `pr`・`merge`・`ready` の語があれば、PR を進めなくても止める（`gh pr view 1 && git merge x && echo pr` など）。分けて打つ
- 正しい道の dg のコマンドを除くのは、`dg` から区切りか `gh` の語までの間に `pr ready`・`pr merge` が続く形で、同じ区切りの中で `dg` より前に `gh` の語がないものだけ（`gh -R o/dg pr merge` の `dg` は gh の引数なので除かない）。`dg` を包むコマンドの引数に gh を書く形は止める
