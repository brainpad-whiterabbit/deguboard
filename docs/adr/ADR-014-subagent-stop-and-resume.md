# ADR-014 止まったサブエージェントの Run は step を終えた事実があるときだけ閉じ、再開を続きとして扱う

- ステータス：承認
- 更新日：2026-11-07

## 背景

[ADR-012](ADR-012-hooks-open-runs.md) は、サブエージェントが終わったとき（SubagentStop）にその Run を数えて閉じ、セッションの終わり（SessionEnd）に開いたままの見直しと手直しの Run を閉じると決めた。2026-11-07 に Claude Code 2.1.318 で、これに合わない振る舞いを 2 つ確かめた。

- サブエージェントが親に質問を返して止まったときも SubagentStop が発火する。親が SendMessage で続きを頼むと、同じ `agent_id` で SubagentStart と SubagentStop がもう一度発火し、記録は同じファイルに追記される。最初の Stop で閉じると、答えを受けてからの作業が記録に入らない
- SubagentStop のフックが走る瞬間、記録には最後の応答（assistant の行と使用量）がまだ書かれていない（最後は api-request の行）。0.5 秒以内に書かれ、その後は増えない。その場で数えると最後の応答が欠ける

また [ADR-013](ADR-013-review-result-on-run.md) は、書く先の見直しの Run がなければ `run review-result` を `NOT_FOUND` にした。前景で起動した見直し役では、フックが終わった後に Run を開いてその場で閉じるので、見直し役が動いている間はいつも書く先がない。

## 決定

### SubagentStop は step を終えた事実があるときだけ閉じる

- step を終えた事実は、実装は PR があること、見直しは結果（`run review-result`）が記録されていること、手直しは開始より後の push があること。ほかの step は事実を求めない
- 事実がなければ閉じず、実行中の記録に止まって待っている印（`waiting_since`。時刻だけで、質問の文は記録しない。MT-4）を付ける。`run list --running` で見え、閉じた Run（Git）には書かない
- 同じ `agent_id` の SubagentStart が来たら、その記録に結び付いた開いた Run を続きとして使い、印を消す。新しい Run は開かない。後の Stop は記録の全体から数えるので、止まる前と再開の後の応答が両方入る
- ※ ADR-017 で置き換え（この項の「次のフック・`dg sync`・SessionEnd のどれかが、書き終わっていれば数えて閉じる」の部分は失効）。閉じる前に、記録の最後の api-request の後に使用量付きの assistant の行が出るまで待つ（上限は数秒）。間に合わなければ閉じずに書き終わり待ちの印（`settling_since`。止まって待っている印とは別）を付けて警告し、次のフック・`dg sync`・SessionEnd のどれかが、書き終わっていれば数えて閉じる。止まって待っている印の Run は、事実がそろっても再開を待つので、次のフックと `dg sync` では閉じない（SessionEnd は下の節のとおり閉じる）。書き終わり待ちを呼び直したときに事実が取れなければ（gh・fetch の一時的な失敗など）、書き終わり待ちの印を消して止まって待っている印に移す

### SessionEnd はこのセッションのサブエージェントの Run をすべて閉じる

記録の場所がサブエージェントの記録（`agent_id` 付き）で開いたままの Run を、このセッションの分だけすべて閉じる。step を終えた事実があれば `success`、なければ実装は `failure`、見直し・手直しなどは `interrupted`。親が自分で進める Run（`agent_id` なし）は今までどおり PR の記録と照合で閉じ、セッションをまたいで開いていてよい。

### 書く先の見直しの Run がなければ結果を保留にする

`run review-result` は、書く先の見直しの Run がなければ `NOT_FOUND` にせず、結果をこのマシンの `deguboard-local/reviews/<ticket>.json` に保留にする（Git に入れない）。フックが見直しの Run を閉じるとき（SubagentStop・前景の PostToolUse・SessionEnd）、その Run の開始より後に置いた保留の結果を結び付けて消す。開始より前に置いたものは前の回のものなので使わずに消す。閉じた最新の見直しの Run にもう結果があるとき（間に手直しを挟まずに前景の見直しを続けたとき）も、書き換えずに保留にする。保留はチケットごとに 1 つで、同じチケットの前景の見直し役を並べて動かすことは扱わない。

[ADR-012](ADR-012-hooks-open-runs.md) の「サブエージェントの Run はフックが開け閉めする」の SubagentStop で閉じる項のうち、止まったら数えて閉じる部分と前景の起動でその場で閉じる部分と、「閉じ損ねはセッションの終わりに閉じる」の節を、この決定で置き換える。あわせて ADR-012 の「結果は step ごとの事実で決める」の項の「なければ `failure`」の部分を置き換える（事実がなければ閉じずに待ち、閉じるのはセッションの終わりだけ）。[ADR-013](ADR-013-review-result-on-run.md) の、書く先がなければ `NOT_FOUND` にする部分と、フックが見直しの Run を結果なしで `failure` にする部分を置き換える。

## 理由

- 止まったことは終わったことを表さない。step を終えた事実で閉じれば、質問で止まった Run を誤って `failure` にせず、再開の後の作業も同じ Run に数えられる
- 再開は同じ `agent_id` で同じ記録に追記されるので、記録の場所で引けば続きとして結べる
- 書き終わりを待つのは、最後の応答の使用量（多くは最も大きい）を欠かさないため。上限を置くのは、フックでエージェントの作業を止めないため
- 止まって待っている印は、人の答えを待つ Run（e14 の「人待ち」と t533 の `wait_human`）を事実から見分ける材料になる
- 保留にするのは、前景の起動では Run を開く時刻（起動の呼び出しが返ったとき）が見直し役の作業の後になり、順を変えられないため

## 採らなかった案

- Stop のたびに閉じ、再開で新しい Run を開く：1 つの作業が複数の Run に割れ、止まる前の量と後の量を足し直す手間が出る
- 前景の見直し役の結果を、記録の中の `run review-result` の呼び出しの引数から読む：コマンドの文字列の形に依存する
- SubagentStart で Run を開く（前景で先に開くため）：頼んだ文もサブエージェントの記録のパスもなく、並べて起動すると取り違える（ADR-012 と同じ）
