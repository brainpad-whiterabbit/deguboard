# ADR-010 画面からの書き込みとエージェントへの依頼

- ステータス：承認
- 更新日：2026-11-05

## 背景

[ADR-006](ADR-006-ui-and-writes.md) では、画面から Core のコマンドを通して Status の変更（カンバンのドラッグ）、Iteration の移動（バックログのドラッグと右クリック）、Iteration・Epic の作成・開始・閉じる・再開、チケットの足し外しを行えるようにした。その後、起票・割り当て・計画・作業・片付けは Skill（`dg*`、AG-2）の手順で進めるようになり、点検と人の承認はその手順の中にある。画面から Iteration や Epic を直接変えると、その流れの外で状態が変わる（Plan の承認と閉じるを画面に置かない ADR-006 の判断と同じ問題）。一方で、画面で見たものをエージェントに頼むには、ID とタイトルを拾い、Skill の名前を思い出してチャットに手で書く手間がある。

ADR-006 の「UI からの書き込みを許す」を反転するので、書き込みの範囲を ADR-006 から分けてこの ADR に置く。画面の構成・配布・コミットの単位は ADR-006 のまま。

## 決定

### 画面から直接書き込むのはチケット詳細と設定画面だけにする

- チケット詳細ではタイトル・本文・Status・属性を直せる。設定画面は `config.yaml` を書く（UI-14）
- それ以外の書き込みは画面に置かない。カンバンとバックログのドラッグ、Iteration・Epic の作成・開始・閉じる・再開とチケットの足し外し、拡張の右クリックの「Iteration を移す」はなくす
- 同期（UI-6）は残す。照合で Status を進めてコミットすることがあるが、Git の事実（ブランチ・PR・マージ）に合わせるだけで、利用者が判断して状態を変える操作ではない

### ほかの変更はエージェントへの依頼文を作ってコピーする

- 画面は、対象（チケット・Iteration・Epic・Plan。複数可）と頼むことと指示から、エージェントに貼る依頼文を作ってクリップボードにコピーするだけで、データには書き込まない
- 依頼文は Core のコマンドで作り、CLI・HTTP・Webview から同じ結果を返す（web は core の実行時のコードを取り込まない。[ADR-007](ADR-007-architecture.md)）。Skill の形は Skill の呼び出し（例 `/dgplan t333 t334`）と、次の行の指示だけにする。呼び出しだけでは頼むことが決まらないもの（起票・作成・外す・分ける・組み直す・持ち越しの割り当て。同じ Skill と対象で別の頼むことと重なるか、行き先が呼び出しに入らないもの）だけは、短い頼みごと（例 `起票して s10 に入れて`・`p3 を組み直して`）を 1 行添える。頼みごとの行は指示の行と同じ位置に置く 1 行として扱い、指示はその次の行に続ける
- Skill を使わないエージェント向けに文章だけの形も選べる。対象の ID を含む頼む 1 文と、`dg` の呼び方の短い 1 文と、指示にする。Skill を持つ頼むことには、`dg` の呼び方の次に、その Skill のトピックの `dg guide <topic>` を読んで進める 1 文を足す（Skill を入れていなくても、承認や品質ゲートの手順を Skill と同じにするため。トピックは Skill の名前から `dg` を除いたもの）。Skill のない頼むこと（閉じる・持ち越しの相談・再開・やめる・done の取り消し・様子を聞く・振り返る・Iteration と Epic の直し・自由に）は、Skill の形を選んでもこの形にする
- 依頼文に入れる対象は ID だけ。題・本文・Status はエージェントが `dg` で読む
- 文章だけの形では、起票の依頼に `--created-by human` を、閉じる・再開・やめる（abandoned）・done の取り消しの依頼に人の指示であることを添える。Skill の形では Skill の手順に任せる
- 操作が 1 つに決まる頼むこと（起票・作成・外す・Iteration と Epic の直し・承認・閉じる・再開・やめる・done の取り消し）は、その操作が `actor.human_only` に入っているか、チケットの遷移を Workflow の `by` が人に限っていれば、依頼文の代わりに人が打つ `dg` のコマンドを出す（画面のボタンという人の入口がなくなるため）。Skill の手順に任せる頼むこと（割り当て・計画・作業・片付けなど）は依頼文のままにし、拒否されたらエージェントが人に頼む
- 吹き出し・右クリック・Shift+F10 のメニューで頼むことを選んだときは、小窓を開くと同時にその依頼文をコピーする（指示の下書きが残っていればそれも含む。指示を足さないことが多いため）。小窓の札で選び直したときも同じ。指示を打ったあとは、コピーのボタンか ⌘↵ で今の指示まで入れてコピーする。見た目の状態からの復元ではコピーしない。コピーに失敗したら小窓は開いたまま理由を出す
- エージェントの起動と、エージェントの入力欄への送り込みはしない（EX-1）。コピーして知らせるだけ

### 入口は行・見出し・タイトル行の吹き出しと右クリックにする

- 行・見出しにマウスを載せると吹き出しのボタンを出し、押すと頼むことの一覧を出す。詳細のタイトルは幅に余裕があるので横に常に出す。場所と状態に合うおすすめを先頭にし、詳細の中の行には入っている Iteration・Epic から外すを足す。右クリックのメニューにも同じ一覧を出す
- 右クリックのメニューの文言は拡張の定義に固定するので、対象で変わる文言は一般の形にする。出す項目とおすすめは、画面が行・見出しに載せた候補（Core の `ask-menu`）で決める
- 指示を書く入力欄は、左パネルとエディタのパネル（ブラウザでは画面）の下に出す。欄に書いたものがそのまま依頼文になる
- VS Code では、左パネルのタイトル行の吹き出し（左パネルのカンバンで選んでいる Iteration や、履歴で開いている行が対象）と、コマンドパレットの「エージェントに頼む」からも頼める
- Iteration 詳細の次の操作の案内（`iteration.show` の `next`）からも、決まった頼むことの依頼文をコピーできる（持ち越しの相談は閉じる依頼とは別の頼むこと）
- ブラウザ（`dg serve`）も同じ画面の部品で、吹き出しと Shift+F10 から頼む（右クリックのメニューは VS Code だけ）
- 行は Ctrl/⌘・Shift+クリックで複数選び、まとめて頼める。選んでいる間は画面の下に選択の帯を出し、そこからも頼める

## 理由

- Iteration・Epic の変更と Status を進めることには、Skill の手順に点検（dgcheck）・承認（dgplan）・照合（dgdone）がある。画面から直接変えるとその外で状態が変わり、Plan の帯や照合と食い違う
- チームのデータの状態を変える入口がチケット詳細とエージェントの 2 つになり（設定画面と同期を除く）、どこで状態が変わったかを追いやすい
- チケット詳細の編集は、開いた 1 件を確かめながらの小さな直しで、手順を通すほどではない。ドラッグは一覧から気軽に動かせるぶん、手順の外の変更が起きやすい。設定はチームのデータではなく道具の設定
- ADR-006 は「画面から書き込めないと、エージェントを使わない利用者が CLI を覚えることになる」として書き込みを許した。この反転の後も、閲覧とチケット 1 件の直しは画面だけで足りる。Iteration・Epic の操作は CLI で行うことになるが、たまにしかせず、計画と一緒に考える操作なので手順に乗せる方を採る
- コピーして渡すだけなら、エージェントの製品（Claude Code・Codex・MCP のクライアント）に依存せず、起動を扱わない方針（EX-1）を保てる
- ID だけなら依頼文が短く、題や本文の古い写しが残らない。説明の文と対象の一覧は、Skill の手順と `dg` で読める内容の繰り返しになる
- 右クリックだけでは頼める場所が見えない。吹き出しは VS Code のツリーの行の操作ボタンと同じ出し方で、ふだんは行の右端の印を隠さない

## 採らなかった案

- **画面から書き込めるまま、依頼文も足す**：手順の外の変更が残り、書き込みの入口が増える
- **チケット詳細も表示だけにする**：1 件の小さな直しまで手順を通すと手間が大きい
- **ドラッグを残し、落とすと依頼文を作る**：動かしたのにカードが元に戻るので分かりにくい
- **コピーの後に Claude Code を開く・送り込む**：特定の拡張に依存し、エージェントの起動に踏み込む
- **依頼文に本文を含める**：長くなり、古い本文が写る。エージェントは `dg` で読める
- **Skill の形にも説明の文と対象の一覧（ID・題・Status・Iteration）を添える**：貼る文が長く、人が読み返す前に Skill の手順と食い違う
- **行に「…」のボタンを常に出す**：狭い左パネルで右端の印と場所を取り合い、一覧まで 2 回押す
- **VS Code の QuickPick と InputBox で作る**：指示が 1 行しか書けず、ブラウザでは別に作ることになる
