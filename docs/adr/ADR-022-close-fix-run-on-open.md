# ADR-022 同じチケットの次の Run を開く処理が、開いたままの手直しの Run をその場で閉じる

- ステータス：承認
- 更新日：2026-11-08

## 背景

親が自分で直す手直し（もう一度の claim が開く Run）には、終わりの出来事がない。[ADR-005](ADR-005-work-metrics.md) は、照合が次の区切り（同じチケットの次の Run の開始・PR の ready・マージ・チケットの終了）を見たときに閉じると決めた。区切りの事実はあっても、`sync` が回るまで Run は実行中に見える。t554 では、3 回目の見直しが終わった後も 2 回目の手直しが実行中に見えた（記録の `finished_at` は正しかった）。

[ADR-018](ADR-018-fix-run-by-marker.md) は、前の手直しをその場で閉じるのを、もう一度の claim と手直しの起動のフックだけにした。見直しの起動のフックと `run start` は、同じ区切りを作っても閉じなかった。

試作で、区切りの判定にずれが 2 つ見つかった。

- 前景の起動は、かかった時間だけ開始を前にする（[ADR-017](ADR-017-review-result-binding-edge-cases.md)）。前にした開始が手直しの開始より前なら、その起動は手直しの区切りにならない
- 照合は手直しより「後」に始まった Run だけを区切りにしていた。時刻は秒までなので、手直しと同じ秒に始まった次の Run を区切りに数えなかった

## 決定

- Run を開く処理（`openRun`）が、開く前に、このマシンで開いたままの同じチケットの手直しの Run を閉じる。claim・もう一度の claim・起動のフック・`run start` のどこから開いても同じ規則になる
- 区切りの判定は照合と同じ。新しい Run の開始が手直しの Run の開始と同じ秒か後のときだけ閉じる。前景の起動で前にした開始が手直しより前なら閉じない
- `finished_at` は RN-6 の決め方のまま。手直しの開始より後で区切りまでの最後の push の時刻で、push がなければ区切り（新しい Run の開始）の時刻
- 結果は照合と同じ `success`。ただし手直しの step を開くときに、前の手直しが別のセッションで開いたものなら、落ちたセッションの残りとみなして `interrupted` にする（[ADR-015](ADR-015-interrupt-stale-session-runs.md)）。見直しなど、ほかの step を開くときは、セッションを問わず `success`
- 同じチケットと step の Run が開いたままなら、二重起動として拒む（SY-5）ので、前の手直しも閉じない。ただし手直しを新しく始める操作（もう一度の claim と印の起動のフック）が手直しの step を開くときは、[ADR-018](ADR-018-fix-run-by-marker.md) のとおり前の手直しを閉じて開き直す。`run start` で手直しの step を重ねて開くのは拒む
- 閉じられなくても（git の失敗など）、Run を開くのは止めない。警告して開き、後の照合が同じ区切りで閉じる
- 照合の区切りも、手直しと同じ秒に始まった次の Run を区切りに数える。照合は、閉じ損ねた手直しの Run（別のマシンで開いた次の Run・前の版の dg で開いた Run）を拾い直す役として残る

### 置き換えるもの

- [ADR-018](ADR-018-fix-run-by-marker.md) の「手直しの Run も印で開く」の節の 2 項目のうち「起動のフックは、印の step が手直しの step なら、」の部分を、この決定で置き換える（手直しの起動だけでなく、どの Run を開くときも閉じる）

## 理由

- 区切りの事実（次の Run の開始）が起きた場所で閉じれば、`sync` を待たずに記録と見え方が一致する。区切りの判定を照合と同じにするので、どちらが閉じても同じ結果になる
- 別のセッションの手直しを `interrupted` にするのは、手直しを新しく始める場合だけにする。見直しを始めるのは、前の手直しが終わった事実の区切りなので、照合と同じ `success` にする
- 同じ秒を区切りに数えるのは、時刻が秒までの記録で前後を決められないため。手直しの後に続けて見直しを開くと、同じ秒になりうる

## 採らなかった案

- 照合の回数を増やす（`dg next` や Stop のフックで sync を回す）：区切りの事実が起きてから閉じるまでの間は残り、フックのたびに git と gh を呼ぶので重い
- 実行中に見える手直しの Run を、画面と `run list` の側で区切りの後なら終わったものとして見せる：記録と見え方が分かれ、集計の側でも同じ判定を持つことになる

## 制限

- 閉じるのは、このマシンで開いたままの手直しの Run だけ。別のマシンで開いた手直しは、そのマシンの照合が閉じる
- 同じ秒の前後は決められないので、同じ秒に開いた次の Run は、手直しより先に始まっていても区切りに数える
- 二重起動の判定と前の手直しを閉じる処理は同じロックの中にないので、同じチケットの Run を別のプロセスが同時に開くと、拒まれた側が前の手直しを閉じることがある
