# ADR-030 Iteration の流れもコードが判定し、guide の節は Core が返し、カスタマイズは Workflow と config と guide.notes に限る

- ステータス：承認

## 要約

Iteration の流れ（段階・次の 1 手・止まる判定・承認の要否）は `dg flow next` が返し、`dg guide` は各手のやり方だけを書く。承認の要否は Workflow の権限の値から決め、`--auto` は「値が `ask_unless_auto` の場面を聞かずに進める」の 1 つの意味にして、各コマンドが受けて判定する。コマンドで止められない判断は関所（`dg checkpoint`）が段階の値で判定して Iteration に根拠付きで記録し、`dg flow next` はその記録で段階を終えたかを決める。利用者が手続きを変える入口は Workflow の値と独自の段階、config の項目、`guide.notes` の枠に限る。Skill の印は書いた dg の版を持ち、VS Code 拡張の更新と dg の警告は版で新旧を比べる。

## 背景

[ADR-011](ADR-011-procedure-in-code.md) は 1 枚のチケットの手続き（段階・次の 1 手・修正ループ・品質ゲート・brief）を Core に移した。Iteration の流れ全体（割り当て → 点検 → 計画 → 作業 → 見直し → リリース）は、なお `dg guide all` の 8 つの規則と止まる判定を親の LLM が読んで求めている。2026-11-08 の検討で、残る問題が次のとおり出た。

- 段階の判定と `--auto` で自動に選んでよい判断が文のままで、LLM が読んで守るので、段階の飛ばしや止まり損ねが確率的に起きる
- 親とサブエージェントは、要る節が 1 つでも guide のトピック全体を読み直す。節だけを渡せば読む量は 75〜87% 減る
- 段階の判定に要る事実のうち「割り当てを終えた・点検した・見直しを終えた」は、Git にもチケットのデータにもなく、会話の中にしかない。コマンドで止められない判断は、dg が判定も記録もしていない
- 利用者が手続きを変える入口が定まっていない。config の値は guide の文に埋まるだけで効くかは LLM 次第、SKILL.md を書き換えると `dg skill install` の更新を受け取れず、CLAUDE.md は形が決まっていないので dg が読めない
- `dg next`・`dg brief` が guide の節の本文を返すには、CLI に同梱した guide-*.md（CL-5）を Core から読む必要があるが、[ADR-033](ADR-033-architecture.md) では Core は CLI に依存しない

この ADR は ADR-011 を置き換えず、その範囲を Iteration の流れと guide の読み込み・カスタマイズに広げる。[ADR-011](ADR-011-procedure-in-code.md) の決定はそのまま有効。

## 決定

### 流れの段階と承認の要否はコードが持つ

- Iteration（かチケットの束）の流れの段階、次の 1 手、止まる判定、承認の要否は Core のコマンド（`dg flow next`）が返す。`dg guide all` は段階の順と判定の規則を書かず、返った手の行い方だけを書く
- 承認の要否は、Workflow の権限の値（[ADR-003](ADR-003-status-and-workflow.md)）をエージェントに当てて決める。段階ごとの値は `flow`（assign・check・plan・audit・release・retro）に、作業の段階のマージは review → done の境目の `decide` に書く。既定は assign・check・plan が `ask_unless_auto`、audit・retro が `always_ask`、release が `human_only`
- `flow` の値のうち、コマンドで止められる操作は dg が判定して拒否する：割り当て（Iteration・Epic への出し入れ）は assign、Plan の承認は plan、Iteration を閉じる・再開するは release。コマンドで止められない場面（点検の直す行・見直しの指摘の表・リリースの手順・振り返りの改善の起票）は、手順が関所を呼んで同じ値で判定する（次の節）
- assign が判定するのは、すでにあるチケットの出し入れだけ。起票のときの指定（`ticket create`・`import` の `--iteration`・`--epic`）は起票の判定（`governance.create`）に、`claim` が自分で入れる Iteration は config の `lint.require_iteration` に従うので、assign の外に置く（同じ操作を 2 つの値で判定しない）
- 動かすのは引き続きエージェントで、dg はエージェントを起動も監視もしない（[ADR-028](ADR-028-agents-and-state.md)・EX-1）

### `--auto` は ask_unless_auto の場面を聞かずに進める意味だけを持ち、各コマンドが受ける

- `--auto` の意味は 1 つ：権限の値が `ask_unless_auto` の場面を、人に聞かずに進める。どの判断を聞かずに進めてよいかは Workflow の値だけが決め、config に `--auto` の範囲を書く項目（前の `auto.merge`・`auto.decisions`）は持たない
- 権限を判定するコマンド（Status の動き・`pr ready`・`pr merge`・流れの段階の操作・カンバンの管理の操作）は `--auto` を受ける。値が `ask_unless_auto` の場面でだけ聞かずに通し、承認者に進めたエージェントを記録する。ほかの場面の `--auto` は拒否する：`always_ask` と `human_only` と Core の固定（[ADR-026](ADR-026-guard-pr-and-data.md)）は越えさせず、聞かない場面（`anyone`）や何も判定しない呼び出しにも付けさせない
- `--auto` はエージェントだけが渡せ、人の承認（`--approved-by`）や人の強制（`--override`）とは一緒に渡せない。`dg workflow set` は `--auto` を受けない
- `dg flow next --auto` は、聞かずに進められる場面（`approval.auto_ok`）と、`--auto` を付けたコマンドを返す。値と拒否の文の細部は `core/commands/permission.ts` と各 `--help` が正本

### 段階を終えたことは、関所の記録を Iteration に根拠付きで足して決める

- 関所（`dg checkpoint <段階>`）は段階の手順が呼ぶ。段階の値（`flow`）で判定し、通ったときだけ Iteration の `checkpoints` に記録（名前・日時・主体・承認者・根拠）を足す。plan は関所を持たず、Plan の承認の記録を使う
- 記録は消さずに足し、会話・人・マシンをまたいで有効にする。通ったときに見たもの（根拠）を添え、根拠が今の事実に合わない記録と `iteration reopen` より前の記録は数えない
- `dg flow next` は、割り当て・点検・見直しを終えたかを記録と根拠で決める。関所を呼び忘れると同じ段階を返し続け、止まる判定が止める
- 止まる判定（同じ段階が事実も変わらずに続いたら止める）は共有せず、`deguboard-local/flow/` に対象ごとに覚える
- 記録を書く対象は Iteration だけ。Iteration のない流れは最初の割り当てで Iteration を決め、決まらないときの割り当ての記録だけをローカルに書く。Epic への見直しは持たない
- 段階ごとの根拠と止まる判定の細部は `core/commands/flow-records.ts` と各 `--help` が正本

### guide の読み込みは Core に置く

- guide の本文（guide-*.md）と読み込み（frontmatter の分離・節の切り出し・共通の節 `{{choices}}` と core のデータから作る表（`{{recommended_metrics}}`）の差し込み・config の値と `guide.notes` の埋め込み）は Core に置く。`dg next`・`dg brief`・`dg flow next` は、指す節の本文を Core の中で読んで返す
- `dg guide` と `dg skill install` は CLI だけの操作のまま（AG-4）で、Core の読み込みを写す
- Core が読むのは同梱の静的な文書だけで、VS Code API・HTTP・React には依存しない（ADR-033 の依存の向きは変えない）。束ねられる入口（VS Code 拡張）でも読めるようにする方法は実装の細部

### カスタマイズは Workflow の値と config の項目と guide.notes の枠で行う

- 利用者が既定の手続きを変える入口は、`workflow.yaml` の値（誰に任せるか・聞かずに進めてよい場面・流れから外す段階 `flow` の `skip`。[ADR-003](ADR-003-status-and-workflow.md)）と、`config.yaml` の項目（マージの方法・検査のコマンドなど。名前は config のスキーマが正本）と、guide の決まった位置に文を差し込む `guide.notes.<topic>` と、下の独自の段階だけにする。値と項目はコードが読んで判定に効かせ、同梱の手順に文を足せるのは `guide.notes` だけ。並列の上限 `work.parallel` の扱いは [ADR-011](ADR-011-procedure-in-code.md) に従う
- 同梱の段階にない段階（検証環境で確かめる、など）は、`workflow.yaml` の `flow` に独自の段階として足す。書くのは、誰が決めるか `decide`・位置 `after`・手順の文書 `guide`（リポジトリの中のパス）の 3 つ。独自の段階はいつも関所で、`dg flow next` は同梱の段階と同じ形（文書の本文・関所のコマンド・承認の要否）で返す
- `after` に書けるのは同梱の段階（work を含む）だけ。同じ `after` の段階は書いた順に行い、独自の段階どうしの順は検査しない
- 手順の文書が読めないときは、警告を出して段階は返す（`guide.notes` と同じ）。位置と返し方の細部は `core/commands/flow.ts` と `dg flow next --help` が正本
- SKILL.md と guide の書き換えはカスタマイズの前提にしない。Skill は `dg skill install` で最新に保てる形のままにする
- 修正ループの回数は config に置かない

### Skill の印は書いた dg の版を持ち、自動の更新と警告は版で新旧を比べる

- SKILL.md は frontmatter の直後に印 `<!-- dg skill v<書いた dg の版> sha256:<印の行を除いた中身のハッシュ> -->` を持つ。ハッシュで手を加えたかを、版で今の dg より古いか新しいかを見分ける
- 自動の更新と警告は版で新旧を比べ、新しい dg が書いた Skill を古いものに戻さない
- 更新・警告の出し分けと手動のインストールの細部は、`packages/core/src/commands/skill-files.ts` とそのテストを正本にする

## 理由

- 段階の判定と承認の要否をコードに置けば、ADR-011 で 1 枚のチケットに得た「毎回同じに守れる」を流れ全体に広げられる。親は 8 つの規則を読まずに 1 手ずつ行える
- 承認の要否を Workflow の値から決めるのは、人とエージェントの分担を書く場所を 1 つにするため。config の `auto.merge`・`auto.decisions` と Workflow の値の両方が「聞くか」を決めると、どちらが効くのかが読めず、片方を緩めてももう片方で止まる
- `--auto` を各コマンドが受けるのは、聞かずに進めるのを `ask_unless_auto` の場面に限るため。dg は流れが `--auto` で始まったかを知らないので、コマンドに渡されなければ `ask_unless_auto` をいつも聞く値（`always_ask` と同じ）にするか、流れの外でも聞かない値（`anyone` と同じ）にするしかなく、値を分けた意味がなくなる。コマンドが受ければ、dg が場面を照らして、`always_ask`・`human_only`・Core の固定を `--auto` で越える呼び出しを拒否できる。聞かずに進めた跡（承認者がエージェント）も、人の承認と区別して履歴に残る
- 聞かない場面の `--auto` も拒否するのは、付けたままのコマンドが、値を厳しくした後もそのまま通るように見えるのを防ぎ、`--auto` が効いた操作だけに跡を残すため
- 関所を通ったときにだけ記録を足せば、手順の途中で止まった段階を終えたものとして飛ばさない。記録は Iteration にあるので、新しい会話や別の人が続きを始めても割り当てと点検をやり直さず、人が「入れない」と決めた候補も聞き直さない
- 記録をずっと有効にすると数日前の点検を根拠に飛ばしてしまうので、根拠を添えて、変わったら数えない。消さないのは、誰がいつ何を見て通したかを履歴に残すため
- コマンドで止められない判断も関所で判定すれば、段階の値がどれも dg の判定になり、手順で頼むだけの値がなくなる
- 止まる判定は、このマシンのエージェントが同じことを回していないかを見るもので、共有する判断ではない
- `dg next`・`dg brief` は Core のコマンドで、CLI・HTTP・MCP が同じ結果を写す（CL-6）。読み込みを CLI に残すと、節の本文を足す処理が入口に入り、入口ごとに結果がずれる。Core に置けば 1 か所で読み、どの入口でも同じ本文が返る
- guide は dg の版と一緒に変わる同梱の文書で、Core が読んでも外の仕組みに依存しない
- 判定に効かせる Workflow の値と config の項目はコードが読むので、効くかが LLM 次第にならない。文を足す口を `guide.notes` の 1 つに限れば、SKILL.md と guide を書き換える理由がなくなり、更新を受け取り続けられる。dg が形を知っているので、決まった位置に差し込める
- 独自の段階を同梱の段階と同じ形で返すのは、流れを回す Skill（dgall）を作り直さずに済ませるため。段階があること・位置・誰が決めるかは dg が判定し、文書が持つのは手のやり方だけなので、効くかは LLM 次第にならない。文書が読めなくても段階を返すのは、落とすと関所を通さずに次へ進むため
- `after` を同梱の段階に限るのは、独自の段階どうしの順（循環・途切れ）の検査を持たずに済ませるため。順は書いた順で足りる
- 印に版を持たせるのは、中身の違いだけでは新旧が分からないため。拡張が中身の違う Skill を同梱のものに揃えると、PATH の dg（ソースから動かす dg など）が拡張より新しいときに、拡張は起動のたびに Skill を古いものに戻し、dg はそれを古いと警告して、互いに書き換え合った。同じ版で止めるのは、ソースの dg が版を上げる前に Skill を変えるため。印の形は各自のマシンに残るデータの形なので、ここに書く

## 採らなかった案

- **フックで手続きを強制する（Stop・PreToolUse）**：止まらないループや誤った拒否のおそれがあり、Claude Code でしか効かない。フックは語の有無で粗く止める線（[ADR-026](ADR-026-guard-pr-and-data.md)）を越える
- **dg がエージェントを起動して流れを進める**：先行プロジェクトで起動と監視が壊れて削除した。製品に依存し、ADR-028 と EX-1 を覆す
- **流れの事実を Run に印として残す**：Run を実績の記録（[ADR-029](ADR-029-work-metrics.md)）の外の用途に使う
- **流れの事実をセッションごとに deguboard-local に残す**：フックのない製品ではセッションを見分けられず効かない
- **終えたことを不透明な値 `resume` で次の呼び出しに写して渡す**：返しただけで終えたとみなすので途中で止まった段階を飛ばし、会話をまたげず、写し忘れると最初からやり直す
- **止まる判定をやめる**：承認待ちやマージ待ちで同じ段階を回し続ける
- **Iteration のない流れの点検・見直しの記録をローカルに置く**：同じ段階の記録が、流れによって共有されたりされなかったりする。ローカルに書くのは、書く先の Iteration が決まらないときの割り当ての記録だけにする
- **`--auto` の範囲を config の項目（`auto.merge`・`auto.decisions`）で決める**：「聞くか」を決める場所が Workflow と 2 つになり、dg はどのコマンドも止められず、守るかが LLM 次第に残る
- **`--auto` を `dg flow next` だけが受け、各コマンドは受けない**：dg は聞かずに進めた操作を見分けられず、`ask_unless_auto` を `always_ask` か `anyone` と同じに扱うしかない
- **人が決める穴（リリース・閉じる・やめる）を、値によらず自動で選ばない手として Core に固定する**：分担を書く場所が Workflow と Core に分かれる。緩めると守りが崩れる操作だけを Core に固定し（ADR-026）、ほかは既定の値（`human_only`・`always_ask`）で同じ扱いにする
- **guide の読み込みを CLI に残し、CLI が next・brief の結果に節を足す**：入口にロジックが入り、HTTP・MCP の結果が CLI とずれる（ADR-033）
- **入口が guide の読み手を Core に注入する**：すべての入口が同じ読み手を渡す必要があり、渡し忘れた入口だけ結果が欠ける。版と一緒に変わる静的な文書に注入の口は要らない
- **SKILL.md・guide・CLAUDE.md の書き換えでカスタマイズする**：Skill と guide は更新を受け取れなくなり、CLAUDE.md は dg が形を読めない
- **独自の段階の手順を `guide.notes` に書く**：`guide.notes` は同梱のトピックの決まった位置に差し込む枠で、同梱にない段階には差し込む先がない。段階の定義（`decide`・`after`）と手順の場所が 2 つのファイルに分かれる
- **独自の段階の `after` に独自の段階を書けるようにする**：順の検査（循環・ない名前）が要る。同じ `after` を書いた順に行えば足りる
- **Skill を追跡して共有する**：dg の版を上げるたびに差分が出て、人によって版が違うと書き戻し合う。Skill は各自が `dg skill install` で入れ、共有する文は `guide.notes` に置く
- **拡張が、中身の違う Skill を版を見ずに同梱のものに揃える**：新しい dg が入れた Skill を起動のたびに古いものに戻し、dg の警告と書き換え合う
- **版を印と別の行に書く**：版を知らない前の拡張が、手を加えていない違う Skill と読んで上書きする。印の行を変えれば、前の拡張は手を加えたものと読んで残す
