# ADR-030 Iteration の流れもコードが判定し、guide の節は Core が返し、カスタマイズは config と guide.notes に限る

- ステータス：承認
- 更新日：2026-11-09

## 背景

[ADR-011](ADR-011-procedure-in-code.md) は 1 枚のチケットの手続き（段階・次の 1 手・修正ループ・品質ゲート・brief）を Core に移した。Iteration の流れ全体（割り当て → 点検 → 計画 → 作業 → 見直し → リリース）は、なお `dg guide all` の 8 つの規則と止まる判定を親の LLM が読んで求めている。2026-11-08 の検討で、残る問題が次のとおり出た。

- 段階の判定と `--auto` で自動に選んでよい判断が文のままで、LLM が読んで守るので、段階の飛ばしや止まり損ねが確率的に起きる
- 親とサブエージェントは、要る節が 1 つでも guide のトピック全体を読み直す。節だけを渡せば読む量は 75〜87% 減る
- 段階の判定に要る事実のうち「この実行で割り当てを終えた・点検した・見直しを終えた」は、Git にもチケットのデータにもなく、会話の中にしかない
- 利用者が手続きを変える入口が定まっていない。config の値は guide の文に埋まるだけで効くかは LLM 次第、SKILL.md を書き換えると `dg skill install` の更新を受け取れず、CLAUDE.md は形が決まっていないので dg が読めない
- `dg next`・`dg brief` が guide の節の本文を返すには、CLI に同梱した guide-*.md（CL-5）を Core から読む必要があるが、[ADR-033](ADR-033-architecture.md) では Core は CLI に依存しない

この ADR は ADR-011 を置き換えず、その範囲を Iteration の流れと guide の読み込み・カスタマイズに広げる。ADR-011 の決定（1 枚のチケットの手続き・人の判断の穴・修正ループと並列の上限を config に置かない）はそのまま有効。

## 決定

### 流れの段階と自動で選べる判断はコードが持つ

- Iteration（かチケットの束）の流れの段階、次の 1 手、止まる判定、`--auto` で自動に選んでよい判断かどうかは Core のコマンド（`dg flow next`）が返す。`dg guide all` は段階の順と判定の規則を書かず、返った手の行い方だけを書く
- 人が決める穴（やめる・done の取り消し・リリースの PR のマージと公開・Epic と Iteration を閉じる）は、config によらず自動で選ばない手として返す（ADR-011 の「人の判断の穴は残す」を変えない）
- 動かすのは引き続きエージェントで、dg はエージェントを起動も監視もしない（[ADR-028](ADR-028-agents-and-state.md)・EX-1）

### 会話の中にしかない事実は resume を写して渡す

- `dg flow next` は、Git とチケットのデータから求められない事実（割り当て・点検・見直しを終えた）を、次の呼び出しに渡す不透明な値 `resume` として返す。エージェントは次に `--resume` でその値をそのまま写して渡し、自分で組み立てない
- `resume` は保存しない（Git にも deguboard-local にも書かない）。値を失っても、段階を飛ばさずに割り当てと点検をやり直すだけになる
- 同じ段階が続き事実も変わらないときに止まる判定も、`resume` を受けて dg が行う

### guide の読み込みは Core に置く

- guide の本文（guide-*.md）と読み込み（frontmatter の分離・節の切り出し・共通の節 `{{choices}}` の差し込み・config の値と `guide.notes` の埋め込み）は Core に置く。`dg next`・`dg brief`・`dg flow next` は、指す節の本文を Core の中で読んで返す
- `dg guide` と `dg skill install` は CLI だけの操作のまま（AG-4）で、Core の読み込みを写す
- Core が読むのは同梱の静的な文書だけで、VS Code API・HTTP・React には依存しない（ADR-033 の依存の向きは変えない）。束ねられる入口（VS Code 拡張）でも読めるようにする方法は実装の細部

### カスタマイズは config の項目と guide.notes の枠で行う

- 利用者が既定の手続きを変える入口は、`config.yaml` の項目（流れから外す段階・自動で選んでよい判断・マージの方法・検査のコマンドなど。名前は config のスキーマが正本）と、guide の決まった位置に文を差し込む `guide.notes.<topic>` だけにする。項目はコードが読んで判定に効かせ、文を足せるのは `guide.notes` だけ
- SKILL.md と guide の書き換えはカスタマイズの前提にしない。Skill は `dg skill install` で最新に保てる形のままにする
- 修正ループと並列の上限は config に置かない（ADR-011 を変えない）。人が決める穴も config の項目にしない

## 理由

- 段階の判定と自動で選べる判断をコードに置けば、ADR-011 で 1 枚のチケットに得た「毎回同じに守れる」を流れ全体に広げられる。親は 8 つの規則を読まずに 1 手ずつ行える
- `resume` を写させるだけにすれば、事実の記録を LLM の組み立てに頼らず、減らしたい確率的な部分を戻さない。保存しないので Git に書く量が増えず、フックのない製品や MCP からも同じに使える。失っても安全側（やり直し）に倒れる
- `dg next`・`dg brief` は Core のコマンドで、CLI・HTTP・MCP が同じ結果を写す（CL-6）。読み込みを CLI に残すと、節の本文を足す処理が入口に入り、入口ごとに結果がずれる。Core に置けば 1 か所で読み、どの入口でも同じ本文が返る
- guide は dg の版と一緒に変わる同梱の文書で、Core が読んでも外の仕組みに依存しない
- config の項目はコードが読むので、効くかが LLM 次第にならない。文を足す口を `guide.notes` の 1 つに限れば、SKILL.md と guide を書き換える理由がなくなり、更新を受け取り続けられる。dg が形を知っているので、決まった位置に差し込める

## 採らなかった案

- **フックで手続きを強制する（Stop・PreToolUse）**：止まらないループや誤った拒否のおそれがあり、Claude Code でしか効かない。フックは語の有無で粗く止める線（[ADR-026](ADR-026-guard-pr-and-data.md)）を越える
- **dg がエージェントを起動して流れを進める**：先行プロジェクトで起動と監視が壊れて削除した。製品に依存し、ADR-028 と EX-1 を覆す
- **流れの事実を Run に印として残す**：Git に書く量が増え、Run を実績の記録（[ADR-029](ADR-029-work-metrics.md)）の外の用途に使う
- **流れの事実をセッションごとに deguboard-local に残す**：フックのない製品ではセッションを見分けられず効かない
- **resume の中身をエージェントが組み立てる**：事実の記録が LLM 次第に戻り、確率的な飛ばしが残る
- **guide の読み込みを CLI に残し、CLI が next・brief の結果に節を足す**：入口にロジックが入り、HTTP・MCP の結果が CLI とずれる（ADR-033）
- **入口が guide の読み手を Core に注入する**：すべての入口が同じ読み手を渡す必要があり、渡し忘れた入口だけ結果が欠ける。版と一緒に変わる静的な文書に注入の口は要らない
- **SKILL.md・guide・CLAUDE.md の書き換えでカスタマイズする**：Skill と guide は更新を受け取れなくなり、CLAUDE.md は dg が形を読めない
