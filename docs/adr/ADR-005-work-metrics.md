# ADR-005 作業の実績

- ステータス：承認
- 更新日：2026-11-07

## 背景

チケットの分割の粒度やモデルの選び方を決めるのに、AI エージェントがどれだけのトークンと時間を使ったかの実績が欲しい。ただし AI の自己申告は正確でなく、会話記録は個人のデータでもある。何を、どこから、どこまで記録するかを決める。

## 決定

### 実測し、自己申告しない

- 使用量は Run 単位で記録する。1 つのチケットに複数の Run を紐づける
- 数は公式に提供される使用量の情報（今は会話記録）から取る。エージェントに数字を言わせて書かない
- 取れない指標は `null` にして警告する。架空の値で補完せず、推定した値には `estimated: true` を付ける
- エージェントごとに取得方法が違う部分は Adapter が吸収する（今は Claude Code・Codex・Copilot）
- Run のエージェント名は `run start` の `--agent` で渡すか、省けば Adapter が dg を呼んだプロセスの環境変数から判定する。製品が付ける変数を確かめられない Adapter は判定せず `--agent` を求める（claim で Run を開くときもエージェントに名前を言わせずに済む）。判定の正本は Adapter のコード

### 記録するもの

- エージェント・モデル・日時・トークン数・結果・エラー・やり直しの理由・step（項目は RN-1）
- ツールの呼び出しの種類（読む・探す・書く・Bash・ほか）ごとの回数と、最初に書くまでの読む・探すの回数。手引き（`dg guide`）を変えたとき、調べる量が減ったかを Run で比べるため（参考節の効果は親の側に出るので Run では比べない）。種類の分け方と、どの Adapter が数えるかの正本は Adapter のコード
- 集計は Run から Step（実装・見直し・手直しを分けて見る）までの単位で表示のたびに求め、保存しない（MT-3）
- Epic・Iteration・Project へは、Run の持つチケットの今の所属でたどる（持ち越したチケットの Run は今の Iteration に数える）。Run に所属を写すと、チケットを動かしたときに Run と食い違うため

### 実装・見直し・手直しを別の Run にする

- 実装の Run は、作業するエージェント自身の `ticket claim` が開き（RN-5）、PR の記録（`ticket update --pr`）か照合が作業ブランチの PR を見つけたときに `success` で閉じる（RN-6）。`finished_at` は PR の作成時刻で、実装は PR を作るまでなので PR がマージされずに閉じていても `success`。PR より後に開き直した Run は照合では閉じない（PR の後の作業は手直しの Run）。やめるときは `unclaim` と `ticket move` の abandoned が `failure` で閉じる（abandoned は手直しの Run も）。PR の要らない作業は `ticket move` の review・done が、PR のない done は `success` で閉じる。閉じた Run への `run finish` は記録を変えない。照合かチケットの操作が閉じる直前に別の文脈が先に閉じた Run は、閉じずに警告するだけで sync と操作は止めない（記録は先に閉じた方のまま）
- ※ ADR-025 で置き換え（この項は失効）。実装をサブエージェントに渡す親は `--no-run` で claim し、サブエージェントが自分で `run start` する。手直しを渡すなら、サブエージェントがもう一度の claim をする（親が開いた Run は、サブエージェントの作業（別の記録）を数えられない）
- ※ ADR-025 で置き換え（この項の「見直し役は見直しの前に `run start` し、終えたら `run finish` する」の部分は失効）。見直し役の見直しは `review`、修正ループの 1 回と人のレビューの後の手直しは `fix` の Run にする。見直し役は見直しの前に `run start` し、終えたら `run finish` する（記録の場所がないときは、後に開くと見直しの応答が期間に入らない）。同梱の software-development と general の `steps` に `review`・`fix` がある
- ※ ADR-025 で置き換え（この項は失効）。手直し（修正ループと人のレビューの後）にはチケットの操作がなく、手順書の `run start`・`run finish` に頼ると Run が残らなかった（修正ループでも開き忘れた）。自分が claim 済みで PR のあるチケットのもう一度の claim を手直しの開始とみなして `opens_on: reclaim` の step（なければ `fix`）の Run を開き（RN-5）、終わりの操作もないので、照合が次の区切り（同じチケットの次の Run の開始・PR の ready・マージ・チケットの終了）を見たときに、それまでの最後の push の時刻で閉じる（RN-6）。修正ループも、見直しの前に `ticket update --pr` で PR を記録するので同じ claim で開き、次の見直しの開始か PR の ready が区切りになる。
- 実装・手直しの Run の抜けは `dg lint` が指摘する（対象は終わっていないチケットと閉じていない Iteration の done。PR（`pr`）があるのに実装の Run がないもの、閉じた実装の Run の後のコミットがどの Run の期間にも入らないもの、見直しの後のコミットに手直しの Run がないもの（安全網））
- ※ ADR-025 で置き換え（この項の「（どちらも claim の `--retry-reason`）」の部分は失効）。手直しの Run には、直した指摘を `retry_reasons` に 1 件 1 行で残す（どちらも claim の `--retry-reason`）。どちらも `fix` なので、`fix` の Run の数は手直しの回数の目安にとどまる。修正ループの上限は手順の側で数える
- 手順は `dg guide work`・`dg guide review` が持つ

### 親の使用量は Run で測らない

- 計画を立て、サブエージェントを進める親の作業は Run にしない（親が自分で実装する分は `implement` に入る）。Run の合計はチケットの作業の量として読み、全体の費用とみなさない
- 親の使用量を測るなら、まず期間を指定した会話記録の親と子の集計から考える

### 推定費用は持たない

- 費用の単価は持たず、トークン数だけを記録する。費用が要るときは利用者が単価を掛ける

### 会話記録を読む許可はリポジトリの設定に置く

- 会話記録（`~/.claude/projects/**`・`~/.codex/sessions/**`・`~/.copilot/session-state/**` など）を読むかどうかは `config.yaml` の `metrics.read_transcripts`（true / false）で決める。チームの方針として Git で共有する
- 個人が拒むときは環境変数 `DEGUBOARD_NO_TRANSCRIPTS` で、そのマシンでは読まない（MT-2）
- 許可がなければ、使用量は `null` のまま、日時・結果などの Run の記録だけを残す。読まなかったとき・取れなかったときは Run を閉じる操作（`run finish` と RN-6 の閉じ方）が警告を返す。Adapter のない agent 名の Run は `run start` が警告する（記録はする）

### 会話記録を Run に結び付ける

- Run を閉じる操作が Run の `agent` の値で Adapter を選び、会話記録から使用量を取る。`run refresh` は後から同じ探し方で取り直し、取れた値だけを書き換える（MT-5）。ツールの回数は取り直さない（閉じた Run で書き換える値を広げない。RN-4）
- ※ ADR-025 で置き換え（この項の「サブエージェントは、開始のフックの入力から自分の記録の場所を取り、親の環境から取らない」の部分は失効）。Run はセッション ID を持つ（予定。実装は t529・t530）。セッション ID は SessionStart フックの入力から取り、`run start`・`ticket claim` が Run に写す（フックのない製品では空）。記録のパスはマシンごとのローカル（`deguboard-local/` の下）に持ち、Git には入れない。サブエージェントは、開始のフックの入力から自分の記録の場所を取り、親の環境から取らない（t530）。数えるのは記録のファイルの先頭から `finished_at` までの応答（サブエージェントの記録は 1 つの依頼で 1 ファイル）。親のセッションのファイルを共有する Run は、`started_at` から `finished_at` までで数える。場所がなければ Run の ID を最初に含む記録（今の推測）から数える。1 つの応答は 1 つの Run にだけ数える。細部は Adapter のコード（`core/agents/adapters/`）とそのテスト

### 写すのは数だけ

- Git に入る記録には、使用量とツールの回数の数とモデル名だけを会話記録から写す。ツールは名前を種類に変えて回数だけを残す。モデル名は会話記録から取れた正式な ID を優先し、別名が残らないようにする（順の正本は `run finish` のコード）。プロンプト・ツールの結果・ファイルの中身・コマンドの文字列・ファイルのパスは写さない。例外はセッション ID だけで、後から数え直すのに RN-1 で残す（記録のパスはローカルに置く）
- 実行中の記録は Git 管理せず、Git に入れるのは Run 完了時の集計だけ（RN-3）
- Run はチケットの ID を持ち、チケットには Run の ID を書き足さない。チケットの Run は Run の側から引く

## 理由

- 自己申告は過小・過大になり、比べられない。公式の使用量なら後から測り直せる
- 単価はモデルや契約で変わり、更新し続ける必要がある。トークン数を残せば費用はいつでも計算できる
- 集計結果はどのみち共有リポジトリに入るので、「読むかどうか」もチームで決めるのが筋。個人の逃げ道は環境変数で足りる
- 数だけなら、チケットをまたいで比べられ、秘密情報が Git に入らない
- 実装の Run の中で修正ループを回すと、見直しと手直しの量が実装に混ざり、チケットの粒度とモデルの選び方の判断に使えない。Run を分ければ `metrics show --step` で比べられる
- 親の使用量を Run で測るには Run の形と多くのコードを変えることになる。親の分は 2026-11-05 の会話記録で単価の比の重みを付けて全体の約 3 割と小さくないが、それを見たうえでも、今はチケットの粒度とモデルの選び方を決める数があれば足りると判断した
- 集計値を保存せず、チケットに Run の ID を書き足さないのは、Run を足すたびに複数のファイルを書き換えて衝突させないため
- 実装の Run の開閉をチケットの操作に付けたのは、手順書を通らずに実装すると `run start`・`run finish` が呼ばれず、Run が残らないか開いたままになったため。使用量は `finished_at` で区切るので、古い手順のまま `run finish` を呼んでも数は壊れない
- 場所がないときの推測では、会話記録を作業ディレクトリと時刻で絞らない。サブエージェントが親と同じ session・作業ディレクトリで並行して動き、区別できないため
- 記録の場所を Run に持つのは、ID の出現で選ぶと、見直し役が後から開いた Run は前の応答を取り逃すため（2026-11 の調査で、成功した見直し 368 件のうち 48 件が出力 300 トークン未満）。パスはホームのパスとユーザ名を含み、Git に入れると他人に見え、別のマシンでは読めないので、マシンごとのローカルに置き、Git にはセッション ID だけを残す

## 採らなかった案

- **推定費用を記録する**：単価表の保守が要り、「推定」が独り歩きする
- **読む許可を利用者ごとにリポジトリの外に置く**：許可の有無がマシンごとに違い、チームで集計が揃わない
- **OpenTelemetry で収集する**：collector が要り、チケットとの紐づけが別に要る
- **チケットごとの `plan` の Run**：入るのは 1 枚を読んで決める 1〜2 回の応答だけで、全体を比べて順を決める考えが入らない
- **Plan に結び付ける親の Run**：Plan の ID は計画の後にしかできず、親の Run は会話の再開をまたいで長く、チケットがある前提のコードを直すことになる
- **すべての Run を Plan に結び付け、1 枚の作業にも軽い Plan を作る**：Plan のない作業と Skill なしの使い方が止まる
- **実装の Run を開けたまま修正ループを回し、`retries` に直した回数を書く**：見直しと手直しの量が実装と分かれない
- **AI に振り返りを書かせて数字を残す**：正確でない
- **会話の中身を記録する**：個人データと秘密情報が Git に入る
- **Run の ID が最初に出た会話記録で結び付ける（今の方法）**：後から開いた見直しの応答を数えられない。場所がないときの落ち先にだけ残す
