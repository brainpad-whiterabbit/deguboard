# ADR-025 Run は harness のフックが印で開け閉めし、step を終えた事実で閉じる

- ステータス：承認

## 要約

Run は harness のフックが印で開け、step を終えた事実で閉じる。サブエージェントの Run は頼む文の印 `deguboard: ticket=<id> step=<step>` で開き、フックが届くセッションでは実装と手直しをいつもサブエージェントに頼む。止まったサブエージェントは事実がなければ閉じずに待つ。落ちたセッションの残りは、次の開始が interrupted で閉じる。フックがなければ Run は記録せず、見直しの結果は持ち主のない保留を見直しの記録にする。

## 背景

Run をエージェント自身が `run start`・`ticket claim` で開き、`run finish` で閉じると、2026-11 の調査で、見直し役が見直しを終えてから `run start` を呼ぶため、見直しの Run の使用量が約 2 割しか入らないことが分かった（成功した見直し 368 件のうち 48 件が出力 300 トークン未満）。自己申告では、開き忘れ・開く時刻の遅れ・閉じ忘れを防げない。

そこで harness（今は Claude Code）のフックが Run を開け閉めする。止まったサブエージェント・落ちたセッション・前景の起動・手直しの区切りの扱いも、この 1 本に今の判断として書く。

## 決定

### サブエージェントの Run はフックが印で開き、自己申告に頼らない

- 親はサブエージェントに頼む文の最初の行に印 `deguboard: ticket=<id> step=<step>` を書く。起動の呼び出しが返ったときのフックが、印のチケットと step の Run を開き、記録の場所をサブエージェントの記録にする。印のないサブエージェント（調べものなど）は Run にしない
- 実装・見直し・手直しのどれも印で開く。サブエージェントは `run start`・`ticket claim` で Run を開かない（委譲する親は `--no-run` で claim する）
- フックが届くセッションでは、親は PR を作るチケットの実装と手直しを、モデルが親と同じときも小さな手直しも、いつもサブエージェントに印で頼む。`dg next` は親が自分で進める道を案内せず、agent が `--no-run` なしで claim（もう一度の claim を含む）すると、Run は開いたうえで頼むよう警告する
- 人の作業、フックが届かないセッションで親が自分で進める実装と手直し、PR の要らない作業（`--without-branch`）は、claim・もう一度の claim・`run start` で開く
- セッションは harness が渡すものから取る（主体はセッションの始まりのフックが入れ、届かないサブエージェントは申告）。セッションの始まりのフックが主体とセッション ID を以後の Bash の環境に入れ、それが届かないサブエージェントの Bash では、製品が親のセッションの ID で付けると確かめた環境変数を Adapter が読む
- フックのイベント・設定・入力の読み方は Adapter に閉じ、Core は製品によらない出来事だけを見る（AG-5）。フックはエージェントを起動も監視もせず（EX-1）、失敗しても作業を止めない
- 受け付ける会話記録のパスは、その agent の Adapter の置き場所の下だけにする（`dg serve` 越しに任意のファイルを読ませない）
- フックの命令は、`dg hooks install` を動かした node と `dg.js` の絶対パスで呼び、git が追跡しないリポジトリの設定（Claude Code は `.claude/settings.local.json`）に書く。追跡する設定には書かない（`--shared` を選べば PATH の `dg` を呼ぶ）。届いていないフックは `dg hooks check` と印で頼む操作が警告する

### 閉じるのは step を終えた事実で決め、止まったら待つ

- step を終えた事実は、実装は PR があること、見直しは結果が記録されていること、手直しは開始より後の push があること
- サブエージェントが止まっても事実がなければ閉じず、止まって待っている印を付けて待つ。同じサブエージェントの再開は同じ Run の続きにする
- セッションの終わりに、そのセッションのサブエージェントの開いたままの Run をすべて閉じる。親が自分で開いた Run はセッションをまたいでよく、PR の記録と照合で閉じる

### 見直しの結果を Run に記録し、見直しの成否をそれで決める

- 見直し役は指摘の数と通ったかを `dg run review-result` で Run に書く。見直しの Run の成否は、その記録の有無で決める
- 修正ループの回数と品質ゲートは、この記録から数える（[ADR-011](ADR-011-procedure-in-code.md)）

### 手直しの Run は次の Run の開始を区切りにその場で閉じる

- 人や、フックが届かないセッションの親が自分で直す手直しの Run は、もう一度の claim が開く（RN-5）
- 手直しには終わりの出来事がないので、同じチケットの次の Run の開始・PR の ready・マージ・チケットの終了を区切りに閉じる
- 次の Run を開く処理が、開く前にその場で前の手直しを閉じる。照合は閉じ損ねたもの（別のマシン・前の版の dg）を拾い直す
- やり直しの理由は `dg run retry-reason` で開いている手直しの Run に書き足す

### 落ちたセッションの残りは、次の開始が interrupted で閉じる

- 同じチケットの見直しか手直しを新しく始めるとき、開いたままの前の Run が別のセッションのものなら、落ちたセッションの残りとみなして `interrupted` で閉じてから開く
- 同じセッションの重ねた見直しは二重の起動として拒む。どちらかのセッションが分からなければ落ちた残りと決めず、今までどおりに扱う

### Run のない間の書き込みは deguboard-local に保留する

- 前景で起動したサブエージェントは、動いている間に Run がない。見直しの結果とやり直しの理由は、書く先がなければこのマシンの `deguboard-local/` にチケットごとに保留し（Git に入れない）、フックがその Run を閉じるときに結び付ける
- 前景の見直し役が動いている間に、別のプロセスの `dg sync`・`dg pr ready` がその保留を見直しの記録（`capture: none`）として先に書いていたら、起動の戻りのフックは新しい Run を開かずにその記録を引き取る（同じチケット・同じセッションで起動より後に書かれた記録だけ）。会話記録を結び付けて使用量を数え直し、`capture: none` を外す。記録を書いた後に置かれた保留の結果（見直し役の呼び直し）があれば、記録の結果をそれに置き換える

### フックがなければ Run は記録せず、見直しの結果は保留を見直しの記録にする

- フックが届かない環境では、印で頼んだサブエージェントの Run を記録しない（Run を作り出さない）
- 見直しの結果は保留のまま残る。開いた見直しの Run も動いているサブエージェントの印もないチケットの保留（持ち主のない保留）を、結果を書いた時刻に閉じた見直しの記録とする。`dg next` の段階と `dg gate` の見直しの条件はこれを数え、何も書かない
- `dg sync` と `dg pr ready` は同じ判定で、持ち主のない保留を閉じた見直しの Run（使用量は null）として Git に書き、保留をその Run に結び付けて消す。この記録にだけ、会話記録を取らなかった印 `capture: none` を付け、ほかの Run には項目を書かない

### 細部の正本

イベントごとの扱い・起動の時刻の補い・区切りの同じ秒の判定・書き終わりの待ち方・sync が閉じる範囲・保留の結び付け方は、次のコードとテストが正本で、「なぜ」はそのコメントとテスト名にある。

- `packages/core/src/commands/hook.ts`（冒頭にイベントごとの扱い）・`packages/core/src/agents/adapters/claude-code-hooks.ts`（Claude Code のフックの入力と発火の順）
- `packages/core/src/commands/run.ts`（`openRun`・`closePreviousFixRun`・`sessionOf`・`run review-result`・`run retry-reason`）・`packages/core/src/run/record.ts`（保留と実行中の記録）・`packages/core/src/commands/setup.ts`（照合の区切り）・`packages/core/src/commands/orphan-review.ts`（持ち主のない保留の判定と数え方・書き方）
- `packages/core/src/commands/hook.test.ts`・`run.test.ts`・`commands-flow-reclaim.test.ts`・`orphan-review.test.ts`・`packages/core/src/agents/agents.test.ts`

## 理由

- 起動の呼び出しの入力には頼んだ文とサブエージェントの ID が同時に入るので、チケット・step と記録を取り違えずに結べる。サブエージェント自身に開かせると、開き忘れと遅れで使用量が欠けた
- 親が自分で進めた Run には親の長い文脈を読み直す分が入り、サブエージェントの Run と比べられない（2026-11-11 の記録では、出力 1 あたりの cache_read がサブエージェントのおよそ 2 倍）。いつも頼めば、チケットの Run の使用量はサブエージェントの会話記録から数えた値にそろう。小さな手直しも例外にしない。フックのない AI では印で頼んでも Run が開かないので、親が自分で進める道を残す。claim を拒まず警告にとどめるのは、フックが届いたかの判定はこのマシンの記録に頼り、外れても作業を止めないため
- 止まったことは終わったことを表さない。事実で閉じれば、質問で止まった Run を誤って失敗にせず、再開の後の作業も同じ Run に数えられる。止まって待っている印は、人を待つ Run を事実から見分ける材料になる
- 見直しの成否を最後の応答の有無で決めると、中身のある結果を出したかが分からない。数で残せば、修正ループとゲートを LLM の読み取りでなく記録から数えられる
- 人や親が自分で直す手直しにはチケットの操作がなく、手順書の `run start`・`run finish` に頼ると Run が残らなかった。自分の claim 済みで PR のあるチケットのもう一度の claim を手直しの始まりとみなせば、操作から開ける
- 区切りの事実が起きた場所で閉じれば、照合を待たずに記録と見え方が一致する。照合と同じ判定にするので、どちらが閉じても同じ結果になる
- フックはどの出来事でもセッション ID を渡し、同じセッションの Run はセッションの終わりが閉じる。別のセッションの Run が開いたままなら、そのセッションの終わりが来なかったと見てよい。閉じずに拒み続けると次の作業の記録が失われ、区切りの success にすると中断が終わった作業に見える
- 落ちたセッションの扱いを見直しと手直しに限るのは、実装の Run がセッションをまたいで続き、PR の記録と照合で閉じるため
- 前景の起動では Run を開く時刻がサブエージェントの作業の後になり、順を変えられない。保留をローカルに置けば Run と Git の形を変えずに結果を失わない
- フックがあれば、前景の見直し役の保留は返ったときに結び付くので、親が次に `dg next`・`dg gate` を呼ぶときまで持ち主のない保留は、フックが記録しなかった見直しと見てよい。フックがないと見直しを数えられず、手順が見直しを繰り返すか止まる。結果を書いた時刻で数えれば、最後のコミットより前の結果が今の見直しにならない
- 保留はこのマシンにしかないので、数えるだけでは別の clone の `dg gate` が見直しを数えられない。Git に書くときに印を付ければ、会話記録から数えていない記録をほかの Run と見分けられる
- 前景の見直し役が動いている間の保留は、フックがあっても別のプロセスの照合が先に記録にしうる。引き取らずに開くと、結果のない Run が失敗で閉じて最新の見直しが失敗に見えるか、同じ見直しを 2 回数える。セッションと起動の時刻で絞れば、ほかの見直し役の記録を取らない
- ハーネスがフックを動かす環境の PATH は利用者のシェルと違いうる（node を mise・nvm・volta などで入れ、対話のシェルでだけ有効にしているなど）。PATH の `dg` を呼ぶと、フックは黙って失敗し Run が残らなかった（2026-11-11）。絶対パスはマシンごとに違うので、追跡しない設定に置く

## 採らなかった案

- **追跡する設定に、PATH の `dg` を呼ぶ命令を書く（今まで）**：ハーネスの PATH に node や `dg` がないと黙って失敗する
- **node を含めた単体の実行ファイルで配る**：node への依存はなくなるが、ビルドと配布の作り直しが大きい
- **`npx deguboard` を呼ぶ**：PATH の npx に頼り、フックのたびに起動が遅い

- **モデルが親と同じなら、親が自分で実装・手直しする（今まで）**：親の長い文脈を読み直す分が Run に入り、サブエージェントの Run と比べられない
- **サブエージェントが自分で `run start`・claim で Run を開く（今まで）**：開き忘れと開く時刻の遅れで使用量が欠け、今回か前の回の Run かも見分けられない
- **サブエージェントの開始のイベント（SubagentStart）で開く**：頼んだ文も記録のパスもなく、並べて起動すると取り違える
- **止まるたび・応答のターンの終わり（Stop）ごとに閉じる**：人の返事を待つ Run まで閉じ、1 つの作業が複数の Run に割れる
- **開いてからの時間で古い Run を閉じる**：作業の長さはまちまちで、動いている Run を閉じうる
- **`dg sync` が別のセッションで開いたままの Run をすべて閉じる**：並行して動いている別の端末のセッションの Run まで閉じる
- **見直し役の最後の応答の文から指摘の数を読む**：文の形に依存し、自己申告を解釈することになる
- **`run finish` に結果の項目を足す**：見直しの Run はフックが閉じるので、見直し役は `run finish` を呼ばない
- **親が頼む文で claim に `--session` を渡させる**：親が自分のセッションの ID を読んで文に書く手順が増え、守られ方が親の手順に依る。続きを頼むとき（SendMessage）に渡し忘れても気づけない
- **持ち主のない保留を、印のない見直しの Run として Git に書く**：使用量もセッションもない Run が、ほかの Run と見分けられずに記録に混ざる
- **照合の回数を増やして手直しの Run を閉じる**：区切りから閉じるまでの間は残り、フックのたびに git と gh を呼ぶので重い
- **手直しを、実装したサブエージェントの会話の続き（SendMessage）で頼む**：起動のフックが来ず Run が開かない。文脈より Run の記録を取る
