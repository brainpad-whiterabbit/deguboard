# ADR-015 別のセッションで開いたままの見直し・手直しの Run は、次の開始が interrupted で閉じる

- ステータス：承認
- 更新日：2026-11-08

## 背景

[ADR-012](ADR-012-hooks-open-runs.md) は、印のあるサブエージェントの Run を起動のフック（PostToolUse）が開き、同じチケットと step の二重起動は拒否して警告にすると決めた。[ADR-014](ADR-014-subagent-stop-and-resume.md) は、閉じ損ねた Run をセッションの終わり（SessionEnd）が閉じると決めた。手直しの Run は、もう一度の claim が前の手直しの Run をこの claim を区切りとして `success` で閉じてから開く（RN-5・RN-6、[ADR-005](ADR-005-work-metrics.md)）。

セッションが落ちて SessionEnd が来ないと、見直しと手直しの Run が開いたまま残り、自動で閉じる仕組みがなかった。

- 見直し：次の見直しの起動は二重の開始として拒否され、`run review-result` はチケットの実行中の見直しの Run（古い Run）に今回の結果を書き、SubagentStop は新しい記録に結び付いた Run を見つけられず何もしない。古い Run は前の見直し役の記録を指したまま閉じず、次の見直しの記録が黙って失われ、そのマシンではそのチケットの見直しの Run を開けなくなる
- 手直し：次のもう一度の claim が前の手直しを区切りとして `success` で閉じ、中断が記録に残らない

Run は開いたセッションの ID（`session`。RN-1）を持ち、harness のフックはどの出来事でも今のセッションの ID を渡し、SessionStart が以後の Bash の環境に `DEGUBOARD_SESSION` として入れる（ADR-012）。

## 決定

### 別のセッションで開いたままの Run は、そのセッションが落ちた残りとみなす

- 印 step=review の起動のフックは、このマシンで開いたままの同じチケットの見直しの Run が別のセッションのものなら、その Run を `interrupted` で閉じてから新しい Run を開く。使用量はその Run の記録の場所から数える。`run review-result` は新しい Run に書く
- もう一度の claim は、開いたままの前の手直しの Run が別のセッションのものなら、`success` ではなく `interrupted` で閉じてから新しい手直しの Run を開く。`finished_at` の決め方（RN-6 の時刻）は今のまま
- 比べるセッションは、フックでは入力のセッション ID、claim では `--session`（なければ環境の `DEGUBOARD_SESSION`）。どちらかのセッションが分からない（null か渡されない）ときは落ちた残りと決められないので、今までどおりに扱う
- `error` には、別のセッションで開いたままだったので落ちたセッションの残りとみなして閉じたことを書く（セッション ID は書かない）
- 同じセッションで同じチケットの見直しの Run を重ねて開くのは二重の起動なので、今までどおり開かずに警告する（前の Run も閉じない）。同じセッションの前の手直しの Run は、今までどおり区切りとして `success` で閉じる

[ADR-012](ADR-012-hooks-open-runs.md) の「サブエージェントの Run はフックが開け閉めする」の、起動で Run を開く項のうち「同じチケットと step の二重起動は拒否されて警告になる」の部分を、この決定で置き換える（別のセッションの見直しの Run は閉じてから開く）。あわせて、もう一度の claim が前の手直しの Run を閉じる規則（RN-5）に、別のセッションの Run を `interrupted` にする場合を足す。

## 理由

- フックの出来事はどれもセッション ID を渡し、同じセッションの中ではサブエージェントの Run を SessionEnd が閉じる。別のセッションの Run がこのマシンで開いたままなら、そのセッションの SessionEnd が来なかった（落ちた）と見てよい
- 閉じずに拒否し続けると、次の見直しの記録が黙って失われ、見直しの Run を開けなくなる。区切りの `success` にすると、中断した作業が終わった作業に見える
- 同じセッションの重ねた見直しは、親が同じチケットの見直し役を並べて起動した誤りなので、閉じると動いている見直し役の Run を壊す。今までどおり拒否する
- 見直しと手直しに限るのは、実装の Run はセッションをまたいで続き、PR の記録と照合で閉じるため（ADR-014）

## 採らなかった案

- 開いてからの時間で古い Run を閉じる：見直しや手直しの長さはまちまちで、動いている Run を閉じうる
- `dg sync` が、別のセッションで開いたままの Run をすべて閉じる：並行して動いている別のセッション（別の端末のエージェント）の Run まで閉じてしまう。次の開始のときだけなら、同じチケットと step を新しく始めるという事実がある
