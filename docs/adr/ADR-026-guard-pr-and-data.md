# ADR-026 PR とデータを守る正しい道は dg のコマンドにし、フックは語の有無で粗く止め、すり抜けは事後に見つける

- ステータス：承認
- 更新日：2026-11-08

## 背景

品質ゲート（`dg gate`、EX-3）を守らせることと、データのリポジトリ（`.git/deguboard/`）を dg の外で書かせないことのために、t532 でツールを使う前のフック（PreToolUse）が Bash のコマンドを字句に分け、`gh pr merge`・`gh pr ready` と PR の指定、`.git/deguboard/` への書き込みを読み分ける形にした。読み違えは通す側に倒れ、見直しのたびに抜け道が見つかった。止めすぎを減らすために文字と言い切れる部分を伏せる形（t545）にしても、伏せた所が次の抜け道になった。

その判断が ADR-019〜021 の 3 本に散り、互いに節と項を置き換え合った。[ADR-001](ADR-001-doc-strategy.md) の基準で、今の判断と理由だけをこの 1 本にまとめ直す。

## 決定

### 守り方は 3 つで組む

- 正しい道の dg のコマンド・フックの粗い拒否・事後の検査の 3 つで守る。フックは書き間違いを防ぐ手がかりで、すり抜け（シェルの外・フックのない環境・わざと隠した形）は事後の検査が見つける
- 権限管理や偽装の防止はしない（同じリポジトリに書ける人を信頼する。[ADR-004](ADR-004-agents-and-state.md)）

### PR を進める正しい道は dg のコマンド

- エージェントが PR を ready にするのは `dg pr ready <ticket>`、マージするのは `dg pr merge <ticket>` で行う。どちらも `dg gate` と同じ判定を満たすときだけ gh を引数配列で呼び、満たさなければ gh を呼ばずに `GATE_FAILED` で満たさない条件と理由を返す。PR の番号はチケットから引く
- ゲートを満たさないまま進める例外は Core に持たせず、人が gh を打つ

### フックは字句を読まず、語の有無だけで粗く止める

- ツールを使う前のフックは、Bash のコマンドを字句に分けて読まない。生のコマンドに dg を経由しない PR を進める gh の語、または `.git/deguboard` の語があれば、引用符・ヒアドキュメント・コメントの中でも止め、正しい道の dg のコマンドへ案内する
- 止めすぎは拒む文の逃げ道（本文の語はファイルに書いて渡す・分けて打つ・データは dg のコマンドで読む）で受け止める
- わざと隠した形は個々に見ない。語として現れない呼び出しと書き込みは通り、事後の検査に任せる
- フックはエージェントを起動しないが、ツールを使う前の呼び出しを読んで拒む

### データの dg の外の変更は事後に見つけて書き込みを止める

- dg のコミットは印を持ち、dg は書き込みのロックを放す前の状態をマシンごとに基準として記録する。印のないコミット・基準と違う作業ツリー・基準の HEAD を捨てた履歴を、dg の外の変更とする
- dg がコマンドを実行するたびと、エージェントが応答を終えたときに確かめる。書くコマンドは `OUTSIDE_CHANGES` で止め、読むだけのコマンドは警告にする。書く前の決め手は書き込みのロックの中の検査で、外の変更を dg のコミットに入れて隠さない
- 戻すか取り込むかは人が決める。取り込みは `dg adopt` が検査を通してから行う

### 細部の正本

止める語と除く形・gh や git の引数・検査の条件と確かめない場面・基準の形・拒む文と戻し方は、次のコードとテストが正本で、「なぜ」はそのコメントとテスト名にある。

- `packages/core/src/commands/pr.ts`（`dg pr ready`・`dg pr merge`）・`packages/core/src/commands/gate.ts`（`judgeGate`）
- `packages/core/src/commands/hook.ts`（`advancesPrOutsideDg`・`touchesDataDir`・`toolRequested`・`turnStopped`）
- `packages/core/src/git/outside.ts`（基準と比べ方・戻し方）・`packages/core/src/git/write.ts`（`withWriteLock`）・`packages/core/src/commands/define.ts`（`runCommand` の検査）
- `packages/core/src/commands/pr.test.ts`・`gate.test.ts`・`hook.test.ts` の「PreToolUse」・`packages/core/src/git/outside.test.ts`

### 置き換えるもの

- ADR-019〜021 の全体
- [ADR-004](ADR-004-agents-and-state.md) の「ツールはエージェントを起動も監視もしない」の節の主体の項のうち、ADR-019 が置き換えた部分（失効の印の先をこの ADR にする）

## 理由

- 正しい道を dg のコマンドにすると、ゲートの判定と gh の呼び出しが 1 つのコードの中でつながり、PR の指定を読む必要がなくなる
- 判定を語の有無だけにすると、読み違えて通す余地がなく、止めすぎの側にしか倒れない。止めすぎても正しい道と逃げ道が 1 つに決まっているので、作業は止まらず拒む文で案内しきれる
- 書かせないことは、シェルの外まで含めて閉じない。書いたら必ず見つかる形なら、すり抜けても次の dg のコマンドで止まり、データが黙って壊れたまま共有されない
- コミットの印とロックの中で記録した作業ツリーの基準を組むと、dg 自身のまとめ待ちの変更と並べて動く dg の書きかけを、外の変更と取り違えない
- 書くコマンドだけを止めるのは、読むコマンドまで止めると戻し方を調べる手段がなくなるため
- 例外を人が gh を打つ形に残すのは、例外を Core に持たせるとエージェントがそれを選べてしまうため（[ADR-011](ADR-011-procedure-in-code.md) の、例外は人の判断に任せる形と同じ）

## 採らなかった案

- **字句の解析を直し続ける**（t532 の分解・t545 の伏せる条件）：シェルの文法は広く、伏せた所と読み違いが抜け道になり、見直しのたびに分岐が増えて閉じない
- **gh を包むラッパーを PATH に置く**：PATH はエージェントや環境が変えられ、絶対パスで外れる。harness の外の人の gh まで変える
- **フックが拒まず、dg のコマンドだけを案内する**：手順を読み飛ばした呼び出しを止められない
- **フックが gh の呼び出しをすべて拒む**：`gh pr create`・`gh pr view` など PR を進めない呼び出しまで止める
- **dg が書いたファイルの一覧を残し、作業ツリーと照らす**：dg がデータに書く場所は多く、どこかで記録を漏らすと dg 自身の変更を外の変更と取り違える
- **dg の外の変更を dg が自動で戻す**：人やエージェントが意図して直した変更まで消す
