# ADR-026 PR とデータを守る正しい道は dg のコマンドにし、フックは語の有無で粗く止め、すり抜けは事後に見つける

- ステータス：承認

## 要約

PR を進めるのは dg のコマンド（`dg pr ready`・`dg pr merge`）だけにし、品質ゲートをチケットの段（`high`・`low`・`free`）の条件で満たすときだけ gh を呼ぶ。満たさない PR のマージは、人が承認したときだけ同じコマンドが行う。緩めると守りが崩れる操作（フックを外す・段を下げる・`workflow.yaml` の書き換え・品質ゲートを越えるマージ）は Core に固定し、設定でも `workflow.yaml` でも緩められない。ツールを使う前のフックは語の有無で粗く止め、フックをすり抜けた変更は、データの dg の外の変更として事後の検査が見つけて書き込みを止める。

## 背景

品質ゲート（`dg gate`、EX-3）を守らせることと、データのリポジトリ（`.git/deguboard/`）を dg の外で書かせないことのために、t532 でツールを使う前のフック（PreToolUse）が Bash のコマンドを字句に分け、`gh pr merge`・`gh pr ready` と PR の指定、`.git/deguboard/` への書き込みを読み分ける形にした。読み違えは通す側に倒れ、見直しのたびに抜け道が見つかった。止めすぎを減らすために文字と言い切れる部分を伏せる形（t545）にしても、伏せた所が次の抜け道になった。

## 決定

### 守り方は 3 つで組む

- 正しい道の dg のコマンド・フックの粗い拒否・事後の検査の 3 つで守る。フックは書き間違いを防ぐ手がかりで、すり抜け（シェルの外・フックのない環境・わざと隠した形）は事後の検査が見つける
- 権限管理や偽装の防止はしない（同じリポジトリに書ける人を信頼する。[ADR-028](ADR-028-agents-and-state.md)）

### PR を進める正しい道は dg のコマンド

- エージェントが PR を ready にするのは `dg pr ready <ticket>`、マージするのは `dg pr merge <ticket>` で行う。どちらも `dg gate` と同じ判定を満たすときだけ gh を引数配列で呼び、満たさなければ gh を呼ばずに `GATE_FAILED` で満たさない条件と理由を返す。PR の番号はチケットから引く
- 判定する条件はチケットの `gate`（品質ゲートの段、TK-9）で決める。`high`（既定）はすべての条件、`low` は見直しを除く条件、`free` は PR が開いていることと衝突しないことだけを判定する。判定しない条件の材料は読まない
- マージは人が承認したときだけ agent が `dg pr merge` に承認者を渡して行い、承認者を PR に残す。承認を断られたらマージせずに待つ。聞かずにマージするのは、`dg guide all --auto` で `auto.merge` が true のときの品質ゲートを通った PR だけで、承認者は渡さない。リリースの PR は常に人が承認する
- 段の条件を満たさない PR を ready にするときは、人が gh を打つ

### 緩めると守りが崩れる操作は Core に固定する

次の操作の権限は Core が持ち、config でも `workflow.yaml`（[ADR-003](ADR-003-status-and-workflow.md)）でも緩められない。判定の順で `workflow.yaml` の値より先に見る。

- フックを外す（`dg hooks uninstall`）：人だけ。エージェントの呼び出しは拒否する
- チケットの段を下げる（`dg ticket update --gate`）：人だけ。エージェントの呼び出しは拒否する。上げるのは誰でもできる
- `workflow.yaml` の書き換え（`dg workflow set`）：エージェントにはいつも人の承認（`--approved-by`）を求め、承認者を履歴に残す。聞かずに進める流れ（`--auto`）でも求める
- 段の条件を満たさない PR のマージ（`dg pr merge`）：呼ぶ主体によらず、いつも人の承認（`--approved-by`）を求める。エージェントは満たさない条件を示して人に聞く。承認者を渡さなければ何も越えず、越えた条件は承認者と一緒に PR に残す
- 承認があっても越えないのは、PR が開いていること・base と衝突しないこと・判定した先端への固定。ほかの条件（検査・見直し・手直しの回数・受け入れ条件）は承認で越える

### フックは字句を読まず、語の有無だけで粗く止める

- ツールを使う前のフックは、Bash のコマンドを字句に分けて読まない。生のコマンドに dg を経由しない PR を進める gh の語、または `.git/deguboard` の語があれば、引用符・ヒアドキュメント・コメントの中でも止め、正しい道の dg のコマンドへ案内する
- 止めすぎは拒む文の逃げ道（本文の語はファイルに書いて渡す・分けて打つ・データは dg のコマンドで読む）で受け止める
- わざと隠した形は個々に見ない。語として現れない呼び出しと書き込みは通り、事後の検査に任せる
- フックはエージェントを起動しないが、ツールを使う前の呼び出しを読んで拒む

### データの dg の外の変更は事後に見つけて書き込みを止める

- dg のコミットは印を持ち、dg は書き込みのロックを放す前の状態をマシンごとに基準として記録する。印のないコミット・基準と違う作業ツリー・基準の HEAD を捨てた履歴を、dg の外の変更とする
- dg がコマンドを実行するたびと、エージェントが応答を終えたときに確かめる。書くコマンドは `OUTSIDE_CHANGES` で止め、読むだけのコマンドは警告にする。書く前の決め手は書き込みのロックの中の検査で、外の変更を dg のコミットに入れて隠さない
- 戻すか取り込むかは人が決める。取り込みは `dg adopt` が検査を通してから行う

### 細部の正本

止める語と除く形・gh や git の引数・検査の条件と確かめない場面・基準の形・拒む文と戻し方は、次のコードとテストが正本で、「なぜ」はそのコメントとテスト名にある。

- `packages/core/src/commands/pr.ts`（`dg pr ready`・`dg pr merge`）・`packages/core/src/commands/gate.ts`（`judgeGate`）
- `packages/core/src/workflow/resolve.ts`（`CORE_FIXED`）・`packages/core/src/commands/permission.ts`（`requireOperation`）・`packages/core/src/commands/governance.test.ts`
- `packages/core/src/commands/pre-tool-use.ts`（`advancesPrOutsideDg`・`touchesDataDir`・`toolDenyReason`）・`packages/core/src/commands/hook.ts`（`turnStopped`）
- `packages/core/src/git/outside.ts`（基準と比べ方・戻し方）・`packages/core/src/git/write.ts`（`withWriteLock`）・`packages/core/src/commands/define.ts`（`runCommand` の検査）
- `packages/core/src/commands/pr.test.ts`・`gate.test.ts`・`hook.test.ts` の「PreToolUse」・`packages/core/src/git/outside.test.ts`

## 理由

- 正しい道を dg のコマンドにすると、ゲートの判定と gh の呼び出しが 1 つのコードの中でつながり、PR の指定を読む必要がなくなる
- 判定を語の有無だけにすると、読み違えて通す余地がなく、止めすぎの側にしか倒れない。止めすぎても正しい道と逃げ道が 1 つに決まっているので、作業は止まらず拒む文で案内しきれる
- 書かせないことは、シェルの外まで含めて閉じない。書いたら必ず見つかる形なら、すり抜けても次の dg のコマンドで止まり、データが黙って壊れたまま共有されない
- コミットの印とロックの中で記録した作業ツリーの基準を組むと、dg 自身のまとめ待ちの変更と並べて動く dg の書きかけを、外の変更と取り違えない
- 書くコマンドだけを止めるのは、読むコマンドまで止めると戻し方を調べる手段がなくなるため
- 段をチケットに持たせるのは、見直しの要らない変更（版上げ・文書の小さな直し）のたびに人が gh を打つと、流れが人で止まるため。段は記録に残るので、どのチケットをどの条件で通したかを後から確かめられる
- フックを外す・段を下げる・`workflow.yaml` の書き換え・品質ゲートを越えるマージを Core に固定するのは、どれもほかの守りの前提だから。フックは dg を経由しない書き込みを止め、段は品質ゲートが判定する条件を決め、`workflow.yaml` はエージェントに任せる範囲を決める。これらを設定で緩められると、エージェントが自分に許す範囲を自分で広げられ、ほかの値をどう書いても守りにならない
- フックを外すのと段を下げるのを承認でなく人に限るのは、どちらも人が 1 つのコマンドを打てば済み、エージェントに任せる利点が小さいため。`workflow.yaml` の書き換えを承認で任せるのは、項目が多く、人が前と後を見て承認した内容をエージェントが書くほうが誤りが少ないため
- 人が承認して agent がマージする形にするのは、決めるのは人のままで、品質ゲートの通過にかかわらず人が打つ手間だけを省くため。承認と越えた条件が PR に残り、先端への固定も同じコードを通る。人が gh を打つと、どちらも残らない
- 承認で越える条件を設定に置かないのは、越えるかどうかは PR ごとに人が満たさない条件を見て決めることで、条件の一覧を先に絞っても人の判断の代わりにならないため
- 衝突と先端を承認でも越えないのは、越えると gh がマージできないか、誰も判定していないコミットをマージすることになり、承認した人が見たものと違うものが入るため

## 採らなかった案

- **字句の解析を直し続ける**（t532 の分解・t545 の伏せる条件）：シェルの文法は広く、伏せた所と読み違いが抜け道になり、見直しのたびに分岐が増えて閉じない
- **区切り（`;`・`&`・`|`・改行）ごとに語の並びを見る**：任意の言語のコード（1 要素ずつ改行した配列・`'gh pr ' + 'merge'`）で語が隣り合わず、また字句の読みに戻る
- **本文の語を止めない（引用符の中だけ伏せる）**：どの引用符が文字か（`sh -c`・`python -c`・`--upload-pack`）を決めるのが t545 の分岐そのもの
- **gh を包むラッパーを PATH に置く**：PATH はエージェントや環境が変えられ、絶対パスで外れる。harness の外の人の gh まで変える
- **フックが拒まず、dg のコマンドだけを案内する**：手順を読み飛ばした呼び出しを止められない
- **フックが gh の呼び出しをすべて拒む**：`gh pr create`・`gh pr view` など PR を進めない呼び出しまで止める
- **dg が書いたファイルの一覧を残し、作業ツリーと照らす**：dg がデータに書く場所は多く、どこかで記録を漏らすと dg 自身の変更を外の変更と取り違える
- **リモートにまだない、印のないコミットだけを見る（基準の HEAD を持たない）**：リモートのないリポジトリでは、この版より前の印のないコミットをすべて外のものとみなしてしまう
- **dg の外の変更を dg が自動で戻す**：人やエージェントが意図して直した変更まで消す
- **段を Plan の details に持つ**：同じ Plan の中でもチケットごとに要る条件が違い、Plan のないチケットに段を付けられない
- **段を変更のパスで決める**：パスで決まるのは回す検査（軽い検査）までで、見直しが要るかはパスから読めない
- **承認したマージは人が画面か gh で行う**：品質ゲートを通った PR やリリースの PR も人が操作するまで流れが止まり、誰の承認でどの条件を越えたかも残らない
- **段を下げるのを規約に置き、コードで人に限らない**：人が段を指示した `--auto` の流れは止まらないが、指示のない段の変更をエージェントが自分で行え、品質ゲートの条件を自分で減らせる
- **承認で越えてよい条件を config の一覧（`merge.approval_overrides`）で絞る**：一覧にない条件は人が承認しても越えられず、人が gh を打つ道に戻る。越えた条件と承認者が PR に残らない
- **Core に固定の操作も `workflow.yaml` の値で緩められるようにする**：`workflow.yaml` を書き換えられるエージェントが、自分でフックを外せる・段を下げられる値にできる
