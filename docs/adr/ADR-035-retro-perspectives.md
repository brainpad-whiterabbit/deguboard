# ADR-035 振り返りの観点と承認した指標の定義はチームの config.yaml に置き、数字は毎回計算して保存しない

- ステータス：承認

## 要約

振り返りの観点（名前と問い）と、人が承認した指標の定義を、チームで共有する `config.yaml` の `retro.perspectives` に置く。指標の定義は dg が実行する式ではなく、数え方の文と出どころのコマンドで、エージェントが読んで計算する。dg は指標を決め打ちせず、既定の観点は定義を持たない。計算した数字は保存せず、振り返りのたびに過去の回も同じ定義で計算し直す。

## 背景

振り返り（`dg guide retro`）の観点と、観点ごとに読む数字は guide に決め打ちしていた。測りたいものと手元のデータで測れるものは利用者ごとに違い、guide の決め打ちは合わないことがある。一方で、指標を振り返りのたびにエージェントが考え直すと、数え方が回ごとに変わり、回どうしを比べられない。s29 の振り返りで s24〜s29 を Agentic-Agile の評価の枠組みの観点で比べたとき、数え方を決めて残す場所がないことが分かった。

## 決定

### 観点と定義はチームの config.yaml に置く

- `config.yaml` の `retro.perspectives` に、観点の ID ごとに名前・問い・承認した指標の定義（指標の ID ごとに、数え方の文・出どころのコマンド・測れない部分）を持つ。形はスキーマ（`packages/core/src/model/config.ts`）が正本で、検査する
- チームで共有する値で、個人の設定では上書きできない（人ごとに数え方が違うと比べられない）
- 観点の一覧は丸ごと 1 つの値として読む。チームが 1 つでも書けば、書いた一覧が全体になり、既定とは混ぜない（既定の観点を消せるようにするため）

### dg は指標を決め打ちしない

- 既定の観点は、Agentic-Agile の評価の枠組み（microsoft/agentic-agile-template の `docs/evaluation-framework.md`）にもとづく 7 つ（成果・見直しの効き目・仕様の質・分け方・エージェントの安定・コスト・改善の追跡）で、どれも指標の定義は空にする
- 定義のない観点には、振り返りのときにエージェントが手元のデータで満たせる指標を、数え方・出どころ・測れない部分つきで提案し、人が承認した定義だけを記録する。指標の候補は guide に置く（決まりではなく、提案の出発点）

### 定義は式ではなく、文と出どころのコマンドで書く

- 指標の定義は、何を何で割るかを書いた文と、数字の出どころの dg（と gh）のコマンドにする。dg は定義を実行せず、エージェントが読んで計算する
- 指標の元のデータを dg から読めるようにするのは、指標ごとの計算を dg に入れるのではなく、読みのコマンドを足して行う

### 定義は専用のコマンドで書く

- 観点と定義は `dg retro perspective`・`dg retro metric`・`dg retro remove` が、スキーマで検査してチームの `config.yaml` に書く。`config set` と設定画面は葉の項目だけを扱い、入れ子の観点は書かない（既定に戻すのは `config unset retro.perspectives`）

### 数字は保存しない

- 計算した指標の値は、ファイルにもチケットにも `config.yaml` にも保存しない。振り返りは、対象の回と直近の回を同じ定義で毎回計算して傾向を出す。計算できない値は「未計測」と理由を書く

## 理由

- 定義を残せば、回が変わっても同じ数え方で比べられる。チームの `config.yaml` に置けば、全員とどのエージェントも同じ定義を読む
- 数字を保存しなければ、定義を変えたときも過去の回を新しい定義で計算し直せ、古い数え方の数字が残らない。エージェントが書いた数字を正として残さずに済む（集計値を保存しない判断は [ADR-029](ADR-029-work-metrics.md) と同じ）
- 式の言語を dg に持つと、式が読めるデータの形を約束として固定することになり、データの形を変えるたびに移行が要る。文と出どころなら、dg のコマンドの出力が増えても定義はそのまま使え、測れない部分も言葉で書ける
- 既定に定義を入れると、測れないデータを前提にした指標や、チームが要らない指標が最初から「承認済み」に見える。空にしておけば、指標は人が承認したものだけになる
- 指標の定義は数え方と出どころが揃って 1 つで、`config set` の 1 項目 1 値では、片方だけ書いた途中の形ができる。専用のコマンドなら 1 回の書き込みで揃った形を検査できる

## 採らなかった案

- **指標を dg に決め打ちし、`dg metrics` が観点ごとの数字を返す**：測りたいものと測れるものは利用者ごとに違う。指標を足すたびに dg の版を上げることになる
- **定義を dg が実行する式（集計の DSL）にする**：式が読めるデータの形が約束になり、gh や履歴から読む指標を書けない
- **計算した指標の値を回ごとに保存する**：定義を変えると過去の値と比べられなくなり、エージェントが計算した値が正として残る
- **観点と定義を `guide.notes.retro` の文書に書く**：形を検査できず、承認した定義を dg のコマンドで足せない
- **定義を個人の設定でも上書きできるようにする**：人ごとに数え方が違うと、同じ回の数字が揃わない
