# ADR-011 既定の手続きは dg のコードが持つ

- ステータス：承認
- 更新日：2026-11-07

## 背景

[ADR-003](ADR-003-status-and-workflow.md) は、手続きを YAML に書かず `dg guide <topic>` のテキストにして AI が読んで判断すると決めた。[ADR-004](ADR-004-agents-and-state.md) は、並列実行・修正ループ・自動マージも guide 側が進めると決めた。チケットを段階（claimed → implemented → reviewed(n) → fixed(n) → ready → merged）に進める既定の手続きは、この決めに沿って guide に書かれ、親の LLM が読んで進めていた。

2026-11 の速度低下の調査で、この形の問題が次のとおり出た。

- 親の LLM が約 55KB の手順を読んで手続きを進めることが、親の出力トークンの 38% と、経過時間の空き 48% の原因だった
- guide は 6 日で 4 倍に肥大した。増えたのは手続きの細部で、各手のやり方ではなかった
- 手続きは LLM が読んで守るので、次の 1 手・修正ループの回数・品質ゲートの守られ方が毎回ずれ得た（確率的）

## 決定

### 既定の手続きは dg のコードが持つ

チケットの作業の既定の手続きは Core のコマンド（`packages/core/src/commands/`）が持つ。[ADR-003](ADR-003-status-and-workflow.md) の「Workflow YAML は制約と語彙を書く」の「書かないもの」の手続きの項（手順は guide のテキストとして読んで判断する）を、この決定で置き換える。

- 段階：チケットが今どの段階にあるか。状態・Run・ブランチの事実から求める
- 次の 1 手：段階から次に行うことを 1 つ返す
- 修正ループの回数と品質ゲート
- サブエージェントに渡す brief

CLI・HTTP・Webview は同じ結果を写す（CL-6）。段階・次の 1 手・品質ゲート・brief の細部は各コマンドの `--help` が正本。

### guide は各手のやり方だけを書く

`dg guide <topic>` は、各手をどう行うか（どう実装し、どう見直し、どう承認を求めるか）だけを書く。段階の順・修正ループの回数・品質ゲートの条件は書かず、Core から受け取る。

### 人の判断の穴は残す

- マージは、`auto.merge` が true で品質ゲートを通った PR のほかは人を待つ。リリースの PR は、`auto.merge` があっても常に人が承認する
- Plan の承認・やめる（abandoned・done の取り消し）は人が決める。Core は人を待つ手を返し、自動化しない
- `--auto` が自動で選ぶのは、戻せる判断だけに限る

### 並列実行・修正ループ・自動マージの進め方も Core が持つ

ADR-004 の「並列実行・修正ループ・自動マージも guide 側が進める」を置き換え、その進め方は既定の手続きとして Core が持つ。並列の上限と修正ループの回数は、ADR-004 のとおり config には置かず、Core の既定の手続きが持ち、guide には書かない。スケジューラは置かず、エージェントを起動も監視もしない（EX-1）。

### YAML に手続きを書く形は採らない

ワークフロー定義（`workflows/<id>.yaml`）に段階や順を書けるようにはしない。ADR-003 の「手続きを YAML に書かない」は変えない。既定の手続きを Core が持つのは、利用者が定義するものではなく、dg の版と一緒に変えるものだから。

## 理由

- 手続きを LLM が読んで進める限り、親の出力と待ちは手順の長さに比例して増えた（背景の調査の数字：出力 38%・空き 48%・guide 6 日で 4 倍）。Core が段階と次の 1 手を返せば、親は長い手順を読まずに 1 手ずつ行える
- 修正ループの回数と品質ゲートを Core に置けば、毎回同じに守れる。確率的に守られていた部分が決まった形になる
- guide を各手のやり方だけに縮めれば、手続きの細部を guide に書き足す流れが止まり、肥大が止まる
- 段階は Git とチケットの事実から求められ、段階を返すだけで動かすのは引き続きエージェントなので、ADR-004 の「ツールはエージェントを起動も監視もしない」を変えない
- 人の承認・マージ・やめるの穴を残すので、ADR-003 の「承認・排他・記録はプログラムで保証し、実装方針・レビュー判断は AI に任せる」の線は変わらない

## 採らなかった案

- **手続きを guide のテキストに置く（今まで）**：親が長い手順を毎回読んで進め、出力と待ちが増え、守られ方が確率的になった
- **利用者が YAML に手続きを書く**：ADR-003 の「手続きまで YAML に書く」と同じく対話が硬直し、手順の変更のたびに定義の形が変わる。段階と修正ループの回数は作業の方針で、利用者ごとの定義にしない
