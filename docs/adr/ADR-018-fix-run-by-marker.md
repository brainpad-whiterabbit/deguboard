# ADR-018 手直しの Run も起動のフックが印で開き、理由は run retry-reason で開いている Run に書き足す

- ステータス：承認
- 更新日：2026-11-08

## 背景

[ADR-012](ADR-012-hooks-open-runs.md) は、実装と見直しのサブエージェントの Run を、頼んだ文の最初の行の印で起動のフック（PostToolUse）が開くと決め、手直しの Run はもう一度の claim が開く形を残した。手直しのサブエージェントは、直し始める前に自分で `ticket claim <id> --retry-reason …` を呼んで手直しの Run を開き、開いたままの前の手直しの Run はその claim を区切りとして閉じる（RN-5・RN-6、[ADR-005](ADR-005-work-metrics.md)）。

この形には次の不便があった。

- claim の側からは、開いている手直しの Run が今回のものか、ひとつ前の残りかを見分けられない。サブエージェントの Bash には `DEGUBOARD_SESSION`・`DEGUBOARD_TRANSCRIPT` が届かず（[ADR-016](ADR-016-session-from-agent-env.md)）、記録の ID でも照らせない
- サブエージェントが自分で開いた Run は、終わりのフックが記録の中の ID から引き当てる移行期の経路（ADR-012）に頼り、印のある Run と扱いが分かれる
- 実装・見直し・手直しで、Run を開く者が違う（フックと claim）

## 決定

### 手直しの Run も印で開く

- 手直しを頼む文（`dg brief --role fix`）の最初の行に、印 `deguboard: ticket=<id> step=<手直しの step>` を置く。手直しの step は Workflow の `opens_on: reclaim` の step（なければ `fix`）
- 起動のフックは、印の step が手直しの step なら、開いたままの前の手直しの Run を区切りとして閉じてから新しい Run を開く。閉じ方はもう一度の claim と同じ規則で、前の Run の開始より後で区切りまでの最後の push の時刻で `success`（push がなければ区切りの時刻）、前の Run が別のセッションのものなら `interrupted`（[ADR-015](ADR-015-interrupt-stale-session-runs.md)）。区切りは起動の時刻で、前景の起動では終わった時刻からかかった時間を引いた時刻（[ADR-017](ADR-017-review-result-binding-edge-cases.md) の補いを含む）。開いている手直しの Run は、いつも 1 本になる
- 手直しのサブエージェントは claim しない。人や親が自分で直すときのもう一度の claim（`ticket claim <id> --retry-reason …`）は今のまま残す

### 理由は run retry-reason で書き足す

- `dg run retry-reason <id> --reason <要約> …` は、このマシンで実行中のそのチケットの手直しの Run の `retry_reasons` に理由を書き足し、回数を理由の数にする。引き方はチケットと step で、`run review-result` と同じ形
- そのチケットの最後の見直しの Run より前に始まった手直しの Run は、その見直しの前の回のもの（照合がまだ閉じていない）なので、書き足さない。`dg next` が待つ手直しを見分けるのと同じ見方
- 書き足す先がなければ（前景の起動では動いている間に Run がない）、理由をこのマシンの `deguboard-local/retry-reasons/<ticket>.json` に、置いた時刻とともに保留にする（Git に入れない）。呼ぶたびに書き足す。フックが手直しの Run を閉じるとき（SubagentStop・前景の PostToolUse・SessionEnd）、その Run の開始より後に置いた理由を結び付けて消す。開始より前に置いたものは前の回のものなので使わずに消す。見直しの結果の保留（[ADR-014](ADR-014-subagent-stop-and-resume.md)）と同じ扱いを、手直しの理由に広げる

### 置き換えるもの

- [ADR-012](ADR-012-hooks-open-runs.md) の「サブエージェントの Run はフックが開け閉めする」の節の最後の段落のうち「、もう一度の claim が開く手直しの Run」の部分を、この決定で置き換える
- [ADR-005](ADR-005-work-metrics.md) の「実装・見直し・手直しを別の Run にする」の、手直しの開き方の項のうち「修正ループも、見直しの前に `ticket update --pr` で PR を記録するので同じ claim で開き、」の部分と、理由の項のうち「（どちらも claim の `--retry-reason`）」の部分を、この決定で置き換える
- ADR-014 の決定は変えない。印のない Run（サブエージェントが自分で `run start` で開いた Run）を終わりのフックが引き当てる移行期の経路（ADR-012）は、ほかの手順がサブエージェントに Run を開かせなくなるまで残す

## 理由

- 区切る判断を「理由を書く時点（claim）」から「起動の時点（フック）」へ移すと、前の手直しの Run を閉じるのは、手直しを新しく始めるという事実のある起動のときになる。起動のフックは今のセッションの ID を持つので、落ちたセッションの手直しも見分けられる
- 理由の書き足しを Run を開く操作から外すと、サブエージェントは Run の ID を知らずに済み、背景・前景のどちらで起動しても手直し 1 回につき Run が 1 本になる
- 最後の見直しより前に始まった手直しを書き足しの先から外すのは、前景の起動でフックがまだ前の回を閉じていない間に、今回の理由が前の回に入るのを防ぐため。修正ループは手直しと見直しを交互に行うので、見直しの開始が回の区切りになる

## 採らなかった案

- 手直しのサブエージェントのもう一度の claim を残し、フックの側で照らす：claim の時点では、開いている Run が今回のものか前の回の残りかを見分ける事実がない
- `run retry-reason` に Run の ID を渡させる：前景の起動では、サブエージェントが動いている間に Run がない
- 保留を作らず、前景の手直しの理由を親が後から書く：親は直した指摘の要約を持たないことがあり、書き忘れても気づけない

## 制限

- 人のレビューの後の手直しを、見直しを挟まずに前景で続けて頼み、その間に照合も走らないと、2 回目の理由が前の回の Run に入る（前の回は 2 回目の起動のフックが閉じる）
- 同じチケットの手直しを前景で並べて動かすことは扱わない（保留はチケットごと）
