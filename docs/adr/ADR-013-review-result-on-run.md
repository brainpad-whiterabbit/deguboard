# ADR-013 見直しの結果を Run に記録し、見直しの Run の成否をそれで決める

- ステータス：承認
- 更新日：2026-11-07

## 背景

[ADR-012](ADR-012-hooks-open-runs.md) は、フックが閉じる見直しの Run を「最後の応答があれば `success`」とした。これは結果を記録する仕組みがなかったための暫定の規則で、見直しが指摘を出したか・通ったかは Run に残らなかった。修正ループの回数と品質ゲート（重い指摘が残っていない）は、親の LLM が見直し役の返した文を読んで数えていた。段階の判定（t533）とゲートの判定（t532）をコードに置くには、見直しの結果が記録に要る。

見直しの Run はフックが開け閉めし（ADR-012）、見直し役は `run start`・`run finish` を呼ばないので、結果は Run を閉じる操作には載せられない。

## 決定

- Run に見直しの結果 `review`（重い指摘の数 `heavy`・軽い指摘の数 `light`・通ったか `passed`）を持つ。見直し以外の Run と、結果を書かずに終わった見直しの Run は `null`
- 見直し役は、指摘の一覧を返す前に `dg run review-result <ticket> --heavy N --light M [--passed]` を 1 回呼ぶ。チケットから、このマシンで実行中の見直し（`review` の step）の Run を引いて結果だけを書く（呼び直せば置き換える）。重い指摘があるのに `--passed` は使い方の誤り
- ※ ADR-014 で置き換え（この項の「どちらでもなければ `NOT_FOUND`」の部分は失効）。実行中の見直しの Run がなければ、チケットの最新の Run（実行中を含む）が閉じた見直しの Run のときだけ、それに 1 回だけ書く（フックが先に閉じたとき）。後に手直しなどの Run が始まっていれば、それは前の回の見直しなので書かない。どちらでもなければ `NOT_FOUND`。閉じた Run に書くのは結果がまだないときだけで、結果の記録がないことで `failure` になっていた Run は `success` に直す
- フックが見直しの Run を閉じるときは、結果が記録されていれば `success`、なければ `failure` にする。[ADR-012](ADR-012-hooks-open-runs.md) の「結果は step ごとの事実で決める」の項のうち、見直しの規則をこの決定で置き換える
- `metrics show` は結果のある Run の数・通った数・指摘の数の合計を集計に出す

## 理由

- 最後の応答の有無は、見直しが中身のある結果を出したかを表さない。結果を数で残せば、修正ループの回数とゲートを LLM の読み取りでなく記録から数えられる（[ADR-011](ADR-011-procedure-in-code.md) と同じ考え）
- Run を開け閉めするのはフックなので、結果は Run の開閉と別のコマンドで書く。チケットから引けば、見直し役は Run の ID を知らなくてよい
- 閉じた Run に 1 回だけ書けるようにするのは、フックが見直し役の終わりより先に閉じる順の違いで結果を失わないため。書けるのを 1 回にして、閉じた記録を何度も書き換えない（RN-4）。チケットの最新の Run に限るのは、前の回の見直しの Run に今の回の結果を書いて、回ごとの記録を入れ替えないため

## 採らなかった案

- `run finish` に結果の項目を足す：見直しの Run はフックが閉じるので、見直し役は `run finish` を呼ばない
- 見直し役の最後の応答の文から指摘の数を読み取る：文の形に依存し、自己申告の文を解釈することになる
