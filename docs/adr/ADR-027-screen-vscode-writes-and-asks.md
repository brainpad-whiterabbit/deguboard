# ADR-027 人の画面は VS Code 拡張にし、画面から書くのはチケット詳細と設定だけで、ほかはエージェントに頼む

- ステータス：承認

## 要約

人の画面は VS Code 拡張だけにし、`dg serve` は開発用に残す。画面から直接書くのはチケット詳細・設定・同期だけにする。ほかの変更は、エージェントへの依頼文をコピーするか開いているターミナルへ送って渡し、画面はエージェントを起動しない。

## 背景

カンバンと詳細を人が見て直す画面について、入口・画面から書く範囲・エージェントへの依頼の形を決める。

## 決定

### 人の画面は VS Code 拡張だけにし、ブラウザは開発用にする

- 人が使う画面は VS Code 拡張（サイドバーを主画面に、詳細はエディタのパネル）だけにする。エージェントは CLI と MCP から使う
- `dg serve` は開発用に残し、利用者の入口にしない
- 画面は 1 つの React アプリにし、`CommandClient` の裏で拡張ホストが Core を直接呼ぶ。拡張はサーバーを起動しない
- `dg` は拡張に同梱し、版の付かない起動ファイルを外（ターミナル・フック・エージェント）から呼べる場所に出す。画面は `dg` がなくても動く

### 画面から直接書くのはチケット詳細・設定・同期だけにする

- チケット詳細では 1 件の小さな直しをし、設定はチームのファイルと個人の上書きに書く。同期は Git の事実に合わせるだけなので残す。エージェントに許す操作のうち、PR のマージ・自動の判断（`auto.*`）・記録（`metrics.read_transcripts`）は個人の上書きで外せないチーム専用にする（PR の流れと記録の形を人ごとに変えないため）
- 始め方の「このリポジトリで始める」だけは例外とし、押したときに開いたターミナルへ `dg init` などを入れて、人が Enter で実行する。エージェントは起動しない（EX-1）
- ほかの書き込み（移動・Iteration・Epic・Plan の操作）は画面に置かず、エージェントに頼む
- 画面からの書き込みも CLI と同じ Core のコマンドと検査を通り、主体は常に human（[ADR-028](ADR-028-agents-and-state.md)）

### 設定は Git のファイルで持ち、VS Code の settings.json を使わない

- チームの `config.yaml` を基本にし、人ごとに違ってよい項目だけを Git に入らないファイルで上書きする。読むのは Core だけにする

### 画面の操作のコミットはまとめる

- 既定はまとめてコミットし、push の時期を設定で選ぶ
- claim・作成・Iteration の開始と再開は、排他と採番のため即座にコミットして push する（[ADR-034](ADR-034-storage-and-id.md)・[ADR-028](ADR-028-agents-and-state.md)）

### 頼むことは依頼文にし、コピーか開いているターミナルへの送り込みで渡す

- 画面は対象と頼むことから依頼文を作り、コピーするか既存のターミナルの入力へ Enter を押さずに送る。データには書かず、ターミナルもエージェントも起動しない
- 依頼文は Core の読み取りだけのコマンド（`ask`）が作り、対象は ID だけにする
- 人に限った操作は依頼ではなく、人が打つ `dg` のコマンドを出す
- 頼む入口は行・見出し・詳細のタイトルの吹き出しに置き、右クリックのメニューには置かない

### 細部の正本

画面の並び・文言・書き込みの範囲・依頼文の組み立て・設定の範囲と書き分けは、次のコードとテストが正本で、「なぜ」はそのコメントとテスト名にある。

- `packages/vscode/src/`：拡張の入口、起動ファイル、片付け、ターミナルへの送り込み
- `packages/web/src/`：画面と `CommandClient` の実装（テストを含む）
- `packages/core/src/`：画面が呼ぶコマンドと依頼文の `ask`、設定の範囲（`model/config.ts`）
- `packages/cli/src/serve.ts`：開発用の配信
- `test/layout/`：画面の配置

## 理由

- e13 で対象をソフトウェア開発に絞り、ブラウザを残す理由がなくなった。人の画面を 1 つにすれば、ブラウザと VS Code の作りの差と保守が 1 つになる
- `dg serve` を開発用に残せば、配置の確認・録画・MCP での確認の経路を失わない
- 画面を 1 つのアプリにして transport だけを差し替えれば、機能の追加と修正が 1 回で済む。拡張ホストは Core を直接呼べるので、サーバーを立てる理由がない
- サイドバーはエディタで何を開いていても見え、幅が狭いので一覧に向く。詳細は本文と属性を並べるのでエディタ領域の幅が要る
- 拡張に CLI を同梱すれば、拡張と CLI の版が揃い、エージェントを使わない利用者も閲覧と詳細の編集ができる
- 拡張のフォルダは版付きで更新のたびに変わる。外からは版の付かない起動ファイルを呼べば、フック・マージドライバ・PATH のリンクを書き直さずに済む
- 画面から Iteration・Epic・Status を直接変えると、Skill の点検・承認・照合の外で状態が変わる。書き込みの入口をチケット詳細と設定と同期に絞れば、変わった場所を追える
- 設定を VS Code の settings.json に置くと CLI とエージェントに届かず、同じ項目の値が入口で食い違う。上書きがないと、人ごとに違う値（worktree の置き場所・使えるモデル・通知）をチームのファイルで取り合う
- コピーと送り込みだけなら、エージェント製品に依存せず起動を扱わない方針（EX-1）を保てる。人に限った操作は依頼しても拒否されるので、人が打つコマンドを出す
- 画面の操作は頻繁で小さく、1 操作 1 コミットでは履歴が埋まる。排他と採番に関わる操作だけ即座にする
- 始め方は初回の 1 回だけの手順なので、CLI の手順（Skill とフックの導入）と二重にせず、ターミナルで実行して失敗を人の目に見えるようにする
- 吹き出しは行の操作ボタンと同じ出し方で、右クリックのメニューは文言が拡張の定義に固定され、対象に合わせられない

## 採らなかった案

- **ブラウザの画面を利用者の入口に残し、両方を提供する**：作りの差と二重の保守が続く
- **ブラウザだけを入口にする**：通知・ターミナルへの送信・VS Code で開く操作が使えなくなる
- **`dg serve` を削除する**：配置の確認・録画・MCP での確認が止まる
- **サイドバーとパネルで別の画面を作る**：機能のずれと二重の保守が起きる
- **詳細もサイドバーの中で開く**：狭い幅に本文と属性を押し込み、一覧に戻る操作も増える
- **一覧の画面をパネルに出すコマンドを持つ**：一覧が 2 つ並んでも見るものが重なるだけ
- **VS Code 拡張もローカルサーバー経由にする**：ポートの衝突と起動順の問題が増える
- **拡張が環境変数で PATH に同梱の `dg` を足す**：統合ターミナルにしか効かず、Claude Code の拡張が起動する `claude` に届かない
- **外から拡張のフォルダの `dg.mjs` を直接指す**：フォルダは版付きで、更新のたびにフックやリンクが切れる
- **拡張が `core` を同梱せず、`dg` を子プロセスで呼ぶ**：`dg` がないと画面が動かない
- **`dg` を npm に公開して入れてもらう**：Node.js と npm を求め、拡張と CLI の版がずれる
- **拡張の起動のたびに PATH のリンクを自動で張る**：利用者の PATH に黙って置くことになる
- **個人の設定を VS Code の settings.json に置く**：CLI とエージェントに届かず、入口で値が食い違う
- **画面の操作ごとに即コミットする**：履歴が埋まり、push の衝突も増える
- **画面から書き込めるまま、依頼文も足す**：手順の外の変更が残り、書き込みの入口が増える
- **ドラッグで動かし、落とすと依頼文を作る**：動かしたカードが元に戻り、分かりにくい
- **コピーの後にエージェント製品を起動して送り込む**：特定の製品に依存し、起動に踏み込む（EX-1）
- **依頼文に題・本文・Status を含める**：長くなり、古い本文が写る
- **始め方のボタンで拡張が Core の init を直接呼ぶ**：CLI の手順と二重になり、出力が人の目に出ない
- **最後に起動した拡張が `current` を取る**：版の古い拡張のウィンドウを開くと CLI が古い版に戻る
- **チケット詳細も表示だけにする**：1 件の小さな直しまで手順を通すと手間が大きい
- **Skill の形にも説明の文と対象の一覧（ID・題・Status・Iteration）を添える**：貼る文が長く、人が読み返す前に Skill の手順と食い違う
- **始め方のボタンで PATH の `dg` を呼ぶ**：ボタンを押す時点で PATH にないことが多く、そのために起動ファイルがある
- **Run の画面を VS Code に作る**：Run は詳細と `dg metrics show` で足りる
