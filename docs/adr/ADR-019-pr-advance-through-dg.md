# ADR-019 PR を進める正しい道を dg のコマンドにし、フックは dg を経由しない gh を粗く拒む

- ステータス：承認
- 更新日：2026-11-08

## 背景

t532 で、品質ゲート（`dg gate`、EX-3）を守らせるために、ツールを使う前のフック（PreToolUse）が Bash のコマンドを字句に分けて `gh pr merge`・`gh pr ready` と PR の指定を読み、そのチケットのゲートで止める形にした。チケットを引けない PR は判定できないので止めなかった。

この形は、読み違えると通してしまう。PR 482 の見直しでは、`2>&1` の `2` を PR の指定と読む、`$PR` や `python -c` の中の呼び出しを読めない、といった指摘が 4 回の見直しでも尽きず、そのたびに字句の分解を足した。シェルの文法は広く、PR の指定を正しく読み切ることは、守る側が失敗するたびにすり抜けになる形だった。

[ADR-004](ADR-004-agents-and-state.md) は、フックを「harness が呼ぶ dg のコマンドで、エージェントを起動も監視もしない」とした。ツールを使う前のフックは、エージェントのツールの呼び出しを読んで拒む点で、この項の範囲を越えている。

## 決定

### PR を進める正しい道は dg のコマンド

- エージェントが PR を ready にするのは `dg pr ready <ticket>`、マージするのは `dg pr merge <ticket>` で行う。どちらも Core のコマンドで、`dg gate` と同じ判定（gate.ts の judgeGate）を満たすときだけ gh を引数配列で呼ぶ（`gh pr ready <番号>`・`gh pr merge <番号> --squash` など）
- 満たさなければ gh を呼ばず、`GATE_FAILED` で満たさない条件と理由を返す。PR の番号はチケットから引くので、PR の指定を読み違えることがない
- ゲートを満たさないまま進める例外（見直し役を起動できない・修正ループの上限を超える・版上げの PR・人が回数を指示した）は持たず、今までどおり人が gh を打つ

### フックは dg を経由しない呼び出しを粗く拒む

- ツールを使う前のフックは、Bash のコマンドに dg を経由しない `gh pr ready`・`gh pr merge`（`gh api` の同じ操作も）が含まれれば、チケットやゲートによらず拒み、dg のコマンドと人に頼む例外を理由に返す。PR の指定は読まない
- 読み切れないものは止める側に倒す。t532 の字句の分解は、止めすぎを減らすためにだけ使う。通すのは、字句で文字と言い切れるもの（どのコマンドも引数をコードとして走らせない、知っているコマンドのときの、置き換えのない引用符とヒアドキュメントの中）だけ。任意の言語のコード（`python -c` など）・`eval`・sh に渡す文字・知らないコマンドがあれば、何も伏せずに判定する
- `.git/deguboard/` への書き込みを拒む判定（t532）は変えない

### 事後の検査で補う

- フックの判定は書き間違いを防ぐ手がかりで、すり抜けを防ぎきらない（シェルの外で走らせる、フックを入れていない環境など）。守り方は「正しい道の dg のコマンド＋粗い拒否＋事後の検査」の 3 つで組む。事後の検査（dg の外の変更を、dg が次に store を開くときに見つける）は後続のチケット（t546）で行う

### 置き換えるもの

- [ADR-004](ADR-004-agents-and-state.md) の「ツールはエージェントを起動も監視もしない」の節の、主体の項のうち「フックは harness が呼ぶ dg のコマンドで、エージェントを起動も監視もしない」の部分を、この決定で置き換える。フックはエージェントを起動しないが、ツールを使う前の呼び出しを読んで拒む。権限管理や偽装の防止をしない（同じリポジトリに書ける人を信頼する）ことは変えない

## 理由

- 正しい道を dg のコマンドにすると、ゲートの判定と gh の呼び出しが 1 つのコードの中でつながり、PR の指定を読む必要がなくなる。読み違えの余地がフックから消える
- フックが拒むのを「dg を経由しない gh」という粗い形にすると、読み違えは止めすぎの側に倒れる。止めすぎても正しい道（dg のコマンド）があるので作業は止まらず、すり抜けより害が小さい
- 例外を人が gh を打つ形に残すのは、例外を Core に持たせると、エージェントがそれを選べてしまうため（ADR-011 の、例外は人の判断に任せる形と同じ）

## 採らなかった案

- **t532 の字句の分解を直し続ける**：シェルの文法が広く、見直しのたびに読み違えが見つかった。読み違えが通す側に倒れる限り、守り方として閉じない
- **gh を包むラッパーを PATH に置く**：PATH の前置はエージェントや環境が変えられ、`/usr/bin/gh` のような絶対パスで外れる。harness の外の人の gh まで変えてしまう
- **フックが拒まず、dg のコマンドだけを案内する**：手順を読み飛ばした呼び出しを止められず、t532 の前に戻る
- **フックが gh の呼び出しをすべて拒む**：`gh pr create`・`gh pr view` など PR を進めない呼び出しまで止め、作業が進まない

## 制限

- 文字として書いただけの `gh pr merge` でも、伏せられない場所（知らないコマンドの引数、置き換えを含む引用符の中など）にあれば止める。そのときは echo・`git commit -m`・`gh pr create --body` などの引用符かヒアドキュメントに入れて書き直す
- 一度ファイルに書いたスクリプトを後で走らせる、gh のエイリアスを作ってから呼ぶ、など 2 段の間接は見ない。事後の検査で補う
