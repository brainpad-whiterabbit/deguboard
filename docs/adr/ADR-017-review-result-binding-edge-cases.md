# ADR-017 前景の見直しの起動の時刻は記録の最初の行で補い、sync は別のセッションの見直しの Run を閉じない

- ステータス：承認
- 更新日：2026-11-08

## 背景

[ADR-015](ADR-015-interrupt-stale-session-runs.md) は、前景の見直しの起動のフックが、別のセッションで開いたままの古い見直しの Run を閉じる前に、起動より後に書かれた `run review-result` の結果を古い Run から外して保留に移し、新しい Run に結び付けると決めた。起動の時刻は、終わった時刻からかかった時間を引いて求める。書かれた時刻は実行中の記録の更新時刻で見て、落ちたセッションの Run はその後に結果を書くほかに更新されないとした。

t543 の見直しで、この前提が崩れる場合が 2 つ見つかった。

- フックの入力にかかった時間（Claude Code の `totalDurationMs`）がないと、起動の時刻が今（見直し役が終わった後）になる。見直し役が古い Run に書いた今回の結果は起動より前のものに見え、保留に移らず、古い Run と一緒に `interrupted` で閉じて失われる
- `dg sync` は、書き終わり待ちの印（`settling_since`。[ADR-014](ADR-014-subagent-stop-and-resume.md)）のある Run をセッションで絞らずに閉じる。落ちたセッションの見直しの Run が書き終わり待ちのまま残り、前景の見直しの間に sync が走ると、古い Run が今回の結果を付けたまま `success` で閉じる。新しい Run には結果が残らない

## 決定

### 起動の時刻と、古い Run を更新する操作

[ADR-015](ADR-015-interrupt-stale-session-runs.md) の決定の「前景の起動では」で始まる項を、この決定で置き換える。

- 前景の起動では、フックが見直し役の終わった後に来るので（ADR-014）、見直し役の `run review-result` は古い Run に書かれている（`run review-result` はセッションを比べない）。古い Run を閉じる前に、起動より後に書かれた結果を古い Run から外して保留に移し（ADR-014 の保留）、新しい Run を閉じるときに結び付ける。起動より前に書かれた結果は、落ちたセッションの見直し役のものとして古い Run に残す
- 起動の時刻は、終わった時刻からかかった時間を引いた時刻。かかった時間が入力にないときは、サブエージェントの記録の最初の行（頼んだ文）の時刻にする。どちらもなければ今の時刻（今までどおり）。開く新しい Run の開始も同じ時刻にする
- 書かれた時刻は実行中の記録の更新時刻で見る。そのため、別のセッションの見直しの Run は、結果を書く操作（`run review-result`）と、その Run のセッションのフックと、次の見直しの起動のフックのほかには更新しない。`dg sync` は書き終わり待ちの印のある Run を閉じるが、見直しの Run のうち sync のセッション（[ADR-016](ADR-016-session-from-agent-env.md) の順で決める）と別のセッションのものは閉じない。それらは次の見直しの起動が上のとおり振り分けて閉じる

### sync が閉じる書き終わり待ちの Run

[ADR-014](ADR-014-subagent-stop-and-resume.md) の決定の書き終わり待ちの項のうち「次のフック・`dg sync`・SessionEnd のどれかが、書き終わっていれば数えて閉じる」の部分を、この決定で置き換える。

- 書き終わり待ちの印のある Run は、次のフック（そのセッションのもの）・`dg sync`・SessionEnd のどれかが、書き終わっていれば数えて閉じる。`dg sync` は、見直しの Run のうち sync のセッションと別のセッションのものを閉じない（上の項）。どちらかのセッションが分からなければ（人が端末や画面から呼ぶ sync など）、今までどおり閉じる

## 理由

- サブエージェントの記録の最初の行は、見直し役が頼んだ文を受け取った時刻で、見直し役の書く結果はいつもそれより後になる。かかった時間がないときに今の時刻を使うより、起動に近い
- 前景の見直し役が sync を呼ぶと（サブエージェントの Bash でもセッションは親のものになる。ADR-016）、そのセッションと別のセッションの見直しの Run を飛ばすので、今回の結果が古い Run と一緒に閉じない。落ちたセッションの見直しの Run は次の見直しの起動まで開いたままになるが、閉じる仕組みは ADR-015 のとおり残る
- セッションの分からない sync で閉じ続けるのは、セッションの分からない Run は落ちた残りと決められないという ADR-015 の扱いに揃えるため。人が前景の見直しの最中に sync を呼ぶ場合は防げない

## 採らなかった案

- 見直しの結果に書いた時刻を持たせる：Run と保留の結果の形が変わる。今回の 2 つの場合は起動の時刻と sync の対象の絞りで防げる
- sync が見直しの Run を書き終わり待ちでもすべて閉じない：同じセッションの見直し役が書き終わり待ちで残ったときに、sync で閉じられなくなる
- 結果が書き終わり待ちの印より後に書かれたかで見分ける：印と更新時刻の差は秒の単位で、印を付けた書き込みも更新時刻を進めるので、見分けが不確か
