# ADR-012 harness のフックが主体を決め、サブエージェントの Run を開け閉めする

- ステータス：承認
- 更新日：2026-11-07

## 背景

[ADR-004](ADR-004-agents-and-state.md) は、主体を Adapter のフックが環境で決めると決めた。[ADR-005](ADR-005-work-metrics.md) は、Run に会話記録のセッション ID を持ち、記録のパスをマシンごとのローカルに置いて、そこから数えると決めた。どちらも、フックが実際に何を渡し、いつ発火するかは実装のときに確かめることにしていた。

それまでは、サブエージェント自身が `run start` で見直しと実装の Run を開き、手直しはもう一度の claim で開いていた。2026-11 の調査で、見直し役が見直しを終えてから `run start` を呼ぶため、見直しの Run の使用量が約 2 割しか入らないことが分かった（成功した見直し 368 件のうち 48 件が出力 300 トークン未満）。

2026-11-07 に Claude Code 2.1.318 で、フックの入力と発火の順を確かめた。

- SessionStart：`session_id`・`transcript_path` が渡る。`CLAUDE_ENV_FILE` に `export NAME=value` を書くと、そのセッションの以後の Bash に入り、サブエージェントの Bash にも届く（`export` がないとシェルの変数になるだけで届かない）
- SubagentStart：`agent_id`・`agent_type` と親の `transcript_path` だけで、頼んだ文もサブエージェントの記録のパスもない。並べて起動すると、その時点で親の記録に Agent の呼び出しがなく、サブエージェントの記録もまだない
- PostToolUse（Agent）：`tool_input.prompt`（頼んだ文の全文）と `tool_response.agentId`・`resolvedModel`・`status` が同じ入力に入り、並べた起動とも一対一に対応する。バックグラウンドの起動は起動の直後に `async_launched` で返り、前景の起動は終わってから `completed` で返る
- SubagentStop：`agent_id`（PostToolUse の `agentId` と同じ）・`agent_transcript_path`（`<session>/subagents/agent-<id>.jsonl`）・`last_assistant_message`。記録の最初の行は頼んだ文。前景の起動では PostToolUse より先に発火する
- Stop は応答のターンごとに、SessionEnd はセッションの終わりに 1 回だけ発火する

## 決定

### 主体とセッションはセッションの始まりに環境へ入れる

SessionStart のフックが、`DEGUBOARD_ACTOR=agent` とセッション ID・記録のパスを `export` 付きで以後の Bash の環境に入れる。`run start`・`ticket claim` は、明示されなければその値を Run のセッション ID と記録の場所に使う。環境はサブエージェントにも届くので、サブエージェントが自分で開いた Run は、後で下の終わりのフックが記録の場所を直す。

### サブエージェントの Run はフックが開け閉めする

- 親はサブエージェントに頼む文の最初の行に印 `deguboard: ticket=<id> step=<step>` を書く。印のないサブエージェント（調べものなど）は Run にしない
- 起動の呼び出しが返ったとき（PostToolUse、matcher は Agent）、印のチケット・step と、agent・モデル・セッション ID・`agentId` を埋めた Run を開き、記録の場所をサブエージェントの記録にする。同じチケットと step の二重起動は拒否されて警告になる。その記録にもう結び付いた Run があれば開かない（前景の起動で、先に来た終わりの出来事がサブエージェント自身の開いた Run を結び付けたとき）
- サブエージェントが終わったとき（SubagentStop）、記録の場所でその Run を引き、記録の最初の文の印でチケットと step を照らして直し、記録の全体から数えて閉じる。前景の起動は終わってから返るので、PostToolUse が開いてその場で閉じ、開始をかかった時間だけ前にする
- 結果は step ごとの事実で決める。実装は PR があれば、手直しは開始より後の push があれば、見直しは最後の応答があれば `success`、なければ `failure`
- 印のある Run がなく、サブエージェントが自分で `run start` していたら（移行の間）、その Run に記録の場所を結び付け、閉じていれば取り直す。結び付けるのは、記録の中の `run start`・`ticket claim` の結果に ID が出た Run のうち、同じセッションで記録の最初の行より後に始まり、ほかのサブエージェントの記録に結び付いていないものだけ（警告や一覧で ID を見ただけの Run を奪わない）

[ADR-005](ADR-005-work-metrics.md) の「実装・見直し・手直しを別の Run にする」のうち、サブエージェントが自分で `run start` する項と、見直し役が見直しの前に `run start` する項、「会話記録を Run に結び付ける」のサブエージェントの記録の場所を開始のフックから取る部分を、この決定で置き換える。親の `ticket claim` が開く実装の Run と、もう一度の claim が開く手直しの Run は今のまま残す。

### 閉じ損ねはセッションの終わりに閉じる

SessionEnd のフックが、このセッションの見直しと手直しの Run のうち開いたままのものを `interrupted` で閉じる。実装の Run は PR の記録で閉じる今の形を残す（セッションをまたいで続く）。

### 会話記録のパスは置き場所の下だけを受け付ける

`run start`・`ticket claim` の記録のパス（HTTP・MCP の入力を含む）と、フックの入力の記録のパスは、その agent の Adapter の会話記録の置き場所（Claude Code は `~/.claude/projects/`）の下だけを使う。シンボリックリンクは解いて比べる。`dg serve` 越しに任意のファイルを読ませないため。

### フックは Adapter に閉じる

フックのイベント・設定のファイル・入力の読み方は Adapter（`core/agents/adapters/`）が持ち、Core の `hook` コマンドは製品によらない出来事だけを見る（AG-5）。`dg hooks install` が設定に書き、もう一度実行しても重ねず、手で足したフックは残す。フックは harness が呼ぶ dg のコマンドで、エージェントを起動も監視もしない（EX-1）。

## 理由

- 起動の呼び出しの入力には頼んだ文と `agentId` が同時に入るので、チケット・step とサブエージェントの記録を取り違えずに結べる。サブエージェント自身に `run start` させると、開き忘れと開く時刻の遅れで使用量が欠けた
- 印は親が書く文の最初の行なので、守られ方は親の手順に依る。終わりのフックが記録の最初の文で照らすので、並べた起動で取り違えても直せる
- 結果を事実で決めるのは、サブエージェントの自己申告に頼らないため（[ADR-011](ADR-011-procedure-in-code.md) と同じ考え）

## 採らなかった案

- SubagentStart で開く：頼んだ文もサブエージェントの記録のパスもなく、並べて起動するとその時点で親の記録にも呼び出しがない
- Stop で閉じ損ねを閉じる：応答のターンごとに発火するので、人の返事を待つ間の Run まで閉じてしまう
- 親が起動の前に印を `deguboard-local` に置き、開始のフックが古い順に取る：並べた起動で順が入れ替わりうるうえ、親の手順が 1 つ増える
