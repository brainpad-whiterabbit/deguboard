## 概要

`dg brief <ticket> --role implement|review|fix` が、サブエージェントに渡す文を組む。先頭に機械が読む印の 1 行 `deguboard: ticket=<id> step=<step>` を置く（PostToolUse の Agent のフックが `tool_input.prompt` からこれを読んで Run を開き、SubagentStop が照合する。t530）。本文には、worktree とブランチ、Plan の範囲と方針、規約の場所、受け入れ条件、ファイルは Read で読み Edit で直して Bash の cat・heredoc・sed -i で読み書きしないこと、Run は開かず閉じないこと（フックが行う）、返すもの、を含める。review の brief には、一覧を返す前に見直しの結果を 1 回記録すること（t531 のコマンド）を含める。fix の brief には直す指摘の一覧を含める。`dg next` の結果に brief を含め、親は自分で文を書かない。速度低下の調査で、親が書く文に道具の指定がなく、実装者が Bash の 15% を編集に使い Edit が 32 回失敗していた。

## 受け入れ条件

- [x] `dg brief <ticket> --role <役>` が、役ごとの文を返す。文の形はテストのスナップショットが正本
- [ ] 文の先頭に印の 1 行 `deguboard: ticket=<id> step=<step>` があり、step は役に対応する Workflow の step（implement は `opens_on: claim` の step、fix は `opens_on: reclaim` の step、review は `review`）
- [x] 文に、場所（worktree・ブランチ）、Plan の範囲と方針（あれば）、規約の場所、受け入れ条件、道具の指定（Read・Edit）、Run を開かず閉じないこと、返すものが含まれる。review には結果を記録する呼び出し、fix には指摘の一覧が含まれる
- [x] `dg next` の implement・review・fix の手に brief が含まれる
- [x] 言語は `ask` と同じく表示言語で選べる（ADR-010）
- [x] `mise run check` が通る
