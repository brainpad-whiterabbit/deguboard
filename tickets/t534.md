## 概要

`dg brief <ticket> --role implement|review|fix` が、サブエージェントに渡す文を組む。worktree とブランチ、Plan の範囲と方針、規約の場所、受け入れ条件、ファイルは Read で読み Edit で直して Bash の cat・heredoc・sed -i で読み書きしないこと、Run は気にしないこと（フックが開閉する）、返すもの、を含める。`dg next` の結果に brief を含め、親は自分で文を書かない。速度低下の調査で、親が書く文に道具の指定がなく、実装者が Bash の 15% を編集に使い Edit が 32 回失敗していた。

## 受け入れ条件

- [ ] `dg brief <ticket> --role <役>` が、役ごとの文を返す。文の形はテストのスナップショットが正本
- [ ] 文に、場所（worktree・ブランチ）、Plan の範囲と方針（あれば）、規約の場所、受け入れ条件、道具の指定（Read・Edit）、Run を気にしないこと、返すものが含まれる
- [ ] `dg next` の implement・review・fix の手に brief が含まれる
- [ ] 言語は `ask` と同じく表示言語で選べる（ADR-010）
- [ ] `mise run check` が通る
