## 概要

KanbanForge の Sprint タブ（SB-2）の形に寄せる。カンバンのタブの上に planned と active の Iteration の表（番号・名前・状態・完了 n/m）を出し、行を押して選ぶ。既定は active、なければ最初の planned。表の末尾に「Iteration なし」の行と「+ Iteration を作る」を置く。planned と active の Iteration がない Project では表を出さず、今と同じ全チケットのカンバンにする。選んだ Iteration の見出し（番号・名前・期間・目標・開始する・閉じる）の下に Epic と担当者（claimed_by。表示は @ の前、全文はツールチップ、選択肢は出てくる値と「なし」）の絞り込みと件数の行を置き、値はハッシュ（?epic=&claimed_by=）に持つ。状態ごとの節は t27 の縦積みで、開閉を Webview の状態に覚え、完了は既定で畳む。「abandoned を出す」のチェックボックスをやめ、中止は最後の畳んだ「中止 n」の節にし 0 件なら出さない（広い画面では列の末尾に畳んで置き、押すと 5 列目として開く）。Iteration のタブはなくす（planned・active はここ、closed は履歴 t35）。Iteration と Epic の状態の表示名（予定・進行中・終了、open・closed）を付ける。バックログの絞り込みにも担当者の select を足す。「自分」の選択肢は status の応答に actor の ID を足せば出せるが core に触るので、このチケットでは扱わず別に起票する。

## 受け入れ条件

- [ ] planned か active の Iteration がある Project では、カンバンの上に Iteration の表が出て、行を押すとその Iteration のチケットだけが下の節に出る。表の開閉と選んだ行はビューを閉じて開いても保たれる
- [ ] Iteration がない Project では表が出ず、全チケットのカンバンになる
- [ ] 見出しの下の行で Epic と担当者で絞れ、件数が出る。値はハッシュに残り、Epic の画面の「この Epic でカンバンを見る」から飛べる
- [ ] 「abandoned を出す」のチェックボックスがなく、中止のチケットがあるときだけ畳んだ「中止 n」の節（広い画面では列）が最後に出る
- [ ] 完了の節は既定で畳まれ、節の開閉はビューを閉じて開いても保たれる
- [ ] サイドバーとブラウザのタブから Iteration が消え、「開始する」「閉じる」「+ Iteration を作る」はカンバンの見出しと表から行える。#/iterations/<id> の詳細の画面は残る
- [ ] バックログの絞り込みに担当者の select がある
- [ ] requirements.md の UI-2・UI-3・UI-5・UI-12 を直し、ADR-006 に表 → 見出し → 節の 3 層を採る理由を足す
