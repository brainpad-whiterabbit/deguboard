## Summary

コミットのないまま push した作業ブランチは、main が進むと先端が main の祖先になり、照合で branch_merged と判定される。in_progress のチケットが review を飛ばして done になり、戻すのに人の操作（done の取り消し）が要る。コードのコメントは、グラフだけでは fast-forward のマージと区別できない限界を認めている。印を書く案（データの形が増える）と、PR のない in_progress を done にしない案（gh のない運用を壊す）があるので、着手の前に dgdiscuss で方針を決める。

## Acceptance criteria

- [ ] コミットのない作業ブランチを push した後に main が進んでも、照合でチケットが done にならないことをテストで示す
- [ ] 作業のあるブランチの fast-forward のマージは、今までどおり done になることをテストで示す
- [ ] 決めた方針が利用者への約束を変えるなら、requirements.md の ST-4 を直す
