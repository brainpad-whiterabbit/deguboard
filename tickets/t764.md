## Summary

コミットのないまま push した作業ブランチは、main が進むと先端が main の祖先になり、照合で branch_merged と判定される。in_progress のチケットが review を飛ばして done になり、戻すのに人の操作（done の取り消し）が要る。claim がブランチを作るときに、ブランチの起点の SHA をチケットに記録する。照合は、作業ブランチの先端が起点と同じならマージ済みにしない。claim の後に人が別の起点からブランチを作り直した形は拾えないことを受け入れる。

## Acceptance criteria

- [x] claim は、作業ブランチを作るときにその起点の SHA をチケットに記録する
- [x] コミットのない作業ブランチを push した後に main が進んでも、照合でチケットが done にならないことをテストで示す
- [x] 作業のあるブランチの fast-forward のマージが今までどおり done になること、起点を記録していない前からのチケットが今の判定のままであることをテストで示す
- [x] requirements.md の ST-4 に、起点と同じ先端はマージ済みにしないことを 1 文で足し、チケットのデータの項に起点の SHA を足す
