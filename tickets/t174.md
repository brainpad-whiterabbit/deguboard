## 概要

今は品質ゲートの修正ループを実装の Run を開けたまま回すので（dg guide review の「Run と終わり方」）、見直しと手直しの量が実装と分かれない。また software-development の Workflow に `steps` がなく、step は自由な 1 語（`implement`・`investigate`）になっている。

次のように変える。

- 同梱の software-development のテンプレートに steps（`implement`・`review`・`fix`・`investigate`）を足す
- 実装の Run は、draft の PR を作った時点で閉じる
- 見直し役のサブエージェントは `review` の Run を記録する
- 修正ループの各回と、人のレビューの後の手直しは `fix` の Run で記録し、やり直しの理由は `--retry-reason` で残す

修正ループを実装の Run の中で回すという今の方針を変えるので、該当する ADR を書き換える。

## 受け入れ条件

- [ ] 同梱の software-development のテンプレートと、このリポジトリの Workflow に steps（implement・review・fix・investigate）がある
- [x] dg guide work と dg guide review の手順が、上の Run の分け方とリトライの理由の書き方になっている
- [x] 品質ゲートと Run の記録の方針を書いた ADR（ADR-005 など）を書き換えてある
- [x] `mise run check:docs` が通る（guide の文書が予算内）
