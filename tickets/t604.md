## 概要

同期の rebase で frontmatter をフィールド単位に 3-way マージするドライバが効くのは tickets と epics の Markdown だけで、Plan・Iteration・Project の素の YAML は git の行単位マージになる。そのため別のフィールドを変えただけでも競合する（2026-11-09 に plans/p67.yaml の closed_at で 3 日間同期が止まった事例）。ドライバの読み込みを frontmatter のない YAML にも広げ、当てるパスに 3 種を足す。

## 受け入れ条件

- [ ] plans/*.yaml・iterations/*.yaml・projects/*.yaml が .gitattributes とローカルの属性ファイルの両方でマージドライバの対象になり、既存の worktree の .gitattributes にも足りない行が足される
- [ ] frontmatter のない YAML を両側で別のフィールドに変えた 3-way が、フィールド単位で解けて書式とコメントを保つ（merge.test.ts）
- [ ] 一時ディレクトリの bare リモート付きリポジトリで、両側が同じ Plan の別のフィールドを変えた分岐を作り、dg sync が競合なしで揃う
- [ ] 両側で同じフィールドを違う値にしたときは、今までどおり競合として報告される
- [ ] requirements.md の SY-4 の対象（チケットと Epic の frontmatter）を広がりに合わせて直し、ADR-002 の該当節に失効の印を付ける
