## Summary

見直し（s34）の観点「構成」。同じ処理が 2 通りずつある。(1) skill-files.ts で、入れてある Skill の確かめを findMissingSkills は stat、staleSkillsIn は readFile で別々に書き、置き場所の重ね方も uniquePlaces と byDir の Map で別に持つ。(2) 拡張の Install が、findMissingSkills の中で組み立てた Skill を使わずに buildSkills をもう一度呼ぶ。(3) commands/run.ts の reviewOfFindings が同じ指摘に isHeavyFinding を 2 回呼び、`["heavy","light"]` の組を hook.ts と model/metrics.ts にも別々に書いている。


## Acceptance criteria

- [ ] 置き場所ごとの SKILL.md の読みが 1 つの関数にまとまり、findMissingSkills と staleSkillsIn の両方がそれを使う
- [ ] 拡張の起動時の Skill の組み立てが 1 回になっている
- [ ] 重い・軽いの組は FINDING_SEVERITIES を使い、reviewOfFindings は指摘ごとに重さを 1 回だけ判定する
- [ ] 既存のテストが変えずに通る
