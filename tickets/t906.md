## Summary

リポジトリごとにカンバンを持てるようになったので、カンバンの中の区切りの Project をなくす。束ね方は Epic・Iteration・ラベルにする。利用者は一人なので、版の混在に備えた段階は踏まず一度に削る。

- チケット・Epic・Iteration・Plan の `project`、`projects/`、`dg project`、各コマンドの `--project`、config の `default_project`、同じ Project の検査をなくす
- Project の既定の Workflow は config の `default_workflow` に移す（チケットの `workflow` での指定は残す）
- active な Iteration はカンバンに 1 つにする
- 今あるファイルの `project` は、やめた項目として書くときに消す（DT-2 の Iteration の `start`・`end` と同じ扱い）。`projects/` のファイルは、dg が同期か書き込みのときに、印を付けたコミットで一度だけ消す（外の変更とみなさない）

## Acceptance criteria

- [ ] `project` を持たないチケット・Epic・Iteration・Plan を作成・読み書きでき、`project` を持つ既存のファイルは読めて、書くときに `project` が消えることをテストで示す
- [ ] `dg project`・`--project`・`default_project` がなくなり、ヘルプ・画面（VS Code 拡張・Web）・MCP から Project の表示と絞り込みが消える
- [ ] 既定の Workflow を config の `default_workflow` で決め、active な Iteration がカンバンに 1 つに保たれることをテストで示す
- [ ] dg が `projects/` を印付きのコミットで消し、外の変更として止まらないことをテストで示す。このリポジトリのデータでも消えて `dg validate` が通る
- [ ] requirements の 3・5.3・5.10・TK・EP・IT・PL の項と ADR-034 の「複数 Project」の節を書き換え、「採らなかった案」に「カンバンの中の区切りとして Project を持つ（カンバンを分けて代える）」を 1 行残す。README・usage（英日）の Project の記述を直す
