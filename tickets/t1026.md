## Summary

`workflow.yaml` の flow（assign・check・plan・audit・release・retro）の値で、dg がコマンドで止められる段階の操作を判定する。`--auto` の意味を「ask_unless_auto の場面を聞かずに進める」の 1 つにする。

## Acceptance criteria

- [ ] Iteration・Epic への出し入れ、`plan approve`、`iteration close`・`reopen` が `flow` の値で判定されることがテストで示されている
- [ ] `ask_unless_auto` の操作のコマンドが `--auto` を受け、そのときだけ聞かずに進めて承認者を agent と記録する。`ask_unless_auto` でない場面の `--auto` は拒否されることがテストで示されている
- [ ] config の `auto.merge`・`auto.decisions` がなくなり、`flow.skip` が `workflow.yaml` の `flow` に移っている
- [ ] `dg flow next` の承認の要否（approval）が `flow` の値から決まる
- [ ] requirements の EX-7・5.10 と ADR-030 が直っている
- [ ] このリポジトリの config の `auto.merge`・`auto.decisions`・`flow.skip` の値が `workflow.yaml` に移り（既定と同じ値は書かない）、元の項目が消えている
