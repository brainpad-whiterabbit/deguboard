## Summary

`workflow.yaml` の flow（assign・check・plan・audit・release・retro）の値で、dg がコマンドで止められる段階の操作を判定する。`--auto` の意味を「ask_unless_auto の場面を聞かずに進める」の 1 つにする。

## Acceptance criteria

- [x] Iteration・Epic への出し入れ、`plan approve`、`iteration close`・`reopen` が `flow` の値で判定されることがテストで示されている
- [x] `ask_unless_auto` の操作のコマンドが `--auto` を受け、そのときだけ聞かずに進めて承認者を agent と記録する。`ask_unless_auto` でない場面の `--auto` は拒否されることがテストで示されている
- [ ] config の `auto.merge`・`auto.decisions` がなくなり、`flow.skip` が `workflow.yaml` の `flow` に移っている。このリポジトリの config のこれらの値も移し（既定と同じ値は書かない）、元の項目を消している
- [x] `dg flow next` の承認の要否（approval）が `flow` の値から決まる
- [x] requirements の EX-7・5.10 と ADR-030 が直り、ADR-030 に `--auto` を各コマンドが受ける理由（聞かずに進めるのを `ask_unless_auto` の場面に限るため）が書かれている
- [x] guide と Skill の雛形と `dg flow next` の文が `auto.merge`・`auto.decisions` を指さず、`--auto` を「`ask_unless_auto` の場面を聞かずに進める」意味で案内している
- [x] CLAUDE.md に残る「Iteration を閉じる・再開するのは人の指示があるときだけ行う」の文が消え、flow の値と guide で案内されている
