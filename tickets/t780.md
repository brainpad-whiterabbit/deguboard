## Summary

観点：テスト。受け入れ条件（t767 の 1・2）は「入口がキャッシュを有効にしてから本体を読み、使えないときは黙って飛ばす」。一方、bundle-cli.test.ts の 2 つのテストは `NODE_COMPILE_CACHE` を環境に置いて起動するので、Node が自分でキャッシュを有効にし、入口の `module.enableCompileCache?.()` を消しても通る。書けない場所のテストも、入口の try/catch ではなく Node の環境変数の扱いを見ている。さらに、キャッシュから読まれたことを Node の内部のデバッグ出力（`NODE_DEBUG_NATIVE=COMPILE_CACHE`）の文言で確かめていて、Node を上げると実装が正しいまま落ちうる。

## Acceptance criteria

- [x] 入口の呼び出しを消すと落ちるテストで、入口がキャッシュを有効にすることを確かめる
- [x] キャッシュの置き場所に書けないときに入口が黙って続けることを、入口の処理として確かめる
- [x] Node の内部の文言に頼る箇所が残るなら、その理由をコメントに書く
