## Summary

dg の既定の値（config の既定・Workflow の雛形・推薦の指標）は dg の文として英語で持ち、画面は既定のままの値だけを表示言語に訳し、書き換えた値は書いたまま出す、という決まりにする（会話で検討した案 A）。今は優先度の判断基準だけが `shownConfigValue` で訳し、振り返りの観点と Workflow のラベルは訳さないので、既定の値ごとに扱いがばらばら。`config.show` が既定を返し、画面は 1 つの判定で既定のままかを決める。

## Acceptance criteria

- [x] `config.show` が、葉の項目と `retro.perspectives` の既定を返す
- [x] 既定のままかの判定と訳の引き方が画面の 1 か所にまとまり、優先度の判断基準も同じ仕組みを通る
- [x] 既定を書き換えた値は、どちらの表示言語でも書いたまま出る
- [x] 訳した文を欄に出した項目は、書き換えずに欄を離れても値が変わらない（今の `storedConfigValue` の振る舞いを保つ）
- [x] ADR-001 の「言語」の節と requirements.md の CL-8・UI-11 に、既定の値の決まりを書く（日本語で書いた古い既定の写しは人の値として扱う、も含める）
- [x] 上の振る舞いをテストが確かめる
