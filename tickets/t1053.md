## Summary

テストと実装の観点（監査 s39）。約束（EX-8・IT-1）は、Iteration の `checkpoints` に記録を消さずに足すことです。一方、実装の `dg checkpoint` は、配列全体を書き換える更新を即時の push で送ります。マージドライバの `pick` は配列を 1 つの値として比べるので、2 つの clone が同じ元から 1 件ずつ足すと競合になります（オフラインで関所を通してから同期した場合も同じです）。`sync --resolve` で片側を採ると、もう片側の記録が消えます。今のテストは 1 つの clone の場合だけを確かめていて、この順序を確かめていません。

**方針**：マージドライバ（merge.ts）で `checkpoints` だけを要素の和集合にする（name・at・by が同じ記録は 1 件にまとめる）。push のやり直しは足さない。即時の push の競合と、オフラインから同期した場合の両方をこれで救う。

## Acceptance criteria

- [x] 2 つの clone で同じ Iteration に別の関所を通し、push を競合させても、同期した後に両方の記録が残る
- [x] `sync --resolve` を使わずに、マージドライバが両方の記録を残す（同じ記録が 2 件にならない）
- [x] 上の順序を、bare リモート付きの 2 つの clone で再現するテストがある
