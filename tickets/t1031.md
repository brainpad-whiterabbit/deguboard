## Summary

照合のきっかけ（ブランチができた → in_progress、下書きでない PR が開いた → review、PR かブランチがマージされた → done）を Core の固定にし、Workflow の `reconcile` をなくす。照合はエージェントの側として境目の判定を受け、PR を使わない進め方も同じきっかけで動く。t1024 から分けた。

## Acceptance criteria

- [x] 照合のきっかけ（ブランチができた → in_progress、下書きでない PR が開いた → review、PR かブランチがマージされた → done）が Core の固定になり、Workflow の `reconcile` がなくなっている
- [x] 照合がエージェントの側として境目の `requires` と `decide` で判定され、`requires` を満たすときだけ進めることがテストで示されている
- [x] PR を使わない進め方（ブランチのマージ）も、既定の `workflow.yaml` で done に進むことがテストで示されている
- [x] ADR-003 に照合のきっかけを Core に固定する理由（PR を使わない進め方も同じきっかけで動く）が書かれ、requirements の WF-2（`reconcile.when`）・ST-4 が直っている
