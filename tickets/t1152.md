## Summary

今の品質ゲートは作業ブランチの先端だけを検査し、main に入る形（main を取り込んだ後の組み合わせ）は検査していない（`--for merge` が見るのは衝突がないことの mergeable だけ）。段が high と low の `dg gate --for merge` に「作業ブランチの先端が base（main）の今の先端を含む」の条件を足し（free は検査をしないので掛けない）、その先端で `actions.test` が通ることを求める。main の取り込みは ready の前に行い（手順は t1154）、merge の時点で main が進んでいたら取り込み直して検査し直す。マージした後の全体の検査はしない。取り込むたびに見直しが無効にならないよう、t1153 の後に入れる。

## Acceptance criteria

- [ ] 段が high と low の `dg gate --for merge` が、作業ブランチの先端が base の今の先端を含まないときに、満たさない条件と、main を取り込んで push し直すという次の手を返し、free では判定しない（判定の組み合わせを純粋な関数のテストで網羅する）
- [ ] ready の前に main を取り込んだ先端で全体の検査が通れば、main が進んでいない限り、merge はその結果を回し直さずに使い、`dg pr merge` はその先端に固定してマージする
- [ ] requirements.md の EX-6 と ADR-026 を、マージの条件が変わったことに合わせて直す
