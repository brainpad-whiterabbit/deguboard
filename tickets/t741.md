## Summary

手直しが 1 回あるチケットで、全体の検査（`mise run check`）が 6 回回っている（実装者・レビュー役・手直し役・親・再レビュー役・`dg pr ready` のゲート）。原因は 2 つある。

- 品質ゲートの `chooseCheck` は `base...HEAD`（PR 全体の差分）で検査を選ぶ。最初の実装でコードを変えた PR は、後の手直しが docs だけでも全体の検査になる
- エージェントが手で回した検査の結果を dg が覚えない。そのため、レビュー役・親・ゲートが同じコミットで回し直す

次の 2 つで、全体の検査を 1 回に減らす。

- 同じコマンドの全体の検査が通ったコミット X を覚えておき、X が HEAD の祖先で `X..HEAD` がすべて `actions.light_paths` に入るなら軽い検査を選ぶ
- ゲートの check と同じ判定で検査だけを回して結果を覚える `dg gate <id> --only check` を足す。作業ブランチの worktree のコミット済みの HEAD で回すので、push の前に検査できる。手順を次のように替える：作業の途中は `mise run test:related`、push の前は `dg gate <id> --only check`。レビュー役と親も同じコマンドを呼び、覚えた結果を使う

## Acceptance criteria

- [x] 全体の検査が通ったコミットの後に light_paths だけのコミットを足すと、`dg gate` の check が軽い検査を回し、detail に前回通ったコミットからの差分で選んだことが出る
- [x] 次のどれかなら全体の検査を回す（bare リモート付きの一時リポジトリのテスト）：全体の検査が通ったコミットの後にコードを変えた・そのコミットが HEAD の祖先でない（rebase・force push）・main を merge で取り込んだ・`actions.test` のコマンドを変えた
- [x] 軽い検査が通っても、最後に全体の検査が通ったコミットの記録が消えない
- [x] `dg gate <id> --only check` は check と同じ判定で、作業ブランチの worktree の HEAD（未コミットの変更がないこと）を検査し、結果を SHA とコマンドごとに覚える。同じ SHA とコマンドで呼び直すと、回さずに覚えた結果を返す
- [x] push の前に `--only check` で通った結果を、push した後の同じ SHA の `dg pr ready`・`dg pr merge` が回し直さずに使う
- [x] implement・fix の brief は push の前に `dg gate <id> --only check` を回すよう、review の brief と guide review の「After fixing」も同じコマンドを呼ぶよう案内する。guide review の「Checks」と `dg gate --help` の説明は新しい選び方と合う。CLAUDE.md の規約では、チケットの作業（段が free を除く）の検査が `dg gate <id> --only check` に替わる（チケットの外の作業は `mise run check` のまま）
