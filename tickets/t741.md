## Summary

手直しが 1 回あるチケットで、全体の検査（`mise run check`）が 6 回回っている（実装者・レビュー役・手直し役・親・再レビュー役・`dg pr ready` のゲート）。原因は 2 つある。

- 品質ゲートの `chooseCheck` は `base...HEAD`（PR 全体の差分）で検査を選ぶ。最初の実装でコードを変えた PR は、後の手直しが docs だけでも全体の検査になる
- エージェントが手で回した検査の結果を dg が覚えない。そのため、レビュー役・親・ゲートが同じコミットで回し直す

次の 2 つで、全体の検査を 1 回に減らす。

- 同じコマンドの全体の検査が通ったコミット X を覚えておき、X が HEAD の祖先で `X..HEAD` がすべて `actions.light_paths` に入るなら軽い検査を選ぶ
- ゲートの check と同じ判定で検査を回して結果を覚える `dg check <id>` を足す。手順を次のように替える：作業の途中は `mise run test:related`、push の後は `dg check`、レビュー役と親は `dg check` の結果を読む

## Acceptance criteria

- [ ] 全体の検査が通ったコミットの後に light_paths だけのコミットを足すと、`dg gate` の check が軽い検査を回し、detail に前回通ったコミットからの差分で選んだことが出る
- [ ] 次のどれかなら全体の検査を回す（bare リモート付きの一時リポジトリのテスト）：全体の検査が通ったコミットの後にコードを変えた・そのコミットが HEAD の祖先でない（rebase・force push）・main を merge で取り込んだ・`actions.test` のコマンドを変えた
- [ ] 軽い検査が通っても、最後に全体の検査が通ったコミットの記録が消えない
- [ ] `dg check <id>` は `dg gate` の check と同じ判定で作業ブランチの最新のコミットを検査して結果を覚え、同じコミットとコマンドで呼び直すと回さずに覚えた結果を返す
- [ ] `dg check` で通った結果を、同じコミットの `dg pr ready`・`dg pr merge` が回し直さずに使う
- [ ] implement・fix の brief は push の後に `dg check` を回すよう、review の brief と guide review の「After fixing」は自分で回さずに `dg check` の結果を読むよう案内する。guide review の「Checks」と `dg gate --help` の説明は新しい選び方と合う。CLAUDE.md の規約では、チケットの作業の検査が `dg check` に替わる（チケットの外の作業は `mise run check` のまま）
