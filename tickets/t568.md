## 概要

ADR-001 は細部の正本をコード・テスト・ヘルプと決めたが、ADR を書く基準が「細部や 1 PR で戻せるものには書かない」の一文しかなく、端のケースやバグ修正ごとに ADR が増えた（ADR-014〜018・022・024）。書き換えの例外は ADR-002〜010 の移行に限られ、ADR-011 以降の細部は消せない（ADR-024 は ADR-008 の版の細部を消せずに生まれた）。ADR-001 を直接書き換え、ADR と要件を書く基準・細部を消す道・まとめ直しの決まり・要件の 1 項の上限を決め、CLAUDE.md を合わせる。

## 受け入れ条件

- [ ] ADR-001 が、ADR を書く場面を「戻すのに移行が要る」「利用者に見える約束とデータの形」「構成と技術の選択」「また提案されそうな案を退ける」に限り、端のケース・バグ修正・版の扱い・1 PR で戻せる規則はテストとコードのコメントの「なぜ」に置くと決めている
- [ ] ADR-001 が、判断を変えずに細部を正本へ移して消すことを、ADR-002〜010 に限らずどの ADR でもいつでもよいと決めている（「予定。実装は tNNN」・「制限」の節の端のケースを含む）
- [ ] ADR-001 が、一部の置き換え（失効の印）が 1 本の ADR に 2 つたまったら、その ADR 全体を置き換える 1 本にまとめ直すと決めている
- [ ] ADR-001 が、置き換え済みの ADR の本文を、ステータスと置き換えた先の 1 行だけに削ってよい（経緯は Git に任せる）と決めている
- [ ] ADR-001 が、要件の 1 項を約束の 1〜2 文と正本への案内にし、1 項の字数に上限を置いて check:docs で検査すると決めている（「大きさの予算は持たない」との関係と、上限の値を含む）
- [ ] CLAUDE.md の「ドキュメント」「チケット」の節と docs/adr/README.md の運用の段落が新しい決定に合い、`mise run check` が通る
