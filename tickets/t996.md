## Summary

使う人には、AI に任せても見直しを飛ばしたり勝手にマージしたりしない理由と、止まった作業が続きから戻れる理由が見えていない。how-it-works.md（日本語版と英語版）に、`dg next` が事実から段階をそのつど求めて次の 1 手を返す仕組みの節を足す。

## Acceptance criteria

- [x] `docs/how-it-works.md` と `docs/how-it-works.ja.md` に、同じ構成で「エージェントが次の一手を決める仕組み」の節がある
- [x] エージェント・`dg next`・事実（チケットの状態と依存、作業ブランチ、PR、Run と見直しの結果、検査の結果、段）の関係と、「聞く → 1 手を行う → また聞く」の繰り返しを示す図が 1 枚ある。図は t990 と同じく手で描いた SVG のファイル（日本語版と英語版）で、GitHub のライトとダークのテーマのどちらでも読める
- [ ] 手順は dg にあること（Skill・`dg guide`・`dg next`）、段階を保存しないので止まっても `dg next` で続きから戻れること、人が決めること（マージの承認・リリース・やめる）は dg が止めて聞き、段で見直しの有無が変わることが書かれている
- [x] 手の一覧とやり方・品質ゲートの条件・手順を dg に持たせた理由を写さず、`dg guide work`・`dg next --help`・usage.md の Quality gate levels・ADR-011・ADR-030 へのリンクで引いている
- [x] ADR-001 の表の how-it-works の行が、この節を含む書く範囲になっている（t990 で足した行で足りれば変えない）
