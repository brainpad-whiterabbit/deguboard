## Summary

見直し（s35）の観点「文書と実装」。ADR-036 は、見つけ損ねた不具合を `origin`・`origin_cause` に記録し、dg は本文に書かれた ID から推し量らないと決めている（`refs` と後のチケットの本文から数えると、依存・例・元のチケットを見分けられないため）。ところが t939 で core に持った推薦の指標 `review.escaped-defect-rate` は、このリポジトリで ADR-036 より前に承認した定義を写したもので、`metrics sources` の `refs` と `ticket show` の本文から数える。guide-retro の「Files and references」の節も、すり抜けた不具合を `refs` で数えるよう案内し、`origin` に触れない。

## Acceptance criteria

- [ ] 推薦の指標 escaped-defect-rate の数え方と出どころが、記録した `origin`（と `origin_cause`）を使い、記録のない古いチケットは測れないものとして扱う
- [ ] guide-retro が、すり抜けた不具合を数えるときに `origin` を指し、`refs` で数える案内が残っていない
- [ ] 上をテスト（推薦の指標と guide の snapshot）が示している
