## Summary

s44 の見直し（観点：文書と実装）の指摘。docs/requirements.md の SY-1 は「データのリモートに届かなければボードを作らずに止める（手元だけで始めるのは `--new-board`）」と書く。一方、実装と usage（docs/usage.md・usage.ja.md の 117 行付近）と導入の画面では、`--new-board` は手元に先に作ってリモートに届いたら push する道で、手元だけに置くのは `--no-data-remote`。`dg init --help` の `new_board` の説明も「届かないときも手元にボードを作る」だけで、届いたら push することを書いていない。利用者が手元だけの運用に `--new-board` を選ぶ原因になる。

## Acceptance criteria

- [ ] requirements.md の SY-1 が、`--new-board` を届いたら push する手元のボードの道として書き、手元だけに置くのは `--no-data-remote` だと分かる（250 字の上限に収まる）
- [ ] `dg init --help` の `--new-board` の説明が、リモートに届いたら push することを書いている
- [ ] `mise run check:docs` が通る
