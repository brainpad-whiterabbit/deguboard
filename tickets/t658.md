## Summary

`/dgall t1000 --gate-free` や `/dgwork t12 --gate-low` のように段を指定すると、着手の前に対象のチケットへ段（t657 の `gate`）を付け、段に合った流れでマージまで進む。指定がなければ high（今と同じ）。人がコマンドに書いた指定を人の決定とみなし、`--auto` ならそのまま進める。

| 段 | 流れ |
|---|---|
| high（既定） | 実装 → 見直し → 手直し → ready → マージ（今と同じ） |
| low | 実装 → ready → マージ（見直しと手直しの往復なし。check は回す） |
| free | 実装 → ready → マージ（見直しも check も回さない） |

- `dg next`：PR のある low・free のチケットは見直しの段階を飛ばす。draft なら reviewed（review_passed）→ `ready`、そうでなければ ready → `wait_merge` にする。止まった Run の waiting_human と done・abandoned・todo の判定は、今のまま先に効く。`ticket show` の `stage` も同じ関数なので揃う
- `dg brief`：low・free のチケットで `--role review` を求められたら警告を返す（止めない）
- `dg flow next --gate <段>`：work の段階の commands で、段の違うチケットにだけ `dg ticket update <id> --gate <段>` を `next` の前に入れる。同じ段のものには入れない。止まる判定（fingerprint）を揺らさないため
- `/dgwork` は `flow next` を通らないので、guide work の手順で着手の前に段を付ける
- t657 のマージの後に着手する。この PR 自体は high で通す
