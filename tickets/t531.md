## 概要

見直し役の Run に、重い指摘の数・軽い指摘の数・通ったか（`passed`）を記録する。新しい仕組みでは見直し役は `run start`・`run finish` を呼ばず、Run はフックが開閉する（t530）ので、記録は**実行中の見直し Run に結果だけを書く独立したコマンド**で行う（例 `dg run review-result <ticket> --heavy N --light M [--passed]`。チケットから、その見直し役が開いている `review` の step の Run を引く）。見直し役は brief（t534）に従い、一覧を返す前にこれを 1 回呼ぶ。

t530 は暫定の規則として「見直しは最後の応答があれば success」で閉じている。このチケットでそれを「結果が記録されていれば success、なければ failure」に置き換える。今は見直しの結果が記録に残らず、修正ループの回数と品質ゲートを親の LLM が数えている。段階（t533）とゲート（t532）はこの記録を読む。

## 受け入れ条件

- [x] Run のスキーマに見直しの結果（重い・軽い指摘の数、通ったか）があり、実行中の `review` の Run に結果だけを書くコマンドがある。見直し以外の step の Run には書けない
- [x] コマンドはチケットの ID から実行中の見直し Run を引く。実行中のものがなければ、閉じた最新の見直し Run に書く（フックが先に閉じたとき）。どちらもなければ `NOT_FOUND`
- [x] SubagentStop が見直しの Run を閉じるときの結果が、t530 の暫定の規則（最後の応答があれば success）から「結果が記録されていれば success、なければ failure」に置き換わっている
- [x] `run list` の出力（`metrics show --run` で 1 件）と `metrics show` の集計に見直しの結果が出る
- [x] requirements.md の RN-1・RN-4・AG-9 に記録する項目と規則が足され、判断は ADR-013 に書いて ADR-012 の該当の項を置き換え、`mise run check` が通る
