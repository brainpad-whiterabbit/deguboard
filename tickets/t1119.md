## Summary

見直し（s41）の観点「テスト」。packages/core/src/git/git.test.ts の「読みの status を繰り返しながら書き込みを続けても、書き込みが index.lock で落ちない」が、s41 の作業中に 3 回、`rev-list --left-right --count HEAD...refs/remotes/origin/deguboard` の unknown revision（GitError）で 1 回だけ落ち、再実行では通った。

コードから読める順序：読み側の syncStatus（sync.ts）は書き込みのロックの外で aheadBehind を呼び、追跡 ref がないと rev-list が失敗する。続けて show-ref で ref の有無を聞くまでの間に、書き側の withWrite の fetch が追跡 ref を作ると、show-ref が成功し、syncStatus は 1 回目の古い失敗を投げる。テストだけでなく、初めての fetch と同時に status を読む利用者にも起こりうる。

## Acceptance criteria

- [ ] 追跡 ref が数えた後に現れたとき、syncStatus が古い失敗を投げず、数え直すか ref がない扱いのどちらかで今の状態を返す
- [ ] 数えられた・ref がない・ref が途中で現れた、の組み合わせを、読まない関数のテストで確かめる
- [ ] git.test.ts の上の件が、読み側の予期しない例外を失敗として拾い、競合の順序に頼らず通る
