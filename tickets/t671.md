## Summary

頼む小窓に discuss（検討する）を足す。対象を読み取りだけで調べ、論点を選択肢で人と相談し、決まったら前後の差を示して承認を得てから反映する。反映の手順は既存の guide（チケットは import、Epic・Iteration は change）に従い、guide-discuss.md には書かない。guide-discuss.md を新設して dgdiscuss を配る。status・retro・carry の Skill はこのチケットでは扱わない（t672・t673・t674）。

dgdiscuss を使う頼むことは discuss だけなので、Skill の形は呼び出しだけにし、頼みごとの 1 行（intent）は付けない。候補では、チケットは「直す」（外すがあればその後）の次、Epic・Iteration は「題・概要を直す」「名前・目標・期間を直す」の次に並べる。答えの決まった「直す」と、これから決める「検討する」を隣に並べるため。

## Acceptance criteria

- [x] `dg guide discuss` が、議論の間はファイルとデータを変えないこと・論点を選択肢で相談すること（guide-choices に従う）・前後の差で承認を得てから反映すること・反映はチケットなら `dg guide import`、Epic・Iteration なら `dg guide change` に従うことを示す（status・retro・carry の節は持たない）
- [x] `dg guide discuss` が、反映するのは題・本文・受け入れ条件・優先度・依存・段だけで、Status・所属・閉じる・やめるが結論になったら合う頼むことを示して止まること、in_progress のチケットは反映の前に動いている Run があれば知らせることを示す
- [x] discuss が todo・in_progress・review のチケット（複数可）と開いている Epic・Iteration の候補に、直す（Epic・Iteration は edit）の後に出て、先頭（おすすめ）にならず、done・abandoned のチケット・closed の Epic・Iteration・Plan には出ないことをテストが確かめる
- [x] discuss の Skill の形が `/dgdiscuss <ID>` になり、頼みごとの 1 行を持たないことをテストが確かめる
- [x] dgdiscuss の SKILL.md ができ、SKILL_SUMMARY と画面の英語の表示名（l10n-core の「検討する」）がある
- [x] 頼む小窓で「検討する」が出るスクリーンショットを PR に載せる
