## Summary

s37 の見直し（観点：README・文書と実装）で、利用者向けの記述が実装と食い違う点が 3 つ見つかった。どちらに合わせるかは計画で決める。

- gh の要否：README.md と README.ja.md の動作環境は「gh は任意。PR の状態をチケットに映すときだけ要る」、docs/requirements.md の「2. 想定利用者と前提」の必須ツールの項は「PR の事実を照合に使うときだけ」と書く。一方、`dg pr ready` と `dg pr merge` は gh を呼ぶ（EX-6）ので、gh がないと PR を出す・マージする手前で止まる
- トークンの記録：README.md と README.ja.md の冒頭の「Measure and improve」（測って改善）は、どの作業でも使ったトークン数を記録すると読める。一方、トークンは `metrics.read_transcripts` が true のときだけ数え、既定は false（MT-2、usage の Count tokens）
- `--dry-run`：docs/usage.md と docs/usage.ja.md の Skill とフックの説明は、`dg hook <event>` に続けて「どちらも `--dry-run` で見られる」と書く。一方、`--dry-run` があるのは `dg skill install` と `dg hooks install` で、`dg hook` にはない

## Acceptance criteria

- [ ] README.md・README.ja.md・docs/requirements.md の gh の要否が、`dg pr ready`・`dg pr merge` が gh を呼ぶことと食い違わない
- [ ] README.md と README.ja.md の冒頭のトークンの記述が、`metrics.read_transcripts` の既定と食い違わない
- [ ] docs/usage.md と docs/usage.ja.md の `--dry-run` の記述が、そのオプションを持つコマンドを指している
- [ ] 英語版と日本語版が同じことを書いている
