## Summary

s33 の振り返りの Try。push が拒まれた後の取り込み直しでエラーを投げると、そのコマンドのコミットが手元に残り、再実行で変更が二重に入る不具合が、s33 で 2 回、別々のエラーで見つかった（t904 の DATA_REMOTE_CHANGED、t909 の DATA_HISTORY_UNRELATED）。どちらも見直しの重い指摘になり、エラーの種類ごとに直した。

次に新しいエラーを足しても同じ形が起きないように、取り込み直しで止まるときにそのコマンドの変更を書かないことを、エラーの種類ごとではなく書き込みの経路で約束する。次の Iteration で、この形の重い指摘を 0 にする。

## Acceptance criteria

- [ ] push が拒まれた後の取り込み直しが、どのエラーで止まっても、そのコマンドのコミットが手元に残らない（HEAD と作業ツリーが書き込みの前のまま）
- [ ] DATA_REMOTE_CHANGED と DATA_HISTORY_UNRELATED 以外のエラーで止まる場合も含めて、bare リモート付きの一時リポジトリのテストで示す
- [ ] 既存のテストが通る
