## Summary

Epic e40 の方針を、dg sync の照合に当てはめる。照合の Run の閉じ方は大きいので 2 件に分け、この件は対象のチケットごとの決定を扱う。手直しの Run と、照合の対象にならなかった実行中の Run の閉じ方は、後の件で同じ列の決め方に加える。

`packages/core/src/commands/setup.ts` の照合は、ロックの外で `collectReconcileFacts` が事実を集め、ロックの中で `reconcileAll` が決めて書く。状態を進める判定の `reconcileStatus`（`packages/core/src/workflow/reconcile.ts`）はすでに純粋な関数だが、`reconcileAll` の対象のチケットごとのループの中では、次が書き込みと一体になっている。

- PR があるときに実装の Run を閉じる（PR の作成時刻と Run の開始時刻の比較と、閉じる書き込み）
- pr と lines の記録、状態の前進、止められた遷移と前の作業の PR の警告
- 閉じた Run の集まりを、後の判定（保留の見直しの数え方）の除外に使う順序の依存

決める関数が「行うことの列」（チケットを進める、pr と lines を記録する、Run をどの結果と finished_at で閉じる、警告する）を返し、行う側はそれを順に実行するだけにする。判定のテストは列を比べるだけになる。commands-flow-reconcile.test.ts（28.9 秒・26 件）では、判定の組み合わせだけを確かめている件が約 11 件、判定と経路の両方を見ている件が約 7 件ある。

## Acceptance criteria

- [x] 照合の対象のチケットごとの、チケットを進める・pr と lines を記録する・PR による実装の Run を閉じる（結果と finished_at）・警告する、の決定が、事実を受け取って行うことの列を返す、git・gh・ファイルを読まない関数にある
- [x] 行う側は列を順に実行し、別の文脈が先に Run を閉じたときの読み直しと、事実を集めた後にチケットが変わったときは判定しない扱いが、今と変わらない
- [x] 照合の結果の push が拒否されたとき（reconcileLocked の push）、コミットをローカルに残して警告し、次の sync で取り込み直して送る今の扱いが変わらず、その取り込み直しの途中で止まっても、閉じた Run の記録と実行中の Run の消去（dropRunning）が二重にも欠けにもならないことをテストで確かめる
- [x] 組み合わせ（PR の有無と作成時刻と Run の開始の前後、前の作業の PR、止められた遷移、done への前進と消えたブランチ）をその関数のテストで確かめ、commands-flow-reconcile.test.ts から判定だけを確かめていた件を移す。移した件と残した件の対応を PR に載せる
- [x] dg sync の出力と書き込みが変わらない
- [x] 全体のテストの時間と commands-flow-reconcile.test.ts の時間の変更前後を PR に載せる
