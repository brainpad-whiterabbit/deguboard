## Summary

Epic e40 の方針を、dg sync の照合に当てはめる。いちばん大きい段。

`packages/core/src/commands/setup.ts` の照合は、ロックの外で `collectReconcileFacts` が事実を集め、ロックの中で `reconcileAll` が決めて書く。状態を進める判定の `reconcileStatus`（`packages/core/src/workflow/reconcile.ts`）はすでに純粋な関数だが、`reconcileAll` の中では次が書き込みと一体になっている。

- PR があるときに実装の Run を閉じる（PR の作成時刻と Run の開始時刻の比較と、閉じる書き込み）
- 手直しの Run を閉じる：区切りを決める `fixRunBoundary` の後、`closeFixRun` がロックの中で `lastPushedAt`（git の読み）を呼んでから閉じる
- 対象外のチケットの実行中の Run を閉じる（終わったチケット、もう一度の claim か、PR のある done、todo、別の主体、で閉じ方が分かれる）
- 閉じた Run の集まりを、後の判定の除外に使う順序の依存

決める関数が「行うことの列」（チケットを進める、pr と lines を記録する、Run をどの結果と finished_at で閉じる、警告する）を返し、行う側はそれを順に実行するだけにする。判定のテストは列を比べるだけになる。commands-flow-reconcile.test.ts（28.9 秒・26 件）では、判定の組み合わせだけを確かめている件が約 11 件、判定と経路の両方を見ている件が約 7 件ある。

## Acceptance criteria

- [ ] 照合の、チケットを進める・pr と lines を記録する・Run を閉じる（結果と finished_at）・警告する、の決定が、事実を受け取って行うことの列を返す、git・gh・ファイルを読まない関数にある
- [ ] 手直しの Run の最後の push の時刻をロックの外でほかの事実と一緒に集め、集めた後にチケットが変わったときは判定しない今の扱いが変わらない
- [ ] 行う側は列を順に実行し、別の文脈が先に Run を閉じたときの読み直しが今と変わらない
- [ ] Run の閉じ方の組み合わせ（終わったチケット、todo、別の主体、PR の有無と作成時刻、次の Run の有無と同じ秒、push の時刻）をその関数のテストで確かめ、commands-flow-reconcile.test.ts から判定だけを確かめていた件を移す。移した件と残した件の対応を PR に載せる
- [ ] dg sync の出力と書き込みが変わらない
- [ ] 全体のテストの時間と commands-flow-reconcile.test.ts の時間の変更前後を PR に載せる
