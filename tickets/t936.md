## Summary

振り返り（s34）の Problem。リリースのチケット（t912・t934）は、受け入れ条件 2（タグの push と Release の公開）がマージの後でないと満たせない。そのため、リリースの PR（#845・#865）は毎回ゲートの acceptance を満たさず、人の承認で条件を外してマージしている。development.md の「リリース」と guide-release のどちらかで、タグと公開をリリースの PR の受け入れ条件から外す（たとえば PR の要らない別のチケットにする）。次のリリースの PR で、承認で外す条件の数を 0 にすることをねらう。


## Acceptance criteria

- [ ] リリースの手順が、リリースの PR のチケットの受け入れ条件を PR の中身で確かめられるものだけにし、タグと公開の扱い（どのチケットでいつ確かめるか）を書いている
- [ ] リリースの PR が、承認で条件を外さずに `dg gate --for merge` を満たせる手順になっている
