## 概要

t532（PR 482）の PreToolUse のフックは、Bash のコマンドを字句に分けて gh pr merge・ready を読み、dg gate で止める。読み違えたときや読めないとき（2>&1 の 2 を PR の指定と読む、$PR、python -c の中など）は「チケットを引けない PR は止めない」の規則で通してしまい、4 回の見直しでも指摘が尽きなかった。

正しい道を Core のコマンド（dg pr ready・dg pr merge。名前は実装で決める）にし、フックは dg を経由しない gh pr ready・merge を粗く止めて dg のコマンドへ案内する。読み違えたときは止める側に倒す。t532 の字句の分解は、止めすぎを減らすためにだけ使う。

## 受け入れ条件

- [ ] dg pr ready・dg pr merge（名前は実装で決める）が Core のコマンドにあり、dg gate を満たすときだけ gh を execFile で呼ぶ。満たさなければ満たさない条件と理由を返し、gh を呼ばない
- [ ] PreToolUse のフックは、dg を経由しない Bash のコマンドに gh の pr ready・pr merge が含まれれば拒み、dg のコマンドへ案内する。字句で無害と言い切れるもの（引用符・ヒアドキュメントの中の文字など）だけを通し、読み切れないものは止める
- [ ] ゲートを満たさないまま進める例外（見直し役を起動できない・上限を超える・版上げの PR・人が回数を指示した）は、今と同じく人が gh を打つ。拒む文と guide-review がそう案内する
- [ ] PR 482 で読み違えた例（2>&1・$PR・python -c の中の gh pr merge など）が、通らずに止まることをテストで確かめる
- [ ] guide（review・all・work）と requirements の AG-9・EX-3 が、dg のコマンドを PR を進める正しい道として書く
- [ ] PreToolUse の守り方を「正しい道の dg のコマンド＋粗い拒否＋事後の検査」にする判断を ADR に書き、ADR-004 の該当の項を置き換えにする（事後の検査は後続のチケット）
