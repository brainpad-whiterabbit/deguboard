## Summary

README.md 冒頭の「You write small tickets with acceptance criteria and approve the plan; agents implement the tickets in parallel, and nothing merges until the quality gate passes.」は、人がチケットを書くと読める。実際は、エージェントが人のアイデアから受け入れ条件の付いた小さなチケットを書いて並列に実装し、品質ゲートを通るまで見直しを繰り返す。エージェントの働きは計測され、振り返りで人がエージェントとソフトウェアの改善を考える。新しい開発フロー図とも食い違うので、冒頭の文をこの流れに合わせる。README.ja.md の対応する文も同じ PR で直す。

人と合意した文言は次のとおり（計画の承認は、下の箇条書き「You stay in charge」「舵は人が握る」に任せて冒頭からは外す）。

- README.md：You bring the idea; agents turn it into small tickets with acceptance criteria, implement them in parallel, and keep revising each one until it passes the quality gate. Every agent run is measured, and in the retrospective you decide how to improve the agents and the software.
- README.ja.md：人がアイデアを出すと、エージェントが受け入れ条件の付いた小さなチケットにし、並列に実装し、品質ゲートを通るまで見直しを繰り返します。エージェントの働きは計測され、振り返りで人がエージェントとソフトウェアの改善を考えます。

新しい冒頭に計測と振り返りが入るので、3 つ目の箇条書き「Measure and improve」「測って改善する」と内容が重なる。箇条書きも、冒頭を繰り返さないように直す。
