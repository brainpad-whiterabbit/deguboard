## Summary

今の Ask Agent には、チケットの目的や何が変わるかを、書き換えずに聞く手段がない（読み取りだけの status は in_progress の進み具合だけを答える）。頼むこと explain（Skill は dgexplain、手順は dg guide explain）を足す。データもファイルも変えず、返答の中に文字の図を 1〜2 枚入れて、人が読んで分かる形で説明する。

対象はチケット・Epic・Iteration で、開いているものも閉じたものも含む（Plan は画面に依存グラフがあるので含めない）。対象なしの候補一覧にも出す。図をページ（artifact など）で出すことは、今回は足さない。

## Acceptance criteria

- [ ] Ask Agent のチケット（どの状態でも）・Epic・Iteration の候補と、対象なしの候補一覧に Explain が出て、選ぶと /dgexplain <ID> と、文章だけの形の依頼文が作られる。並びでは free の直前（対象なしでは status の隣）に置き、先頭（おすすめ）にしない
- [ ] dg guide explain が、答え方（1 文の要約 → 文字の図 1〜2 枚（位置・前後・通り道から選ぶ）→ 具体例 → 用語の言い換え → 受け入れ条件を平たく言い直したチェックリスト）と、読む範囲（チケット・関わるコードと ADR）を示し、dg の書き込み・ファイル・ブランチ・コミットをしないと明記している
- [ ] 複数のチケットを対象にしたときは 1 件ずつ説明して関係（依存・同じ Epic）を 1 枚の位置の図にまとめ、Epic・Iteration では中のチケットとその進みを位置の図で示すと guide にある
- [ ] done・abandoned・review のチケットでは、それぞれ PR で変わったこと・やめた理由・PR が受け入れ条件をどう満たすかを添えると guide にある
- [ ] dg skill install で dgexplain が配られ、札の 1 文（SKILL_SUMMARY）と画面の訳がある
- [ ] docs/usage.md と docs/usage.ja.md の頼むことの説明に Explain がある
