## Summary

Epic e40 の方針を、ゲートの切り出しで形が決まった後に規約と文書にする。後のチケット（保留の見直し・事実の導出・照合・claim）はこの規約に沿って進める。

方針は次の 3 つの層。

- 判定のテスト：事実から結果を決める処理は、コマンドの run の中に書かず、決める関数（git・gh・ファイルを読まない）に置く。入力は事実の型・今の時刻・解決済みの Workflow、出力は結果か行うことの列。組み合わせはこの関数のテストで網羅する（既定の事実から 1 つだけ変える形か、表で掛け合わせる形）
- 事実の読み取りのテスト：git・gh の状態から事実の型を作る処理は、事実ごとに本物の git で確かめる。読めないとき（gh がない、PR がない、前の作業の PR）を値で返すこともここで確かめる
- 経路のテスト：コマンドの結合テストは経路ごとに代表を 1〜2 件にする（集めて決めて行うが通る、push・lock・競合・gh の引数・記録の形）。判定の組み合わせを結合テストで足さない。準備は雛形から写し、1 件の中で init しない

コマンドの中を「集める・決める・行う」に分けるのは構成の選択なので、ADR-033 の本文を書き換える。
