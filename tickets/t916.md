## Summary

見直しの指摘に原因の種類を付けられるようにしたうえで（依存先のチケット）、見直し役が迷わず付けられるように review の guide で見分け方を案内する。あわせて、retro の guide の「Causes of rework」が、手直しの理由の文と PR のコメントを読んで分ける今のやり方から、`metrics show` の原因ごとの数を読むやり方に変わるようにする。

仕様の質の指標の定義（config.yaml の retro.perspectives.spec の ticket-caused-rework-rate）は、このチケットでは変えない。変えるのは、マージした後の振り返りで提案して人が承認してから。

## Acceptance criteria

- [ ] review の guide の「Return」に、7 種類の原因の見分け方があり、ticket と category の「受け入れ条件の漏れ」の違いが書いてある
- [ ] retro の guide の「Causes of rework」が、`metrics show` の原因ごとの数を読む形になり、原因の数のない Run を測れないものとして扱うことが書いてある
- [ ] guide のスナップショットが更新され、`mise run check:docs` が通る
