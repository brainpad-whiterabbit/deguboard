## Summary

見直し（アーキテクチャ・テスト）：packages/core/src/git/sync.ts の syncStatus は、aheadBehind が数えられなかったとき show-ref で追跡 ref を確かめ、あれば aheadBehind(repo, true) で同じ rev-list をもう一度呼んで失敗を投げさせる。1 回目の失敗を捨てて同じ git を呼び直している。この「追跡 ref はあるのに数えられないと投げる」経路に packages/core/src/git/git.test.ts のテストがない。また packages/vscode/src/setup.ts の skillsHooksCommands と packages/web/src/store.tsx の SNAPSHOT_KEY は、本番では同じファイルの中だけで使い、ほかはテスト（setup.test.ts・store-cache.test.tsx）からだけ使う export になっている。

## Acceptance criteria

- [ ] syncStatus が、追跡 ref があるのに数えられないとき、rev-list を呼び直さずに失敗を投げる
- [ ] 追跡 ref があるのに数えられないとき syncStatus が投げることを、テストが確かめる
- [ ] skillsHooksCommands と SNAPSHOT_KEY が、export を外すか、テストのために export する理由をコメントに書いている
