## 概要

いまの ADR の運用（判断を変えるたびに新しい番号で置き換える・失効の印・印 2 つでのまとめ直し・判断と理由は書き換えない）は、AI で開発する頻度の高い小さな判断の修正のたびに番号・一覧・参照の張り替えを要し、実装を遅くしている。古い記述が残ると、エージェントがそれを正として読む誤りのもとにもなる。

ADR を「今の判断」だけを書く文書に改め、判断を変える PR で本文を直接書き換える（履歴は Git に任せる）。冗長は許すが誤りは残さず、長くなったら定期的に分割・整理する。細部の正本は引き続きコード・テスト・ヘルプにする。2026-11-09 の会話で人が承認した方針。

決めた方針：

- 判断を変えたら、同じ PR でその ADR の本文を書き換える。番号は変えない。失効の印・まとめ直しの規則・「判断と理由は書き換えない」はなくす
- 覆した判断のうち、また提案されそうなものは「採らなかった案」に 1 行で残す（エージェントは Git の履歴を読まないため）
- テーマごと要らなくなった ADR と、統合で元になった ADR はファイルごと削除する。置き換え済みの表とステータスの「置き換え」はなくす。番号は使い回さず、一覧に「最後に使った番号」を置く
- PR が誤りにした ADR の細部は、その PR で消す（「直さず報告に書く」はやめる）
- 各 ADR の冒頭に、決定の要約（2〜3 文）を置く
- 1 本が長くなったら（check:docs の 8,000 字の警告）、または Iteration の見直しで、「ADR の分割・整理」のチケットを起票し、分割・統合・削除・細部の削除・実装との照合・テストや lint に移せる判断の洗い出しをまとめて行う
- 機械で守れる判断はテスト・lint・フック・検査に守らせ、ADR は理由の説明にとどめる
- コードのコメントから指すのは、番号の変わらない要件 ID と「なぜ」。ADR 番号はファイルの先頭のコメントの 1 つまで
- 同梱の guide（他のリポジトリにも配る）には、このリポジトリの ADR 番号を書かず、基準の中身を 1 文で書く
