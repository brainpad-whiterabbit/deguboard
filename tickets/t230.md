## 概要

見直し（テスト・設定ファイル）。scripts/install-vsix.mjs の spawnSync("code", ["--install-extension", …]) と hasCode() の execFileSync("code", ["--version"]) に時間の上限がない。リモートの code CLI は --version にはすぐ答えるが、--install-extension は VS Code の窓口のソケットの応答を上限なく待つので、この環境では mise run install が毎回 900 秒以上止まる。mise.toml の install・vsix:install の説明と development.md:127 は「code CLI がなければ飛ばす」だけで、応答しないときの扱いがない。また development.md:40 は worktree ごとに mise run install を案内するので、作業中のブランチのビルドが --force で VS Code の拡張を差し替える

## 受け入れ条件

- [ ] install-vsix の code の呼び出しに時間の上限があり、超えたら手で入れるコマンドを案内して失敗にせず終える
- [ ] worktree の用意（development.md の始め方とエージェントの手順）は VS Code に拡張を入れずに依存とビルドだけを行う（タスクを分けるか、飛ばす指定を足す）
- [ ] mise.toml の説明と development.md に、応答しないときと worktree での扱いが書いてある
- [ ] 上限を超えたときの扱いを、偽の code を使うテストで確かめる
- [ ] mise run check が通る
