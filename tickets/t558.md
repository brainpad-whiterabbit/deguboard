## 概要

t546 の 1 回目の見直しの Run（572 秒）のうち約 6 分は、競合を再現するスクリプトを、引数を直し回数を 40 回から 100 回に増やしながら 4 回回した時間だった。2 回目の見直しでも同じスクリプトに約 2 分を使った。100 回のうち当たったのは 0〜2 回で、疑いはコードを読んだ時点で持てていた。

時間を使ったのは 1 回の長さではなく、結論の決まった疑いを試し方を変えて回し直したことだった。また、1 回あたり 1〜2% でしか起きない不具合は、100 回回しても 1 度でも当たるのは 63〜87% で、当たらなくても不具合がないとは言えない。そのため上限は秒数ではなく、回し直さないことと、確率でしか起きない不具合を動かさないことで決める。秒数（1 分）の上限は、根拠が t546 の 1 件しかなく、ビルドしてから 1 回確かめるような要る確認まで止め、`mise run check` を含むかが読み手で分かれるので置かない。

CLAUDE.md に書く文の案：

> PR の見直しで、疑いを確かめるために動かすのは 1 回までにし、引数や回数を変えて回し直さない。競合のように確率でしか起きない不具合は、再現を試さずにコードの根拠（どの順序で何が起きるか）で重い指摘にし、再現するテストは手直しに任せる。決まった検査（`mise run check`）はこれに含めない。

このリポジトリの規約として CLAUDE.md に書く（見直しのサブエージェントも CLAUDE.md を読む）。利用者に配る `dg guide review` には書かない。

## 受け入れ条件

- [x] CLAUDE.md に、PR の見直しで疑いを確かめるために動かすのは 1 回までとし、引数や回数を変えて回し直さないことが書いてある
- [x] CLAUDE.md に、確率でしか起きない不具合は再現を試さずにコードの根拠（どの順序で何が起きるか）で重い指摘にし、再現するテストは手直しに任せることが書いてある
- [x] CLAUDE.md の同じ箇所に、決まった検査（`mise run check`）はこの上限に含めないことが書いてあり、秒数の上限は書いていない
