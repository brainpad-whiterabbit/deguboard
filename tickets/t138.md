## 概要

エージェントが CLI でチケットを動かすと左パネルは自動で描き直されるが、行が黙って移るだけで何が変わったか分からない。KanbanForge の SP-10（views/sprint/changes.ts・sprint.css の .kf-changed）と同じ形で、前回の描画と比べて変わった行の枠を短く点滅させる。deguboard では左パネルが retainContextWhenHidden で隠れている間も描き直されることと、ドラッグで自分が書き込めることに合わせる。改善案の K1。要件が増えるので requirements.md の UI-2 に書く

## 受け入れ条件

- [ ] 左パネルのカンバンで、前回の描画から Status か Iteration が変わった行と新しく現れた行の枠が 2 回点滅し、点滅の後には何も残らない
- [ ] 初めて描くとき・消えた行・左パネルから自分でドラッグして動かした行は点滅しない
- [ ] 左パネルが隠れている間に起きた変化は、左パネルが見えたときに点滅する
- [ ] prefers-reduced-motion が reduce のときは点滅しない
- [ ] 前回との比べ方が DOM に依存しない関数になっていて、vitest のテストがある
- [ ] requirements.md の UI-2 に点滅の約束が書かれている
- [ ] パネルとブラウザ版の画面は変わらない
