## 概要

t487 の方針（dg が書く定型の文は英語）に沿って、ticket create・import・epic create の雛形が書く本文の節を `## Summary`・`## Acceptance criteria`・`## References` にする。節の名前はコードが字のまま読むデータの形なので、読む側（lint の節の欠け・ticket check・ticket update --acceptance・ticket show の acceptance・brief・gate・画面）は日本語（`## 概要`・`## 受け入れ条件`・`## 参考`）と英語のどちらの名前も読む。読む側が両方を読むので、既存のチケットを書き換える移行は要らない。t488 の見直しで、英語にした guide が節の名前まで訳していたことから起票した（t488 では字のままの名前に戻す）。

## 受け入れ条件

- [ ] ticket create・import と epic create の雛形が英語の節（`## Summary`・`## Acceptance criteria`）を書く
- [ ] lint の節の欠け・ticket check・ticket update --acceptance・受け入れ条件の取り出し（ticket show・brief・gate）が日本語と英語のどちらの節の名前も読み、テストが両方を確かめる
- [ ] 参考節を読む処理（brief・見直し）が `## References` と `## 参考` の両方を読む
- [ ] 画面のチケット詳細が、英語の節の本文を今の日本語の節と同じに出す
- [ ] requirements.md の TK-3・EP-1 が英語の節の名前を約束し、日本語の名前も読むと書いてある
- [ ] mise run check が通る
