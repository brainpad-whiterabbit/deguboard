## Summary

観点はテスト。EX-6 と pr.ts の説明は段に応じた条件を約束しているが、テストは judgeGate を直接確かめているだけになっている。足りないのは次の 3 つ。

- pr.test.ts：low・free のチケットで、見直しの Run がなくても gh pr ready・gh pr merge が呼ばれるテスト
- gate.test.ts：low・free では見直しの Run・push の時刻・fetch を読まない、という judgeGate のコメントの約束のテスト（今は check を回さないことだけを確かめている）
- program.test.ts：CLI で `dg ticket update --gate none` が gate を外すことを、往復で確かめるテスト

## Acceptance criteria

- [x] free のチケットで dg pr ready と dg pr merge が見直しなしに gh を呼び、low のチケットで受け入れ条件に印がないと merge が GATE_FAILED になる（pr.test.ts）
- [x] low・free の判定が、リモートの追跡 ref がないか fetch できないときでも通る（gate.test.ts）
- [x] CLI で --gate low を付けた後 --gate none で外すと、ticket show に gate が出ない（program.test.ts）
