## 概要

同じ会話記録のファイルで 2 つの Run の期間が重なると、Adapter は重なった間の応答を両方の Run に数える（ほかの Run が数えた行かを見ていない）。2026-11-05 に確かめると、期間が重なる Run の組 739 組のうち 11 組が同じファイルに結び付き、二重に数えていた。

- 1 つの見直し役が複数のチケットの Run を同時に開いた（t252・t253・t254 の review が 3 つとも output 7,831）
- implement を閉じないまま fix を始めた（t179、t177）
- implement を開いたまま別のチケットの見直し・手直しをした（t254 と t249〜t251、t248 と t247、t310 と t318）

警告では値が直らないので、数える側で「1 つの応答は、その応答より前に ID が出ていて、まだ開いている Run のうち、いちばん新しく始まったものだけに数える」と決めて防ぐ。それぞれの Run の finish は、ファイルの中のほかの Run の ID と、閉じた Run の開始・終了の時刻を見れば、ほかの Run と相談せずに同じ答えを出せる。

## 受け入れ条件

- [x] Claude Code の Adapter が、同じファイルで期間が重なる Run の応答を、いちばん新しく始まった開いている Run にだけ数える（先に閉じた側・後に閉じた側のどちらでも、1 つの応答を 2 つの Run に数えないことをテストで確かめる）
- [x] Codex の Adapter でも同じ規則で、重なった区間の累計の差を除く
- [ ] 過去の 11 組を run refresh で取り直し、同じ応答を 2 つの Run に数えていない
- [x] run start が、このマシンで同じ agent の Run が開いたままのとき警告する（記録はする）
- [x] dg guide review が、見直し役は 1 つの Run で 1 枚のチケットを見ると書いている
- [x] ADR-005 の「会話記録を Run に結び付ける」に規則と理由を書き、mise run check が通る
