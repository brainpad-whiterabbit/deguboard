## 概要

フックの仕組み（t530）は、フックの入力の項目（`tool_response.agentId`・`agent_transcript_path` など）、サブエージェントの記録のパスの規則、記録の書き出しの順序といった、Claude Code が約束していない内部の形に依存している。版が上がって壊れると、気づくのは Run の数字が欠けてからになる。`dg hooks check` で、設定にフックが入っているか、ハンドラ（`dg hook <event>`）が動くか、直近のフックの入力に要る項目があったか（ハンドラが受け取った入力の項目の有無を `deguboard-local/` に残して読む）を診断し、欠けていれば何が壊れたかを警告する。`dg validate` からも同じ診断を呼ぶかは実装時に決める。

## 受け入れ条件

- [x] `dg hooks check` が、Claude Code の設定に dg のフックが入っているか（イベントごと）と、ハンドラのコマンドが動くかを報告する
- [x] ハンドラが受け取った直近の入力について、要る項目（PostToolUse：`tool_input.prompt`・`tool_response.agentId`。SubagentStop：`agent_id`・`agent_transcript_path`。SessionStart：`transcript_path`）の有無を記録し、`hooks check` が欠けている項目を警告する
- [x] 記録に残すのは項目の有無と時刻だけで、値（prompt の中身・パス・メッセージ）は残さない（MT-4）
- [x] guide-overview の `dg hooks install` の案内に `hooks check` を添え、`mise run check` が通る
