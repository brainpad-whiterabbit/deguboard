## Summary

rebase が時間切れになると GitError が投げられ、rebase --abort に届かない。途中の HEAD が基準に記録され、次のコマンドでは空の競合（ファイル名のない SYNC_CONFLICT）になる。sync は作業ツリーが汚れていると途中の HEAD の上でコミットし、その後の abort でそのコミットを失う恐れがある。dg のプロセスが殺されたときは、外の変更（OUTSIDE_CHANGES）と誤って報告する。fetch と push の時間切れは届かない（unreachable）ではなく GitError で落ちるので、claim のコミットだけがローカルに残る。

## Acceptance criteria

- [x] rebase が時間切れや例外で終わっても、rebase --abort をしてから失敗を返す
- [x] 書き込みの入口で rebase の途中の状態を見つけたら、取り消すか、何が起きたかと直し方を示して止まる。外の変更とは報告しない
- [x] fetch と push の時間切れは、リモートに届かないときと同じ扱いにする
- [x] 上の 3 つをテストで示す
