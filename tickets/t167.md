## 概要

見直し（audit-s5、観点：アーキテクチャ／文書と実装）の指摘。core の出力の設計が要るので、Iteration には入れない。

- 「着手できるか」を 3 か所で組み立てている。core は after の待ちを plan.show の waiting にだけ出す（packages/core/src/commands/plan.ts:214）。web は after と deps_done から待ちを自分で求め直す（packages/web/src/components/plan-graph.ts:123・152–195 の waitingOn・remainingWaits）。エージェントは guide-work.md の手順どおり、plan show の waiting と ticket show の deps_done を自分で合わせる
- 消したチケットを after が指すと、core は待ちに残し、web は「着手可」と出す
- 帯の「次」（planProgressLine）は依存グラフの段の順で選ぶが、guide-work は items の順で先のものから選ぶ。たとえば items が [A(after B), B, C] で B が done なら、帯は C を、エージェントは A を選ぶ

## 受け入れ条件

- [ ] core のコマンドの出力（plan.list か plan.show）に、Plan のチケットの残りの待ちの相手と着手可が載っている
- [ ] web は着手可・待ちの計算を持たず、その値を読んで表示する
- [ ] guide-work の手順が、その値を見て次に着手するものを選ぶ
- [ ] 帯の「次」と手順が選ぶ「次」が同じ順で決まり、その順が requirements（UI-13 か WF の節）に書かれている
- [ ] 消したチケットを after が指すときの扱いが、画面と CLI で同じになっている
