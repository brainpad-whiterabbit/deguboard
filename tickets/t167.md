## 概要

見直し（audit-s5、観点：アーキテクチャ／文書と実装）の指摘。core の出力の設計が要る。

- 「着手できるか」を複数の所で組み立てている。core は after の待ちを plan.show の items[].waiting にだけ出す（packages/core/src/commands/plan.ts:215）。web は after と deps_done から待ちを自分で求め直す（packages/web/src/components/plan-graph.ts:123 の waitingOn・153–171 の remainingWaits）。帯の planProgressLine（plan-graph.ts:178–200）と、カンバン・バックログの行の「着手可・待ち」の印（components/row-end.tsx:26–42、t163）がこれを使う。エージェントは guide-work.md の手順どおり、plan show の waiting と ticket show の deps_done を自分で合わせる
- web の planState（plan-graph.ts:26–31）は PlanRow.progress を使わずに完了を数え直す（t204 から移した）
- 消したチケットを after が指すと、core は待ちに残し、web は待ちから外して「着手可」と出す（plan-graph.ts:97・101）
- 帯の「次」は依存グラフの段の順（plan-graph.ts:185）で選ぶが、guide-work（52 行）は items の順で先のものから選ぶ。たとえば items が [A(after B), B, C] で B が done なら、帯は C を、エージェントは A を選ぶ
- plan-graph.ts の FINISHED は t186 も扱う。待ちの計算を消すときは t186 と順を合わせる

## 受け入れ条件

- [ ] core のコマンドの出力（plan.list か plan.show）に、Plan のチケットの残りの待ちの相手と着手可が載っている
- [ ] web（plan-graph.ts・row-end.tsx）は着手可・待ちの計算を持たず、その値を読んで帯とカンバン・バックログの行に出す
- [ ] web の Plan の完了の判定（planState）は Plan の progress から決める
- [ ] guide-work の手順が、その値を見て次に着手するものを選ぶ
- [ ] 帯の「次」と手順が選ぶ「次」が同じ順で決まり、その順が requirements（UI-13 か WF の節）に書かれている
- [ ] 消したチケットを after が指すときの扱いが、画面と CLI で同じになっている
