## Summary

s37 の振り返りの Try。t990 と t996 の受け入れ条件は `dg next` が検査の結果を読むと書いていたが、packages/core/src/commands/next.ts は検査の結果を読まず、リリース前の見直しで t1000 として直した（review の escaped-defect-rate は s37 で 15%（2/13）、origin_cause はどちらも ticket）。今の起票の補足（docs/guide-notes/import.md、t994）は節の番号・ファイル・関数の名前を確かめるよう案内するが、実装の振る舞い（何を読むか・何を呼ぶか・既定の値）には触れていない。補足を、受け入れ条件と範囲に書く実装の振る舞いもコードを読んで確かめてから書くよう広げる。s38 以降で origin_cause が ticket の漏れを 0 件にするのがねらい。

s38 の振り返り（retro-s38）で、起票の前提が事実と食い違う例が続いた。リリース前の見直しで起票した t1018（git の項目にはボタンもコマンドもないと書いたが「確かめ直す」のボタンがある）、t1019（README.md は light の検査で足りるとしたが、light の検査に入らない test/scripts/vscode-readme.test.ts が読む）、t1020（@types/vscode 1.123 系は npm に存在しない）。どれも実装か計画の途中で人の判断が要った。補足が確かめる対象を、コードの振る舞いに加えて、外の版や設定・テストが読むファイルなどの事実にも広げる。s39 で、前提の誤りで人に判断を仰いだチケットを 0 件にするのがねらい。

## Acceptance criteria

- [ ] dg guide import に差し込む補足（docs/guide-notes/import.md）が、受け入れ条件と範囲に書く実装の振る舞い（何を読むか・何を呼ぶか・既定の値）を、起票のときにコードを読んで確かめてから書くよう案内している
- [ ] 補足に、根拠（t990・t996 の受け入れ条件と next.ts の食い違いを t1000 で直したこと、s37 の escaped-defect-rate 2/13）が書かれている
- [ ] 補足が、受け入れ条件と範囲の前提にする外の事実（依存の公開された版、どのテストや検査がそのファイルを読むか）も、起票のときに確かめてから書くよう案内し、根拠に s38 の t1018・t1019・t1020 が書かれている
