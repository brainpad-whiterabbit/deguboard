## Summary

リリース前の見直し（構成の観点）の指摘。振る舞いは変えない整理。

- データのリモートの決め方（init で受けた名前 > config の `git.data_remote` > コードのリモート）が、`packages/core/src/commands/context.ts` の openContext と `packages/core/src/storage/remote-name.ts` の resolveConfigDataRemote に別々に書かれている。`model/config.ts` の `dataRemoteNameOf` が同じ規則を持つが、openContext は使っていない。remote-name.ts のコメントは「openContext と同じ決め方」と書き、揃えるのを人の記憶に頼っている
- `git/sync.ts` の `remoteRef` は `git/repo.ts` の `dataRemoteRef` をそのまま呼ぶだけの別名で、`git/facts.ts` のローカル変数 `remoteRef`（コードのリモートの ref）と紛らわしい
- 既定のリモート名 `"origin"` が `context.ts` と `commands/setup.ts` に別々に書かれている
- `storage/remote-name.ts` の `readDataTarget` は、同じファイルとテストだけが使う export になっている

## Acceptance criteria

- [x] データのリモートの決め方が 1 つの関数にあり、openContext と Stop のフックの速い経路の両方がそれを使う
- [x] データの ref の名前が 1 つになり、既定のリモート名が 1 か所で決まる
- [x] テストのためだけの export がなくなるか、そのことがコメントに書いてある
- [x] 既存のテストが通る（振る舞いは変えない）
