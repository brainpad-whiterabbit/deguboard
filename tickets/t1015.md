## Summary

見直し（s38）の観点「構成」。次の重なりと使われない公開がある。

- packages/cli/src/program.ts の selfMergeDriver と packages/cli/src/hooks.ts の selfCommand が、node と dg の起動ファイルを同じように組む（selfCommand は実パスに解き、selfMergeDriver は解かない）
- シェルの引数を囲む処理が packages/core/src/git/merge.ts の shellQuote、packages/core/src/commands/client.ts の shellArg、packages/vscode/src/terminals.ts の quote の 3 つある（shellArg だけが先頭の = を囲む）。あわせて setup-check.ts が Webview の取り決めを置く client.ts から initCommandLine を値として取り込み、client.ts は setup-check.ts から型を取り込むので、依存が両向きになっている
- packages/core/src/commands/index.ts が公開する hookInstallStateOf・HookInstallState・SetupCheckOptions・SetupItemId を、core の外で使う箇所がない

web の initCommandLine の写し（テストで core と同じかを確かめている）は、web が core から型しか取り込めないため意図して置いているので対象にしない。

## Acceptance criteria

- [x] マージドライバとフックが dg を起動するコマンドを、1 つの関数で組む
- [x] シェルの引数を囲む処理が core の 1 つの関数にまとまり、merge.ts・client.ts・vscode の terminals.ts がそれを使う（先頭の = も囲む）
- [x] setup-check.ts と client.ts の間で、値の取り込みが両向きにならない
- [x] 上に挙げた core の外で使われない公開を外すか、公開する理由をコメントに書く
