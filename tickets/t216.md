## 概要

t206 は PR の経路（ST-6）だけを直した。gh を使わず Git の事実だけで照合すると、前の作業でマージ済みのブランチがリモートに残っているとき、 同じ名前で claim した直後に branch_pushed が真・先端が base の真の祖先となり branch_merged が真になって done に進む（packages/core/src/git/facts.ts の collectBranchFacts）。 ローカルに残った古いブランチを checkout して push した場合も同じ。入口（ticket.claim と ticket.update の branch 変更）で止める。 照合の側で「先端のコミット日時が branch_at より古ければ merged にしない」守りは、時計のずれに頼るので採らない（2026-11-02 に人と決定）

## 受け入れ条件

- [ ] 記録しようとするブランチの ref（ローカルか <remote>/<branch>）が残っていて先端が base の真の祖先なら、ticket claim と ticket update --branch が BRANCH_IN_USE で拒否し、別の名前にするか古いブランチを消すよう案内する
- [ ] done・abandoned 以外の別のチケットが同じ branch を記録しているときも拒否する
- [ ] ref がない・先端が base と同じ・base にない作業があるときは今までどおり通る
- [ ] 上の 3 つを、一時ディレクトリの bare リモート付きのリポジトリでテストする
- [ ] requirements.md に約束を一文足し、ADR-004 にこの対策と、採らなかったコミット日時の案（claim の後に古い ref が push し直される形は残る）を書く
- [ ] `mise run check` が通る
