## 概要

チケットの作業の段階（claimed → implemented → reviewed(n) → fixed(n) → ready → merged、と blocked・waiting_human）を、Run・PR・Git の事実と Plan から都度求め、保存しない（Plan の進捗と同じ考え）。`ticket show` に `stage` を足し、`dg next <ticket>` が「次にやる 1 手」（起動する役・渡す brief・その後に親が呼ぶ dg のコマンド・人に聞く承認）をデータで返す。修正ループの上限（手直し 2 回）はここで数え、超えたら人を待つ段階にする。サブエージェントが質問で止まって「止まって待っている」印の付いた開いた Run（t541）があるチケットも `wait_human` にし、親はその質問を人に伝えて答えを続きとして送る手になる。親の LLM は `dg next` を呼んで 1 手を実行するだけになる。

## 受け入れ条件

- [x] `ticket show` の `stage` が、Run（実装・見直し・手直しとその結果、止まって待っている印）・PR（draft・open・merged）・ブランチの事実・Plan の待ちから求まり、求め方のテストがある
- [x] `dg next <ticket>` が次の 1 手を返す。1 手は種類（implement・review・fix・ready・wait_merge・wait_human・done）と、その手に要るデータを持つ。上限を超えた手直しと、止まって待っている Run のあるチケットは `wait_human` になる
- [x] `dg next` は読み取りだけで、CLI・HTTP・MCP から同じ結果を返す（CL-6・AG-4）
- [x] requirements.md に段階と次の 1 手の約束が足され、ADR-003 の決定に合い、`mise run check` が通る
