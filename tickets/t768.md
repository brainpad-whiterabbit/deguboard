## Summary

PreToolUse のフックは Bash・Edit・Write のたびに走る。判定は 1 ms もかからないが、@deguboard/core の入口から全部（core の 96 ファイル・zod・yaml・commander）を読み、全コマンドを組み立てるので、1 回に約 225 ms かかる（静かなとき）。判定と記録を、重い依存を持たない core のモジュールに切り出し、bin/dg.js は main を読む前に PreToolUse を処理する。設定に書くフックのコマンドは変えない。計測用の試作では約 54 ms だった。

## Acceptance criteria

- [x] PreToolUse の判定と記録（hook-inputs・hook-sessions）は zod・commander・yaml に依存しない core のモジュールにあり、今の hook コマンドも PreToolUse ではそれを呼ぶ
- [x] bin/dg.js は dg hooks install が書く PreToolUse の呼び出しを CLI 全体を読まずに処理し、ほかの argv と扱わない入力（JSON でない・別のツール・初期化していないなど）は今の経路に回す
- [x] 拒む Bash・拒む書き込み・通す Bash・gh pr merge・初期化していない・git の外・JSON でない入力で、速い経路と今の経路の標準出力・標準エラー・終了コード・記録が同じことをテストで確かめる
- [x] 軽いモジュールの静的な import が node の組み込みと許したファイルだけであることをテストで確かめる
- [x] dg hooks install が書くコマンドの形と、速い経路が受け持つ argv が同じ定義から来る
- [x] main の作業ツリーで ls の Bash の PreToolUse を 5 回測り、中央値が 100 ms 以下であることを PR の本文に書く
