## 概要

ADR-004「human と agent の区別は申告に基づく」と ADR-005「Run の ID を最初に含む会話記録に結び付け、ID が出た後の応答を数える」を、harness のフックが環境と記録のパスで確定させる決定に書き換える。速度低下の調査で、見直し役が見直しを終えた後に `run start` を呼ぶため見直しの Run の使用量が約 2 割しか入らないこと（成功した見直し 368 件のうち 48 件が出力 300 トークン未満）、`--actor` の申告が忘れられると `by: [human]` と `actor.human_only` が素通りすることが分かった。

決定の形（t529・t530・t534 の前提）：サブエージェントの Run は、起動の直後のフック（PostToolUse の Agent）が、その呼び出しの prompt と agentId から brief の印 `deguboard: ticket=<id> step=<step>` を読んで、埋まった Run を開く。終了のフック（SubagentStop）がサブエージェント自身の記録の印で照合し、そのファイル全体から使用量を取って閉じる。結果は step ごとの事実の規則で決める。見直しと手直しの Run の開閉はサブエージェントの手順から外す。親が自分で進める Run は claim が開き、記録の場所は SessionStart の環境から付く。閉じ損ねは SessionEnd で見直しと手直しだけ拾う。フックは起動も監視もしないので EX-1 は保つ。フックのない製品では今の申告と推測に落ちることも決定に書く。

## 受け入れ条件

- [ ] ADR-004 の「主体は申告に基づく」が、Adapter のフックが環境（`DEGUBOARD_ACTOR`）で決め、フックのない製品では申告に落ちる決定に書き換わっている
- [ ] ADR-005 の「会話記録を Run に結び付ける」が、Run に残した記録の場所（セッション ID と記録のパス）から数え、場所がなければ今の推測に落ちる決定に書き換わっている。採らなかった案に「ID が最初に出た記録」を移している
- [ ] ADR-005 に、サブエージェントの Run は起動の直後のフック（PostToolUse の Agent）が prompt の印と agentId から開き、終了のフックが記録で照合して閉じること、結果は step ごとの事実の規則で決めること、見直しと手直しの Run の開閉はサブエージェントの手順から外すことが決定として書かれている。採らなかった案に「サブエージェントが自分で run start する（今まで）」と「終了のフックが後付けで作る（実行中が見えず、二重起動を拒めない）」がある
- [ ] requirements.md の AG-1・RN-1・RN-5・MT-2 が新しい決定と矛盾しない
- [ ] docs/adr/README.md の更新日が合い、`mise run check` が通る
