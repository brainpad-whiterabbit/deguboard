## 概要

ADR-004「human と agent の区別は申告に基づく」と ADR-005「Run の ID を最初に含む会話記録に結び付け、ID が出た後の応答を数える」を、harness のフックが環境と記録のパスで確定させる決定に書き換える。速度低下の調査で、見直し役が見直しを終えた後に `run start` を呼ぶため見直しの Run の使用量が約 2 割しか入らないこと（成功した見直し 368 件のうち 48 件が出力 300 トークン未満）、`--actor` の申告が忘れられると `by: [human]` と `actor.human_only` が素通りすることが分かった。フックは起動も監視もしないので EX-1 は保つ。フックのない製品では今の申告と推測に落ちることも決定に書く。

## 受け入れ条件

- [ ] ADR-004 の「主体は申告に基づく」が、Adapter のフックが環境（`DEGUBOARD_ACTOR`）で決め、フックのない製品では申告に落ちる決定に書き換わっている
- [ ] ADR-005 の「会話記録を Run に結び付ける」が、Run に残した記録の場所（セッション ID と記録のパス）から数え、場所がなければ今の推測に落ちる決定に書き換わっている。採らなかった案に「ID が最初に出た記録」を移している
- [ ] requirements.md の AG-1・RN-1・MT-2 が新しい決定と矛盾しない
- [ ] docs/adr/README.md の更新日が合い、`mise run check` が通る
