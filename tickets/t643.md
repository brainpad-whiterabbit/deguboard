## 概要

t638 の PR #582 で `dg pr merge t638 --delete-branch` を呼んだ。gh pr merge は「Base branch was modified」で失敗し（main に別の PR が入って競合していた）、マージはされなかった。それでも作業ブランチの worktree は消えていた。`dg pr merge` は、gh がローカルのブランチを消せるように、gh を呼ぶ前に worktree を消す（packages/core/src/commands/pr.ts の removeBranchWorktree）。そのため、マージに失敗すると、rebase して直すための worktree がない状態で返る。ブランチはリモートに残るので作業は失われないが、手で `git worktree add` し直して、準備のコマンドも回し直す必要があった。

## 受け入れ条件

- [ ] `--delete-branch`（か config の merge.delete_branch）でマージが失敗したとき、作業ブランチの worktree が残るか、元の場所に戻されて作業を続けられる
- [ ] マージが成功したときは、今までどおりリモートとローカルの作業ブランチと worktree が消える
- [ ] マージの失敗で worktree をどう扱ったかが、エラーか警告に出る
- [ ] 上の 3 つをテストで確かめている
