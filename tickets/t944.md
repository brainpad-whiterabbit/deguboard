## Summary

見直し（s35）の観点「テスト」。画面の読み（`store.tsx` の `refreshStatus`、15 秒ごとの読みと書き込みの後の reload）と `dg` の読みのコマンドが走らせる `git status --porcelain` は、index を新しくするために、データの worktree の `.git/worktrees/deguboard/index.lock` を一瞬取る。`withLock` が直列にするのは dg の書き込みどうしだけなので、同時に走る dg の書き込み（`git add`・`commit`）が `index.lock: File exists` で落ちる。s35 では、エージェントの `ticket update --pr` が 1 回これで落ち、`mise run test:vscode` も 2 回落ちた（回し直すと通った）。画面を開いたままエージェントが dg で書くと、確率で失敗する。

## Acceptance criteria

- [x] dg が走らせる読みの git（status など、書き込みを伴わないもの）が、データの worktree の index.lock を取らない
- [x] 読みの status を繰り返し走らせながら dg の書き込みを続けても、書き込みが index.lock で落ちないことをテストが確かめる
- [x] test/vscode/host.ts のコメントのうち、Git の読みについて古くなった記述を直す
