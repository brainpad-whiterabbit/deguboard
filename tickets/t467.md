## 概要

設定画面のチームのタブで、既定が空でない文字列の項目（git.remote・worktree.root など CONFIRM_KEYS のもの）を空にして保存すると、確認の文が「`` にする」と崩れる。実際には core が既定（origin など）に戻す。確認の文を、既定に戻すことがわかる文にする。t438 より前からある振る舞いで、p62 の t438 の見直しで出た範囲の外の指摘。clears-to-default のチケットで core が返す値を使えるなら使う。

## 受け入れ条件

- [ ] チームのタブで既定が空でない文字列の項目を空にすると、確認の文が既定の値に戻すことを示す（例：「既定の origin に戻す」）
- [ ] 空でない値に変えるときの確認の文は今のまま
- [ ] 日本語と英語の両方の表示言語で文が崩れない
- [ ] 上をテストで確かめる
- [ ] mise run check が通る
