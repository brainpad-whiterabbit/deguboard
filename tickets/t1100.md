## Summary

次の 3 ファイルは、雛形を使わず `createFixture()` から 1 件ごとに dg init をして、チケット・claim・作業ブランチの push まで準備している（2026-11-17、main ae436adf、全体のテストの中の時間）。

- `packages/core/src/git/merge.test.ts`（31.9 秒・40 件）：`twoClones` が件ごとに、clone A で init → ticket create → sync → clone B で init
- `packages/core/src/commands/pr.test.ts`（26.1 秒・34 件）：`prepared` が件ごとに、init → workflow set → ticket create → claim → checkout・commit・push → 偽の gh
- `packages/core/src/commands/orphan-review.test.ts`（21.3 秒・28 件）：`prepared` が件ごとに、init → ticket create → claim → checkout・commit・push → 偽の gh → ticket update

dg のコマンド 1 回は git を何度も起動する（一時リポジトリで数えると init 26 回、claim 23 回、sync 23 回、ticket create 19 回）。pr.test.ts の 1 件は git を平均 117 回起動し、そのうち約 90 回が準備にあたる。同じ準備をファイルごとに 1 度だけ `createFixtureFrom("prepared", …)` で済ませている gate.test.ts は 13.1 秒。

準備をファイルごとに 1 度だけ作る雛形に寄せ、各件は写すだけにする。雛形の仕組み（`packages/core/test/helpers/git-fixture.ts` の `createFixtureFrom`、`packages/core/test/helpers/commands-context.ts` の `initializedFixture`）はもうあるので、新しく作るものは要らない。

## Acceptance criteria

- [ ] merge.test.ts・pr.test.ts・orphan-review.test.ts の各件が、準備で dg init を呼ばず雛形から写す（init 自身を確かめる件を除く）
- [ ] 3 ファイルのテストの件数と、確かめている内容を減らさない
- [ ] 雛形を作った時刻が準備に残るところ（pr.test.ts の `ctx.now = () => new Date(Date.now() + 60_000)`、orphan-review.test.ts の `later(-120)`）で、件の中の時刻との前後関係が雛形を作った時刻によらない理由を、テストのコメントに書く
- [ ] 3 ファイルの時間と全体のテストの時間について、同じ端末で測った変更前後を PR に載せる
