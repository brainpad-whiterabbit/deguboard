## 概要

t534 では、変更の少ない暫定の形として fix の文に印を置かず、サブエージェントが `ticket claim --retry-reason` で手直しの Run を開く（AG-9）。implement・review・fix をすべて印で開く形にそろえる。

- fix の文に印 `step=<opens_on: reclaim の step>` を置く
- フックは起動のとき、開いたままの前の手直しの Run を区切りとして閉じてから、新しい Run を開く。最後の push の時刻で success、別のセッションのものは interrupted にする（今の reclaim と同じ規則）。開いている手直しの Run はいつも 1 本になる
- サブエージェントは、新しい `run retry-reason <ticket> --reason …` で理由を書き足す。チケットと step で開いている Run を引くのは、`run review-result` と同じ形。Run がまだなければ（前景の起動）保留にして、フックが閉じるときに結び付ける
- 自分で開いた Run の扱い（hook.ts の「移行期の経路」）が要らなくなる

背景：claim の側からは、開いている手直しの Run が、今フックが開いたものか、ひとつ前の残りかを見分けられない。サブエージェントの Bash には DEGUBOARD_SESSION・DEGUBOARD_TRANSCRIPT が届かず、ID で照らすこともできない。そこで、区切る判断を「理由を書く時点」から「起動の時点」へ移す。
