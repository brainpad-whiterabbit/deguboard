## 概要

観点：文書と実装。(1) guide-work は「worktree は worktree の場所に手で作る」と書くが、作れなかったとき claim の worktree は null で、警告にも場所がない。(2) guide-all の見出し「マージは人が行う」が、auto.merge が true なら自動でマージすることと合わない。(3) dg pr merge の --delete-branch は付けるだけの旗で、config の merge.delete_branch: true をその回だけ打ち消せない。(4) CL-5 と dg guide --help の「ない節は一覧を返す」が、実際は使い方の誤り（終了コード 2）でエラーの文に一覧を入れる動きと言い回しがずれる。

## 受け入れ条件

- [x] worktree を作れなかったときに、どこに作ればよいかが guide か警告の文から分かる
- [x] guide-all のマージの見出しが auto.merge の扱いと合っている
- [x] config の merge.delete_branch が true のとき、その回だけブランチを消さない手段があるか、できないことが help に書かれている
- [x] ない節を指定したときの扱いが、CL-5・dg guide --help・実装で同じ言い回しになっている
