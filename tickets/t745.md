## Summary

dg serve は Origin・Host・Content-Type のどれも見ていない。dg serve を動かしている間に悪意のあるサイトを開くと、Content-Type が text/plain の POST（事前の確認が要らない要求）で config.set を呼ばれ、worktree.setup に任意のコマンドを入れられる。続けて ticket.claim を送られると、そのコマンドがこのマシンで動く。config.set は commit して push するので、pull したほかの人の claim でも動く。Host を見ていないので DNS rebinding でも突かれる。

## 採るやり方

- Host・Origin・Content-Type の 3 つを見る。呼ぶ側（画面・テスト・test/layout・scripts/record-gifs.mjs）は同じオリジンから application/json で呼んでいるので変えずに済む。VS Code 拡張は postMessage、dg mcp は stdio なので関わらない
- Host は名前だけを見て、ポートは比べない。DNS rebinding はドメイン名でしか成り立たないので IP そのものは通してよく、ポートを転送したとき（VS Code Remote など）と --host 0.0.0.0 のときも開ける
- Origin は要求の Host と比べる（Host を先に確かめるので安全で、転送した画面からも書ける）
- 採らない：起動のたびに作る合言葉（dg open・録画・配置のテスト・Playwright MCP の手順をすべて変えるので、開発用の道具には重い）。HTTP からの config.set などを止める（画面からの設定の書き込み（ADR-027）を壊す）

## Acceptance criteria

- [x] Host の名前が localhost・IP そのもの（127.0.0.1・[::1] など）・--host で指定した名前のどれでもない要求を 403 で断る。ポートは比べない（ポートを転送しても開けるように）
- [x] Origin があり、要求の Host と違う要求（Origin: null を含む）を 403 で断る
- [x] Content-Type が application/json でない POST を 415 で断る
- [x] 断った要求で config.set が書かれないこと、同じオリジンから application/json で呼べば今までどおり動くこと、ポートの違う Host と Origin の組（転送）でも動くことをテストで示す
- [x] requirements.md の UI-8 に、別オリジンとほかのホスト名からの要求を断ることを 1 文で足す
- [x] ADR-027 の「localhost に閉じれば、認証なしでも他のマシンから触れない」という理由を、ブラウザを踏み台にした要求は Host と Origin で断る、という理由に書き換える
- [x] dg serve のヘルプに、別オリジンとほかのホスト名からの要求を断ることを足す。断ったときは英語の文とコード付きの JSON を返す
