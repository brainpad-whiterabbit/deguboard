## Summary

dg serve は Origin・Host・Content-Type のどれも見ていない。dg serve を動かしている間に悪意のあるサイトを開くと、Content-Type が text/plain の POST（事前の確認が要らない要求）で config.set を呼ばれ、worktree.setup に任意のコマンドを入れられる。続けて ticket.claim を送られると、そのコマンドがこのマシンで動く。config.set は commit して push するので、pull したほかの人の claim でも動く。Host を見ていないので DNS rebinding でも突かれる。

## Acceptance criteria

- [ ] Host がバインド先（127.0.0.1・localhost・[::1]・--host で指定した名前）とポートに合わない要求を 403 で断る
- [ ] Origin があり、自分のオリジンと違う要求を 403 で断る
- [ ] Content-Type が application/json でない POST を 415 で断る
- [ ] 断った要求で config.set が書かれないことと、同じオリジンから application/json で呼べば今までどおり動くことをテストで示す
- [ ] requirements.md の UI-8 に、別オリジンとほかのホスト名からの要求を断ることを 1 文で足す
