## Summary

見直し（s35）の観点「文書と実装」。t936 で、guide-release の手順 3 がリリースを 2 つのチケット（版を上げる PR のチケットと、タグと公開のチケット）に分け、手順 1 のあとで `<S>` に起票するようにした。一方 `dg flow next` は、`<S>` のチケットがすべて終わっているときだけ release（規則 7）を返し、そうでなければ規則 5 の「open な Plan にない todo」で plan を返す。そのため、dgall がリリースの段の途中で止まって再開すると plan の段に回され、release に戻れない。公開のチケットが in_progress の間も release が返らない。flow と guide のどちらに寄せるか（リリースのチケットを見分けて release の段の作業として扱うか、起票の時期や置き場所を変えるか）は計画で決める。設計の判断が要るので、s35 の外に置く。

## Acceptance criteria

- [ ] リリースの段でリリースのチケットを起票した後も、`dg flow next` がリリースの段を返し、公開のチケットが終わるまで plan の段に戻らない
- [ ] guide-release と guide-all の手順が、決めた扱いと合っている
- [ ] 上の振る舞いをテストが確かめる
