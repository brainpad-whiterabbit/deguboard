## Summary

使う人には、dg の全体の構成と、Run がどこからどこまで記録されるのか（親セッション・harness のフック・dg・サブエージェントの役割）が見えていない。使う人に向けた仕組みの文書 `docs/how-it-works.md` と `docs/how-it-works.ja.md` を足し、README から引く。usage.md は人がする操作の置き場所なので、仕組みの説明は別の文書にする。

## Acceptance criteria

- [ ] `docs/how-it-works.md`（英語）と `docs/how-it-works.ja.md`（日本語）が同じ節の構成で置かれている
- [ ] 「Overview」の節が、全体の構成（Git の中のデータ、Core とその上の CLI・`dg serve`・VS Code 拡張・Web、Skill・`dg guide`・`dg next` で動くエージェント、Run を記録するフック）を 1 枚の図と要素ごとに 1〜2 行の説明で示している
- [ ] 「How Runs are recorded」の節が、Mermaid のシーケンス図で Run ごとの区間を `rect` で囲んで示し、どの Run にも入らない親セッションの作業が見分けられる。図の下に範囲の決まり（印の起動で開き step を終えた事実で閉じる、使用量はサブエージェントの会話記録だけ、フックが届かないと記録されない）が数行で書かれている
- [ ] パッケージの依存の規則・ADR-025 と ADR-033 の判断・要件の細部を写さず、リンクで引いている
- [ ] README.md と README.ja.md から how-it-works にリンクしている
- [ ] ADR-001 の「正本と各文書の書く範囲」の表と本文に、how-it-works の書く範囲（書く・書かない）が足されている
