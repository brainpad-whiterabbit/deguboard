## Summary

使う人には、dg の全体の構成と、Run がどこからどこまで記録されるのか（親セッション・harness のフック・dg・サブエージェントの役割）が見えていない。使う人に向けた仕組みの文書 `docs/how-it-works.md` と `docs/how-it-works.ja.md` を足し、README から引く。usage.md は人がする操作の置き場所なので、仕組みの説明は別の文書にする。

## Acceptance criteria

- [x] `docs/how-it-works.md`（英語）と `docs/how-it-works.ja.md`（日本語）が同じ節の構成で置かれている
- [x] 「Overview」の節が、アーキテクチャの層（使う人・UI・入口・Core とそのモジュール・保存・外部）と依存と呼び出しの向きを示す 1 枚の図と、要素ごとに 1〜2 行の説明を持っている。図は手で描いた SVG のファイル（日本語版と英語版の 2 つ、`docs/images/` に置く）で、GitHub のライトとダークのテーマのどちらでも読める
- [ ] 「How Runs are recorded」の節が、Mermaid のシーケンス図（フックの参加者は「Hooks (Claude Code)」）で Run ごとの区間を `rect` で囲んで示し、どの Run にも入らない親セッションの作業が見分けられる。図の下に範囲の決まり（印の起動で開き step を終えた事実で閉じる、使用量はサブエージェントの会話記録だけ）が数行で書かれ、描かない場合が 1 行ずつの注記と usage.md へのリンクで添えられている（low・free には見直しの Run がない、フックが届かないと Run が残らない、使用量は `metrics.read_transcripts` が true のときだけ数える）
- [x] パッケージの依存の規則・ADR-025 と ADR-033 の判断・要件の細部を写さず、リンクで引いている
- [x] README.md と README.ja.md の Tips（ヒント）の上に「How it works」（仕組み）の節があり、一言と GitHub の絶対 URL のリンクを置いている。「Documentation」（ドキュメント）の一覧にも how-it-works があり、英語で書かれた文書についての一文が今の文書に合っている
- [x] ADR-001 の「正本と各文書の書く範囲」の表と本文に、how-it-works の書く範囲（書く・書かない）が足されている
