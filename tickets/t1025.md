## Summary

流れではない管理の操作を、`workflow.yaml` の governance（delete・config・reassign・epic・create）と、緩めると守りが崩れる Core の固定で判定する。

## Acceptance criteria

- [ ] チケットを消す・チームの設定を変える・担当の付け替えと他人の claim を外す・Epic を閉じる/再開する・起票が、`governance` の値で判定されることがテストで示されている
- [ ] `hooks uninstall`・段を下げる操作は agent の呼び出しが拒否され、`workflow set` と品質ゲートを越える `pr merge` はいつも人の承認（`--approved-by`）を求めて承認者を履歴に残す（`--auto` でも聞かずには書けない）。`workflow.yaml` では緩められない
- [ ] config の `actor.human_only` と `merge.approval_overrides` がなくなっている
- [ ] ADR-009・ADR-026 と requirements の 5.10・EP-4・EX-10・WF-6 が直り、CLAUDE.md の「人の指示があるときだけ行う」操作の文が、dg がまだ判定しない Iteration の閉じる・再開する（t1026）を除いて消え、CLAUDE.md と development.md の `merge.approval_overrides` を指す文が直っている
- [ ] 品質ゲートを越える `pr merge` は、PR の状態・衝突・判定した先端など今も越えられない条件を除き、人の承認（`--approved-by`）で越えられることがテストで示されている
- [ ] このリポジトリの config から `actor.human_only` が消え、使っている値が `workflow.yaml` に移っている
- [ ] guide と Skill の雛形が `actor.human_only`・`merge.approval_overrides` を指さず、governance と Core の固定で案内し、`workflow set` の承認は前と後を人に見せてから求めるよう案内している
