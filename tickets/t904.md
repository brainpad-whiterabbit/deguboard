## Summary

データ（deguboard ブランチ）の fetch・push の先を、コードのリモート（作業ブランチ・PR の照合・gh）と別のリモートにできるようにする。手元の置き場所（データの worktree・deguboard-local・ロック・マージドライバ・フックの検出）は変えない。

- config に `git.data_remote`（リモートの名前。省くと `git.remote` と同じ。個人の設定で上書きできる）を足す。最初の init はデータを読む前に要るので `dg init --data-remote <名前か URL>` で渡す。URL なら dg がリモートを足してから取り込む
- データの操作（同期・書き込み・仮番号の振り直し・外の変更の検出・init の取り込み・画面の裏の fetch・Stop のフックの速い経路）はデータのリモートを、照合・claim の起点・gate・ブランチの後片付け・brief・PR へのリンクはコードのリモートを使う。`fetchAll` はデータとコードの取得に分ける
- 設定したデータのリモートがそのクローンにないときは、オフライン（SY-6）とみなさない。push の要る操作（sync・claim・作成など）はエラーにして `git remote add` を案内し、読むだけの操作は警告する
- 移行の途中の取りこぼしを防ぐ：取り込んだ config の `data_remote` が、そのコマンドが使っているデータのリモートと違えば push せずに止め、もう一度の実行を案内する

## Acceptance criteria

- [x] `git.data_remote` を設定すると、データの fetch・push は設定したリモートに、作業ブランチと PR の照合はコードのリモートに向かうことを、bare リモートを 2 つ付けた一時リポジトリのテスト（init・sync・claim・照合）で示す。`dg init --data-remote` に URL を渡すと、リモートを足して取り込む
- [x] `git.data_remote` を省いた既存のリポジトリは、今と同じ振る舞いのまま（既存のテストが通る）
- [x] 設定したデータのリモートがないとき、push の要る操作はエラーで `git remote add` を案内し、読むだけの操作は警告で続くことをテストで示す
- [x] 取り込んだ config でデータのリモートが変わったとき、push せずに止めて再実行を案内することをテストで示す
- [x] データのリモートから取り込んだコミットを dg の外の変更とみなさない（Stop のフックの速い経路を含む）ことをテストで示す
- [x] requirements の 5.1・SY-1・5.10 と ADR-034 の「置き場所」の本文、usage.md・usage.ja.md、guide に、別のリポジトリへ移す手順（新しいリポジトリへの push → config の変更を両方に push → 元のブランチを消す）を書く
