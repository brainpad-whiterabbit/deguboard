## 概要

親が自分で直す手直し（もう一度の claim）の Run には、終わりの出来事がない。RN-6 の区切り「同じチケットの次の Run の開始」を sync が後から見つけるまで実行中に見え、t554 では 3 回目の見直しが終わった後も 2 回目の手直しが実行中に見えた（記録の finished_at は正しい）。

区切りの判定は変えず、Run を開く処理（openRun）でその場で閉じる（案 B）。今は前の手直しをその場で閉じるのはもう一度の claim と手直しの起動のフックだけで、見直しの起動と run start は同じ区切りを作っても閉じない。

試作（main 823f010 に入れてコミットしていない）で、mise run check が通ることと、一時リポジトリで t554 の流れを再現して見直しの起動で閉じることを確かめた。試作の途中で、前景の起動で補った開始の扱いと同じ秒の扱いの問題を見つけた（受け入れ条件 3・4）。検討と実機確認の結果は https://claude.ai/artifact/PZdF3B21Xnre5PNwpafLRW にある。

## 受け入れ条件

- [ ] claim・起動のフック・run start のどこから Run を開いても、openRun が同じチケットの開いている手直しの Run を閉じてから開く。ticket.ts と hook.ts の closePreviousFixRun の呼び出しはなくなる
- [ ] 閉じた結果が sync と同じになる。手直しの step を開くときの別のセッションの手直しは interrupted（ADR-015）、ほかの step を開くときはセッションを問わず success。finished_at は RN-6 の決め方
- [ ] 前景の起動で補った開始が手直しの開始より前なら閉じない。手直しと同じ秒の開始は区切りに数える
- [ ] sync の fixRunBoundary も、手直しと同じ秒に始まった次の Run を区切りに数える
- [ ] テストがある：見直しの起動のフックと run start が同じセッション・別のセッションの手直しを閉じる、前景の補った開始が手直しの前と後、同じ秒（openRun と sync の両方）
- [ ] ADR-018 の「手直しの起動だけが前の手直しを閉じる」を置き換える ADR があり、RN-5・RN-6 と、関係するコマンドのヘルプ（sync・hook・ticket claim）が新しい振る舞いに合っている
