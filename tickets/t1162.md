## Summary

t1153 で、見直した SHA に base を 1 回だけ自動でマージした先端なら前の見直しを数えるようになった。マージコミットの親がまたマージコミットのとき（見直し → 取り込み → main が進んで取り込み直し）は数えず、見直しのやり直しが要る。t1152・t1155 で merge の前に main を取り込み直す流れになると、この形は並べて進めるたびに起きる。base だけを取り込んだマージコミットの連なりを、見直した SHA まで辿って数える。

## Acceptance criteria

- [ ] 先端から base だけを取り込んだマージコミットが続き、その先が見直した SHA なら、`dg gate` の review の条件と `dg next` の段階が前の見直しを数える（判定の組み合わせを純粋な関数のテストで網羅する）
- [ ] 連なりの途中に、取り込みの後の別のコミット、tree が自動マージの結果と違うマージコミット、rebase があれば数えない
- [ ] 一時の worktree が判定の後に残らない（git を通すテストで確かめる）
- [ ] `dg gate --help` の review の条件の説明と、requirements.md の RN-10 を直す
