## Summary

t1153 で、見直した SHA に base を 1 回だけ自動でマージした先端なら前の見直しを数えるようになった。マージコミットの親がまたマージコミットのとき（見直し → 取り込み → main が進んで取り込み直し）は数えず、見直しのやり直しが要る。t1152・t1155 で merge の前に main を取り込み直す流れになると、この形は並べて進めるたびに起きる。先端から base だけを取り込んだマージコミットの連なりを辿り、着いた見直した SHA に今の base を 1 回だけ自動でマージして、tree が先端と同じなら数える。段ごとのマージと一括のマージで tree が違う場合は数えない（見直しのやり直しになり、安全側に倒れる）。

## Acceptance criteria

- [x] 先端から base だけを取り込んだマージコミットが続き、その先が見直した SHA で、その SHA に先端の base の親を 1 回自動でマージした tree が先端の tree と同じなら、`dg gate` の review の条件と `dg next` の段階が前の見直しを数える（判定の組み合わせを純粋な関数のテストで網羅する）
- [x] 取り込みの回数によらず、自動マージは 1 回だけ作る（git を通すテストで確かめる）
- [x] 連なりの途中に、取り込みの後の別のコミット、手で解いた競合、rebase があれば数えない
- [x] 一時の worktree が判定の後に残らない（git を通すテストで確かめる）
- [x] `dg gate --help` の review の条件の説明と、requirements.md の RN-10 を直す
