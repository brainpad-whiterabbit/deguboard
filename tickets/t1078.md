## Summary

作成・claim・Iteration の開始などの即時の操作は、push.mode によらず取り込みと push をする（SY-2・SY-3、packages/core/src/git/write.ts の writeLocked）。そのため Git を使うテストは、即時の操作のたびに fetch・merge-base・rebase・push が走る（commands-flow-ticket.test.ts の 37 件で git を 4662 回起動し、そのうちこの 4 つが 150〜180 回ずつ。2026-11-17 に測った）。SY-6 はリモートがなくても同期を除くすべての操作が動くと約束しているので、同期を確かめないテストファイルはデータのリモートのない fixture で回す。

## Acceptance criteria

- [x] データのリモートのない fixture で回すファイルと、リモート付きのまま残すファイル（同期・取り込み・push・リモート・即時の操作の取得を確かめるもの）を、理由とともにテストのコメントに書く
- [x] 即時の操作の push の経路と、push.mode auto の経路を確かめるテストが残る
- [x] 全体のテストの時間と、遅い上位 5 ファイルの時間の変更前後を PR に載せる
