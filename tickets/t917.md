## Summary

振り返りの観点「見直しの効き目」の指標 escaped-defect-rate（見直しをすり抜けて、マージの後に見つかった不具合）は、今は `metrics sources` の refs と後のチケットの本文を読んで数えている。refs は ID が書いてあることしか伝えないので、どれが見つけ損ねかを毎回読み手が判断している。s30〜s33 では、触れていた 25 件の本文を読んで 7 件を見つけ損ねと判断した。

不具合を直すチケットに、どのチケットの変更から出た不具合か（`origin`。元のチケットの ID の配列）と、原因の種類（`origin_cause`。t915 の見直しの指摘の原因と同じ 7 種類）を持たせる。数えるのは、振る舞いの誤りと、変更と同時に直すべきだった文書のずれの両方。チケットのデータの形が変わるので、判断の理由を ADR-029 の本文に書く。

## Acceptance criteria

- [x] チケットに `origin`（元のチケットの ID の配列）と `origin_cause`（t915 と同じ 7 種類）があり、`ticket create`・`ticket import`・`ticket update` が受ける
- [x] 存在しない ID・自分自身の ID・誤った原因の種類は拒まれる
- [x] `metrics sources` がチケットごとに `origin` と `origin_cause` を返す
- [x] ADR-029 の本文と要件の TK の項が、今の形に合っている
- [x] 既存のテストが通る
