## Summary

t1149 では、予約せずに agent が claim すると push の間に別のセッションが予約でき、claim と予約がすれ違う隙間を受け入れてコメントに残した。両方が止まることはないが、予約の約束が一時的に破れる。agent の claim が push の前にロックの中でチケットの予約を書くようにして隙間を閉じる。

## Acceptance criteria

- [x] agent の claim が push の前に予約の判定と書き込みをロックの中で行い、別のセッションの next --reserve と claim がすれ違わない
- [x] ロックを push の間は持たない（ほかのセッションの --reserve を 10 秒の待ちで落とさない）
- [x] push が拒まれてリモートの変更を取り込み直す途中で止まったときも、予約と claim が食い違ったまま残らない（git を通すテストで確かめる）
- [x] 判定の組み合わせを判定の関数のテストで確かめる
