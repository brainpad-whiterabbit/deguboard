## 概要

t417（PR #390）で、同じ会話記録で期間が重なる Run の応答を「いちばん新しく始まった開いている Run」にだけ数える規則を入れた。譲る相手は、自分より後に始まり期間が重なり、そのファイルで ID が開始から 1 分以内に出た Run。ところが、別のファイルで始まった Run の ID を 1 分以内に表示しただけでも相手になり、応答をどちらの Run も数えなくなる。実際に、t276 の review（r20261103-022216-6c83）と t280 の review（r20261103-022217-8d30）は、02:22:19 に始まった別の Run（t275 の implement など）に譲って、2 本とも 0 になる（2026-11-05 の run refresh --dry-run）。このため 2 本は取り直しておらず、二重に数えたまま。

## 受け入れ条件

- [ ] 別のファイルで始まった Run の ID を 1 分以内に表示しただけでは、その Run に応答を譲らない（テストで確かめる）
- [ ] run refresh --dry-run で、t276 と t280 の review の Run の組が、同じ応答を片方だけに数える（もう片方を 0 にし、両方を 0 にしない）
- [ ] t276 と t280 の review の Run を run refresh で取り直した
- [ ] mise run check が通る
