## 概要

ADR と要件が膨らむ一番の入口は起票で、受け入れ条件が最初から「新しい ADR を書く」「RN-5・AG-9 を直す」を求めていた（t531・t543・t553・t556）。実装の手順は ADR を読み直す正本に並べ、見直しは文書を直していないことを重い指摘にし、Iteration の見直しは「意図を正本（ADR）に書く」起票を勧める。依存先のチケットで ADR-001 に決めた基準を、エージェントが読む手順と brief に写す。

## 受け入れ条件

- [ ] guide-import.md が、受け入れ条件に新しい ADR や要件の書き足しを入れるのは ADR-001 の基準に当たるときだけとし、それ以外はテストとコメントで約束を示す条件にすると書いている
- [ ] guide-work.md と brief.ts の implement が、読み直して直す正本から ADR を外し、要件は約束だけを直すと書いている
- [ ] guide-review.md と brief.ts の review が、ADR や要件に細部を足した変更を指摘にし、文書を直していない重い指摘を約束・手順・規約の変更に限ると書いている
- [ ] guide-audit.md が、ADR の細部と実装のずれを「ADR の細部を消す」として起票し、意図した設計はテストかコメントで押さえる起票を勧めると書いている
- [ ] brief.ts の文の変更に合わせたテストが通り、`mise run check` が通る
