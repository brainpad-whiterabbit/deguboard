## 概要

今は実装・見直し・手直しの Run しかなく、計画を立てて依頼文を書く親が調べた量が残らない。2026-11-05 の検証では、## 参考 節の項目の 69% が親の依頼文（Plan の範囲・方針）にも書かれていた。参考節が効くとしたら親の側なので、そこを測れるようにする。Run は必ずチケット 1 枚に結び付き、会話記録は Run の ID が出てから finished_at までを数える。そこで、親がチケットを 1 枚ずつ調べる間を、そのチケットの `plan` の Run にする。

## 受け入れ条件

- [ ] 同梱の Workflow のテンプレート（software-development・general）の `steps` に `plan` がある
- [ ] `dg guide plan` が、チケットごとに `run start <id> plan` から Plan の範囲・方針を書くまでを Run にし、並行させずに 1 枚ずつ閉じると書いている
- [ ] `dg guide work` か `dg guide parallel` が、依頼文の前に親が調べ直すときも、同じ step の Run で記録すると書いている
- [ ] このリポジトリの Workflow（software-development）に `plan` の step がある（workflow set で足す）
- [ ] ADR-005 の「実装・見直し・手直しを別の Run にする」と `dg guide run` の step の表を直し、`mise run check` が通る
