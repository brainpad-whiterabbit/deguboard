## 概要

同じユーザのセッションは主体の ID がどれも `<ユーザ>/agent` なので、あるセッションが claim して進めているチケットに、別のセッションがもう一度の claim（手直しの始まり）や unclaim をできてしまう。claim したセッションを `deguboard-local/` に記録し、別のセッションのその操作を止める。生きているかはすでにあるフックの記録で見て、監視は足さない。Git のデータの形は変えない。Plan とチケットを claim の前に予約するのは後続のチケットで行う。

## 受け入れ条件

- [x] agent の claim が、呼んだセッション（サブエージェントなら起動した親。`sessionOf` と同じ決め方）がそのチケットを進めていると `deguboard-local/` に記録し、Git のデータには書かない
- [x] 別のセッションが記録したチケットに agent がもう一度の claim・unclaim をすると拒否され、拒否の文が記録したセッションと越え方を示す
- [x] `--take-over` を付けると拒否を越え、記録は呼んだセッションに移る
- [x] 記録したセッションに SessionEnd が届いたか、最後にフックが届いてから 30 分（`dg next` が落ちたセッションの Run を見分ける時間と同じ）が過ぎた記録は無視される
- [x] セッションがわからない呼び出し（フックのない製品）と人の操作は記録を作らず、拒否もされない（警告だけ）
- [x] 判定はファイルを読まない関数に置き、組み合わせをその関数のテストで網羅する。requirements の ST-7 か SY-5 に約束を 1〜2 文で足す
