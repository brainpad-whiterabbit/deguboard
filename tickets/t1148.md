## 概要

同じユーザのセッションは主体の ID がどれも `<ユーザ>/agent` なので、あるセッションが進めている承認済みの Plan のチケットを、別のセッションが claim・もう一度の claim・unclaim できてしまう。どのセッションがどのチケットと Plan を進めているか（予約）を `deguboard-local/` に記録し、別のセッションの操作を止める。生きているかはすでにあるフックの記録で見て、監視は足さない。Git のデータの形は変えない。

## 受け入れ条件

- [ ] agent の claim・`dg next <ticket>`・承認された Plan を進め始めるときに手順が最初に呼ぶ dg のコマンドが、呼んだセッション（サブエージェントなら起動した親）がそのチケット・Plan を進めていると `deguboard-local/` に記録し、Git のデータには書かない
- [ ] 別のセッションが予約したチケット（予約した Plan のチケットを含む）を agent が claim・もう一度の claim・unclaim すると拒否され、拒否の文が予約したセッションと越え方を示す。`dg next` はそのチケットに進む手を返さず、別のセッションが進めていることを返す
- [ ] `--take-over` を付けると拒否を越え、予約は呼んだセッションに移る
- [ ] 予約したセッションに SessionEnd が届いたか、最後にフックが届いてから一定の時間（`dg next` が落ちたセッションの Run を見分ける 30 分と揃える）が過ぎた予約は無視される
- [ ] セッションがわからない呼び出し（フックのない製品）と人の操作は予約を作らず、拒否もされない（警告だけ）
- [ ] 判定はファイルを読まない関数に置き、組み合わせをその関数のテストで網羅する。requirements の ST-7 か SY-5 に約束を 1〜2 文で足す
