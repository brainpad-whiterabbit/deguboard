## Summary

権限の 5 つの値（human_only・always_ask・ask_unless_auto・anyone・agent_only）の判定を入れ、境目を越えるすべての操作と例外の動きに当てる。requires は越える条件で、満たしても自動では進まない。照合のきっかけを Core に固定するのは後続のチケットで行う。

## Acceptance criteria

- [x] claim・PR を出す・`pr merge`・`ticket move` が、境目の `requires` と `decide` で判定され、5 つの値の表（決定版 04 の節）どおりに通す・承認を求める・拒否することがテストで示されている
- [x] 承認が要る操作は、エージェントが `--approved-by` で承認者を記録して進め、付けなければ拒否される。人は `--override "理由"` で `agent_only` と満たさない `requires` を越えられ、理由が履歴に残る。エージェントの `--override` は拒否される
- [x] abandon・back・reopen が `exceptions` の値で判定される
- [x] Workflow の `transitions` がなくなり、`boundaries` と `exceptions` に移っている
- [x] requirements の WF-1・WF-2（`requires`）・ST-2 が直っている
- [x] 境目を飛ばす動き（in_progress → done など）が、間の境目をすべて越えたものとして厳しいほうの方針で判定されることがテストで示されている
- [x] 書き込みのコマンドが、Core の固定 → exceptions → boundaries → flow → governance の順に最初に当てはまったものの値で判定され、どれにも当たらなければ誰でもできる（flow・governance の中身は後続のチケット）
- [x] guide が人の指示を承認とみなして `--approved-by human` を付けるよう案内している
- [x] ADR-003 に、権限の 5 つの値・`--approved-by`・`--override` と、権限は自己申告の手すりで AG-10 のフックが要ることが書かれている
