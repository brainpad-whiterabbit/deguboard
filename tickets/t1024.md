## Summary

権限の 5 つの値（human_only・always_ask・ask_unless_auto・anyone・agent_only）の判定を入れ、境目を越えるすべての操作と例外の動きに当てる。requires は越える条件（満たしても自動では進まない）で、照合のきっかけ（ブランチができた → in_progress、下書きでない PR が開いた → review、PR かブランチがマージされた → done）は Core が固定で持つ。

## Acceptance criteria

- [ ] claim・PR を出す・`pr merge`・`ticket move`・照合が、境目の `requires` と `decide` で判定され、5 つの値の表（決定版 04 の節）どおりに通す・承認を求める・拒否することがテストで示されている
- [ ] エージェントは `--approved-by` で承認者を記録して進め、人は `--override "理由"` で `agent_only` と満たさない `requires` を越えられ、理由が履歴に残る。エージェントの `--override` は拒否される
- [ ] abandon・back・reopen が `exceptions` の値で判定される
- [ ] 照合のきっかけが Core の固定になり、Workflow の `reconcile` と `transitions` がなくなっている
- [ ] requirements の WF-1・WF-2・ST-2・ST-4 が直っている
