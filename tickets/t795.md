## Summary

エージェントを並列に動かすと、それぞれの `mise run check` が vitest のワーカーをコア数に近い数ずつ立てる。8 コアの上で 20 を超えるワーカーと git のプロセスが重なり、検査が重くなる。check のテストの段を、worktree をまたいで共有する lock で囲み、同時に走る全体のテストを 1 本にする。品質ゲート（`dg gate --only check`）も `mise run check` を呼ぶので、同じく効く。CI に移す案は採らない（ADR-008）。

## Acceptance criteria

- [x] `mise run check` のテストの段が、`git rev-parse --git-common-dir` の下の lock ファイルを `flock` で取ってから回り、別の worktree の全体のテストと同時に走らない
- [x] lock がすぐ取れないときは、待っていることを 1 行出してから待つ。待ちに独自の上限は付けない（gate の検査の打ち切りに任せる）
- [x] format:check・lint・typecheck・check:docs と、`mise run test:related`・`mise run check:light` は lock の外で回る
- [x] `flock` がない環境では、テストを lock なしで回し、検査を落とさない
- [x] lock で待つ理由が、mise.toml のコメントと check の description に書かれている
