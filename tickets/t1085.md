## Summary

今は 60 秒おきに fetch して未取り込みの数を印に出すだけで（UI-6）、取り込むには人が同期のボタンを押す。書くコマンドは書く前に取り込む（SY-2）ので、古いのは画面の表示だけ。データは専用の worktree にあり、取り込んでも利用者のコードの作業ツリーには触らない。

そこで、core の createLocalClient が status の後ろで行う fetch（backgroundFetch、packages/core/src/commands/local.ts）の直後に、同じ書き込みのロックの中で、手元に未 push のコミットも未コミットの変更もなければ fast-forward だけで取り込み、画面を読み直させる。core に置くので、VS Code 拡張と dg serve の両方で効く（入口は写すだけ）。未 push がある・未コミットの変更がある（commit.mode が batch・manual のまとめ待ちの変更も含む）・dg の外の変更（SY-7）があるときは取り込まず、今までどおり人の同期に任せる（知らせ方は t1086）。

## Acceptance criteria

- [x] 未取り込みがあり、手元に未 push のコミットと未コミットの変更がないとき、次の fetch の後に人の操作なしで取り込まれ、左パネルとエディタのパネル（dg serve ではブラウザの画面）が新しいデータを映す
- [x] 取り込みは fast-forward に限り、未 push のコミット・未コミットの変更（commit.mode が batch・manual のまとめ待ちの変更も含む）・途中の rebase（SY-9）・dg の外の変更（SY-7）のどれかがあるときは取り込まない
- [x] 自動の取り込みは status の後ろの fetch と同じ書き込みのロック（SY-5）の中で行い、ロックを待たずに取れたときだけ取り込む
- [x] リモートに届かないとき・取り込みが失敗したときは、通知を出さずに今の印（バッジ）を出し続ける
- [x] Git 操作のテストを一時ディレクトリの bare リモート付きリポジトリで足す
- [x] 要件 UI-6 の 1 文を、fast-forward で済むときは自動で取り込む約束に直す
- [x] push が拒否されてリモートの変更を取り込み直す途中で作業が止まった状態（途中の rebase が残る）では自動の取り込みをせず、データを壊さないことをテストで確かめる
