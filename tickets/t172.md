## 概要

Run の `retries` は回数だけで、なぜやり直したかが残らない。作業の実績の分析（s5 で Run が長くなりリトライが増えた件）で、原因を切り分けられなかった。

`dg run finish` に `--retry-reason <理由>`（繰り返し指定できる）を足し、Run に `retry_reasons`（文字列の配列）を記録する。理由は検査の失敗・見直しの指摘などの要約を 1 行で書く。MT-4 と同じく、秘密・コマンドの文字列・パスは書かない。

## 受け入れ条件

- [ ] `dg run finish` に `--retry-reason` があり、指定した理由が Run の JSON の `retry_reasons` に残る（指定しなければ空の配列か null）
- [ ] `--retries` を省いて `--retry-reason` を指定したときは、理由の数を回数にする。両方を指定して数が食い違えば拒否する
- [ ] requirements.md の RN-1・MT-4 と ADR-005 の「記録するもの」が `retry_reasons` を含む
- [ ] 記録と拒否のテストがある
