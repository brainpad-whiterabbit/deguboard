## Summary

同じ status で状態と一緒に書く時刻（closed_at・started_at・approved_at）だけが違う競合は、マージドライバが早い方を採って自動で解く（t775、SY-4）。一方、merge.ts の earlierTimes は両側に status があり同じときだけ働き、Plan のファイルには status がないので、Plan の approved_at・closed_at だけが違う競合は自動で解けず、sync が止まる。SY-4 と sync のヘルプ（approved_at も自動で解く）の約束と食い違う。ADR-034 が挙げる「Plan の closed_at の競合で同期が 3 日止まった」と同じ形。v0.25.0 の Release の本文に既知の制約として書いた。t787 の実装で見つかった。

## Acceptance criteria

- [x] 両側の Plan が同じ時刻のフィールド（approved_at・closed_at）を持ち、その値だけが違う競合を、早い方を採って自動で解き、警告と sync の data.resolved（auto: true）で知らせる
- [x] 片側だけに時刻がある競合と、読めない時刻の競合は、これまでどおり競合のまま残る
- [x] 上の 2 つを、Plan のファイルの形でテストが確かめる
- [x] SY-4・sync のヘルプ・ADR-034 の記述が、Plan を含めた今の振る舞いと合っている
