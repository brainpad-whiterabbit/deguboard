## 概要

`plan create` の循環の検査は Plan の `after` だけを見て、チケットの `depends_on` の循環は TK-2 が別に拒否する。両方をまたぐ循環（`after` で t1 が t2 を待ち、t2 の `depends_on` に t1 がある）は拒否されず、2 枚が互いを待って着手できなくなる。実行計画のグラフは止まるが、矢印が右から左へ描かれる（t402 の見直しで判明）。Plan の中の `after` と `depends_on` を合わせて循環を検査する。

## 受け入れ条件

- [ ] Plan の中の `after` と `depends_on` をまたぐ循環を `plan create` が拒否し、循環の経路をメッセージに出す
- [ ] `after` だけの循環と `depends_on` だけの循環の既存の拒否は変わらない
- [ ] requirements の Plan の節を直し、core のテストに「またぐ循環」を足して `mise run check` が通る
