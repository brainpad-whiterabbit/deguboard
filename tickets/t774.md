## Summary

sync が競合で止まると、`data.conflicts` と警告はファイル名しか返さない。マージドライバはぶつかったフィールドを知っているのに stderr に書くだけなので、人に remote か local かを選ばせる材料を集めるのに、データのブランチの差分を掘る手間がかかった（s26 の closed_at）。チームで使うとき、競合を短く解けるようにする。

## Acceptance criteria

- [x] `data.conflicts` はファイル名の配列のままにし、新しい `data.conflict_fields` が、ファイル・フィールド・base・local・remote の値を持つ
- [x] 値は、分岐点・ローカルの先頭・リモートの先頭の 3 つでマージドライバと同じ判定を回して求める。rebase が止まったコミットの後でぶつかる分も含め、`--resolve` が解く競合をすべて示す
- [x] 本文がぶつかったときは、ぶつかった行の塊（ローカル側とリモート側の行）だけを返す
- [x] 警告の文が、ファイル名だけでなくフィールドと両側の値を示す
- [x] `dg guide overview` の「When sync stops」が、その値を表にして人に選ばせる手順になっている
- [x] bare リモートの 2 つの clone でぶつけたテストで、フィールドと両側の値が返る（2 つ目のコミットでぶつかる場面も含む）
- [x] requirements の SY-4 が、競合で返す内容に合っている
