## Summary

s41 の実装のエージェントが回した test:related は 4 回とも 180 秒を超え、Bash の前景の上限で背後に回された（全体の mise run check は 140 秒）。vitest run --changed origin/main は import をたどって選ぶので、registry・gate・pr・next から読まれる core のコマンドを 1 つ変えるとほぼ全部のテストが選ばれ、そのうえ全体のテストの lock の外で、並列の worktree（work.parallel 5、8 CPU）と CPU を取り合う。s41 の実装のエージェントでは、経過時間の 3〜6 割がテストと検査だった。作業の途中のテストは、変えたテストファイルと、変えたソースのファイルと名前で対になるテスト（foo.ts に対する foo.test.ts・foo-*.test.ts）だけを回す。import はたどらず、結合テストは push の前の dg gate <id> --only check に任せる。

## Acceptance criteria

- [ ] s41 の t1103 の差分（packages/core/src/commands/hook.ts・orphan-review.ts・orphan-review-judge.ts とそのテスト）に当たる変更で、test:related が回すテストのファイル数と時間を PR に載せ、時間が 60 秒を下回る
- [ ] 変えたテストファイルと、変えたソースのファイルと名前で対になるテストが回り、ほかのテストは回らない
- [ ] 関わるテストがないときは、何も回さずに成功する
- [ ] 選び方と、選ばれないテストは push の前の dg gate <id> --only check が見ることを、mise.toml の test:related の description に書き、CLAUDE.md の「開発環境とコマンド」の記述と食い違わない。名前で対になるテストを持たないソースのファイルを変えたときは、その旨を 1 行出す
- [ ] vitest.workers.ts の isRelatedRun が、今までどおり test:related の実行を見分けてワーカー数を決める
