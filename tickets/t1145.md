## Summary

Workflow の既定値は packages/core/src/workflow/resolve.ts が正本だが、guide と Skill の雛形が既定値や値ごとの場合分けを文で書いていて、既定値を 1 つ変えるだけで多くの文書を直すことになり、直し漏れも起きる（t1144 のあと guide-done.md と guide-change.md に Iteration を閉じる既定を human_only とする記述が残った）。承認が要るかは dg が Workflow の値から決めて返し（ADR-030）、guide はそれに従う共通の規則だけを持つようにする。利用者向けの文書・ADR・check:docs の検査は、分けたもう一方のチケットで扱う。

## Acceptance criteria

- [x] guide と Skill の雛形が Workflow の値で決まる内容（操作ごとの既定値と、値ごとの場合分け）を書かない。承認が要るかは、dg が返すコマンドと拒否の応答、または操作の前に承認の要否を返す dg の入口で決まり、guide はそれに従う共通の規則だけを 1 か所に持つ（guide-done.md と guide-change.md の Iteration を閉じる既定の記述も消える）
- [x] 既定値を確かめるテストのほかに、既定値が変わると落ちるテストがない（振る舞いを確かめるテストは Workflow の値を明示する）
