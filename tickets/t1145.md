## Summary

Workflow の既定値は resolve.ts が正本だが、guide・Skill の雛形・usage（英語版と日本語版）・README・ADR がそれぞれ既定値や値ごとの場合分けを文で書いていて、既定値を 1 つ変えるだけで多くの文書を直すことになり、直し漏れも起きる（t1144 のあと guide-done.md と guide-change.md に Iteration を閉じる既定を human_only とする記述が残った）。承認が要るかは dg が Workflow の値から決めて返し（ADR-030）、guide はそれに従う共通の規則だけを持つ。利用者向けの文書は既定値を並べずに dg workflow show を指し、ADR は個々の鍵の値でなく既定を決める原則と理由を書く。

## Acceptance criteria

- [ ] guide と Skill の雛形が Workflow の値で決まる内容（操作ごとの既定値と、値ごとの場合分け）を書かない。承認が要るかは、dg が返すコマンドと拒否の応答、または操作の前に承認の要否を返す dg の入口で決まり、guide はそれに従う共通の規則だけを 1 か所に持つ（guide-done.md と guide-change.md の Iteration を閉じる既定の記述も消える）
- [ ] usage.md・usage.ja.md・README.md・README.ja.md が既定値の一覧を持たず、dg workflow show と Workflow の節を指す（packages/vscode/README.md は README.md から作られる）
- [ ] ADR（003・009・011・026・030）が既定を決める原則と理由を書き、個々の鍵の既定値を写さず、値の正本を resolve.ts に案内する
- [ ] 既定値を確かめるテストのほかに、既定値が変わると落ちるテストがない（振る舞いを確かめるテストは Workflow の値を明示する）
- [ ] mise run check:docs が文書の中の Workflow の既定値の書き写しを検出する（できないときは理由を PR に書く）
