## 概要

見直し（audit-s11、観点：文書と実装）。依頼文（ask）まわりで、コメント・ヘルプ・ADR と実装の小さな食い違いがある。どちらに合わせるかは計画で決める。

- packages/web/src/pages/iterations.tsx 2 行・board.tsx 15 行のコメントは Iteration の「開始」をエージェントに頼むと書くが、頼むこと（ASK_ACTIONS）に start はない（開始は claim の手順が行う、ADR-006）。board.tsx の「Status の変更」も、汎用の move ではなく work・done・abandon・undo_done で頼む
- `dg ask-menu --help`（ask.ts の askMenu の summary）は「左パネルの吹き出しと右クリック」が使うと書くが、エディタのパネルの詳細やブラウザでも使う
- ADR-010 の「頼む操作が actor.human_only に入っていれば人のコマンドを返す」は、操作が 1 つに決まる頼むことだけに当てはまる（assign・plan・done など Skill に任せるものは依頼文を返し、拒否されたらエージェントが人に頼む）
- ADR-010 の入口（行・見出しの吹き出しと右クリック）と入力欄（左パネルとパネルの下）に、タイトル行・コマンドパレット・選択の帯・ブラウザが入っていない
- ADR-010 の「1 行目は Skill の呼び出し」は、Skill のない頼むこと（close・reopen・abandon・undo_done・status・retro・edit・free）では dg の呼び方になる
- ask.ts の edit は Epic で「題・概要を直す」だが、人に回したコマンドは `--title` だけ。split は新しいチケットを起票するのに、依頼文に `--created-by human` を添えていない（create などは添える）

## 受け入れ条件

- [x] iterations.tsx・board.tsx のコメントが、頼める操作（ASK_ACTIONS）と食い違わない
- [x] dg ask-menu --help の説明が、使う場所を左パネルだけに限らない
- [x] ADR-010 の人に回す範囲・入口と入力欄・Skill のない頼むことの 1 行目の書き方が実装と合う（更新日と一覧も直す）
- [x] Epic の edit の文言と人に回すコマンドが合い、split の依頼文に起票者の扱いが入る（入れないなら理由をコメントに書く）
