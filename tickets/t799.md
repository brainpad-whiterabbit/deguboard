## Summary

観点：アーキテクチャ・設定・テスト。t795 で mise.toml の tasks.check に足した flock の lock は、複数行のシェルを run の配列に直接書き、pnpm run test を呼ぶ。CLAUDE.md と development.md は、mise のタスクは pnpm scripts を呼ぶだけにすると決めている。また lock の振る舞い（待つ 1 行・flock や git がないときの lock なし）を確かめるテストがない。lock のファイルを作れないと exec 9> の失敗で check 全体が止まる（flock がないときと違い、lock なしで回らない）。main の worktree では git rev-parse --git-common-dir が相対の .git を返すので、待つ 1 行の lock の場所が相対になる。

## Acceptance criteria

- [x] mise の check のテストの段が pnpm script を 1 つ呼ぶだけになり、lock の処理はスクリプトにある
- [x] lock が取られているときに待つ 1 行を出してから回ること、flock がないときと lock を作れないときに lock なしで回ることを、テストが確かめる
- [x] 待つ 1 行の lock の場所が絶対パスである
