## Summary

t1153 の判定は、先端が見直した SHA に base を取り込んだマージコミットのあいだ、`dg ticket show`・`dg next`・`dg gate` を呼ぶたびに一時の worktree を checkout して自動マージの tree を作り、結果を覚えない。大きなリポジトリでは、これらの呼び出しが遅くなる。同じ組の結果を覚えて使い回す。

## Acceptance criteria

- [ ] 同じ（見直した SHA・取り込んだ base のコミット）の組では、自動マージの tree を 1 回だけ作り、次からは覚えた結果を使う
- [ ] 組のどちらかのコミットが変われば作り直し、覚えた結果が判定を誤らせない（判定の組み合わせを純粋な関数のテストで確かめる）
- [ ] git を通すテストで、2 回目の呼び出しが一時の worktree を作らないことを確かめる
