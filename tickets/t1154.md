## Summary

s42 では見直しの手直しのたびに push の前の全体の検査（130〜180 秒）を回し、全体の検査が 1 チケットあたり 2.0 回になった（s41 の後半は 1.13 回）。結果が読めた gate で途中の全体の検査が落ちたのは 3 回で、2 回は見直しの前の 1 回目、1 回は不安定なテスト。手直しの後の検査が実際の失敗を見つけた例はなかった。

見直しの前（と手直しの後）の検査を config の新しい項目で決める（未設定なら今と同じく全体の検査）。`dg gate --only check` はその項目の検査を回し、`--for ready`・`--for merge` の check は `actions.test` を回す。見直しが通り、先端が今の main を含まないときに、`dg next` が main を取り込む手を返す（手続きは Core が持つ。ADR-011）。全体の検査は取り込んだ先端で 1 回回す。マージの条件は最後の先端で全体の検査が通ることのままなので、見逃しは増えない。

## Acceptance criteria

- [ ] config に見直しの前の検査の項目（例：`actions.pre_review_test`）があり、未設定なら `dg gate --only check` が今と同じく `actions.test` を回す（テストで確かめる）
- [ ] その項目のコマンドが Run の `check_seconds` に数えられ、requirements.md の 5.10 に項目が載っている
- [ ] 見直しが通り、作業ブランチの先端が今の base を含まないとき、`dg next` が ready の前に base を取り込む手を返す（判定を純粋な関数のテストで網羅する）
- [ ] guide-work.md・guide-review.md・brief.ts が、push の前は `dg gate --only check`（見直しの前の検査）と指示し、main の取り込みのやり方を書いている
- [ ] このリポジトリの config に typecheck・lint・`test:related` を回す mise タスクを設定し、CLAUDE.md の「開発環境とコマンド」を同じ順に直している
- [ ] 全体の検査が見る範囲（`mise run check` の段と回すテスト）が下がっていないことを PR の本文で示す
