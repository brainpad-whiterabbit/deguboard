## Summary

フックがないと、見直し役の `run review-result` は書く先の Run がなく保留になり、`dg next` は review を返し続け、`dg gate` の review・fix_rounds が満たせずに止まる。持ち主のない保留（保留の結果があり、同じチケットの見直しの Run が開いておらず、動いているサブエージェントの印もないもの）を、結果を書いた時刻に閉じた見直しとして、next の段階と gate の review・fix_rounds が数える。next・gate は読むだけのまま書き込まない。

## Acceptance criteria

- [ ] Run のないまま保留になった見直しの結果があると、next が reviewed として扱い、通っていれば ready、重い指摘があれば fix を返す（テスト）
- [ ] gate の review と fix_rounds が持ち主のない保留を数え、通った保留があれば `--for ready` が通る（テスト）
- [ ] 結果を書いた時刻が作業ブランチの先頭の push より前の保留は数えない（テスト）
- [ ] 同じ push の後に保留が複数あるときは、最新の 1 件だけを数える（テスト）
- [ ] 見直しの Run が開いているか、動いているサブエージェントの印があるチケットの保留は数えない（テスト）
- [ ] ADR-025 に「フックがなければ Run は記録せず、見直しの結果は保留を見直しの記録にする」判断を書き、RN-9 を直す
