## 概要

手順書（`dg guide work`）を通らずにその場で実装すると、`run start` が呼ばれず Run が残らない（t436）。agent の `ticket claim` で実装の Run を開くようにし、Run の開始をチケットの操作に付随させる。サブエージェントに実装を渡すとき（並行・段階のモデル）は親が `--no-run` を付け、サブエージェントが今までどおり `run start` する。

## 受け入れ条件

- [x] agent の `ticket claim`（`--without-branch` を含む）で、Workflow の step のうち `opens_on: claim` のもの（なければ `implement`）の Run が開く。agent 名は判定（同じ Epic の前のチケット）か `--agent` で決め、どちらもなければ開かずに警告する
- [x] 開いた Run の ID を、出力の最後の行と JSON の `data.run` に出す
- [x] `--no-run` で Run を開かない
- [x] 同梱のテンプレートの実装の step に `opens_on: claim` が付き、`dg validate` が `opens_on` を検査する
- [x] `dg guide` の work・run・parallel を新しい開き方に合わせて直す（普段の経路から run start を外し、委譲では `--no-run`）
- [x] requirements（RN・claim の約束）と ADR-005 の「作業するエージェント自身が start する」を書き換える
