## Summary

見直し（s31、文書と実装）。t857 の拡張は Skill の中身だけを比べて同梱のものに揃えるので、PATH の dg（ソースの dg など）が拡張より新しいと、起動のたびに Skill を古い版に戻す。すると `dg hooks check`・`next`・`brief` はそれを「older than this dg」と警告し、両者が書き換え合う。このリポジトリでは `git pull` のあとに `mise run dg -- skill install` をし、worktree では拡張を入れ直さないので、起きやすい。Skill の印に、書いた dg の版を持たせる（例 `<!-- dg skill v0.28.0 sha256:… -->`）。拡張は、自分より新しい版の Skill を上書きしない。dg の警告は、自分より古い版の Skill だけを「older」と出す。印に版のない今の Skill は、この変更より前の dg が書いたものなので古いとみなす。版がどう違えば何をするか（同じ版で中身が違うとき、自分より新しい版の Skill を見つけたときの扱い）は計画で決める。t857 の受け入れ条件 2 の「古いこと」と実装の「違うこと」のずれも、ここで扱う。

## Acceptance criteria

- [x] Skill の印が書いた dg の版を持ち、版を比べる理由が ADR（印の形はデータの形なので）に書かれている
- [x] 拡張は自分より新しい dg が書いた Skill を上書きしない。印に版のない Skill と古い版の Skill は、今までどおり更新する
- [x] 古い Skill の警告と拡張の通知の文が、実際の比べ方（新旧か、違うだけか）と合っている
- [x] 上の振る舞いをテストで確かめる
- [x] requirements.md の AG-2 が、拡張は新しい版の Skill を戻さないことを書いている
