## Summary

見直し（s31、文書と実装）。t857 の拡張は Skill の中身だけを比べて同梱のものに揃えるので、PATH の dg（ソースの dg など）が拡張より新しいと、起動のたびに Skill を古い版に戻す。すると `dg hooks check`・`next`・`brief` はそれを「older than this dg」と警告し、両者が書き換え合う。このリポジトリでは `git pull` のあとに `mise run dg -- skill install` をし、worktree では拡張を入れ直さないので、起きやすい。どちらの版が新しいかを比べるか（印に書いた dg の版を持つなど）は設計の判断なので、計画で決める。t857 の受け入れ条件 2 の「古いこと」と実装の「違うこと」のずれも、ここで扱う。

## Acceptance criteria

- [ ] 拡張と PATH の dg の版が違うときの Skill の扱いが決まり、理由がコードのコメント（判断なら ADR）に書かれている
- [ ] 決めた扱いで、新しい dg が書いた Skill を拡張が古い版に戻さないか、戻すことが通知と警告の文から分かる
- [ ] 古い Skill の警告と拡張の通知の文が、実際の比べ方（新旧か、違うだけか）と合っている
- [ ] 上の振る舞いをテストで確かめる
