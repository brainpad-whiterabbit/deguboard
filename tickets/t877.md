## Summary

「こういう機能がほしい」のような相談の言い方から、agent が起票して done まで実装を進めてしまうことがある。仕組みで着手を縛ると（Sprint を着手の関所にする案などを検討して取り下げた）、人が指示した場合も止まってしまうので採らない。代わりに、agent の振る舞いの決まりとして、頼まれた段階までしか進まないことと、人の指示にはゲートや手順を避ける操作でも従うことを書き、要件 AG-3 にも利用者への約束として 1 文足す。

## Acceptance criteria

- [x] `dg guide overview` に「相談・要望には答えるか提案するまでにし、起票・着手・マージは人が頼んだ段階までにする」項がある
- [x] 同じ項に「人が明示的に指示したことは、品質ゲートや手順を避ける操作でもそのとおりに行う」とある
- [x] 同じ項に「Skill の呼び出しは、その Skill が受け持つ範囲を頼んだものとみなす」とある
- [x] `dg guide overview` の Skill の表で、`work` の使う場面が「人がチケットを進めるよう頼んだとき」と読める書き方になっている
- [x] CLAUDE.md の「作業はチケットに紐づける」が、頼まれた作業に範囲を限る書き方になっている
- [x] requirements.md の AG-3 に「起票・着手・マージは人が頼んだ段階までにする」旨の 1 文と、`dg guide overview` への案内がある
