## Summary

必須を満たさない間にタイトル行のセットアップのアイコンを押すと、開いた時の確かめ直し（store.tsx の recheckSetup）で reload が走る。その途中で dg init の後の reload の event が来ると reload が重なり、先に始まった方が config.show の NOT_INITIALIZED で catch に入って、後から setNeedsSetup(true) にし、新しい成功を上書きする。ボードが使えるのに #/setup のチェックリストが残る（UI-12 とずれる）。app.test.tsx のテスト「必須を満たさない間にタイトル行のセットアップのアイコンを押していても、必須を満たすと推奨のチェックリストを残さず、来る前の画面の一覧に変わる」が `mise run check` でときどき落ちる原因でもある（Expected "#/backlog", Received "#/setup"）。t1091 でこのテストの event の送り方を直してもテストが落ちにくくなるだけで、本体の競合は残る。

## Acceptance criteria

- [ ] 重なった reload のうち最新でない方は、needsSetup・notice などの状態を書き換えない
- [ ] 古い reload が NOT_INITIALIZED で失敗し、新しい reload が成功する順序を決めて再現するテストが web にあり、直した後に通る
- [ ] 既存のテスト「必須を満たさない間にタイトル行のセットアップのアイコンを押していても、必須を満たすと推奨のチェックリストを残さず、来る前の画面の一覧に変わる」が順序によらず通る
