## Summary

s33 の振り返りで、仕様の質の指標（ticket-caused-rework-rate：手戻りの原因がチケットにあったチケットの割合）を数えようとしたが、Git に残る記録は見直しの指摘の数と手直しの理由の文だけで、原因の種類が分からなかった。s30〜s33 の手直しの理由 64 件は、どれも成果物のどこが悪いかの形で書かれていて、なぜそうなったかは書かれていない。

見直し役（実装者とも手直し役とも別のエージェント）が、指摘の 1 件ごとに原因の種類を付ける。種類は固定の 7 つ：ticket（受け入れ条件か範囲が、その場面を書いていなかった）・plan・implementation・tests・documents・environment・unknown。ticket は、PR が受け入れ条件を満たしていないという今の category の「受け入れ条件の漏れ」とは別のもの。

指摘の一覧は今までどおり deguboard-local に置き、Git の見直しの Run には、重い指摘と軽い指摘のそれぞれについて原因ごとの数だけを書く。`metrics show` がそれを合計して返す。これより前の Run は原因を測れないものとして扱う。Run のデータの形が変わるので、判断の理由を ADR-029 の本文に書く。

## Acceptance criteria

- [ ] 見直しの指摘のスキーマに 7 種類の `cause` があり、ない値か誤った値は `run review-result` が INVALID_INPUT で拒む
- [ ] 見直しの Run の `review` に、重い指摘と軽い指摘のそれぞれについて原因ごとの数が入り、指摘の一覧は Git に入らない
- [ ] `metrics show` が原因ごとの数を合計して返し、原因の数のない前の Run を missing に数える
- [ ] ADR-029 の本文と、要件の見直しの結果の項が、今の形に合っている
- [ ] 既存のテストが通る
