## Summary

今の /dgdiscuss は、チケットの不明な点・食い違う点から論点を拾うので、受け入れ条件の文言を詰めて終わることが多い。`--deep` を付けたときは、決めた観点をすべて確かめ、論点のある観点だけを掘り、大きな判断を先に決めてから受け入れ条件に進ませる。`--deep` なしの手順は変えない。

## Acceptance criteria

- [x] guide-discuss.md の frontmatter の `argument-hint` と `description` に `--deep` があり、Skill の雛形に写る（テスト）
- [x] `--deep` のとき、手順が次の観点を持つ：要るか（今やるか・やめる・後回し）、目的と成果（誰の何が良くなるか・利用者への約束が変わるか）、方式と採らなかった案、範囲（分ける・まとめる・ほかのチケットとの重なり。重なりは、開いたチケットを `dg ticket list --query` でタイトルの語から探し、候補の References のファイルと突き合わせる）、順序・依存・優先度、前提とリスク（競合・環境差）、戻しやすさ（移行の要否・ADR を書く場面に当たるか）、利用者とエージェントへの見え方（ヘルプ・guide・警告の文）（テスト）
- [x] `--deep` のとき、対象（チケット・Epic・Iteration）を問わず、エージェントはすべての観点を確かめ、論点のある観点だけを掘り、外した観点は理由を 1 行で示す（テスト）
- [x] `--deep` のとき、方式の論点では案を 2 つ以上、利点と欠点の表で比べさせ、受け入れ条件の文言は観点の論点が決まった後に回させる（テスト）
- [x] やめる・分ける・移すの結論は、`--deep` でも今の「案内して止まる」に従う（反映の範囲は変えない）
- [x] `--deep` の手順は guide-discuss.md の 1 つの節にまとめ、ほかの節には「`--deep` のときはその節に従う」の案内だけを足す（テスト）
