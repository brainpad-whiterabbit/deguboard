## 概要

Claude Code の Adapter は、Run を結び付ける会話記録を session の候補、作業ツリーの候補の順に探し、見つかった中で Run の ID が最初に出たファイルを選ぶ。ところが `dg run start` の警告は開いたままのほかの Run の ID を出すので、ID を見ただけの別の session のファイルが session の候補に入り、そのファイルに結び付くことがある。そのファイルで同じ時刻に始まった Run がいると応答をすべて譲り、使用量が 0 になる。refresh を呼ぶ session によって結び付く先が変わるので、finish と refresh で答えが違う。ADR-005 の「Run の ID を最初に含むファイルに結び付ける」とも食い違う。t422（PR #393）の見直しで見つかった。例：t421 の Run r20261105-110304-62f7（session 0d0127a5 の親で 11:03:08 開始）は、別の session（24f1b73a）から refresh すると、11:04:01 に run start の警告でこの ID が載った agent-a8e67….jsonl に結び付き、output 6819 が 0 になる（r20261105-111455-ced9 も同じ）。

## 受け入れ条件

- [x] run start の警告などで ID を見ただけのファイルには、session の候補にあっても Run を結び付けない（テストで確かめる）
- [x] 同じ Run は、どの session の環境から finish・refresh しても同じファイルに結び付き、同じ値になる（テストで確かめる）
- [x] run refresh --dry-run で r20261105-110304-62f7 と r20261105-111455-ced9 が 0 にならず、t417・t419・t422 で確かめた Run の値は変わらない
- [x] mise run check が通る
