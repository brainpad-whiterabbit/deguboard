## 概要

観点：文書と実装。`dg flow next` は段階ごとに guide の 1 節（`guide.text`、読み直しは `dg guide <topic> --section <節>`）だけを返すが、その節がほかの節を参照している。audit の「見直しの手順」は「観点」「サブエージェントに任せる」「同じ指摘を繰り返さない」を参照し、flow が見直し済みの判定に使うラベル `audit-<S>` の付け方（「起票するチケット」）が入らない。work の「流れ」は「claim の前後」「実装の結果を受け取る」「実装する」、plan の「流れ」は「Plan の作り方」、release は「リリースの手順がないとき」を参照し、assign は承認の取り方の節（「割り当てを提案するとき」）が入らない。一方で guide-all は「guide.text のとおりに進める」と書く。guide-all の書き方と FLOW_GUIDE が返す節のどちらに合わせるかは計画で決める。

## 受け入れ条件

- [x] dg flow next の各段階で、エージェントが読むよう案内される本文（guide.text か案内されたトピック）が、その段階で参照する節をすべて含む
- [x] audit の段階で、ラベル audit-<S> の付け方が読む本文に入っている
- [x] 参照の閉じ方をテストで確かめている（返す節の本文が「」で参照する節が、読む本文の中にある）
- [x] guide-all の「guide.text のとおりに進める」の記述が実装と合っている
