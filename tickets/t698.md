## Summary

2026-11-11、PATH の dg（~/.local/bin/dg → dg.js、#!/usr/bin/env node）が Claude Code の環境で node を見つけられず、フックが毎回失敗していた。mise run dg -- hooks check は dg 自身の環境（mise が node を PATH に足す）で確かめるので、どのイベントも handler: ok で、received_at はすべて null なのに警告がなかった。サブエージェントの実装の Run（t686〜t688）は黙って記録されなかった。mise に限らず、nvm・volta・fnm・Homebrew などでも、ターミナルとハーネスの PATH が違えば同じことが起きる。

人の判断（2026-11-11）で、install はそのとき動いている node と dg.js の絶対パスを命令に書き、マシンごとのパスなので追跡しない .claude/settings.local.json に書く。node を上げてパスが変わったら、hooks check の警告で気づき install をやり直す。単体の実行ファイルでの配布と npx deguboard は採らない（配布の作り直しが大きい・PATH の npx に頼り起動が遅い）。

## Acceptance criteria

- [ ] 既定の install が、動いている node と dg.js の実パスを引用したフックの命令を .claude/settings.local.json に書き、そのファイルが git の無視に入っていなければ warnings で知らせることをテストが確かめる（--personal と --command は今までどおり）
- [ ] .claude/settings.json に dg のフックが残っていれば、install が warnings で知らせることをテストが確かめる
- [ ] dg hooks check が、引用した絶対パスの命令を unverified にせずに確かめ、node か dg.js のパスがなくなっていれば警告することをテストが確かめる
- [ ] このリポジトリの .claude/settings.json から dg のフックを外し、development.md の dg:link と README の「Node.js を PATH に置く」の案内を、dg hooks install と dg hooks check の手順に直している
- [ ] ADR-025 と requirements の該当項が、新しい書く先と命令の形に合っている
