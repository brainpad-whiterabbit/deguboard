## Summary

複数の `workflows/<id>.yaml` をやめ、カンバンに 1 つの `workflow.yaml` にする。項目は states（5 つの Status の表示名）・boundaries（前へ進む隣どうしの 3 つの境目の requires と decide）・exceptions（abandon・back・reopen）・wip・flow・governance の 6 つ。同梱するのは既定の 1 つだけにする。権限の判定は後続のチケットで入れ、このチケットは形と読み書きと検査まで。

## Acceptance criteria

- [x] - [ ] `workflow.yaml` の 6 つの項目を読み、誤り（未知の項目・値・事実、増やした Status など）を `dg workflow validate` と読み込み時に指摘することがテストで示されている
- [x] - [ ] `dg init` が既定の `workflow.yaml` を 1 つ置き、`--template` と同梱のテンプレート（software-development・general）がない
- [x] - [ ] `dg workflow show`・`dg workflow set` が 1 つのファイルを扱い、`dg workflow list` がない
- [x] - [ ] Workflow の `steps` がなくなり、Run の step の語彙（investigate・implement・review・fix・merge）と Run を開く操作（implement は agent の claim、fix はもう一度の claim）を Core が持つ
- [x] - [ ] ADR-003 の本文が書き換えられ（カンバンに 1 つ、状態と境目の方針の枠組み、`workflow set` は Core の固定でいつも人の承認（`--approved-by`）が要ること）、「チケットごとに Workflow を選ぶ」と「`workflow set` を人だけにする」が採らなかった案に残っている。requirements の 5.8 が直っている
- [ ] - [ ] このリポジトリの `workflows/` の 3 つ（consulting・general・software-development）がなくなり、使っている値が `workflow.yaml` に移っている（既定と同じ値は書かない）
- [x] - [ ] `workflow.yaml` のどの項目も省け、省いた項目は同梱の既定と同じ Core の既定になることがテストで示されている
- [x] - [ ] Workflow の `id`・`name`・`labels` がなくなり、表示名が `states` の `label` に移っている
- [x] - [ ] 画面（ボード）が 1 つの `workflow.yaml` から表示名を読んでいる
