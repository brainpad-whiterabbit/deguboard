## 概要

観点=アーキテクチャ。対象=setup.ts の closeReconciledRun と ticket.ts の closeRunsWith。食い違い：sync は別の文脈が先に閉じた Run の REJECTED を警告にして止めない（t482）が、move・unclaim・update --pr の closeRunsWith は捕まえず、チケットの変更ごと失敗する。setup.ts の「実装／手直し」のラベルは run.ts の openedRunLabel の重複。closeRunsWith は opener ごとに実行中の記録を読み直す（sync は 1 回読んで渡す）。ticketUpdate は書き込みのロックの中で gh（timeout 30 秒）を呼んで PR の時刻を取る。

## 受け入れ条件

- [ ] チケットの操作が付随して閉じる Run を別の文脈が先に閉じていても、操作は通り警告が出る（テストで確かめる）
- [ ] REJECTED の扱いと Run のラベルが sync とチケットの操作で 1 か所の実装を使う
- [ ] ticket update --pr の PR の時刻の取得が書き込みのロックの外で行われる
- [ ] RN-6 と ADR-005 の記述がコードと一致する
- [ ] mise run check が通る
