## 概要

dg ticket import の下書き YAML で、引用符なしの値の中の「空白＋#」以降はコメントとして捨てられ、本文が切れたまま起票される（audit-s7 の t231・t233 で `#/config`・`#/board` の後ろが消え、見直しまで気づかなかった）。import はすぐにコミットと push まで進むので後から直すのが面倒。packages/cli/src/program.ts:337 の readDrafts は parseYaml で値だけを読んでいるので、parseDocument でコメントの位置まで読み、本文になる項目（title・summary・acceptance の各項目・body）が引用符なしの値で行末にコメントがあれば、下書きの番号と項目名を出して UsageError（INVALID_INPUT、終了コード 2）で起票をやめる。引用した値や、ブロック（`|`）の見出しの後ろのコメントは本文を切らないので拒否しない。guide の下書きの例のように key・epic などの行末コメントは今のとおり使える。fields の値は対象にしない。

あわせて、readDrafts は YAML の構文エラーを包まず INTERNAL（終了コード 1）にしていて、readYamlFile（program.ts:348）の INVALID_INPUT と扱いが違うので揃える（t204 から移した）。guide import の書き方の案内（t241 をまとめた）もここで足す

## 受け入れ条件

- [ ] 本文になる項目（title・summary・acceptance の各項目・body）の値が引用符なしで行末にコメントがあると、ファイルでも標準入力（-）でも、dg ticket import が下書きの番号と項目名を出して INVALID_INPUT（終了コード 2、--json ならエラーの JSON）で失敗し、コミットしない
- [ ] key・epic・priority などほかの項目の行末コメントと、行だけのコメントは今のとおり使える
