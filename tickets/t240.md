## 概要

dg ticket import の下書き YAML で、引用符なしの値の中の「空白＋#」以降はコメントとして捨てられ、本文が切れたまま起票される（audit-s7 の t231・t233 で `#/config`・`#/board` の後ろが消え、見直しまで気づかなかった）。import はすぐにコミットと push まで進むので後から直すのが面倒。packages/cli/src/program.ts の readDrafts は parseYaml で値だけを読んでいるので、parseDocument でコメントの位置まで読み、本文になる項目（title・summary・acceptance の各項目・body）の値の行末にコメントがあれば、下書きの番号と項目名を出して UsageError で起票をやめる。guide の下書きの例のように key・epic などの行末コメントは今のとおり使える

## 受け入れ条件

- [ ] 本文になる項目（title・summary・acceptance の各項目・body）の値の行末にコメントがあると、dg ticket import が下書きの番号と項目名を出して起票せずに失敗する
- [ ] key・epic・priority などほかの項目の行末コメントと、行だけのコメントは今のとおり使える
- [ ] 引用符で囲んだ値や body の | のブロックの中の # は本文として残る
- [ ] cli のテストで、拒否する場合・使える場合・引用した値の場合を確かめる
- [ ] mise run check が通る
