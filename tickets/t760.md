## Summary

見直しの step 名は review に決め打ちで、定数も 2 か所に重複している。steps を書いた Workflow に review がないと、見直しの Run が拒否されて品質ゲートを通れないが、validate は何も言わない。後から depends_on を足して開いた Plan の after と互いに待つ循環ができても、書き込みは通り、lint を回すまで気づかない（PL-3 は今これを lint で拾う約束）。

## Acceptance criteria

- [x] steps を書いた Workflow に review の step がないとき、workflow validate が警告する
- [x] 見直しの step 名の定数は 1 か所にある
- [x] ticket create と update は、depends_on が開いた Plan の after と循環を作るとき拒否する
- [x] 上の 2 つの検査をテストで示し、requirements.md の PL-3 を書き込みでも拒否する約束に直す
