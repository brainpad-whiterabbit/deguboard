## Summary

前景で見直し中に、別のプロセスの sync が保留を先に見直しの記録として書くと、起動の戻りのフックが結果のない見直しの Run を新しく開き、止まりのフックがそれを失敗で閉じて、最新の見直しが失敗に見える。フックは、同じチケット・同じセッションで起動より後に書かれた見直しの記録があれば、新しく開かずに引き取る。

## Acceptance criteria

- [ ] 前景の見直し中に sync が保留を記録にした後、起動の戻りのフックが新しい Run を開かず、その記録に会話記録を結び、使用量を取り直す（テスト）
- [ ] 引き取った記録から `capture: none` が外れ、最新の見直しが結果なしの失敗にならず gate が通る（テスト）
- [ ] 別のセッションや起動より前に書かれた記録は引き取らない（テスト）
- [ ] RN-4 に、引き取りで閉じた見直しの記録を書き換える例外を足す
