## Summary

guide-work の文面は 1 件ずつ進めると読める。“advance one ticket at a time” とあり、plan show の next の 1 件だけを見て、PR を出すまで次を選ばず、PR ごとと wait_merge・wait_human で人に尋ねて止まる。guide-plan の claim の原則（Claim only the one ticket you can advance right now）も同じ向きに読める。guide-parallel は許可（may）の形で、始める条件が next なので、ready が複数あり実行枠が空いていても並列にならない。

dgall の work の段で flow next が渡す guide.text（flow.ts の FLOW_GUIDE.work）は guide-work の節だけで、guide-parallel は見出しを持たないので節として渡らない。並列の上限を config に移すことは別のチケットで扱う。

## Acceptance criteria

- [x] guide-work で Plan を進めるとき、plan show の ready が 2 件以上あり、サブエージェントを起動できるなら、dg guide parallel に従うのが既定だと書いてある。“one ticket at a time” と「PR を出してから次を選ぶ」の記述はない
- [x] guide-parallel は、始める条件と空いた枠を埋める先を plan show の ready で示し、許可（may）の形で書いていない
- [x] 並列で進めるとき、PR を出したあとと wait_merge・wait_human で止まらない。人に尋ねるのは、承認が要るときと、ready も空いた枠もなくなったときだけだと書いてある
- [x] guide-plan の claim の原則が、並列で今起動する分を claim することと食い違わない
- [x] guide-parallel に節の見出しがあり、flow next の work の段の guide.text に parallel の手順が入ることをテストで確かめている
