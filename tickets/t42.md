## 概要

2026-10-31 15:48:44 の「照合で t30: in_progress → done」。起票時は「feat/watch-data-dir は main より 1 コミット先で push 済み、PR #40 は OPEN」と書いたが、それは 15:55 ごろの状態で、照合の時点とは違っていた。

### 原因

- 15:47:32 t30 を claim（当時の main は fdcb587、PR #38 のマージ結果）。作業ブランチ feat/watch-data-dir はここから切られ、commit はまだない（先端 = fdcb587）。push もしていない
- 15:48:23 PR #39（t37）が squash マージされ、main が a47f139 に進む
- 15:48:44 別のセッション（t37 のマージ後の finish 手順）の `dg sync` が照合。先端 fdcb587 は base（origin/main = a47f139）と同じではなく、真の祖先なので `facts.ts` の `branch_merged` が true。PR はまだなく（`gh pr view` が「PR がない」と答え pr_open / pr_merged は false）、software-development の reconcile は 1 本目の `pr_merged` を飛ばし、2 本目の `branch_merged` で done にした
- 15:49:11 ブランチに唯一の commit 71b31fe が入り、15:49:15 に PR #40 が作られた。どちらも照合の後

つまり真になったのは `branch_merged` で、形は t38（切ったばかりで commit のないブランチを、main が進んだ後の照合が merged とみなす）と同じ。dg の版は main の a47f139（PR #39 の取り込み直後）か、その 1 つ前の fdcb587。t37 で変わった主体の ID の扱いは関係しない。

### 対処（t38 と同じ PR）

in_progress で push していないブランチは、先端が base に含まれていても作業がまだないとみなして `branch_merged` を偽にする。照合の結果（`reconciled`）に当てはまった規則の条件（`when`）を残す。
