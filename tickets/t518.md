## 概要

観点=文書と実装・アーキテクチャ。対象=ticket.ts の reclaim の skipped の案内文、setup.ts の lint_run_fix_missing と REVIEW_STEP、consulting テンプレート、guide-run。食い違い：reclaim の既定 step は fix で、fix のない consulting では claim が「dg run start <id> fix」と拒否されるコマンドを案内する。lint は fix を探すので代わりの step で記録した手直しを常に抜けとみなし、sync の区切りも効かない。見直しの step は "review" の決め打ちで、実装・手直しの step を opens_on から引く作り（RN-5・WF-5）と合わない。step の役割を Workflow で表すか、step がない Workflow では飛ばすかを決める。設計の判断が要るので Iteration に入れない。

## 受け入れ条件

- [ ] 手直し・見直しの step が Workflow にないときの claim の案内・lint・sync の振る舞いが決まり、ADR-005・guide-run に書いてある
- [ ] 見直しの step を決め打ちせず、決めた方法で Workflow から解く（テストで確かめる）
- [ ] mise run check が通る
