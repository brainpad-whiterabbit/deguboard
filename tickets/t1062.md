## Summary

アーキテクチャの観点（監査 s39）。
- CLI の hooks install と uninstall は、主体を別の方法で決めている（agent でなければ human）。ほかのコマンドの入口は、human と agent 以外の値をエラーにしている。hooks uninstall は人だけの操作なので、誤った `--actor` の値が判定を緩めるほうに倒れる
- packages/web/src/test-helpers.ts の偽の ticket.update が、t1023 で消えた `fields` の入力をまだ受けて属性に混ぜている

## Acceptance criteria

- [ ] hooks の install と uninstall に human と agent 以外の主体を渡すと、ほかのコマンドと同じエラーになり、それを確かめるテストがある
