## Summary

頼む小窓の retro（振り返る）は Skill を持たず（skill: null）、1 文の依頼で任せているので、観点と深さが回ごとにばらつく。guide-retro.md を新設して dgretro を配る。対象は今までどおり閉じた Iteration だけ（ask の候補と同じ）。振り返りの結果はデータに残さず（ADR-029 の採らなかった案に合わせる）、チャットで返す。

## Acceptance criteria

- [ ] `dg guide retro` が、観点（成果：目標・done・abandoned・持ち越し／流れ：段とチケットごとの時間とトークンの外れ値・失敗と中断の Run／手戻り：レビューの heavy・fix の Run・retries・done の取り消し／比較：前の Iteration・モデル別）ごとに読む dg のコマンドと答える問いを示し、指示で観点が決まっていなければ観点を複数選択で 1 回聞く（成果がおすすめ）
- [ ] 計測の抜け（missing・estimated_runs・no_runs）を観点にかかわらず注意書きとして添え、抜けのある値は推し量らず「わからない」と書くことを guide が示す
- [ ] 所見ごとに数字かチケット ID の根拠を付けて Keep / Problem / Try の表にまとめ、Try の各行に扱い（起票・ticket update・規約や guide の改善を起票・直さない（理由））を付け、反映する行を複数選択で承認を得るまでデータを書き換えず、起票は dg guide import の書き方に従うことを guide が示す
- [ ] `dg skill install` で dgretro の SKILL.md ができ、SKILL_SUMMARY に ja・en の文があり、retro の Skill の形が `/dgretro <S>` になることをテストが確かめる
- [ ] guide-overview の「Skill のない頼むこと」・dg ask の --help・ask.test.ts の Skill を持たない頼むことのテストから retro を外し、retro の文章だけの依頼文も観点を選ぶ・承認を得て起票する流れに合わせる
- [ ] README.md と README.ja.md の「ボトルネックを調べる」の説明を、観点を選ぶことと承認を得て改善を起票することに合わせる
