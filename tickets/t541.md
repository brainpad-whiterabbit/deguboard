## 概要

t530 の続き。実機（Claude Code 2.1.318、2026-11-07）で確かめた 2 つの振る舞いに、t530 の SubagentStop と SessionEnd のハンドラを合わせる。

1. サブエージェントが親に質問を返して止まると SubagentStop が発火し、親が SendMessage で続きを送ると**同じ `agent_id`** で SubagentStart と SubagentStop がもう一度発火する（記録は同じファイルに追記）。t530 はこの最初の Stop で「PR がない」として `failure` で閉じるので、答えを受けてからの作業が記録に入らない
2. SubagentStop のフックが走る瞬間、記録のファイルには最後の応答（assistant の行と使用量）がまだ書かれていない（最後は api-request の行）。0.5 秒以内に書かれ、その後は増えない。その場で数えると最後の応答が欠ける

直す規則：SubagentStop では、step が終わった事実（実装：draft PR がある。見直し：結果が記録されている。手直し：開始より後の push がある）があるときだけ閉じる。なければ Run は開いたまま残し、「止まって待っている」印（時刻だけ。質問の文は MT-4 のとおり記録しない）を実行中の記録に付ける。同じ `agent_id` の SubagentStart が来たら、その開いた Run を続きとして使い、印を消す。閉じる前に、記録のファイルの最後の api-request より後に assistant の行（使用量付き）が出るまで待つ（上限数秒）。間に合わなければその場では閉じず、次の機会（次のフック・`sync`・SessionEnd）で数えて閉じる。SessionEnd は、このセッションの `agent_id` 付きの開いた Run をすべて閉じる（見直し・手直しは `interrupted`、実装は draft PR がなければ `failure`）。親が自分で進める Run（`agent_id` なし）は今までどおり PR の記録で閉じ、セッションをまたいで開いていてよい。「止まって待っている」印の付いた開いた Run は、e14 の「人待ち」と t533 の `wait_human` の材料になる。

## 受け入れ条件

- [ ] SubagentStop は、step が終わった事実があるときだけ閉じる。なければ閉じず、実行中の記録に「止まって待っている」印（時刻）を付け、`run list --running` でそれが分かる
- [ ] 同じ `agent_id` の SubagentStart が、開いた Run を続きとして使い、印を消す（新しい Run を開かない）。その後の Stop でファイル全体を数えて閉じたとき、最初の Stop までの応答と再開後の応答の両方が使用量に入るテストがある
- [ ] SubagentStop は、記録の最後の api-request より後に assistant の行が出るまで待ってから数える（上限は数秒）。間に合わなければ閉じずに警告し、次のフック・`sync`・SessionEnd のどれかが数えて閉じる
- [ ] SessionEnd は、このセッションの `agent_id` 付きの開いた Run をすべて閉じる（見直し・手直しは `interrupted`、実装は draft PR がなければ `failure`、あれば `success`）。`agent_id` のない Run は触らない
- [ ] 前景の起動（Stop が PostToolUse より先に来る形）の扱いは t530 のまま壊れていない
- [ ] requirements.md の RN-6 と ADR-005 の記述が実装に合い、`mise run check` が通る
