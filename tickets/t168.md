## 概要

見直し（audit-s5、観点：文書と実装）の指摘。仕様の判断が要る。

- guide-work.md:21 は、planned の Iteration のチケットに着手すると聞かずに `iteration start` する。ほかに active の Iteration があるかは見ない
- `iteration start`（packages/core/src/commands/iteration.ts:196–212）は planned かどうかしか確かめない。`iteration reopen`（iteration.ts:260–277）も、ほかの active を見ずに active に戻す
- カンバンは最後に札で選んだ Iteration（board.iteration）を先に選び、それがなければ番号の小さい active を選ぶ（packages/web/src/pages/board.tsx:93–103）
- guide-work の手順 1 の「Iteration に入れる」（t214、active がなければ次の planned）と、guide-assign・audit・release・all・plan の「active を勧める」も、active が 1 つの前提で書いている
- 前の Iteration を閉じる前に次のチケットに着手すると active が 2 つになり、まだ札で選んでいない画面の既定は古い方になる。active を 1 つに限るかどうかは、requirements（IT-1）にも ADR にも書いていない

## 受け入れ条件

- [ ] active を複数許すかどうかが requirements（IT-1）に書かれ、理由が ADR にある（ADR-004 は予算 99% なので、置くなら ADR-006 を先に考える）
- [ ] 決めたとおりに、`iteration start`・`iteration reopen`、手順（guide-work の手順 1 と 2、guide-all・assign・audit・release・plan の既定の勧め方）、カンバンの既定の選び方（札で選んだ Iteration がないとき）が揃っている
