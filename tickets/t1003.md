## Summary

s37 の見直し（観点：構成）で、packages/cli/src/hooks.ts の `installHooks`・`uninstallHooks`・`checkHooks` が、設定ファイルの書き込み・.gitignore への追記・判定を cli の中で行っていることが分かった。CLAUDE.md は「すべての操作は packages/core/src/commands/ のコマンド定義に置き、入口にロジックを書かない」と定め、ADR-033 の例外（AG-4 の CLI だけの操作）に hooks は入っていない。Skill は同じ形を core に移している（packages/cli/src/skill.ts の冒頭のコメント）。

あわせて、packages/cli/src/gitignore.ts は core の git 層を通さずに git を呼ぶ。packages/vscode/src/launcher.ts の dg コマンドの設置の判定も入口にあり、cli の側と役割が重なるかは確かめていない。

core に移すか、hooks を CLI だけの操作に入れて理由を ADR-033 に書くかは計画で決める（設計の判断が要るので Iteration に入れない）。

## Acceptance criteria

- [x] `dg hooks install`・`uninstall`・`check` の判定と書き込みが、CLAUDE.md と ADR-033 の決まりに合う場所にある（core に移すか、CLI だけの操作として ADR-033 と要件に理由がある）
- [x] cli から git を呼ぶ処理が、core の git 層を通るか、通らない理由がコメントにある
- [x] VS Code の launcher.ts の設置の判定を、入口に置くか共有の部品に寄せるかが決まり、PR の本文かコメントにある
- [ ] 移した処理のテストがあり、`dg hooks` の振る舞いが変わっていない
