## Summary

親セッション（dgall・dgwork を回す指揮役）は、PR を作るチケットの implement と fix を自分でせず、1 件だけのときもサブエージェントに brief で頼む。
チケットの Run の使用量を、サブエージェントの会話記録から数えた値にそろえるため（親で進めた Run は親の長い文脈を読み直す分が入り、2026-11-11 の記録では出力 1 あたりの cache_read がサブエージェントのおよそ 2 倍だった）。
指揮役のトークンは、チケットと関係のない相談も混ざるので計測しない（ADR-029 の「親の作業は Run にしない」は変えない）。
フックが届くセッション（今は Claude Code）だけを対象にする。フックのない AI では印で頼んでも Run が開かないので、今の、親が自分で進める手順を残す。手直しは小さくても例外を作らない。
人が自分で進める作業と、PR の要らない作業（`claim --without-branch`）は対象にしない。

## Acceptance criteria

- [x] guide（work・review・run・overview）で、implement と fix は、フックが届くセッションでは小さな手直しを含めていつもサブエージェントに brief で頼む手順になっている。親が自分で進める手順は、フックが届かないときの手順としてだけ残っている
- [x] `dg next` の説明と返す commands が、フックが届くセッションでは、モデルが親と同じときも親が自分で進める道を案内しない（テスト）
- [x] agent が、フックが届いたセッション（hook-sessions）から `--no-run` なしで `ticket claim` を呼ぶと、サブエージェントに頼むよう警告が出る（`--without-branch` を除く。もう一度の claim を含む）。フックが届いていないセッションでは出ない。claim と Run の開き方は今のまま（テスト）
- [x] ADR-025・ADR-029 の、親が自分で進める Run についての記述が今の判断に書き換わり、requirements.md の RN-5 が約束と食い違っていない
