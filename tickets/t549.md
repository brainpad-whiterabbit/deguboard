## 概要

t543（PR #486）の見直しで残った軽い指摘 2 件。

- 前景の起動で durationMs が取れないと、起動の時刻が今になる。見直し役が古い Run に書いた結果は保留に移らず、古い Run と一緒に interrupted で閉じられて失われる
- dg sync の closeStoppedRuns はセッションで絞らない。落ちたセッションが書き終わり待ちの途中で落ち、前景の見直しの間に sync が走ると、古い Run が今回の結果を付けたまま success で閉じる。新しい Run には結果が残らない

## 受け入れ条件

- [ ] 前景の起動で durationMs がないときも、起動より後に書かれた見直しの結果が新しい Run に結び付く（テストで確かめる）
- [ ] 見直しの間に sync が走っても、別のセッションの古い見直しの Run を今回の結果付きで閉じない（テストで確かめる）
- [ ] ADR-015 の「その後に結果を書くほかに更新されない」の前提と決定の文がコードに合う
- [ ] mise run check が通る
