## 概要

観点：不具合（t605 の実装で見つかった）。`--resolve` を付けない `dg sync` の `renumberProvisional` は、ローカルのファイルの中身をリモートの先端にそのまま書くため、リモートが同じファイルの競合しない別フィールドを変えていると、その変更が消える。`--resolve` の道（`renumberCollisions`）は merge-base の上で書き直してマージドライバを通すので失わない。

## 受け入れ条件

- [x] 一時ディレクトリの bare リモート付きリポジトリで、ローカルが仮番号のチケットを持ち、リモートが同じファイルの別のフィールドを変えた分岐を作ると、dg sync の後にリモートの変更とローカルの変更の両方が残る
- [x] 既存の仮番号の振り直しのテストが通る
- [x] 振り直しの途中で失敗したとき、まとめ待ちの変更と作業ツリーが元に戻る
