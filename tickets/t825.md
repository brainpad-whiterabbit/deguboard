## Summary

VS Code 拡張を Marketplace（Publisher ID は作成済みの `deguboard`、拡張の ID は t827 で `deguboard.deguboard` にする）と Open VSX（Cursor・Windsurf・VSCodium の利用者が使う）に出す。GitHub Actions には、Release の公開をきっかけに、その Release に添付した VSIX（ローカルで検査し SHA256 を本文に載せたもの）を両方に出すワークフローを 1 つだけ置く。CI では build しない。プラットフォームは指定せず 1 つの VSIX を出す。Marketplace へは trusted publishing（`vsce publish --oidc`、PAT を使わない）で、Open VSX へは GitHub の secret に置いたトークンで出す。検査は CI で回さず、ローカルの検査をマージの条件にするのは変えない。初回の公開と公開先の準備は、このチケットのあとに人が t840 で済ませる。

## Acceptance criteria

- [ ] Release を公開したときだけ走り、その Release に添付した VSIX を Marketplace と Open VSX に出すワークフローが `.github/workflows/` にある。CI では build しない
- [ ] Marketplace へは PAT を使わず trusted publishing で出し、Open VSX へは secret に置いたトークンで出す。それ以外の秘密を使わない
- [ ] ワークフローが検査（`mise run check` など）を回さない
- [ ] ADR-008 の本文が「CI で検査はしないが、Marketplace と Open VSX への公開には GitHub Actions を使う」という今の判断と理由に書き換わっている
- [ ] development.md の「リリース」が、利用者に届ける経路として Marketplace と Open VSX を含み、下書きの Release に VSIX を添付してから公開する順番と、その準備（Marketplace の trusted publishing の設定、Open VSX の namespace と secret）を案内している
