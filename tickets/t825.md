## Summary

VS Code 拡張を Marketplace（Publisher ID は作成済みの `deguboard`）に出す。GitHub Actions には、Release の公開をきっかけに VSIX を作り、trusted publishing（`vsce publish --oidc`、PAT を使わない）で Marketplace に出すワークフローを 1 つだけ置く。検査は CI で回さず、ローカルの検査をマージの条件にするのは変えない。初回の公開は人が Marketplace の管理画面から手でアップロードする想定。

決まっていないこと（着手の前に人に確かめる）:
- 拡張の `name`（今の `deguboard-vscode` のままにするか `deguboard` にするか）。公開したあとに変えると別の拡張になる
- Open VSX にも出すか

## Acceptance criteria

- [ ] Release を公開したときだけ走り、VSIX を作って Marketplace に出すワークフローが `.github/workflows/` にある。PAT などの秘密を使わない
- [ ] ワークフローが検査（`mise run check` など）を回さない
- [ ] ADR-008 の本文が「CI で検査はしないが、Marketplace への公開には GitHub Actions を使う」という今の判断と理由に書き換わっている
- [ ] development.md の「リリース」が、利用者に届ける経路として Marketplace を含み、Release の公開で Marketplace に出ることと、trusted publishing の準備（Marketplace 側の設定）を案内している
- [ ] 拡張の `name` と Open VSX の扱いが人の判断どおりになっている
