## Summary

今の README は「カンバンボード」として始まるので、Jira・Redmine に MCP を足した構成との違いが伝わらない。英語版と日本語版の冒頭・箇条書き・新しい節で、Agentic-Agile の開発の流れを守るツールであることを先に出す。

## Acceptance criteria

- [x] 英語版と日本語版の冒頭が、「AI エージェントに開発を任せるための開発の流れを Git リポジトリに組み込むツールで、カンバンはその窓口」と説明している
- [x] 箇条書きが 4 つになっている。先頭に「決まりを仕組みで守る」がある。「主導権は人」から根拠のない約束（振り回されない）が消えている。「チームで共有」「測って改善」は今のまま
- [x] 「仕組み」の節のすぐ上に、新しい節「なぜ deguboard か」（英語版は Why deguboard）がある。Jira・Redmine・GitHub Projects に MCP を足した構成との比較表を、5 つの軸（エージェントに任せる・決まりと承認・測って改善・チームで共有・導入と運用）で並べ、13 の観点（次に何をするか・中断と再開・並列の作業・人の承認・品質ゲート・エージェントの誤操作・エージェントの作業の記録・振り返りの指標・同時編集の競合・見られる人・他のサービスとの連携・置き場所・導入の手間と費用）で比べている。他のツールが有利な行も入れ、有利な側のセルの頭に ✅ を付け、優劣を付けられない行には付けない。フックがすべて効くのは今は Claude Code だということが書いてある。他のツールにもある機能（PR のマージで Issue を閉じる、ブランチ保護、ワークフローの遷移の条件）を deguboard だけの違いとして書かない。向かない場面の節は作らない
- [x] 表の deguboard の列が、README・docs/usage・docs/how-it-works・docs/requirements.md に書いてある振る舞いだけで書かれている（ない機能を約束しない）
- [x] ヒントの「カンバンの操作はエージェントに頼む」が、決まりの点検を通すためという理由つきで「使い方」の冒頭に移っている。動作環境の「エージェント」の項から、新しい節と重なる部分が消えている
- [x] 英語版に相対リンクがない。`mise run check:docs` が通る（節の構成・アンカー・重複）

### 比較表の案（検討で練った日本語版の文面。実装で直してよい）

| 軸 | 観点 | チケット管理ツール＋MCP | deguboard |
|---|---|---|---|
| エージェントに任せる | 次に何をするか | エージェントが指示書と会話から判断する | ✅ dg がチケット・ブランチ・PR・Run の事実から次の 1 手を返す |
| | 中断と再開 | 会話の文脈に頼る | ✅ 事実から段階を求めるので、同じ依頼で続きから再開する |
| | 並列の作業 | ブランチや作業場所は人やエージェントが用意する | ✅ チケットごとに作業ブランチと worktree を作り、エージェントが並列に実装する |
| 決まりと承認 | 人の承認 | どこで人に聞くかを指示書に書き、守るかはエージェント次第 | ✅ Workflow で決め、人だけが行える操作は dg がエージェントに拒否する |
| | 品質ゲート | CI とブランチ保護で組める | ✅ 検査と、別のエージェントによる独立した見直しを、判定したコミットに結びつけて判定する |
| | エージェントの誤操作 | MCP の権限の範囲なら、エージェントは何でもできる | ✅ 決まりに合わない操作は拒否し、dg を通さないデータの書き換えやマージは止める |
| 測って改善 | エージェントの作業の記録 | 残らない | ✅ フックが作業ごとに時間・やり直し・トークンを記録する |
| | 振り返りの指標 | 人の作業の指標（ベロシティ・バーンダウンなど）が充実 | エージェントの指標の推移から改善を起票する |
| チームで共有 | 同時編集の競合 | ✅ サーバーが一元管理するので、競合が起きにくい | 項目ごとに自動で解き、解けない競合は両側の値を示して人が選ぶ |
| | 見られる人 | ✅ エンジニア以外も Web で見られ、権限も細かく分けられる | リポジトリと VS Code を使う人 |
| | 他のサービスとの連携 | ✅ 豊富 | Git と GitHub だけ |
| 導入と運用 | 置き場所 | 外部サービスと認証 | ✅ リポジトリのブランチ。clone すれば人もエージェントも読める |
| | 導入の手間と費用 | サービスの契約か、サーバーの運用が要る | ✅ 拡張と CLI を入れるだけ。MIT で、サーバーは要らない |

軸の英語名の案：Hand work to agents・Rules and approvals・Measure and improve・Made for teams・Setup and operation。

### 実装のときに決める論点（決めたら PR の本文に書く）

- 「置き場所」と「導入の手間と費用」はどちらも外部サービスが要らないことを言っている。1 行にまとめるか、「置き場所」を「人もエージェントも同じボードを clone で読める」に絞る
- 「次に何をするか」と「中断と再開」は、どちらも事実から段階を求めることから来ている。まとめて 1 行にするか
- 他のツールの列の「残らない」「何でもできる」は言い切りが強い。「エージェントの作業ごとの記録はない」「MCP の権限の範囲で操作でき、手順の決まりはない」のように範囲を限って書くか
- 「品質ゲート」は、他のツールでも CI とブランチ保護で組めるので差が小さい。✅ を残すか
