## Summary

人がチケットの中身をひと目でつかむためのラベルを、プロジェクトが決めた軸（触る部分・変更の種類など）に沿って付けられるようにする土台。軸はチームの `config.yaml` の `labels.axes` に名前と 1 行の説明で置く。既定はオフで、書いていない（まだ決めていない）・`[]`（止めると決めた）・一覧（使う）の 3 つの状態を持つ。振り返りの観点（`retro.perspectives`、ADR-035）と同じく、入れ子なので専用のコマンドで書く。検討案は https://claude.ai/artifact/KGayJ5QkZpiv4ojHquoDYT

## Acceptance criteria

- [x] `labels.axes`（軸の名前と説明の一覧）をスキーマで検査し、書いていない・`[]`・一覧の 3 つの状態を区別して読める。チームだけが持ち、個人の設定では上書きできない
- [x] `dg label axis set <name> --description` と `dg label axis remove <name>` が軸を書き、`governance.config` で判定する。`config set` は `labels.axes` を書かない
- [x] Core が軸の候補（既定の候補の area・kind、推薦の impact・platform・audience）と kind の推薦の語彙（feature・bug・refactor）を英語の名前と説明で持ち、`dg label axis list --candidates` で出す
- [x] 設定画面が軸を読むだけで出す（UI-14。候補のままの軸の説明は表示言語に訳す）
- [x] requirements.md の 5.10 に `labels.axes` の項を足し、新しい ADR に軸と語彙の置き場所・既定はオフで点検が勧めること・統合は書き換えること・採らない案（flow の段・許可リスト・読み替え・ラベルの ID・チケットの軸ごとの項目・既定の軸）を書く
