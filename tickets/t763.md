## Summary

品質ゲートの「最後の push より後の見直し」は、作業ブランチのリモートの先端のコミット日時を push の時刻の近似として比べる。別の clone で先に作ったコミットを見直しの後に push したとき、時計のずれ、古いコミットへの force-push では、見直していないコミットで条件が通る。見直しを始めたときの作業ブランチのローカルの先端（refs/heads/<branch>）を Run に記録し、品質ゲートと dg next の両方がその SHA で判定する。SHA を持たない前からの Run は、今のコミットの日時の比べ方で判定する。保留の見直しを push の区切りでまとめる処理はコミットの日時のままにする。

## Acceptance criteria

- [ ] 見直しの Run と、フックのない AI の見直しの結果は、始めたとき（または結果を書いたとき）の作業ブランチのローカルの先端の SHA を記録する
- [ ] 品質ゲートと dg next は、最後に通った見直しの SHA がリモートの先端と同じかで判定する。SHA を持たない見直しは今のコミットの日時の比べ方で判定する
- [ ] 見直しの前に作ったコミットを見直しの後に push したときゲートが落ちること、push の前に見直して後で push したとき通ること、SHA のない見直しが今までどおり判定されることをテストで示す
- [ ] requirements.md の Run の項（RN）に見直しの SHA を記録することを 1 文で足し、dg gate --help の見直しの条件を SHA で判定する形に直す
