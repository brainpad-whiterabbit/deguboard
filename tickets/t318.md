## 概要

今はどのチケットも同じモデルで処理している。Plan の details にチケットごとの段階（`tier`：`light`・`standard`・`heavy`）を持たせ、`config.yaml` の `models.*` で段階をモデル名に対応させる。手順（guide）がそれを読んでサブエージェントの `model` に渡す。dg はエージェントを起動しない（ADR-004）ので、dg が持つのは段階と対応の記録だけにする。

- 段階は dgplan が scope・approach と一緒に決め、人は承認の表で確かめる。モデル名は Plan に書かない（Adapter とモデルの世代に依存させない）
- 役割ごとのモデル：実装と修正ループはチケットの段階、見直し役は親のモデル（品質ゲートを弱めない）、実装の中の調べものは `models.light`
- 1 件だけ進めるときも、段階のモデルが親と違うときだけ実装をサブエージェントに渡す。同じなら今までどおり親が実装する
- `models.*` が空なら親のモデルのまま（今の振る舞い）。モデルを選べない環境でも今の振る舞いのまま

## 受け入れ条件

- [ ] `plan create --tier t3=light` で `details.<ticket>.tier` が記録され、`plan show` に出る。不正な値と Plan に入れていないチケットは拒否される
- [ ] config に `models.light`・`models.standard`・`models.heavy`（string、既定は空）があり、設定画面に出る
- [ ] guide-plan に `--tier` と段階の基準（light：文書・設定・文言だけ／heavy：設計の判断・データの形・複数パッケージ・原因の分からない不具合／standard：それ以外）があり、承認の表に段階の列を出す
- [ ] guide-work と guide-parallel に、段階のモデルが親と違えば実装をそのモデルのサブエージェントに渡し、`run start --model` を付けることが書いてある
- [ ] guide-work に、実装の中の調べもののサブエージェントは段階によらず `models.light` で起動する（空なら親のモデル）と書いてある
- [ ] guide-review に、見直し役は段階によらず親のモデル、修正ループは実装者と同じモデルで進めると書いてある
- [ ] requirements.md の PL-1（details の tier）と 5.10（models.*）、ADR-004 の Plan の節（段階を Plan に書く理由）を直し、`mise run check:docs` が通る
- [ ] plan create の tier と configFields の models.* のテストがあり、`mise run check` が通る
