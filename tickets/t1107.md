## Summary

Epic e40 の方針を dg sync の照合に当てはめる 2 件目（1 件目は t1105。t1105 で入れた「行うことの列」を返す決める関数に、残りの Run の閉じ方を加える）。

`packages/core/src/commands/setup.ts` の `reconcileAll` では、次がまだ書き込みと一体になっている。

- 手直しの Run を閉じる：区切りを決める `fixRunBoundary` の後、`closeFixRun` がロックの中で `lastPushedAt`（git の読み）を呼んでから閉じる
- 照合の対象にならなかった実行中の Run を閉じる（終わったチケット、もう一度の claim か、PR のある done、todo、別の主体、で閉じ方が分かれる）

手直しの Run の最後の push の時刻はロックの外でほかの事実と一緒に集め、決める関数がこれらの閉じ方も列で返すようにする。

## Acceptance criteria

- [ ] 手直しの Run の閉じ方（区切りは次の Run の開始・前進・終わったチケット。結果と finished_at）と、照合の対象にならなかった実行中の Run の閉じ方（終わったチケット、もう一度の claim、PR のある done、todo、別の主体）を、t1105 の決める関数が返す行うことの列に入れる
- [ ] 手直しの Run の最後の push の時刻（lastPushedAt）をロックの外でほかの事実と一緒に集め、集めた後にチケットが変わったときは判定しない
- [ ] 照合の結果の push が拒否されたとき（reconcileLocked の push）、コミットをローカルに残して警告し、次の sync で取り込み直して送る今の扱いが変わらず、その取り込み直しの途中で止まっても、閉じた Run の記録と実行中の Run の消去（dropRunning）が二重にも欠けにもならないことをテストで確かめる
- [ ] Run の閉じ方の組み合わせ（終わったチケット、todo、別の主体、PR の有無と作成時刻、次の Run の有無と同じ秒、push の時刻）をその関数のテストで確かめ、commands-flow-reconcile.test.ts から判定だけを確かめていた件を移す。移した件と残した件の対応を PR に載せる
- [ ] dg sync の出力と書き込みが変わらない
- [ ] 全体のテストの時間と commands-flow-reconcile.test.ts の時間の変更前後を PR に載せる
