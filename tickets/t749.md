## Summary

push が届かない（unreachable）とき、writeLocked は仮番号を付ける操作以外も、警告を 1 つ足してローカルのコミットのまま成功を返す。そのため、オフラインの 2 台で同じチケットを claim でき、別々に Iteration を start すると active が 2 つになる（IT-1 が黙って崩れる）。Epic・Iteration・Plan はオフラインで作っても仮番号にならず、番号がぶつかると dg では解けない。仮番号のチケットも claim でき、仮番号がブランチ名に入ったまま、振り直しでチケットの branch だけが書き換わる。

## Acceptance criteria

- [x] push が届かないとき、ticket claim・iteration start・iteration reopen は自分のコミットを捨てて失敗し、worktree も Run も作らない
- [x] push が届かないとき、epic・iteration・plan の create は自分のコミットを捨てて失敗する
- [x] 仮番号のチケットの claim は、先に dg sync で番号を確定するよう案内して拒否する
- [x] リモートに届かない bare リモートで、上の 3 つをテストで示す。リモートのない運用（SY-6）は今までどおり書けることもテストで示す
- [x] requirements.md の SY-3 と DT-5 を、届かないときに失敗する約束に合わせて直す
