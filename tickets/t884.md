## Summary

今はリリースの PR で `dg pr merge` が `GATE_FAILED` を返すと、人に `gh pr merge` を打ってもらうよう案内し、フックも agent の `gh pr merge` を止める。そのため人がマージのコマンドを打っている。リリースの PR は、マージしてよいかを人に聞き、承認されたら agent が dg のコマンドでマージできるようにする。前回のリリースのマージがどの条件で止まったかは、着手するときに t872 の記録で確かめる。

## Acceptance criteria

- [ ] リリースの PR は、マージしてよいかを人に聞き、承認されたら agent が dg のコマンドでマージする。人に gh のコマンドを打ってもらう案内は出さない
- [ ] 誰が承認してマージしたかが記録に残る
- [ ] 人の承認がなければ、agent はリリースの PR をマージできない
- [ ] 承認があっても、衝突（`mergeable`）と head の確かめは外さない
- [ ] guide（release・review）、requirements.md の項、関わる ADR を同じ PR で直す
