## 概要

経過（チケット 1 枚の history）は git log でそのチケットのファイルに絞っているが、git は data ブランチの 3,028 コミットすべての木の差分を取って確かめるので約 360ms かかる。結果のキャッシュは data ブランチのコミットのたびに外れる。data ブランチだけの写し（bare clone）で計ると、変更パスの Bloom filter 付きの commit-graph があってパスが 1 つのときは約 13ms だった（3,028 コミットのうち 3,015 を差分なしで飛ばした）。パスが 3 つだと git 2.47 は索引を使わず約 310ms、commit-graph がなければパスが 1 つでも約 330ms。調査の結果は https://claude.ai/artifact/DRdnJTikZviCUmfaCmbnF6

## 受け入れ条件

- [ ] チケット 1 枚の経過の git log を Bloom filter が効く形（パス 1 つ）で読み、拡張子の違うファイルの経過も今と同じに出ることをテストで確かめている
- [ ] data ブランチのコミットを Bloom filter 付きの commit-graph が覆う仕組みがあり、書き込みと同期で増えたコミットも足される
- [ ] commit-graph を書けない・古い git・浅い clone でも、経過は今と同じ結果で出る
- [ ] 利用者のリポジトリに commit-graph を書くかどうかと、その時機の判断を示す（ADR を書く場面に当たるなら ADR に、当たらなければコメントとテストに）
- [ ] 実際のリポジトリで、チケット詳細の経過の時間を変更の前後で計って PR に示す
