## 概要

ticket create / import は --summary を ## 概要 に入れるだけで、## 受け入れ条件 には空の `- [ ] ` を置く。lint の lint_acceptance_empty は本文全体を見るので、この空行をチェックリストと数えて指摘しない。guide create の例も --summary だけで起票する形になっている。createInput に acceptance（自由文の配列。CLI ではカンマで割らない）を足して雛形に並べ、lint を ## 受け入れ条件 の節の中で `- [ ] ` に続く文字があるかで判定し、guide と requirements の TK-3 を直す

## 受け入れ条件

- [ ] `dg ticket create --acceptance "<条件>"` を繰り返すと、本文の ## 受け入れ条件 に項目ごとの `- [ ]` が並ぶ
- [ ] `ticket import` の下書きの `acceptance:` でも同じ本文になる
- [ ] `--acceptance "a, b"` はカンマで割れず 1 項目になる。`--label a,b` は今までどおり 2 項目
- [ ] 雛形のまま（`- [ ] ` だけ）のチケットに `dg lint` が lint_acceptance_empty を出し、## 概要 にだけチェックリストがある本文も空と判定する
- [ ] `dg guide create` の例に --acceptance と YAML の acceptance が載る。requirements.md の TK-3 が summary と acceptance から雛形を作ることと lint の指摘を書く
