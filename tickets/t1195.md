## Summary

s43 の見直し（観点：文書と実装）の指摘。語彙と統合の操作（`dg label add`・`update`・`remove`・`merge`）は名前を小文字にそろえる（`dg label add --help` に「UI becomes ui」とある）。一方、チケットに書く `--label`（`ticket create`・`ticket update`・`ticket import`）と `ticket list --label` は大文字小文字をそのまま扱う。そのため、語彙に `ui` があるボードで `--label UI` を書くと `UI` がチケットに残って lint の指摘になり、統合済みの名前を大文字で書くと統合先へ読み替えられない（TK-13 の読み替えの約束が大文字では漏れる）。`ticket list --label UI` は `ui` のチケットに当たらない。

方針は決めた（s44 の検討）。チケットに書くとき（`ticket create`・`update`・`import` の `--label`）と絞るとき（`ticket list --label`、画面の絞り込み）に、軸や語彙の有無にかかわらず名前を小文字にそろえ、語彙・統合と同じ規則にする。そろえた後に統合済みの名前を読み替える。既存のチケットに大文字のラベルが残るボードでは、そのラベルは書き直されるまでそのまま残し、絞り込みでは小文字の名前で当たるようにする。利用者に見える変化なので、Release の本文に書く。このボードには大文字のラベルは 0 件で、移行は要らない。

## Acceptance criteria

- [x] `ticket create`・`update`・`import` の `--label` が名前を小文字にそろえてから統合済みの名前を読み替えることを、純粋な関数のテストで確かめている（`UI` が語彙の `ui` に当たる、統合済みの名前を大文字で書いても統合先になる）
- [x] `ticket list --label` と画面のラベルの絞り込みが、大文字小文字の違う名前でも同じチケットに当たる（大文字のラベルが残る既存のチケットにも当たる）ことをテストで確かめている
- [x] 大文字のラベルを持つ既存のチケットの読み込みと `dg validate` が通り、lint が今までどおり大文字小文字だけが違う組を指摘することをテストで示している
- [ ] `ticket create --help` と `ticket list --help` が小文字にそろえることを書き、requirements.md の該当の項（TK-13）と名前の規則を書いた ADR-037 の箇所を同じ PR で直している
