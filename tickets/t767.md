## Summary

t624 はコンパイルキャッシュを bin/dg.js でだけ有効にしていて、VSIX に同梱する dist/cli/dg.mjs（入口は packages/cli/src/bundle.ts）では使っていない。拡張の利用者の dg（フックを含む）は毎回すべてをコンパイルし直している。dg.mjs は 2MB を 1 ファイルに束ねている（codeSplitting: false）ので、その中で enableCompileCache を呼んでも dg.mjs 自身はもうコンパイル済みで、キャッシュに残らない（試して、キャッシュの置き場所に何も書かれないことを確かめた）。dg.mjs を、キャッシュを有効にしてから本体の chunk を読む小さな入口にする。ADR-008 の「同梱の CLI を 1 つの ESM に束ねる」を変える。外からキャッシュを有効にした計測では、同梱の dg.mjs の PreToolUse が約 182 ms から約 158 ms になった。

## Acceptance criteria

- [ ] 同梱の dg.mjs は入口だけを持ち、コンパイルキャッシュを有効にしてから本体の chunk を読む。使えない Node や書けない置き場所では黙って飛ばす（bin/dg.js と同じ）
- [ ] 2 回目からの起動で本体の chunk がキャッシュから読まれることを確かめ、PR の本文に書く
- [ ] 本体の chunk は dg.mjs と同じディレクトリに置き、guide・Web の画面・skill.md の引き方は変わらない
- [ ] フックのコマンドの形と同梱の dg のパス（dist/cli/dg.mjs）は変わらず、入れ直しは要らない
- [ ] VSIX に dg の chunk が入り、VSIX から入れた dg で dg --version と PreToolUse が動くことを PR の本文に書く
- [ ] ADR-008 の同梱の CLI を束ねる項を書き換える
- [ ] 同梱の dg.mjs で PreToolUse を 5 回測り、有効にする前と後の中央値を PR の本文に書く
