## Summary

サブエージェントが止まって親の続きの依頼を待つ間も Run は開いたままで、その時間が Run の時間（duration_seconds）に入る。t929 の手直しの Run は、親が人に質問している 4 時間を含めて 4h09m56s と記録され、作業は約 5m31s だった。待ちの印（waiting_since）はフックの処理の時刻で付け外しされ、閉じるときに消えるので、待ちは残らず、時刻と順序にも左右される。

閉じるときに、使用量と同じ会話記録から待ちの区間を数え、閉じた Run に待った秒数を残す。待ちは「ターンが終わってから、親からの依頼が記録に入るまで」の空きだけにし、自分のバックグラウンドのコマンドの通知・harness の催促で続いた空きと、ツールの結果を待つ間は作業に数える。入力の出どころは記録の文でなく項目で見分ける。duration_seconds は経過時間のまま残し、作業時間は表示と集計のたびに経過時間から待ちを引いて出す。待ちを数えられない Run（親が自分で開いた Run、関数のない Adapter の Run）は 0 でなく null にする。フックの待ちの印は dg next の表示にだけ使い、数には使わない。

## Acceptance criteria

- [ ] Claude Code の Adapter が会話記録と Run の範囲から待ちの区間を返し、待ちは親の依頼（origin.kind が coordinator）で続いた空きだけで、ほかの入力で続いた空きとツールの結果を待つ間は作業になり、知らない形の入力では null と警告になることをテストが確かめている
- [ ] 閉じた Run に waited_seconds が入り、区間は started_at から finished_at の範囲で切られ、数えられない Run は null になることを、t929 の手直しの記録の形（待ち 4h04m25s）を含むテストが確かめている
- [ ] dg run list と dg metrics show が active_seconds と waited_seconds を出し、値の欠けた Run を missing に数える
- [ ] requirements.md の RN-1 と metrics の項、ADR-025 と ADR-029 の本文が、待ちを数えて作業時間から除くことに合っている
