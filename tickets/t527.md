## 概要

ADR-003「手続きは YAML に書かず `dg guide` のテキストにして AI が判断する」を反転する。チケットの作業の既定の手続き（段階 claimed → implemented → reviewed(n) → fixed(n) → ready → merged、次の 1 手、修正ループの回数、品質ゲート、サブエージェントに渡す brief）は dg のコードが持ち、guide は各手のやり方だけを書く。利用者が YAML に手続きを書く形は引き続き採らない。人の判断の穴（Plan の承認・マージ・やめる）は残す。速度低下の調査で、親の LLM が 55KB の手順を読んで手続きを進めることが、親の出力トークンの 38%・経過時間の空き 48%・guide の 6 日で 4 倍の肥大の原因と分かった。

## 受け入れ条件

- [ ] 新しい ADR-011 に「既定の手続き（段階・次の 1 手・修正ループの回数・品質ゲート・brief）は dg のコードが持つ。guide は各手のやり方だけ」の決定があり、理由に調査の数字（親の負荷・guide の肥大・守られ方が確率的）と、ADR-003 の「Workflow YAML は制約と語彙を書く」の「書かないもの」の手続きの項（と ADR-004 の「並列実行・修正ループ・自動マージも guide 側が進める」の項）を置き換えることが書かれている
- [ ] ADR-001 の書き方どおり、ADR-003・ADR-004 の置き換えた節の頭に「※ ADR-011 で置き換え（この節は失効）」の 1 行があり、ほかの判断と理由は書き換えていない
- [ ] 採らなかった案に「手続きを guide のテキストに置く（今まで）」と「利用者が YAML に手続きを書く」の両方がある
- [ ] requirements.md の EX-3・CL-5 が新しい決定と矛盾しない（段階と次の 1 手は Core のコマンド、guide は手のやり方。未実装の部分は予定（e15））
- [ ] docs/adr/README.md の有効な ADR の表に ADR-011 があり、`mise run check` が通る
