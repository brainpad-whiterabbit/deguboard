## Summary

`iteration close`・`epic close`・`epic reopen` は書き込みを溜めるので、push されるまで別の環境からは開いたままに見え、二重に閉じられて sync が競合で止まった（s26 の closed_at が両側で違った）。作成・開始・再開と同じように、すぐ push し、リモートの状態と照らして書く。

## Acceptance criteria

- [ ] `iteration close`・`epic close`・`epic reopen` が、溜まった変更を待たずにすぐ push する
- [ ] 別の環境がもう閉じた Iteration・Epic を閉じようとすると、リモートを取り込んで閉じ済みと分かり、競合を残さない
- [ ] 二重に閉じる場面を、bare リモートの 2 つの clone で確かめるテストがある
