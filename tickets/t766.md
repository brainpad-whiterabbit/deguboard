## Summary

テストの時間の 84%（951s / 1130s）は、1 件に 1s 以上かかる 432 件が占める（core が全体の 80%）。原因は、テストごとに createFixture（bare・clone 2 つ・push）→ init → 起票・config・commit を git の子プロセスで一から作ること（例：hook.test.ts の prepared()、70 件・131s）。

まず createFixture の結果（bare と clone 2 つ）を 1 度だけ作り、テストごとに写して remote の URL を書き換える（B）。hook.test.ts で効果を測り、足りなければ init まで済んだ状態を写して git worktree repair で直す（A）に進む。写すと init の worktree と clone の remote URL が持つ絶対パスが雛形を指したままになるので、直す必要がある。

## Acceptance criteria

- [x] 今のやり方・B（A に進んだら A も）の hook.test.ts の時間を、同じマシンで続けて各 3 回回した中央値と、そのときのロードアベレージで PR に載せている
- [ ] 効果があれば、替えるテストファイルを計測から選んで選んだ理由を PR に書き、mise run test の時間の変化を PR に載せている
- [x] 写したリポジトリが一から作ったものと同じに振る舞うこと（リモートの URL・deguboard のブランチ、A に進んだときは worktree も）をテストで確かめている
- [x] 雛形と写したもの、どちらの一時ディレクトリもテストの後に消える
