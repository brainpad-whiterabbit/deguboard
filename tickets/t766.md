## Summary

テストの時間の 84%（951s / 1130s）は、1 件に 1s 以上かかる 432 件が占める（core が全体の 80%）。原因は、テストごとに createFixture（bare・clone 2 つ・push）→ init → 起票・config・commit を git の子プロセスで一から作ること（例：hook.test.ts の prepared()、70 件・131s）。init まで済んだ状態をファイルごとに 1 度だけ作り、テストごとにディレクトリを写す。まず hook.test.ts で今のやり方と比べて効果を測り、効果があれば重いテストファイルへ広げる。

## Acceptance criteria

- [ ] 雛形を写すやり方と今のやり方の hook.test.ts の時間を、同じ条件で測って PR に載せている
- [ ] 効果があれば、createFixture を使う重いテストファイルを雛形を写すやり方に替え、mise run test の時間の変化を PR に載せている
- [ ] 写したリポジトリが一から作ったものと同じに振る舞うこと（リモートの URL・worktree・deguboard のブランチ）をテストで確かめている
- [ ] 雛形と写したもの、どちらの一時ディレクトリもテストの後に消える
