## 概要

見直し（audit-s11、観点：アーキテクチャ）。規約の違反はないが、s11 で入ったコードに重複と使われない残りがある。

- packages/core/src/commands/ask.ts：askHumanChecks（テストだけが使う）と buildAsk が同じ `ACTIONS[action].human?.(s, withinOf(s, within))` を呼ぶ（片方だけ直すとテストと判定がずれる）
- ask.ts の withinOf（startsWith("s"/"e")）・KIND_OF_PREFIX・runningTickets の startsWith("t") と、model/id.ts の ID_PREFIX が、接頭辞と種類の対応を別々に持つ
- packages/web/src/components/ticket-props-browser.tsx の Draft・draftOf はパネルでも使うのにブラウザ用のファイルにある
- packages/vscode/src/context-menu.ts の MenuTicket の iteration・project は t300 で外した「Iteration を移す」のためのもので、今は使わない（web の parts.tsx の BacklogItem も載せ続け、6 行のコメントは古い部品名を指す）
- Plan の状態の表示名（承認待ち・承認済み・閉じた）が core の ask.ts（PLAN_STATE_LABEL）と web の ask-composer.tsx（subOf）の両方にある
- ask-menu の組の鍵の書式（ID を空白でつなぎ @within を後ろに置く）が core（parseKey・normalizeKey）と web（ask-menu.tsx の askKey・ask-composer.tsx の splitKey・main.tsx）にあり、一致をテストで照らしていない
- packages/vscode/src/extension.ts の deliverToSidebar・askInSidebar・askCurrentInSidebar・askInPanel・askFromPalette が同じ形を繰り返す
- core の公開の面に出ているが使われない export（ask.ts の AskWithin・targetLine・askActions など）
