## 概要

競合で止まった同期を戻すには、今は人が deguboard worktree で git reset --hard し、OUTSIDE_CHANGES で止まり、dg adopt を挟んで dg sync を回すと、git と dg をまたいで 3 段かかる。人が remote か local を選んだら、dg sync --resolve がマージドライバに採る側を渡し、競合したフィールド（本文なら行）だけその側の値で rebase を続け、基準の更新・照合・push まで 1 回で行う。remote と local は対称で、コミットは捨てず、履歴を force push しない。採った値と捨てた値を結果に返す。rebase の中では git の ours が upstream（リモート）側になる点に注意する。

## 受け入れ条件

- [x] 一時ディレクトリの bare リモート付きリポジトリで、両側が同じ Plan を閉じた分岐を作り、dg sync --resolve remote（と local）が競合したフィールドだけ選んだ側の値を採って rebase を続け、照合と push まで行って ahead 0 / behind 0 になる
- [x] 競合していない未 push のコミットと、競合したファイルの競合していないフィールドはそのまま残る
- [x] 結果の data に、ファイル・フィールド・採った値・捨てた値の一覧が出る
- [x] 実行後に OUTSIDE_CHANGES にならない（外の変更の基準の更新を書き込みのロックの中で行う）
- [x] 仮番号の振り直しとまとめ待ちの未コミットの変更が混ざっても、振り直し → まとめ待ちのコミット → resolve の順で処理され、テストで確かめられている
- [x] CONFLICT_REMEDY と guide overview の「同期が止まったとき」が、人に remote か local を選択肢で聞いて --resolve を 1 回呼ぶ手順に差し替わり、--auto でも自動で選ばない旨が書かれる。requirements.md の SY-4 に戻し方の 1 文を足す
