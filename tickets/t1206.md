## Summary

`git.data_remote` に `none` を書くと、データのリモートがなしになる。コードのリモートがあっても、データはリモートのないリポジトリと同じ経路（SY-6）で動く。公開リポジトリにチケットや Run の記録を出したくないとき、チームで使う前に手元で試すときに使う。作業ブランチの push と PR の照合はコードのリモートのまま変えない。

## Acceptance criteria

- [x] `git.data_remote: none` のとき、コードのリモートがあっても、dg はデータのブランチを fetch も push もせず、起票・claim・`iteration start` はローカルにコミットして成功する。作業ブランチの push と PR の照合は `git.remote` で動く（テストで示す）
- [x] `dg init --no-data-remote` は、データのリモートに届くかを確かめずに手元にボードを作り、config に `git.data_remote: none` を記録する。`dg init` の出力：新しいボードをリモートへ push したときは、リモートを読める人なら誰でも読めることと `--no-data-remote` を伝える。`--no-data-remote` のときは、`git push --all`・`--mirror` で出ることと共有に戻す方法を伝える
- [x] データのブランチがデータのリモートにあるボードでは、チームの `git.data_remote` を `none` にする `dg config set` を拒み、`--local` を案内する。`--local` で `none` にするのは通し、claim がほかの人を排他しなくなることと戻し方を警告する。push が拒否されて取り込み直す途中で止まっても、none の判定の前後でコミットを残さない（テストで示す）
- [x] `none` を空かリモートの名前に戻して `dg sync` すると、それまでのデータの履歴がそのリモートに push される（テストで示す）
- [x] requirements.md の SY-1・SY-6 と、5.10 の `git.data_remote` の項に、データのリモートをなしにできる約束を書く
- [x] usage.md と usage.ja.md に、データを手元だけに置く使い方を書く（共有に戻すと履歴が丸ごと push されること、「なし」にしてもリモートにあるデータのブランチは消えないこと、チームのボードがあるリモートで始めると `DATA_HISTORY_UNRELATED` になること、共有しつつ公開しないなら非公開のリポジトリを指せばよいこと）
