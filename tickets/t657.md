## Summary

チケットに品質ゲートの段 `gate`（`high`・`low`・`free`）を持たせ、`dg gate`・`dg pr ready`・`dg pr merge` は段に応じた条件だけを判定する。`gate` のないチケットは high として扱い、判定は今と同じになる。

| 段 | merge で判定する条件 | ready で判定する条件 |
|---|---|---|
| high（既定） | pr・acceptance・review・fix_rounds・mergeable・check | pr・review・fix_rounds・check |
| low | pr・acceptance・mergeable・check | pr・check |
| free | pr・mergeable | pr |

- 段を下げるのは人の指示によるもので、守りは規約にする。コードで人に限ることはしない（`/dgall --gate-free --auto` が止まらずに進めるようにするため）
- low・free では、見直しの Run と push の時刻（fetch を含む）を読まない
- 段の条件の外で進めるときは、今と同じく人が gh を打つ。フックは今のまま
- 流れの変更（`dg next`・`dg flow next`・Skill・guide・CLAUDE.md）は t658 で扱う
- この PR 自体は high で通す

## Acceptance criteria

- [x] ticket create・import・update で gate を付けられ、update では null（CLI では none）で外せる。不正な値（medium など）は拒まれる（テスト）
- [x] low のチケットは、見直しの Run がなくても pr・acceptance・mergeable・check で dg gate を通り、受け入れ条件に印がないと acceptance で落ちる（テスト）
- [x] free のチケットは、merge では pr・mergeable だけ、ready では pr だけを判定し、actions.test が落ちる設定でも通る（テスト）
- [x] gate のないチケットの条件は今の high と同じで、dg gate の出力（GateView）に判定した段 gate が出る
- [x] dg gate・dg pr ready・dg pr merge の説明から「例外はない」の文がなくなり、段の説明がある
- [x] requirements.md に TK-9（段と既定の high）を足し、EX-6 を段に応じた条件に直す
- [x] ADR-026 の「例外は Core に持たせず人が gh を打つ」と、その理由を段の判断に書き換え、採らなかった案（Plan の details に持つ・パスで決める・コードで人に限る）を 1 行ずつ足す
