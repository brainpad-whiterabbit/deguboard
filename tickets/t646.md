## 概要

VS Code のパネルでチケット詳細を新しく開くと、呼び出し 14 本が 1 本ずつ処理され、1 本ごとに Store の再走査（2,224 ファイルの stat、1 回 約 43ms）が走る。合計 約 600ms で、開く時間 1.2 秒の半分を占める。画面が Promise.all でまとめて投げる読みを 1 つの束として受け、束ごとに再走査を 1 回にする。他のプロセスの変更が見えるまでの約束は変えない。調査の結果は https://claude.ai/artifact/DRdnJTikZviCUmfaCmbnF6

## 受け入れ条件

- [ ] プロセス内の CommandClient が、複数の読みのコマンド（write: false）を再走査 1 回で処理する呼び方を持ち、テストで確かめている
- [ ] 束の中の 1 本が失敗しても他の結果は返り、失敗はそのコマンドの失敗として返る
- [ ] 書き込みのコマンドは束に入れられず、今どおり 1 本ずつ処理される
- [ ] Webview（postMessage）と HTTP の入口が束を写し、store の reload とチケット詳細の読みが束で呼ぶ
- [ ] チケット詳細を新しいパネルで開いたときの再走査の回数と時間を、変更の前後で計って PR に示す
