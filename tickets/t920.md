## Summary

振り返りの観点「エージェントの安定」の測れていない部分（失敗のない Run の中で起きた遠回り）を測れるようにする。今の Run の `tools` はツールの呼び出しの種類ごとの回数で、働いた量は分かるが、無駄だった働きと分けられない。s30〜s33 の implement の書き込み ÷ 変えたファイル（1.5〜2.6）や、変更 100 行あたりの呼び出し（21〜24）を試したが、遠回りと普通の編集を見分けられなかった。

遠回りの最も直接の手がかりは、失敗したツールの呼び出し（落ちたコマンド、当たらなかった Edit、失敗したテストや検査の実行）。Claude Code の会話記録の `tool_result` は失敗の印（`is_error`）を持つ。Run を閉じるときに、ツールの回数と同じく会話記録から失敗した呼び出しの数を数え、`tools` に入れる。Git に写すのは数だけ（MT-4・ADR-029 の、ツールの結果とコマンドの文字列は写さない、の中に収める）。失敗の印を読めないエージェントの Run は missing に数える。

振り返りの指標の定義を足すのは、このチケットではしない（マージの後の振り返りで提案して、人が承認してから）。

## Acceptance criteria

- [x] Run の `tools` に、失敗したツールの呼び出しの数（`errors`）が入り、会話記録の失敗の印から数える。許可を断られた呼び出しと hook に拒まれた呼び出しも数える（印だけで数え、結果の文は読まない）
- [x] 失敗の印を読めないエージェントか会話記録の Run では、`errors` が取れないものとして扱われ、`metrics show` が missing に数える。この項目より前の Run も同じに扱う
- [x] `metrics show` が `errors` を合計して返す
- [x] Git に入る Run に、ツールの結果の中身とコマンドの文字列が入らないことをテストで示す
- [x] ADR-029 の本文と、要件の RN-1 か MT の項が、今の形に合っている
- [x] 既存のテストが通る
