## 概要

頼む小窓は候補を選ぶと `/dgdone t470` のような Skill と対象の札が出るだけで、初めて見る人には何が起きるか分からない。core の `ask` が候補ごとに「この対象にエージェントが何をするか」の 1 文（`meaning`）を返し、小窓は Skill と対象の札の下、指示欄の上に灰色の 1 文で出す。依頼文（`text`）には入れない。候補を選び直すと文も変わり、候補のボタンの言葉と札のコマンドを結ぶ。言語は `ask` の `language`（画面の表示言語）に従い、日本語と英語。文章形式の「頼む 1 文」と材料を共有し、二重に持たない。

## 受け入れ条件

- [ ] `dg ask` の結果と `candidates` の各項目に `meaning` が入り、依頼文 `text` には含まれない
- [ ] 24 種の頼むことすべてで `meaning` が空でなく、対象の ID から始まり、Status を変える頼むこと（done・やめる・再開・done の取り消し）は行き先の Status を含む。core のテストで網羅する
- [ ] `language` が en のときは英語の文になる
- [ ] 小窓は選んだ候補の `meaning` を札の下・指示欄の上に出し、候補を選び直すと文が変わる。「自由に」は Skill を使わないことを示す文になる
- [ ] web のコンポーネントのテストと l10n のスナップショットに説明行が入る
- [ ] requirements.md の UI-15 か ADR-010 に、説明の 1 文を画面に出し依頼文には入れないことを書く
