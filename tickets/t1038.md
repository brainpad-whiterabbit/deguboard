## Summary

Marketplace で拡張の名前 deguboard は、試しの版を Remove したため永久に予約され、元の publisher でも使えなくなった（公式の Publishing Extensions の Removing extensions）。packages/vscode/package.json の name を deguboard-vscode にし、拡張の ID を deguboard.deguboard-vscode にする（t827 の判断を変える）。パッケージ名を参照する箇所（.github/workflows/publish-extension.yml の pnpm --filter、.oxlintrc.json、mise.toml、pnpm-lock.yaml など）もすべて直す。displayName は deguboard のままでよい。

あわせて docs/development.md の「リリース」の「初めて出す前に、一度だけ準備する」に、t840 の切り分けでわかったことを足す。名前 deguboard で本物の VSIX を新規に上げると「Your extension has suspicious content」で拒否されたが、名前 deguboard-test では、README と説明文を最小にした版を新規に上げ、その後に本物の VSIX を Update で上げると通った。なので、初回の新規の上げが拒否されたら、README と説明文を最小にした VSIX を新規に上げ、検査（Verifying）が終わってから本物の VSIX を Update で上げる、と書く。試しの版や不要な版を外すときは Unpublish にし、Remove しない（名前が永久に予約されるため）とも書く。書くのは手順だけにし、手で作るときのコマンドは実際に動かしたものだけにする。

GitHub Release から入れた deguboard.deguboard の利用者には、ID が変わるため別の拡張として扱われることに注意する（必要なら README・usage の導入の手順を直す。README の Marketplace からの導入は t826 で扱う）。

## Acceptance criteria

- [ ] packages/vscode/package.json の name が deguboard-vscode で、mise run vsix で作った VSIX の extension.vsixmanifest の Identity の Id が deguboard-vscode になっている
- [ ] パッケージ名 deguboard を参照していた箇所（publish-extension.yml の pnpm --filter など）がすべて deguboard-vscode を指し、品質ゲートの検査が通る
- [ ] docs/development.md が拡張の ID を deguboard.deguboard-vscode と書き、「初めて出す前に、一度だけ準備する」に、新規の上げが拒否されたときに最小の VSIX を新規に上げてから本物を Update で上げる手順と、Remove せず Unpublish にすることを書いている
