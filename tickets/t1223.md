## Summary

active の Iteration はカンバンに 1 つに限るが、ほかに active があると planned の Iteration のチケットも claim で in_progress にでき（開始できない警告だけが出る）、active でない Iteration で作業が進む矛盾が起きる。「in_progress・review のチケットの Iteration は active でなければならない」を Core の固定の規則にし（Workflow の requires にはしない。既存の workflow.yaml に既定が届かないため）、着手と作業の状態への戻しで守る。抜け道（--override）は置かず、出口はチケットを active に移す（flow.assign）か今の active を閉じる（flow.release）の 2 つ。Iteration のないチケットは対象外（lint_iteration_missing が見る）。

## Acceptance criteria

- [x] 判定は git・ファイルを読まない関数に置き、経路（claim・move・戻し）と Iteration の状態（active・planned でほかに active あり／なし・closed）の組み合わせをその関数のテストで網羅する
- [x] claim（--without-branch も）は、チケットの Iteration が planned でほかに active があるとき拒否し、エラー文で「チケットを active の Iteration に移す」「今の active を閉じる」を案内する。--override でも越えられない
- [x] ticket move で todo から前へ進めるとき、claim と同じく、ほかに active がなければ planned の Iteration を開始し、あれば拒否する
- [x] done・abandoned から in_progress・review へ戻すとき、チケットの Iteration が active でなければ拒否する
- [x] ADR-031・ADR-009・requirements の IT-1、claim と move のヘルプ、guide-work の Iteration の警告の記述を新しい規則に書き換える
