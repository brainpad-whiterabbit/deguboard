## 概要

metrics show（Run・チケット・Epic・Iteration・Project・Agent・Model・Step で絞り、--by で同じ単位ごとに合計を出す）とは別に、どこに無駄があるかを探すための数を出すコマンドを core のコマンド定義に足す（名前は計画のときに決める）。出す数は、最初の受け入れ率（手直しの Run がないチケットの割合）、工程（Run の step：implement・review・fix）ごとのトークンと時間の割合、モデル・tier ごとの比較、Iteration ごとの推移、外れ値の Run とチケット。tier は Run になく Plan の項目（model/plan.ts）にあるので、Plan からたどる。PR の差分の行数は gh があるときだけ出し、ないときは missing に数える。数だけを出し、良し悪しは判定しない（ADR-029 の推定費用を持たない判断と同じく、解釈は人とエージェントに任せる）。Agentic-Agile の評価の枠組み（docs/evaluation-framework.md）の、活動ではなく成果を測る考え方に寄せる。要件が増えるので requirements.md を同じ PR で直し、判断は新しい ADR に書く（ADR は決めたら書き換えない。ADR-001）。

## 受け入れ条件

- [ ] Iteration・Epic・Project・期間で絞って、上の 5 種類の数を出せる
- [ ] `--json` で同じ数を出せ、CLI は core のコマンド定義を写すだけになっている
- [ ] gh がなくても動き、差分の行数は missing に数える
- [ ] 良し悪しの判定や推定費用を出さない
- [ ] requirements.md に新しいコマンドの約束があり、判断は新しい ADR に書いてある（ADR-029 の判断を変えるなら置き換えの印を付け、docs/adr/README.md の一覧を直してある）
- [ ] 集計のテストがあり、`mise run check` が通る
