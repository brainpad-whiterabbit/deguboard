## 概要

metrics show の合計とは別に、どこに無駄があるかを探すための数を出すコマンドを core のコマンド定義に足す（名前は計画のときに決める）。出す数は、最初の受け入れ率（手直しの Run がないチケットの割合）、工程（実装・見直し・手直し）ごとのトークンと時間の割合、モデル・tier ごとの比較、Iteration ごとの推移、外れ値の Run とチケット。PR の差分の行数は gh があるときだけ出し、ないときは missing に数える。ADR-005 のとおり数だけを出し、良し悪しは判定しない。Agentic-Agile の評価の枠組み（docs/evaluation-framework.md）の、活動ではなく成果を測る考え方に寄せる。要件が増えるので requirements.md と ADR-005 も同じ PR で直す。

## 受け入れ条件

- [ ] Iteration・Epic・Project・期間で絞って、上の 5 種類の数を出せる
- [ ] `--json` で同じ数を出せ、CLI・HTTP は core のコマンド定義を写すだけになっている
- [ ] gh がなくても動き、差分の行数は missing に数える
- [ ] 良し悪しの判定や推定費用を出さない
- [ ] requirements.md と ADR-005 に新しいコマンドの約束と判断がある
- [ ] 集計のテストがあり、`mise run check` が通る
