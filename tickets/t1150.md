## Summary

利用者が読む変更履歴は GitHub Release の本文だけ（CHANGELOG ファイルはない）。v1.2.0 の本文には Iteration の ID（「The s41 release」）、Internals・Tooling の段落、検査が通ったことの一文が入っている。これらを書かない規約と、残すものを、CLAUDE.md に置く。あわせて、`mise run vsix` が出す「Release の本文に貼る文」を英語にし（Release の本文は英語で書く規約に合わせ、手で訳さなくて済むようにする）、公開のたびに本文が規約に沿うかを確かめる場面を development.md の「タグと公開のチケット」に置く。比較リンクは規約に入れない。deguboard の利用者全体に向けた guide-release.md は変えない（製品の約束にするかは別に決める）。公開済みの v1.0.0〜v1.2.0 の本文は別のチケットで直す。

## Acceptance criteria

- [x] CLAUDE.md「コードの規約」の GitHub Release の本文の項に、本文は利用者向けに書き、内部の識別子（チケット・Iteration・Epic・Plan の ID、要件番号、ADR 番号）と、利用者に効果のない変更（テスト、検査の結果、内部の作り替え、開発ツール、貢献者向けの文書）を書かない、とある
- [x] 同じ項に残すもの（利用者に見える変化、互換性を壊す変更と移行の手順、セキュリティの修正、動かす条件の変化、利用者向け文書の変更、導入の方法と SHA256 の確かめ方）があり、内部の変更でも利用者に効果があれば効果として書く、とある
- [x] docs/development.md「リリース」節の Release の本文の手順が、規約を写さずに CLAUDE.md を指し、かつ「タグと公開のチケット」の受け入れ条件に「公開した Release の本文が CLAUDE.md の Release の本文の規約に沿う」がある
- [x] scripts/vsix-sha256.mjs が出す「Release の本文に貼る文」（SHA256 と確かめ方）が英語になり、test/scripts/vsix-sha256.test.ts がその英語の文を確かめる
- [x] mise run check:docs が通る
