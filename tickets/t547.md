## 概要

t533（PR #484）の 4 回目の見直しで残った指摘を直す。t533 は、見直しの上限を超えて指摘が残ったまま、人の指示でマージした。

いちばん大きい問題は、`dg next` の「実装・手直しの Run が実行中なら終わりを待つ」が、手直しの Run の閉じ方と合わないこと。手直しの Run は、直すエージェントのもう一度の claim が開き、push した後も、次の見直しの Run の開始か PR の ready を区切りにした `sync` まで開いたままになる。そのため手直しの後に `dg next` を呼ぶと、段階は fixed で kind は review なのに、commands が「実行中の Run の終わりを待つ（新しく起動しない）」に置き換わる。指示どおり待つと先へ進まない。止まるのは、修正ループの「手直し → 見直し」と、人のレビューの後の「手直し → 見直し」。失敗の後に開き直した手直しの場面も、実際には開いたままの Run になるので同じところで止まる。

直し方：待つ対象に入れる手直しの Run を、その Run の開始より後に push がないもの（`pushedAt` が undefined か `started_at` より前）だけにする。push の後は見直しを起動させる（見直しの開始がその手直しの Run を閉じる）。実装の Run は `ticket update --pr` が閉じるので、今のまま待ってよい。「作業の途中の push」と「直し終えた push」はデータでは区別できないので、その限界を help か guide に 1 行書く（途中の push を見直されたくなければ、親はサブエージェントが返るまで `dg next` を呼ばない）。

## 受け入れ条件

- [x] 開いたままの手直しの Run があり、その開始より後に push があれば、`dg next` が review の手（見直し役を起動する commands）を返す。push がまだなければ「終わりを待つ」を返す。両方のテストがあり、失敗の後に開き直した手直しのテストも開いたままの Run で書き直されている
- [x] 待つ手に置き換えるのは implement・review・fix・ready の手だけで、done・wait_deps・wait_merge では置き換えない。待つ対象の Run は `branch_at` より後に始まったものに絞る
- [x] `dg next --help` の「その手の Run が実行中なら待つ」が今の振る舞い（実装・手直しの実行中も待つ。手直しは push の前だけ）に合い、wait_human の条件の繰り返しの文に手直しの失敗が入っているか、重複が消えている
- [x] `NextStep.running_run` のコメントが「この手か、待つべき実装・手直しの Run」になっている
- [x] 途中の push と直し終えた push を区別できない限界が、help か guide-review に書かれ、`mise run check` が通る
