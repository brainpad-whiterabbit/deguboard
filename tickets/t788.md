## Summary

観点：アーキテクチャ・設定ファイル・文書と実装。t768〜t770 で足した所に、手で揃える写しと使われていない所が残っている。
- 速い経路のファイルの一覧が、`packages/vscode/vite.cli.config.ts` の `FAST_PATH_FILES` と `packages/cli/src/fast-hook.test.ts` の `ALLOWED` の 2 か所にある（今は同じ 13 件）
- bin/dg.js と bundle.ts が、キャッシュを有効にしてから速い経路を試し、受け持たなければ本体に回す同じ流れを持つ。cli の fast-hook.ts が output.ts のフックの書き方を写している
- `storage/remote-name.ts` が Store の config の読み方（誤りは既定値、マップでなければ上書きなし）を写している
- hook.ts の `handle` の `tool_requested` の分岐には処理が来ない。記録の流れが pre-tool-use.ts とほぼ同じ
- `HOOK_SESSIONS_DIR`・`DATA_WRITE_DENIED`・`DATA_BASH_DENIED`・`toolDenyReason`・`ToolRequestedView` の export がほかから使われていない
- core の fast-hook.ts と hook.ts の冒頭のコメントが、速い経路の入口として bin/dg.js だけを指す（t769 から bundle.ts も呼ぶ）
