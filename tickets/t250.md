## 概要

見直し（audit-s8、観点：アーキテクチャ・文書と実装）の指摘。

- packages/web/src/app.tsx:67（useLastHref）のコメントは「Iteration・Epic の ID は Project ごとの連番で、新しい Project でも通りうる」と書くが、DT-3（requirements）と ADR-002 では番号はリポジトリ全体で一意。挙動は lastHashUsable が Project の一致を見るので害はない
- web と core に同じ名前で意味の違うものが並ぶ：web の row-end.tsx の関数 planReadiness と core の planReadiness（commands/plan.ts）、web の plan-graph.ts の type PlanNext と core の interface PlanNext、web の config.tsx の matchesQuery(field, query) と core の matchesQuery(ticket, query)
- packages/web/src/test-helpers.ts の withPlanFacts は export されているが同じファイルの中でしか使われない（コメントは外から使う前提で書いている）
- depends_on の待ちの規則（WF-2。見つからない依存先は待ちに数える）を core の plan.ts の planReadiness と storage/store.ts の depsDone が別々に書いている

## 受け入れ条件

- [ ] app.tsx の useLastHref のコメントが DT-3 と食い違わない
- [ ] web の同じ名前の別物が、core の名前と区別できる名前になっている（例：readinessBadge・BandNext・fieldMatchesQuery）
- [ ] withPlanFacts の export とコメントが使い方に合っている
- [ ] depends_on の待ちの判定が core の 1 か所にあり、planReadiness と depsDone がそれを使う
- [ ] 画面とコマンドの振る舞いは変わらず、mise run check が通る
