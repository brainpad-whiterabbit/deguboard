## Summary

軸ごとのラベルの名前と 1 行の説明（語彙）を、データのブランチの `labels.yaml` に置く。最上位のキーをラベルの名前にして今のマージドライバを当て、別々のラベルを同時に足しても競合しないようにする。語彙を書く操作は Workflow の新しい項目 `governance.labels` で判定する。

## Acceptance criteria

- [ ] `labels.yaml`（最上位のキーがラベルの名前で、`axis`・`description`・`created_at`。統合の記録は `merged_into`・`merged_at`）をスキーマで検査し、マージドライバを当てるパスに足す。別々のラベルを両側で足してもマージで競合しないことをテストで示す
- [ ] `dg label list` が軸と語彙、語彙ごとの件数と最後に使われた日を出し、`--merged` で統合の記録、`--undefined` で語彙にない名前とその件数を出す
- [ ] `dg label add <name> --axis --description`・`dg label update <name> --description`・`dg label remove <name>` が語彙を書く。説明のない語彙・どの軸にもない語彙・手順の接頭辞（`audit-`・`retro-`・`release-`）・統合済みの名前・空白かカンマを含む名前を拒み、名前は小文字にそろえる（日本語は使える）。名前は軸をまたいで 1 つだけで、ほかの軸にある名前は拒む。remove はチケットが使っている語彙を拒む
- [ ] Workflow に `governance.labels`（既定は `always_ask`）を足し、語彙を書く操作をそれで判定する
- [ ] `dg label axis remove` は語彙が残っている軸を拒む
- [ ] requirements.md の 5.1 の配置に `labels.yaml`、5.8 と WF-7 に `governance.labels` を足し、docs/usage.md と docs/usage.ja.md にラベルの軸と語彙の節を同じ構成で足す
