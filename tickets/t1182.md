## Summary

軸ごとのラベルの名前と 1 行の説明（語彙）を、データのブランチの `labels.yaml` に置き、読めるようにする。最上位のキーをラベルの名前にして今のマージドライバを当て、別々のラベルを同時に足しても競合しないようにする。同期の経路の 500 行の規則により、語彙を書く側（`dg label add`・`update`・`remove` と `governance.labels`）は別のチケットに分けた。

## Acceptance criteria

- [x] `labels.yaml`（最上位のキーがラベルの名前で、`axis`・`description`・`created_at`。統合の記録は `merged_into`・`merged_at`）をスキーマで検査し、名前は軸をまたいで 1 つだけにする。読めない項目は止めずに `dg validate` で報告する
- [x] `labels.yaml` をマージドライバを当てるパスに足し、別々のラベルを両側で足してもマージで競合しないことをテストで示す
- [x] push が拒否されてリモートの変更を取り込み直すとき、同じラベルを両側で違う値に変えた `labels.yaml` の競合で止まり、`dg sync --resolve` で戻せることをテストで示す
- [x] `dg label list` が軸と語彙、語彙ごとの件数と最後に使われた日を出し、`--merged` で統合の記録、`--undefined` で語彙にない名前とその件数を出す
- [x] requirements.md の 5.1 の配置に `labels.yaml` を足す
