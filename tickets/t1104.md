## Summary

Epic e40 の方針を、照合が読む事実の導出に当てはめる。`packages/core/src/git/facts.ts` の `collectBranchFacts` は、ref の有無・tip と base の SHA・`merge-base --is-ancestor`・branch_base・status を読みながら、その中で branch_merged を決めている（同じ SHA、新しいブランチ、作業のないブランチ、祖先かの分岐）。`collectPrFacts` は PR を読みながら、その中で前の作業の PR を外す判定（branch_at より前の PR）をしている。

この 2 つの判定を読み取りから切り出すと、照合（t1105）の判定のテストが事実の型だけで書けるようになる。git の読み取りそのものは `packages/core/src/git/facts.test.ts` に残す。

## Acceptance criteria

- [ ] branch_merged を決める処理が、ref の有無・tip と base の SHA・祖先かどうか・branch_base・status を受け取る、git を読まない関数にある
- [ ] 前の作業の PR を外す判定が、PR の値と branch_at を受け取る、gh を読まない関数にある
- [ ] 2 つの関数の組み合わせをそのテストで確かめ、git/facts.test.ts と commands-flow-reconcile.test.ts から判定だけを確かめていた件を移す（git・gh を読む件は残す）。移した件と残した件の対応を PR に載せる
- [ ] dg sync の結果（状態の遷移・警告・記録）が変わらない
