## Summary

今の品質ゲートは、見直しが記録した SHA が作業ブランチのリモートの先端と一致するときだけ見直しを数える。ready の前に main を取り込むと先端が変わり、見直しのやり直しが要る。先端が「見直した SHA」と base のコミットを親に持つマージコミットで、tree が自動マージの結果と同じなら、前の見直しを数える。rebase は対象外とし、見直しをやり直す。自動マージの結果は、一時の worktree で見直した SHA に base をマージして作る（要件の git 2.30 以上では、作業ツリーなしで tree を作る merge-tree --write-tree が使えないため）。

## Acceptance criteria

- [ ] 先端が上の形のマージコミットなら、`dg gate` の review の条件と `dg next` の段階が前の見直しを数える（判定の組み合わせを純粋な関数のテストで網羅する）
- [ ] 競合を手で解いて tree が自動マージの結果と違うとき、取り込みの後に別のコミットがあるとき、rebase したときは、前の見直しを数えない
- [ ] 自動マージの結果を一時の worktree で作り、判定の後に worktree が残らない（git を通すテストで確かめる）
- [ ] `dg gate --help` の review の条件の説明と、requirements.md の RN-10 を直す
