## 概要

設定画面の自分のタブは、保存（config.set / config.unset）の後に `config show --fields` で読み直す。保存が通ったのに読み直しだけが失敗すると、同じ catch に落ちて「保存できない」と出て、実際は保存できているのに利用者を誤らせる。保存の失敗と読み直しの失敗を分けて伝える。あわせて、2 つの項目をほぼ同時に保存したとき、先に始めた読み直しの古い応答で画面を置き換えないようにする。p62 の t438 の見直しで出た範囲の外の指摘。

## 受け入れ条件

- [ ] 保存が通って読み直しだけが失敗したとき、保存できたことと、読み直せなかったことを分けて出す
- [ ] 保存そのものが失敗したときは、今までどおり保存できない旨を出す
- [ ] 2 つの保存の読み直しが逆の順に返っても、後に始めた保存の結果が画面に残る
- [ ] 上の 3 つをテストで確かめる
- [ ] mise run check が通る
