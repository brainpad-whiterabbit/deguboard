## Summary

Epic e40 の方針を、claim ともう一度の claim（reclaim）に当てはめる。

`packages/core/src/commands/ticket.ts` の `ticketClaim` の run は、`isReclaim`、status と assignee による拒否、許可の確認と事実の読み取り、ブランチが使えるかの確認（git）、base の tip（git）、更新を書き込みの中で混ぜて行う。`reclaim` は Run を開いた後、`packages/core/src/commands/run.ts` の `closePreviousFixRun` で前の手直しの Run を閉じる。その中で、`lastPushedAt`（fetch して読む）、`fixRunFinishedAt`（純粋）、別のセッションで開いた Run を interrupted にする判定、閉じる commit が混ざっている。

照合（K6）で決めた Run の閉じ方と同じ形にそろえる。commands-flow-reclaim.test.ts（19.4 秒・16 件）では、判定の組み合わせだけを確かめている件が約 6 件ある。

## Acceptance criteria

- [ ] claim の拒否（status、assignee、もう一度の claim かどうか）の判定が、git・ファイルを読まない関数にある
- [ ] 前の手直しの Run を閉じるか、その結果（success・interrupted）と finished_at を、push の時刻・セッション・区切りを受け取る読まない関数で決め、finished_at は fixRunFinishedAt で出す
- [ ] 判定の組み合わせをその関数のテストで確かめ、commands-flow-reclaim.test.ts から判定だけを確かめていた件を移す。移した件と残した件の対応を PR に載せる
- [ ] dg ticket claim の出力と書き込みが変わらない
- [ ] commands-flow-reclaim.test.ts の時間の変更前後を PR に載せる
