## Summary

作業ブランチに ID が入らず、チケットのブランチを ID で探せない。claim は `--branch` を省いたときだけ `feature/<id>-<slug>` を使い、渡された値はそのまま記録する。`dg next` と guide は `--branch <type>/<content>` を、development.md は `<種類>/<内容>` を案内するので、エージェントが渡す名前から ID が抜ける。dg がブランチ名を `<id>-<英語の内容>` に組み立てて強制し、その規則を dg の出力で案内する。このリポジトリは dg の規則をそのまま使い、development.md にブランチ名の決まりを書かない。チケットの外の作業のブランチ名は決めない。値は 50 文字まで。日本語の title から ASCII の断片を拾うと中身を誤らせるので、既定の slug は英語の title のときだけ作る。

## Acceptance criteria

- [ ] `ticket claim --branch` と `ticket update --branch` は、値の前に `<id>-` を付けて記録し、自分の ID と `-` で始まる値はそのまま使う（`--branch none` は今までどおり）
- [ ] 別のチケットの ID で始まる値と、英小文字・数字・ハイフン以外を含む値と、50 文字を超える値は拒まれる
- [ ] `--branch` を省いた claim は title が ASCII だけなら `<id>-<title の slug>`、ほかの文字を含むなら `<id>` になり、`feature/` が付かない。`BRANCH_IN_USE` の検査は組み立てた後の名前で行われる
- [ ] `ticket claim --help`・`ticket update --help`・`dg next`・`dg guide work` が、名前の形と値に使える文字（短い英語）を案内する
- [ ] requirements.md の ST-3 に名前の形の約束があり、development.md からブランチ名の決まりの一文が消えている
