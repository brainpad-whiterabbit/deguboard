## Summary

データのブランチ名（今は決め打ちの `deguboard`）を config の `git.data_branch`（省くと `deguboard`）で変えられるようにする。カンバン専用のリポジトリに `deguboard-webapp`・`deguboard-api` のようにリポジトリごとのブランチを置き、各コードのリポジトリが自分のブランチだけを取り込む。カンバンはリポジトリごとに独立し、番号・依存・Iteration・Epic はまたがない。

- 最初の init はデータを読む前に要るので `dg init --data-branch <name>` で渡す
- `deguboard` ブランチと ref の名前がぶつかるので、`/` を含む名前は拒む（`deguboard-<名前>` を guide で勧める）。名前はリモートの URL から自動では決めない
- t904 の移行の検出を、データのブランチ名の変更にも広げる（リモートとブランチ名を同時に変える移行も止まる）

## Acceptance criteria

- [x] `git.data_branch` を設定すると、init・sync・書き込み・外の変更の検出がそのブランチだけを使い、同じリモートのほかのデータのブランチを取り込まないことを、bare リモート付きの一時リポジトリのテストで示す
- [x] 1 つのデータのリモートに 2 つのコードのリポジトリが別々のブランチ名で init・起票・sync して、互いのカンバンが混ざらないことをテストで示す
- [x] `/` を含むブランチ名を拒み、理由と勧める名前を出す
- [x] 省いた既存のリポジトリは今と同じ `deguboard` を使う（既存のテストが通る）
- [x] 取り込んだ config で `git.data_branch` が変わったとき、push せずに止めて再実行を案内することをテストで示す
- [x] requirements の 5.1・SY-1・5.10、ADR-034、usage.md・usage.ja.md、guide に、専用のリポジトリで複数のカンバンを持つ使い方と、見る権限はリポジトリ単位で分けられないことを書き、guide の移行手順にブランチ名の変更を含める。requirements の 8（対象外）に、1 つのカンバンで複数のリポジトリを扱うことを足す
